## 命名规则

- 人工阅读的文档使用"编号 + 中文主题"，例如 `01-Provider适配框架.md`。
- `README.md`、API 路径、数据库字段和代码标识保留行业约定名称。
- 功能编号、需求编号和 ADR 编号必须保持稳定；移动文档不能改变这些追踪 ID。
- 尚未进入开发的版本只维护一份版本规划，进入开发门禁后才拆成功能规格。
- 历史材料必须放入 `99-历史归档`，不得与当前权威文档并列。

## 文档权威性

- **产品范围**：[版本总览](02-产品与版本/当前版本/V1-版本总览.md) > 功能主文档 > 实现状态
- **接口字段**：[OpenAPI](04-技术架构/当前版本/V1-openapi.yaml) > 接口契约文档
- **数据物理**：migration 文件 > 数据模型文档
- **架构决策**：[冻结决策](06-决策记录/V1-冻结决策.md) > ADR > 设计文档

当文档之间出现不一致时，优先采信权威级别更高的文档。发现冲突时应提出修订，而非自行判断。

实现进度与验证证据只在 [V1 实现状态](02-产品与版本/当前版本/V1-实现状态.md) 维护；其他文档中的勾选、百分比或“已完成”字样不作为进度依据。

> 目录说明：`04-技术架构/系统设计/` 与 `05-测试与发布/` 目前是空目录（未纳入 Git）。系统设计写在功能规格 §7 或 `04-技术架构/当前版本/`；测试策略、E2E 与发布门禁文档尚未建立，发布门禁暂见[版本进入开发门禁](02-产品与版本/版本进入开发门禁.md)与 V1 产品需求第 11 节。
