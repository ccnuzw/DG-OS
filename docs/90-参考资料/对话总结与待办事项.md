# 对话总结与待办事项

基于 2024-01-XX 完整对话记录，本文档提炼关键共识、决策和后续行动计划。

## 达成的核心共识

### 1. 产品定位

✅ **DGOS = 本地优先的 AI 应用开发框架**
- 不是操作系统，是应用框架
- 提供统一的 Provider/Skills/MCP 底层能力
- 支持可热更新的应用模块
- 本地优先，云端为可选增强

### 2. 技术架构

✅ **技术栈确定**
- 桌面：Tauri 2 + Rust
- 数据库：SQLite（不用 PostgreSQL）
- 前端：React + TypeScript + Vite
- 模块系统：Module Federation
- UI：Shadcn/ui + 统一设计系统

✅ **不使用的技术**
- ❌ QuickJS/Node.js（Skills/MCP 自己运行）
- ❌ PostgreSQL（本地优先）
- ❌ Redis（单机不需要）

### 3. 核心能力边界

✅ **Provider 适配框架**
- 我们开发：统一接口、多厂商适配
- 模型分类标签内置维护
- 支持多个同类型 Provider
- 排序和默认选择机制

✅ **Skills/MCP 管理**
- 使用现有标准，不重新实现
- 我们只负责：管理界面、安装、调用
- Skills/MCP 自己运行，返回结果
- Skills 是可选增强，非必选

✅ **模块系统**
- Module Federation 实现热更新
- 独立开发、独立版本管理
- 粗粒度权限控制
- 所有模块强制使用统一设计系统

### 4. 版本策略

✅ **V1.0 聚焦底层框架（3 个月）**
- Provider 框架
- Skills/MCP 管理
- 模块系统
- AI 工作台
- 系统设置

✅ **无限画布分多版本实现**
- V1.2：画布核心
- V1.3：节点系统
- V1.4：实时执行
- V1.5：工作流导入导出

✅ **生态系统后续完善**
- V1.5：应用市场
- V2.0：云端同步、协同编辑

### 5. 关键设计决策

✅ **已冻结 15 个决策**
- D001-D015 见 [V1 冻结决策](../06-决策记录/V1-冻结决策.md)
- 覆盖技术栈、架构、功能范围、运行模式

✅ **统一设计系统（强制）**
- 所有模块必须使用统一主题
- 禁止自定义样式覆盖
- CI 检查 + 人工审核

✅ **局域网协同**
- 始终开启 HTTP 服务
- 简单认证（用户名/密码）
- 远程设备只读模式
- 实时显示连接用户
