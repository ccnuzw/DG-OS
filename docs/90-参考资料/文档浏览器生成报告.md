# DG-OS 文档浏览器生成报告

浏览器文件是从 `docs/` 下 Markdown 生成的派生结果，不手工维护；内容与 Markdown 不一致时以 Markdown 为准。

## 当前产物

| 文件 | 内容 |
| --- | --- |
| `产品文档浏览器.html` | 查看器（总览、阅读、功能、图谱、演进、时间线 6 个视图）。查看器本身不含项目数据 |
| `产品文档浏览器-文档数据.js` | `window.SPEC_DOCS_DATA`：全部 Markdown 全文、功能清单、实现状态、决策、版本和能力主线，供 `file:` 离线打开。两个文件必须放在同一目录 |

## 生成方式

生成器是仓库内的 [`tools/spec-docs-pro`](../../tools/spec-docs-pro/README.md)（spec-docs-pro 2.0.0 的脚本与查看器原样拷贝），入口 `scripts/docs-tools.mjs`：

| 命令 | 作用 |
| --- | --- |
| `npm run docs:check` | 检查编号、链接与锚点、AC 与测试设计、分支追踪、状态词、演进矩阵、规划版本文档 |
| `npm run docs:browser` | 重新生成上面两个文件（有数据质量提示时失败） |
| `npm run docs:browser:check` | 在临时目录重新生成并与已提交文件比较，忽略生成时间；文档变化后忘记重新生成时失败 |

项目配置在 [`docs/spec-docs.config.json`](../spec-docs.config.json)：项目名、功能到能力主线的映射，以及忽略 REF001（原因见 [V1 需求编号 §3.4](../03-功能规格/V1/00-V1需求编号.md)）。

### 数据来源

| 浏览器内容 | 来源 |
| --- | --- |
| 功能清单 | 功能主文档 frontmatter（`feature_id`、`spec_status`、`risk`、`track`）和 §1 功能卡 |
| 实现状态 | [V1 实现状态](../02-产品与版本/当前版本/V1-实现状态.md) §3 的“编号”“状态”列，状态只用标准词（规划中 / 开发中 / 本地验证 / 待验收 / 已完成 / 阻塞 / 已废弃） |
| 能力主线与时间线 | [功能演进矩阵](../02-产品与版本/功能演进矩阵.md)：总览表加每条主线一张“阶段”表 |
| 版本 | 版本路线图、`当前版本/`、`后续版本/` |
| 决策 | [V1 冻结决策](../06-决策记录/V1-冻结决策.md) 的 `## Dxxx` 标题 |
