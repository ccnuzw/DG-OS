# AI 助手运行基础完善推进计划

> 文档性质：推进计划（实施范围），更新于 2026-11-10。用户已授权 ASST-F1～F6 全批次实施：**完善 AI 助手自身及公共运行基础，为未来服务更多场景做准备，不在本阶段开发场景应用。** 新增公开语义以[运行基础技术设计](../04-技术架构/当前版本/AI助手运行基础技术设计.md)及对应功能/接口契约为准；授权实施不等于授权任意外部调用，完成度以唯一实现状态记录为准。
> 本计划承接 [CHAT 持续完善方案](AI会话持续完善方案草案.md)，取代偏场景落地的[旧应用化计划](../99-历史归档/2026-11-09-AI助手应用化实施推进计划.md)。旧 `ASST-A1`～`ASST-A6` 及其子任务退出当前排期、保留编号；本文使用新的稳定局部标识 `ASST-F1`～`ASST-F6`，不是版本号、功能 ID 或正式 AC 编号。
> 本文只维护范围、顺序、任务与出口；实现进度、运行证据和阻塞集中维护于 [V1 实现状态](当前版本/V1-实现状态.md)。不因本计划提升 V2/V7 门禁，不将原 CHAT-P1/CHAT-P6 未完成的真实兼容与事实质量验收自动关闭。

## 1. 目标和边界

### 1.1 最终目标

使 AI 助手具有可靠、完整、可复用的执行基础。未来接入新场景时，主要新增：**业务上下文适配、业务工具和结果处理**；不需要复制模型/工具循环、审批机制、上下文预算或取消与恢复状态机。

用现有 **AI 助手与 provider-console 模型调试台** 验证复用。允许为消费新增基础能力调整这两个现有入口，不新增资料分析、笔记、画布、绘画或编程应用，不以测试专用接口代替真实消费者。

### 1.2 做与不做

| 本阶段建设 | 明确不纳入 |
| --- | --- |
| 公共运行契约、模型能力说明与一致的执行语义 | 通用 Agent 平台、多 Agent 团队、CLI 运行时复制 |
| 上下文来源、预算、受控引用及按需读取 | 知识库产品、向量数据库、默认跨会话长期记忆 |
| 统一工具接入机制、Skills 兼容与实际消费 | 画布/绘画/项目修改工具、任意 Shell、Skill 脚本/Hooks |
| 文本/结构化结果校验、受控资产引用与可靠交付 | 统一业务作品库、业务文档编辑器、图片生成服务 |
| 生命周期、核实、检查点与显式继续的复用 | 无人值守任务调度、自动跨应用执行、通用 DAG 引擎 |
| 调用来源、资源范围、配额与控制通道 | 自动提高并发、默认并行工具、默认扩大批准范围 |
| 真实兼容、任务质量和复用证据 | 用模拟结果宣布外部兼容、为达标自动反复重试 |

PDF/DOCX 解析、OCR、网页抓取不作为基础建设前置。输入验证使用现有文本和图片资产、固定 Skill 资源与受控工具结果。未来业务所需的专用解析或生成能力另行规划。

### 1.3 责任分层

| 运行基础负责 | 调用入口/未来业务负责 |
| --- | --- |
| 运行身份、能力准入、事件、取消、核实、终态 | 用户目标、呈现与业务完成条件 |
| 上下文装配、来源记录、预算与按需读取协议 | 经公开接口提供内容及其业务含义 |
| 工具循环、精确审批、超时、回执和 unknown | 工具的实际实现、对象权限、业务校验和补偿实现 |
| 输出结构检查、有限结果保留及交付核实 | 最终业务产物保存、编辑、发布与版本规则 |
| 可信来源绑定、逐步授权、资源限制 | 在宿主许可范围内选择能力；不能自授身份和权限 |

复用 `AiExecutor`、`AiService`、现有 Provider/Skills/MCP 与账户生命周期。聊天保留其消息、历史和会话仓储职责；模块不读取聊天私有数据库，不为复用能力创建隐藏聊天会话。不为统一名称强行重排所有入口或引入新 crate。

### 1.4 权威依据与规划输入

依据：[V1-FR-006](../03-功能规格/V1/02-应用模块/06-AI工作台.md)、[D136 公共 AI 技术设计](../04-技术架构/当前版本/D136-AI公共服务技术设计.md)、[D140 持续完善设计](../04-技术架构/当前版本/AI会话持续完善技术设计.md)、[D140/D141 决策](../06-决策记录/V7-冻结决策.md)、[版本路线图](版本路线图.md)。已有规格能覆盖的工作直接沿用；只有公开语义变化才补直接受影响契约和决策。

已识别的规划输入：聊天固定文本上限与附件导入额度存在差异；聊天与模块的按需技能、附件、摘要和恢复能力不等价；模块运行审计不能当作完整结果存储；模块资源满载下控制通道和细粒度资源范围需要完善。实施前绑定代码快照并核对现状，不能把这些输入泛化为所有路径均存在故障。

## 2. 六批推进与依赖

| 批次 | 核心目标 | 主要交付 | 进入条件 | 阶段出口 |
| --- | --- | --- | --- | --- |
| ASST-F1 基线与公共契约 | 明确已有能力、实际限制和共享边界 | 能力差异表、固定评测集、最小公共契约、首切片技术设计 | 当前实现与既有规格 | 本地基线可复查，下一切片语义可开发；真实未测项保留阻塞 |
| ASST-F2 上下文供给基础 | 不再只把聊天文本拼进请求 | 来源/版本引用、统一预算、按需读取、摘要有效性 | F1 对应契约及授权/资源底线明确 | 可解释实际输入和省略范围；超限、撤权、来源变化安全处理 |
| ASST-F3 工具与 Skills 基础 | 让不同能力沿同一安全循环工作 | 可信工具注册、统一调用/回执、Skill 需求与兼容、公共按需消费 | F1；依赖读取和大结果的部分先有 F2 | 宿主已有能力与 MCP 共用循环，无新业务工具和隐含授权 |
| ASST-F4 结果与交付基础 | 生成结果可以被调用方可靠处理 | 结构约束、校验、输出引用、有界保留、交付与核实 | F1；来源引用依赖 F2，工具结果依赖 F3 对应接口 | 不合格结果不冒充成功，断开后可核实，交付重试不重调模型 |
| ASST-F5 生命周期与资源控制 | 多入口接入后仍可停止、隔离和恢复 | 观察者/运行解绑规则、快照、显式继续、控制通道、配额与清理 | F1 安全模型；接续 F2～F4 的持久内容和回执 | 饱和与故障下控制可达，旧权限不复活，外部副作用不重放 |
| ASST-F6 双入口复用与质量收口 | 证明基础可复用且真实有效 | 两个现有入口真实消费、支持矩阵、质量对比、受影响消费者回归 | 从 F1 开始积累案例；最终收口依赖 F2～F5 | 无第二执行循环，支持范围有证据，未覆盖范围明确 |

依赖不是要求整批完成才开始下一批：F1 完成公共输入/授权契约后，F2 与 F3 的元数据及兼容部分可并行；F4 可先冻结结果契约；依赖正文读取、结果保留和检查点的实现再接续。只有共享契约和持久化语义必须先行。

**安全不等到 F5 再补。** F1 先明确每步授权、取消、资源上限和 unknown 不变量；F2/F3/F4 每次新增能力必须同时实现对应拒绝与撤销路径，不能先开放再补权限。F5 完成跨入口、饱和及重启的统一收口。F6 的评测和回归贯穿所有批次。

不承诺日历工期或虚构完成率。每次只冻结下一组可独立验证的任务，避免先写完全部未来规格才开始实现。

## 3. ASST-F1：能力基线与公共运行契约

| 任务 | 实施内容 | 交付与完成判定 |
| --- | --- | --- |
| ASST-F1-01 能力差异核对 | 对照聊天、单任务、`host.ai`、LAN 的输入、事件、工具、结果、生命周期和权限 | 按“已实现/只在某入口支持/未验证/不支持”分别描述；保留有意的权限差异，不追求所有入口能力相同 |
| ASST-F1-02 模型与协议能力说明 | 核对文本流、工具流、视觉、推理、结构化输出、窗口和用量的表示与来源 | 区分配置声明和实测证据；未知不当支持；不满足请求时外发前说明，不静默换模型或能力降级 |
| ASST-F1-03 固定基线评测 | 建立上下文、工具、Skills、输出、取消/恢复、隔离六组案例；复用已有 smoke | 每组含成功、边界和失败路径；人工标注期望事实/行为；记录样本、配置、费用及真实/替身等级，不用非空输出判成功 |
| ASST-F1-04 最小公共运行契约 | 明确调用身份、输入约束、能力需求、事件顺序、唯一终态、取消/查询权限、来源租约和交付边界 | 写入直接受影响接口和技术设计，确定原调用方迁移；新字段不允许携带可自授的 user/权限/system 身份 |
| ASST-F1-05 首切片决策与阻断修复 | 对实际发现的重复派发、越权、控制不可达或数据丢失优先定位 | 已有契约缺陷直接修复；公开并发/恢复语义变化先裁决；未关闭的风险阻断受影响能力，不能用新界面绕过 |

**范围控制：**本批只冻结公共边界及下一切片所需语义，不提前设计全部未来业务对象。能力说明是判断接口是否适用，不是允许模型自主换 Provider、扩大工具集合或增加费用。

**真实基线授权：**获准的 OpenAI-compatible、Anthropic 各至少一条路径；按声明支持的能力分别验证。MCP 使用获准只读服务和隔离可核实副作用服务。先明确端点、模型、测试数据外发范围、工具、调用次数/费用上限和停止条件；不默认使用生产凭据。缺授权只阻断真实部分，本地任务集和契约工作继续。

## 4. ASST-F2：上下文供给与预算

| 任务 | 实施内容 | 交付与完成判定 |
| --- | --- | --- |
| ASST-F2-01 上下文来源与引用 | 区分用户指令、历史、摘要、所选内容、Skill、工具结果；引用绑定内容来源、版本/摘要和允许读取范围 | 复用既有资产与资源服务，调用方提供引用不等于获得权限；内容文字不能变成宿主政策；不新增业务资料库 |
| ASST-F2-02 统一预算与准入 | 统一模型窗口、宿主硬上限、输出预留、图片、工具 schema、历史与结果预算 | 同一请求的检查与实际派发使用一致预算规则；区分估算和真实 usage；未知窗口/图片成本采取明确保守策略，不直接取消 24 KiB 保护 |
| ASST-F2-03 按需读取及覆盖记录 | 提供有界目录/范围读取，限制次数、累计字节与运行时间；固定源版本 | 能说明哪些片段实际交给模型、哪些省略；不得把“交给模型”说成“理解正确”；路径越界、版本过期和撤权时拒绝，无静默全文外发 |
| ASST-F2-04 摘要与任务进展有效性 | 复用已有显式摘要，明确来源范围/版本、保留约束和失效条件；适配非聊天输入的必要机制 | 原文不被摘要替代或删除；来源变化可核实；失败保留原数据；额外模型调用显式计入授权和预算，不默认自动摘要 |

**建议最小切片：**先让现有文本/图片资产及固定 Skill 资源以受控引用参与请求，再统一读取预算；不先引入检索引擎。图片只在模型确实支持且有授权时进入；不从图片引用推断具备 OCR 或图片生成能力。

**阶段场景：**Given 固定版本资源超过单次预算且包含嵌入式越权指令，When 用户选择范围并按需读取，Then 模型只收到获准且计量的部分，覆盖情况可查、越权指令不改变权限；来源改变或切账户后原引用不能继续读取。检查资料导入成功但请求不能容纳时的明确反馈。

## 5. ASST-F3：统一工具与 Skills 消费

| 任务 | 实施内容 | 交付与完成判定 |
| --- | --- | --- |
| ASST-F3-01 可信工具接入端口 | 复用现有共享循环与本地工具端口，统一 MCP 和现有宿主资源读取的注册、输入 schema、身份、事件与结果 | 不造第二工具循环；前端/模型不能任意注册宿主函数；实现工具与授予使用权分开；不新增业务写工具 |
| ASST-F3-02 工具副作用与失败语义 | 由可信宿主确定许可范围与风险类别，记录取消、结果查询、去重及补偿是否实际可用 | 先验证完整参数与 schema 再审批；批准绑定确切调用；未发出/成功/失败/unknown 分开；不能相信工具自称“只读”，不能承诺外部恰好一次 |
| ASST-F3-03 统一结果处理 | 共用大小上限、受控分段读取、结构与来源校验；保留失败及省略信息 | 大结果不无界复制或挤掉固定约束；非法结果不伪装成功；已有副作用不因结果解析失败重执行；持久结果沿 F4 契约 |
| ASST-F3-04 Skills 需求与兼容 | 明确技能的适用说明、所需能力与固定版本；公共入口复用按需正文/包资源消费 | 需求仅用于兼容检查，不自动绑定/授权 MCP；失效 pin 不换版继续；保留空技能和手选路径，无脚本或任意文件访问 |
| ASST-F3-05 技能效果回归 | 固定任务对比不用技能/使用固定技能的事实、格式、约束和成本 | 证明实际资源消费并人工核对任务改善；不把加载回执当质量证明；升级后重跑受影响任务，不自动追随新版本 |

**阶段场景：**在同一现有入口分别消费已授权宿主 Skill 资源和获准 MCP 工具；拒绝、过期、schema 变化、撤权及异常大结果都产生真实且一致的行为。已完成外部副作用后流断开，只核实，不通过新模型 call ID 自动重放。

本批不为“统一”降低 MCP 当前逐次审批强度；未来只读自动批准或范围授权须独立裁决。

## 6. ASST-F4：输出契约与可靠交付

| 任务 | 实施内容 | 交付与完成判定 |
| --- | --- | --- |
| ASST-F4-01 输出约束 | 支持普通文本和调用方声明的结构化结果约束，明确引用/资产引用与正文区别 | 使用有界 schema 与解析；模型原生结构输出支持不足时明确拒绝或按预先声明的生成后校验方式运行，不把 prompt 要求当强约束 |
| ASST-F4-02 校验与语义分层 | 区分模型结束、结构校验、引用校验、交付与业务保存 | schema 合法不等于事实正确或业务变更已批准；无效输出不触发副作用；不自动追加收费修复调用，不静默改结构凑合通过 |
| ASST-F4-03 有界结果保留 | 定义结果内容、引用、来源与运行绑定的有限保留/读取/过期方式 | 与普通审计分离，明确大小、期限、账户清理和权限；复用已有资产/内容存储能力，不建通用作品库；文件/图片引用仅指向真实存在且获准内容 |
| ASST-F4-04 交付核实与去重 | 明确客户端断开、交付确认丢失、读取失败及结果过期的处理 | 重连可核实是否生成和是否仍可读取；重复领取不重调模型、不重复工具副作用；过期/丢失不得解释成“未执行”，业务保存不在运行基础中假报成功 |

**开发前必须冻结：**结果保留是否为必需或显式选择、内容归属、存储上限/期限、访问主体、删除与已有消息/资产引用关系；确认回执的幂等与并发规则。若需要新 migration，只追加并验证旧库升级；不能把生成正文放进普通运行审计解决持久化。

**阶段场景：**Given 结构化输出不符合 schema，Then 明确校验失败并保留受控诊断，不调用应用变更。Given 生成已完成但终态响应丢失，When 在同一获准来源下查询/读取结果，Then 得到同一原运行的结果或明确过期状态，没有额外 Provider 请求。

## 7. ASST-F5：生命周期、安全与资源控制

| 任务 | 实施内容 | 交付与完成判定 |
| --- | --- | --- |
| ASST-F5-01 运行与观察者分离 | 区分切标签、隐藏、关闭文档、模块卸载、账户结束和进程退出；明确各入口取消/脱离观察规则 | 生命周期策略由宿主和已批准入口决定，不由不可信调用方任意设置；页面消失不被当作运行成功，脱离观察不等于获得后台自治许可 |
| ASST-F5-02 快照与重新观察 | 复用持久运行记录，明确快照/事件序号、晚到事件和结果读取 | 不要求建立无限事件日志；观察恢复不重新派发；新观察者不能据 run ID 获得取消、批准或内容访问权 |
| ASST-F5-03 检查点与显式继续 | 复用 D140 步骤和不重放机制，按需要提供给公共入口，不复制聊天仓储 | 新意图绑定原进展并重新准入；旧批准不复用；未决工具 unknown/审计异常阻断，人工报告不改写历史成功状态 |
| ASST-F5-04 来源与资源范围隔离 | 固定可信账户代次、调用来源和资源授权，分别定义读取/控制/交付权限 | 账户、模块、文档或资源范围由实际授权模型校验，不能只凭字符串 ID；撤权再授权不复活旧租约；同 JS realm 不宣传为沙箱 |
| ASST-F5-05 配额与控制可达性 | 明确活动运行、等待审批、在途工具、读取量、结果量和费用预算；为停止/核实提供有界可用路径 | 饱和下控制仍可达且不被无界控制请求耗尽；释放/取消不误占新代次配额；不通过无限扩容、提高超时或默认加并发掩盖问题 |
| ASST-F5-06 清理与故障恢复 | 验证正常退出、崩溃、保留期限、账号删除及迟到回执 | 存储/审计失败不谎报成功；清理不删除其他来源数据；取消不承诺撤销外部执行/计费；重启仅核实或显式新意图继续 |

**并发基线：**保持既有聊天生成槽和审批限制，只有独立评估证明需要且契约获批才调整。配额首先使用可信且可度量的调用、字节、时间和 Token 上限；没有可靠价格时只能展示估算，不能保证精确金额硬封顶，必须保留 unknown 用量。

**阶段场景：**两个现有入口交错运行，包含等待审批、资源满载、页面关闭、撤权、重新登录、终态丢失和进程重启；核实控制可达、结果归属正确、无跨来源内容泄露、无旧批准复活和重复副作用。故障注入可用受控本地服务，真实服务证据另列。

## 8. ASST-F6：双入口复用与真实质量验收

| 任务 | 实施内容 | 交付与完成判定 |
| --- | --- | --- |
| ASST-F6-01 现有入口逐片接入 | AI 助手与 provider-console 分别消费已冻结的共享上下文、工具、输出和核实能力 | 不要求 UI 相同或权限相同；模块无需创建聊天会话，不读取聊天私有状态；修改包按现有受控发布/升级规则执行 |
| ASST-F6-02 受影响消费者回归 | 核对聊天、单任务、模块和 LAN 的实际调用点 | 公共符号变化同批迁移调用方；不保留新的旧循环/别名兼容层；有意限制继续有效，尤其不扩大 LAN 与 CLI 权限 |
| ASST-F6-03 真实兼容和质量对比 | 沿 F1 固定任务集跑实际获准模型/MCP，人工核验摘要、技能、结构结果与约束保持 | 按 Provider/模型/配置及能力分别记录，不能用一个组合代表所有模型；本地、WebView、真实上游证据不互相替代 |
| ASST-F6-04 接入契约与示例 | 基于真实两个消费者整理能力选择、上下文引用、工具接入、结果交付和恢复的使用说明 | 示例沿生产 API，无测试专用后门；未来应用只补适配代码；维护说明不替代接口字段的权威定义 |
| ASST-F6-05 支持声明与持续回归 | 列支持能力、限制、平台、Provider/MCP 组合、权限前提和恢复方式 | 每次交付绑定代码/配置/Skill pin/schema 快照；协议或版本更新复验受影响集合，问题回到原责任任务，不自动重试粉饰成功率 |

### 8.1 评估与出口标准

- **确定性边界：**全部约定拒绝、去重、撤权、取消、交付与恢复用例通过；任一越权、重复副作用、unknown 报成功、结果串属均阻断对应路径，不用平均成功率抵消。
- **模型质量：**在首轮外部运行前固定输入、关键事实/约束、评分规则和适用组合；同任务重复运行，报告逐次结果和样本数。成功率与事实保持的数值门槛在 F1 基于用途明确后固定，不事后降低或删掉失败分母。
- **质量对比：**上下文整理不得凭空新增关键事实，技能应有实际消费证据，结构结果必须通过约定校验；模型正确性由人工核验，不只让模型自评。无法稳定完成的组合不进入支持声明。
- **时间与资源：**记录首个可见反馈、总耗时、人工纠正、审批负担、用量、费用与资源峰值；区分必要成本和新增机制成本。未知费用不记为 0；性能目标在实现前按相同负载和机器基线冻结。
- **复用证明：**两入口都实际运行获准能力，入口差异仅在适配/权限/呈现；没有第二工具循环、第二预算算法、隐藏聊天会话或绕开生产授权的演示路径。
- **交付诚实：**缺真实端点/额度授权时可以交付本地机制，但不能宣称全部兼容或本计划所有验收完成。保留原 CHAT 真实验收欠项并在同一状态来源闭环。

## 10. 实施组织与验证

## 11. 起手顺序与整体完成判定

### 11.1 下一次获准实施后的首批任务

1. **F1-01/02/03**：先核对真实能力差异，固定案例与本地基线，整理尚缺外部授权的矩阵；不开发应用。
2. **F1-04/05**：以“现有两个入口复用上下文和按需技能”为首切片，冻结最小输入/事件/权限边界并修复已确认的关键阻断。
3. **F2-01/02**：实施受控来源引用与统一预算，先覆盖已有文本/图片资产和固定资源；F3 的工具/Skill 元数据与兼容工作可在契约明确后并行。
4. **F2-03/04 与 F3**：补按需读取、摘要有效性和统一能力消费；每项同时验证拒绝、撤权与资源上限。
5. **F4/F5**：接续结构化结果、可靠交付、观察恢复和资源饱和收口；不得为赶进度跳过已定义的持久化/安全前置。
6. **F6**：两个现有入口逐片消费，并完成最终真实质量和复用验收；不以此启动场景应用开发。

外部端点、数据范围及额度未授权时，真实评测保持阻塞；本地基线、已冻结契约内实现和生产本地旅程可继续。用户确认方向不等于默认允许使用任何凭据或收费服务。

### 11.2 整体完成判定

- 两个现有入口能够通过公开能力消费上下文、工具/Skills、结果和运行核实，不复制核心循环或依赖聊天私有存储。
- 每项新增共享能力都有真实消费者与可运行行为证据，不交付未来才会使用的空接口、无状态实现或假结果。
- 生命周期、资源饱和、跨来源隔离、结果丢失/过期和显式继续具备可核实行为，无未关闭的关键安全/数据丢失风险。
- 真实 Provider/MCP 兼容及模型质量按支持范围完成验证；未覆盖的组合不宣称可用，旧验收欠项不被新编号掩盖。
- 未来应用接入说明明确三类适配责任：提供上下文、实现业务工具、处理最终结果；业务对象、作品管理、画布调度和 CLI 执行仍留各自领域。

最终交付说明只报告实际完成的能力、验证、支持限制和剩余阻塞。整体成果是可复用的运行基础，不是已经接入所有未来场景，也不是获得自主执行权限。
