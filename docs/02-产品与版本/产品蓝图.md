## 2. 产品概述

### 2.1 产品一句话

DGOS 是一个**本地优先的 AI 应用开发框架**，提供统一的 Provider 适配、Skills/MCP 管理和可热更新的模块系统，让开发者能够快速构建可扩展的 AI 应用，让用户数据完全可控。

### 2.2 产品使命

**让每个人都能拥有自己的 AI 应用平台，数据主权完全掌握在自己手中。**

我们相信：
- AI 应用不应该被云端服务商锁定
- 用户数据不应该被强制上传到云端
- 开发者不应该重复造轮子（Provider 适配、模块管理）
- 应用不应该因为架构问题而无法维护（避免单文件巨石）

### 2.3 产品愿景

**成为 AI 应用开发的标准框架，就像 React 之于 Web 应用、Electron 之于桌面应用。**

**3 年目标（2027）**：
- 开发者使用量：10,000+ 活跃开发者
- 应用模块生态：1,000+ 第三方应用模块
- 用户使用量：100,000+ 活跃用户
- 成为 AI 应用开发的首选框架

**核心价值主张**：
1. **本地优先**：本地数据与管理功能默认离线可用（调用云端模型仍需网络），云端为可选增强
2. **强制模块化**：从架构层面避免代码腐化
3. **开放生态**：应用模块可独立开发、热更新
4. **数据主权**：用户数据完全可控，不被锁定

### 2.4 我们不是什么

明确边界，避免范围蔓延：

- ❌ **不是操作系统**：不管理进程、文件系统、设备驱动
- ❌ **不是 AI 模型训练平台**：只调用现有模型，不训练模型
- ❌ **不是纯云端 SaaS**：本地优先，云端为可选增强
- ❌ **不是 Low-Code 平台**：专注 AI 应用场景，不是通用开发平台
- ❌ **不是办公套件**：不提供文档、表格、演示等功能
- ❌ **不是项目管理工具**：不提供任务、看板、甘特图
- ❌ **不是代码托管平台**：不提供 Git 服务器

### 2.5 核心差异化

| 对比维度 | DGOS | 云端 AI 平台 | 传统 IDE 插件 |
| --- | --- | --- | --- |
| **数据主权** | ✅ 本地优先，数据可控 | ❌ 数据必须上传 | ✅ 本地 |
| **可扩展性** | ✅ 应用模块热更新 | ❌ 功能由平台控制 | ⚠️ 插件受 IDE 限制 |
| **Provider 统一** | ✅ 统一适配层 | ⚠️ 各平台自己实现 | ❌ 无统一适配 |
| **离线可用** | ✅ 本地管理离线可用 | ❌ 必须联网 | ✅ 离线 |
| **跨应用共享** | ✅ Provider/Skills 共享 | ❌ 数据孤岛 | ❌ 仅 IDE 内 |
| **应用生态** | ✅ 独立应用市场 | ⚠️ 受平台限制 | ⚠️ 受 IDE 限制 |

## 3. 用户角色与场景

### 3.1 核心用户角色

| 角色 | 占比 | 核心需求 | 痛点 | DGOS 解决方案 |
| --- | --- | --- | --- | --- |
| **应用开发者** | 40% | 快速开发 AI 应用 | 需要自己对接各种模型 API | 统一 Provider 框架 |
| **插件开发者** | 20% | 扩展功能模块 | 缺少标准化框架 | 模块系统 + 热更新 |
| **最终用户** | 30% | 使用 AI 能力 | 工具分散、数据不互通 | 统一平台 + 数据主权 |
| **企业管理员** | 5% | 统一管理团队资源 | 无法管控成本和权限 | 组织管理（V5） |
| **集成者** | 5% | 接入新 Provider/Skills | 适配复杂 | 标准接口 + 文档 |

### 3.2 核心用户故事

#### 故事 1：应用开发者快速开发（P0）

```
作为一个应用开发者
我想要基于 DGOS 框架快速开发一个 AI 代码审查工具
这样我就不用自己处理 Provider 适配、模块管理等底层问题
而可以专注于代码审查的业务逻辑

验收标准：
- 1 天内搭建起可运行的应用
- 可调用任意已注册的 Provider
- 可使用 Skills/MCP 能力
- 应用可以打包发布到应用市场（V3）
- 用户可以热更新我的应用

价值：
- 开发效率提升 10 倍（从 2 周到 1 天）
- 无需关心底层适配
- 自动获得所有 Provider 支持
```

#### 故事 2：最终用户本地使用（P0）

```
作为一个隐私敏感的用户
我想要在本地使用 AI 工具，数据不上传云端
但我也希望可以选择性地使用云端增强功能
比如官方 Provider、跨设备同步等

验收标准：
- 默认本地运行；使用本地模型时无需联网
- 数据存储在我的电脑上（SQLite）
- 可选注册云端账号（V3），绑定本地用户与跨设备同步（V4）
- 局域网内可以协同工作
- 数据导出随时可以迁移

价值：
- 数据完全可控，不被锁定
- 隐私得到保护
- 灵活选择云端增强
```

#### 故事 3：插件开发者开发模块（P0）

```
作为一个插件开发者
我想要开发一个新的功能模块（如无限画布）
这样用户就可以通过应用市场安装我的模块
而且我的模块可以独立迭代、热更新

验收标准：
- 模块代码独立仓库管理
- 模块可以独立测试
- 模块更新无需重启 DGOS
- 模块可以声明所需权限
- 用户可以评分和评论我的模块（V3）
- 我可以查看下载统计（V3）

价值：
- 独立开发和发布
- 快速迭代
- 建立个人品牌
- 可能获得收入（V4+）
```

#### 故事 4：企业管理员统一管理（V5）

```
作为一个企业管理员
我想要统一管理团队的 AI 资源
包括 Provider 配置、成员权限、用量统计
这样可以控制成本、保证安全

验收标准：
- 创建组织并邀请成员
- 配置组织级 Provider（团队共享）
- 查看组织用量统计和账单
- 设置成员权限（Owner、Admin、Member）
- 审计日志（操作记录）

价值：
- 成本可控（统一配置、用量透明）
- 安全可控（权限管理、审计日志）
- 团队协作（共享配置、协同工作）
```

| 文件管理 | 只做 AI 资产管理，不做通用文件管理器 |

## 5. 核心流程

### 5.1 V1 最小用户旅程

```
新用户首次使用（10 分钟完成）：

1. 下载 DGOS-v1.0.dmg
2. 安装到应用程序文件夹
3. 首次启动，创建本地用户
4. 系统引导：添加 Provider
5. 输入 OpenAI API Key
6. 测试连接成功
7. 进入 AI 工作台
8. 输入提示词："写一个 Python 函数"
9. 查看流式响应结果
10. 查看历史记录

用户获得价值：
✅ 可以立即使用 AI 能力
✅ 数据存储在本地
✅ 本地数据与配置离线可用（调用云端模型需要网络）
```

### 5.2 V2 画布工作流

```
用户使用画布（V2）：

1. 打开画布编辑器模块
2. 创建新画布
3. 添加节点：
   - ImageNode（上传图片）
   - PromptNode（输入提示词）
   - LLMNode（选择 GPT-4）
   - OutputNode（查看结果）
4. 连接节点
5. （可选）在 LLM 节点选择 Skill 增强
6. 点击执行，实时查看结果
7. 保存画布
8. 导出工作流 JSON
9. 分享给团队成员

用户获得价值：
✅ 可视化编排工作流
✅ 复用和分享工作流
✅ 团队协作更高效
```

### 5.3 V3 应用市场流程

```
开发者发布应用（V3）：

1. 开发模块（遵循开发指南）
2. 本地测试通过
3. 打包模块（dgos build）
4. 登录云端账号（V3 提供，D040），提交到应用市场
5. 填写应用信息（名称、描述、截图）
6. 等待审核
7. 审核通过，应用上架
8. 查看下载统计和用户评论

用户安装应用（V3）：

1. 打开应用市场
2. 搜索"代码审查助手"
3. 查看应用详情（截图、评分、评论）
4. 点击安装（未登录时先登录云端账号，D010）
5. 应用自动下载并安装
6. 应用出现在侧边栏
7. 打开应用使用
8. 应用有更新时收到通知
9. 点击更新（热重载，无需重启）

生态价值：
✅ 开发者可以独立发布应用
✅ 用户可以方便地发现和安装应用
✅ 应用可以独立迭代
```

### 5.4 V4 云端增强流程

```
用户使用云端功能（V4）：

1. 登录云端账号（V3 应用市场起可注册，D040）
2. 绑定本地用户到云端账号
3. 选择使用官方 Provider（无需自己配置 API Key）
4. 查看积分余额
5. 调用模型（消耗积分）
6. 充值积分（支付宝/微信支付）
7. 查看用量统计和账单
8. 在另一台电脑登录
9. 自动同步已安装模块和配置
10. 打开画布，邀请团队成员协同编辑
11. 实时看到对方的操作和指针

云端价值：
✅ 无需自己配置 API Key
✅ 跨设备数据同步
✅ 实时协同编辑
✅ 但仍然本地优先（可选功能）
```

## 7. 技术架构概要

详见 [技术架构](../04-技术架构/总体架构.md) 和 [V1 冻结决策](../06-决策记录/V1-冻结决策.md)。

### 7.1 技术栈选型

**当前采用**：
- 桌面容器：Tauri 2（轻量、跨平台）
- 后端语言：Rust（性能、安全、强制模块化）
- 数据库：SQLite（零配置、单文件）
- ORM：SeaORM 1.1（类型安全、异步）
- 前端：React 19、TypeScript、Vite、Zustand

**规划（尚未引入）**：
- Web 框架：Axum（用于局域网 HTTP 服务，V1-FR-010）
- 模块加载：Module Federation（仅限受信任的本地模块包，见 D025/D028）
- UI 组件：基于 Shadcn/ui 的统一组件库（V1-FR-005，D008）

具体版本以[技术栈选型](../04-技术架构/技术栈选型.md)和仓库的 `Cargo.toml`/`package.json` 为准。

**明确不采用**：
- ❌ 内嵌 QuickJS/Node.js 等通用脚本运行时（技能内容不执行，见 D016；MCP 服务器按协议独立运行）
- ❌ PostgreSQL（本地优先，SQLite 足够）
- ❌ Redis（单机不需要）
- ❌ MinIO/S3（文件系统足够）

### 8.2 积分计费（V4）

## 10. 竞争分析

### 10.1 竞品对比

| 产品 | 定位 | 优势 | 劣势 |
| --- | --- | --- | --- |
| **DGOS** | 本地优先 AI 应用框架 | 数据主权、可扩展、强制模块化 | 新产品，生态待建立 |
| **LangChain** | AI 应用开发框架 | 生态成熟、文档完善 | 偏开发库，不是用户产品 |
| **Flowise** | 低代码 AI 工作流 | 可视化、易用 | 云端为主，数据不可控 |
| **n8n** | 工作流自动化 | 通用性强 | 非 AI 专用，学习成本高 |
| **Cursor/Copilot** | AI 代码助手 | IDE 集成 | 仅代码场景，不通用 |

### 10.2 护城河

1. **技术护城河**：
   - 强制模块化架构（避免代码腐化）
   - Module Federation 热更新（独特技术方案）
   - 本地优先 + 云端增强（兼顾隐私和体验）

2. **生态护城河**：
   - 应用模块市场（V3）
   - 开发者社区
   - 第三方应用生态

3. **数据护城河**：
   - 用户数据和工作流
   - 跨应用共享的 Provider 配置
   - 历史记录和使用习惯
