# V1.0 产品需求

## 1. 文档目标

本文档只定义 DGOS 第一版本（V1.0）功能。

本文档冻结 V1.0 交付范围。若 V1.0 子文档之间出现表述不一致，以 [V1 版本总览](V1-版本总览.md) 的范围口径为准；接口、数据表、架构和验收细节分别见同目录下的专项文档。

## 2. V1.0 定位

V1.0 建立本地优先的 AI 应用开发框架最小闭环：提供 Provider 适配、Skills/MCP 管理和模块系统基础能力，验证框架可扩展性。无限画布等核心价值功能分多版本完成，不阻塞 V1.0 交付。

### 2.1 核心目标

- ✅ 打通底层能力框架最小闭环
- ✅ 验证架构可扩展性
- ✅ 建立强制模块化规范
- ✅ 避免重蹈老项目覆辙
- ✅ 为后续版本打好底座

### 2.2 非目标

- ❌ 不求功能完整（画布、市场、协同延后）
- ❌ 不求用户规模（先验证架构正确）
- ❌ 不求商业变现（V2.0 才考虑）
- ❌ 不支持 Windows（V1.1 再做）

## 5. V1.0 核心流程

### 5.1 用户首次使用流程

```
1. 用户下载 DGOS-v1.0.dmg
2. 拖拽到应用程序文件夹
3. 双击启动 DGOS
4. 系统提示创建本地用户
5. 输入用户名、密码
6. 创建用户成功，进入主界面
7. 系统提示配置 Provider
8. 点击"去配置"，跳转到系统设置
9. 点击"添加 Provider"
10. 选择 OpenAI 兼容类型
11. 输入名称、base_url、API Key
12. 点击"测试连接"
13. 测试成功，保存 Provider
14. 回到主界面，打开 AI 工作台
15. 输入提示词："你好"
16. 选择模型：gpt-4
17. 点击发送
18. 查看流式响应结果
19. 查看历史记录
```

### 5.2 安装 Skill 流程

```
1. 打开系统设置
2. 点击"Skills 管理"
3. 点击"浏览 Skills 仓库"
4. 搜索或浏览 Skills 列表
5. 点击某个 Skill 查看详情
6. 点击"安装"
7. 输入配置（如 API Key）
8. 安装完成
9. Skills 出现在已安装列表
10. 回到 AI 工作台
11. 发起对话时，可选择该 Skill
12. Skill 增强生成效果
```

### 5.3 局域网协同流程

```
主机：
1. DGOS 启动时自动启动 HTTP 服务
2. 显示局域网地址：http://192.168.1.100:3000
3. 显示认证密码（随机生成或用户设置）

远程设备：
1. 打开浏览器
2. 访问 http://192.168.1.100:3000
3. 输入用户名、密码
4. 认证成功，进入 DGOS Web 端
5. 可以使用主机的 Provider、Skills、MCP
6. 可以发起对话
7. 可以查看历史记录
8. 不能修改 Provider 配置（只读模式）

主机显示：
1. 实时显示连接用户列表
2. 显示用户名、IP 地址、连接时间
3. 可以强制断开某个用户
```

## 6. V1.0 核心业务规则

### 6.1 决策引用说明

本章节引用的冻结决策详见 [V1 冻结决策](../../06-决策记录/V1-冻结决策.md)。决策编号以 `D` 开头，一旦分配永不改变。

### 6.2 Provider 管理规则

**配置与调用**：
- 用户可配置多个同类型 Provider（如多个 OpenAI 账号），通过拖拽排序，排序第一的作为默认选择（引用 **D012**）
- Provider 配置包含：名称、类型、base_url、API Key、重试策略
- API Key 必须加密存储（SQLCipher 或 AES-256）
- 调用失败时，可配置重试次数（默认 3 次）和指数退避策略（1s、2s、4s）
- 可重试错误：429 速率限制、5xx 服务器错误、网络超时；不可重试：401 认证失败、400 参数错误

**模型同步**：
- Provider 创建成功后，自动获取模型列表并缓存到 `models` 表
- 模型分类标签内置维护：`text-generation`、`image-generation`、`video-generation`、`audio-generation`
- 用户可手动刷新模型列表，缓存有效期 24 小时

**流式调用**：
- 流式调用返回 SSE（Server-Sent Events）格式数据
- 流中断时，保存已接收部分到数据库，避免用户看到的内容丢失
- 使用记录必须包含：tokens、latency、success、error_code

**边界约束**：
- V1 只实现 OpenAI 兼容适配器（引用 **D001** 技术栈决策）
- 不支持 OAuth 账号自动刷新 token（V2.0）
- 不支持图片生成（V1.1）

### 6.3 Skills/MCP 管理规则

**标准协议**（引用 **D005**）：
- Skills 使用 LangChain Tools 标准，MCP 使用 Anthropic Model Context Protocol 标准
- DGOS 只管理和调用，不执行 Skills/MCP 代码（引用 **D003**：不嵌入 QuickJS/Node.js 运行时）
- Skills 必须提供 HTTP API 或 CLI 接口

**安装与调用**：
- Skills 从远程仓库获取元数据（名称、描述、配置项）
- 安装时保存配置（如 API Key），加密存储
- 调用时通过 HTTP/CLI 调用远程 Skills，MCP 通过标准协议连接服务器

**可选增强**：
- Skills 在 AI 工作台中是可选的，用户可以不选择 Skills 直接调用 LLM
- Skills 调用失败不阻塞 LLM 调用，只记录错误日志

### 6.4 模块系统规则

**模块生命周期**（引用 **D004**）：
- 使用 Module Federation 实现运行时动态加载，无需重启应用
- 模块卸载：清理内存和事件监听器
- 模块热重载：更新后自动加载新版本

**权限模型**（引用 **D006**）：
- V1 采用粗粒度模块级权限：`providers.call`、`skills.execute`、`mcp.call`、`storage.read`、`storage.write`、`network.local`
- 授权时机：模块安装时用户一次性授权，官方模块自动授予所有权限
- 模块更新增加权限时需要用户重新授权

**设计系统强制**（引用 **D008**）：
- 所有模块必须使用统一设计系统 `@dgos/ui`，禁止 inline styles 或自定义 CSS 覆盖主题变量
- 主题切换（亮色/暗色）全局生效
- CI 检查：扫描模块代码，禁止出现 `style={{}}` 或自定义 CSS 变量
- 模块审核时检查视觉一致性

### 6.5 本地用户管理规则

**用户创建与隔离**：
- 本地用户无需邮箱，只需用户名和密码
- 密码使用 bcrypt 或 Argon2 哈希存储
- 每个用户有独立的数据目录，数据完全隔离，不能跨用户查询

**登录与会话**：
- 登录成功后生成 JWT Token，有效期 24 小时
- Token 到期前自动刷新，登出时清除 Token

**边界约束**：
- V1 不支持云端账号（V2.0）、邮箱验证、OAuth 登录、2FA

### 6.6 局域网协同规则

**服务启动**（引用 **D007**）：
- 桌面应用启动时自动启动 HTTP 服务，监听 `0.0.0.0:3000`（端口可配置）
- 只监听局域网，不暴露到公网
- macOS 首次启动时会弹窗询问防火墙权限

**认证与权限**（引用 **D013**）：
- 使用简单的用户名/密码认证（HTTP Basic Auth 或 JWT），默认生成随机密码
- 无认证不能访问任何接口
- 远程设备只读模式，不能修改 Provider 配置（引用 **D007**）
- 远程设备可以使用主机的 Provider、Skills、MCP，可以发起对话和查看历史记录

**实时状态**（引用 **D013**）：
- 使用 WebSocket 连接维持实时通信，心跳检测每 30s
- 断线重连：客户端自动重连，最多重试 5 次
- 主机显示实时在线用户列表（用户名、IP、连接时间），可强制断开某个用户

**边界约束**：
- V1 不支持实时协同编辑（V2.0）、画布协同（画布还未实现）、HTTPS（局域网内认为安全）

### 6.7 画布相关预留设计

虽然无限画布在 V1.2-V1.5 才实现，但 V1 需要预留架构接口（引用 **D009**）：

**从老项目学习**：
- 保留交互逻辑（拖拽、连线、缩放手感）
- 重做架构（避免单文件巨石，限制每个节点文件 < 200 行）
- 节点执行方式：实时执行（用户操作立即执行），非批量执行
- 支持循环节点（LoopNode）

**预留接口**：
- 画布数据模型：`projects` 表包含画布 JSON
- 节点类型注册机制：模块可以注册自定义节点类型
- 节点执行引擎：支持异步执行和状态管理

**演进路径**详见 [功能演进矩阵](../功能演进矩阵.md) 第 6 节：V1.2（画布核心）→ V1.3（10+ 节点）→ V1.4（实时执行）→ V1.5（工作流导入导出）。

## 7. V1.0 状态机与异常处理

### 7.1 Provider 状态机

```
[创建] → [测试连接]
         ├─ 成功 → [启用] ← 用户可禁用/启用
         └─ 失败 → [配置错误]

[启用] → [调用中]
         ├─ 成功 → [空闲]
         ├─ 401 错误 → [API Key 无效]（不重试）
         ├─ 429 错误 → [速率限制] → 重试（1s、2s、4s）
         ├─ 5xx 错误 → [服务器错误] → 重试（最多 3 次）
         └─ 网络错误 → [网络异常] → 重试
```

**重试策略**：
- 可重试错误：429 速率限制、5xx 服务器错误、网络超时
- 不可重试错误：401 认证失败、400 参数错误、404 未找到
- 重试次数：默认 3 次（可配置）
- 重试间隔：指数退避（1s、2s、4s）

### 7.2 Skills 安装状态机

```
[浏览仓库] → [查看详情] → [开始安装]
              → [下载元数据]
              → [配置参数]（如 API Key）
              → [保存配置]
              → [安装完成]

[已安装] ← 可启用/禁用
         → [调用]
            ├─ 成功 → [记录使用]
            └─ 失败 → [记录错误]（不阻塞 LLM 调用）
```

### 7.3 MCP 连接状态机

```
[未连接] → [连接中]
           ├─ 成功 → [已连接] → [获取工具列表]
           └─ 失败 → [连接失败]

[已连接] → [心跳检测]（每 30s）
           ├─ 正常 → [已连接]
           └─ 超时 → [断线] → [自动重连]（最多 5 次）
```

### 7.4 模块加载状态机

```
[未加载] → [加载中]
           → [验证权限]
           → [加载代码]
           ├─ 成功 → [运行中]
           └─ 失败 → [加载失败]（显示错误信息）

[运行中] → [卸载]
           → [清理资源]
           → [已卸载]

[运行中] → [热重载]
           → [卸载旧版本]
           → [加载新版本]
           → [运行中]
```

### 7.5 异常处理原则

**网络超时**：
- Provider 调用：默认 30s，失败后重试
- Skills 调用：默认 60s，失败记录日志但不阻塞 LLM
- MCP 连接：默认 10s，失败后自动重连

**数据完整性**：
- 使用记录必须保存：即使调用失败也要记录（success=false）
- 流式输出中断：保存已接收部分到数据库，避免用户看到的内容丢失
- 模块权限检查：未授权调用返回 403 错误

**用户友好错误**：
- API Key 无效（401）：提示"请检查 API Key 是否正确"
- 网络错误：提示"网络连接失败，请检查网络设置"
- 速率限制（429）：提示"请求过于频繁，请稍后重试"
- 模块权限不足（403）：提示"该功能需要授权，请前往设置授权"
