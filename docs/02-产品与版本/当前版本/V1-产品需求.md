## 1. 文档目标

## 2. V1.0 定位

V1.0 建立本地优先的 AI 应用开发框架最小闭环：提供 Provider 适配、Skills/MCP 管理和模块系统基础能力，验证框架可扩展性。无限画布等核心价值功能分多版本完成，不阻塞 V1.0 交付。

### 2.1 核心目标

- ✅ 打通底层能力框架最小闭环
- ✅ 验证架构可扩展性
- ✅ 建立强制模块化规范
- ✅ 避免重蹈老项目覆辙
- ✅ 为后续版本打好底座

### 2.2 非目标

- ❌ 不求功能完整（画布、市场、协同延后）
- ❌ 不求用户规模（先验证架构正确）
- ❌ 不求商业变现（V4 才考虑）
- ❌ 不支持 Windows（V1 发布门禁后补齐）

## 5. V1.0 核心流程

### 5.1 用户首次使用流程

```
1. 用户下载 DGOS-v1.0.dmg
2. 拖拽到应用程序文件夹
3. 双击启动 DGOS
4. 系统提示创建本地用户
5. 输入用户名、密码
6. 创建用户成功，进入主界面
7. 系统提示配置 Provider
8. 点击"去配置"，跳转到系统设置
9. 点击"添加 Provider"
10. 选择 OpenAI 兼容类型
11. 输入名称、base_url、API Key
12. 点击"测试连接"
13. 测试成功，保存 Provider
14. 回到主界面，打开 AI 工作台
15. 输入提示词："你好"
16. 选择模型：gpt-4
17. 点击发送
18. 查看流式响应结果
19. 查看历史记录
```

### 5.2 技能发现与使用流程

1. 打开技能中心，直接浏览随应用发布的官方分类库。
2. 需要扩展时选择预置来源，搜索并查看作者、许可、依赖和修订。
3. 确认安装；系统暂存、校验内容并发布不可变本地版本，失败可恢复。
4. 启用技能，在 AI 工作台选择与当前场景兼容的条目。
5. 宿主检查依赖与权限，固定版本并按需加载正文和必要资源。
6. 完成模型任务，记录所用版本与安全结果摘要；工具执行仍须授权。

官方基础包无需外站下载；第三方来源失联不影响本地列表。

### 5.3 局域网协同流程

```
主机：
1. DGOS 启动时自动启动 HTTP 服务
2. 显示局域网地址：http://192.168.1.100:3000
3. 显示认证密码（随机生成或用户设置）

远程设备：
1. 打开浏览器
2. 访问 http://192.168.1.100:3000
3. 输入用户名、密码
4. 认证成功，进入 DGOS Web 端
5. 可以使用主机的 Provider、Skills、MCP
6. 可以发起对话
7. 可以查看历史记录
8. 不能修改 Provider 配置（只读模式）

主机显示：
1. 实时显示连接用户列表
2. 显示用户名、IP 地址、连接时间
3. 可以强制断开某个用户
```

## 6. V1.0 核心业务规则

### 6.1 决策引用说明

本章节引用的冻结决策详见 [V1 冻结决策](../../06-决策记录/V1-冻结决策.md)。决策编号以 `D` 开头，一旦分配永不改变。

### 6.2 Provider 管理规则

**配置与调用**：
- 用户可配置多个同类型 Provider（如多个 OpenAI 账号），通过拖拽排序，排序第一的作为默认选择（引用 **D012**）
- Provider 配置包含：名称、类型、base_url、API Key、重试策略
- API Key 存入系统钥匙串，数据库只保存引用（D023 取代早期的 SQLCipher/AES-256 方案）
- 调用失败时，可配置重试次数（默认 3 次）和指数退避策略（1s、2s、4s）
- 可重试错误：429 速率限制、5xx 服务器错误、网络超时；不可重试：401 认证失败、400 参数错误

**模型同步**：
- Provider 创建成功后，自动获取模型列表并缓存到 `models` 表
- 模型分类标签内置维护：`text-generation`、`image-generation`、`video-generation`、`audio-generation`
- 用户可手动刷新模型列表，缓存有效期 24 小时

**流式调用**：
- 流式调用返回 SSE（Server-Sent Events）格式数据
- 流中断时，保存已接收部分到数据库，避免用户看到的内容丢失（当前实现：取消只产生一次 `stream_interrupted`，部分内容是否持久化尚待 FR-006 决策，见实现状态 PRE04-06）
- 使用记录必须包含：tokens、latency、success、error_code

**边界约束**：
- V1 只实现 OpenAI 兼容适配器（引用 **D001** 技术栈决策）；已由 D-待编号-A 修订：V1 实现 `openai_compatible` 与 `anthropic` 两种协议，接入任意三方兼容服务（草案，见 FR-001 §2.4）
- 不支持 OAuth 账号自动刷新 token（后续版本，路线图未分配）
- 不支持图片生成（后续版本，路线图未分配）

### 6.3 Skills/MCP 管理规则

**Skills（D016 替代 D003/D005 的旧 Skills 定义）**：
- 以 `SKILL.md` 为入口管理指令与资源，不要求 HTTP/CLI，不采用 LangChain Tools 作为技能内容标准。
- 官方内置、官方精选和第三方生态身份独立；统一分类，作者/来源/许可可追溯。
- 应用只调用 DGOS 本地技能服务，不直接访问第三方站点；预置来源不等于镜像整站内容。
- 安装、读取与执行分离；不嵌入通用脚本运行时，不自动执行下载脚本，密钥由凭据服务管理。
- 用户启用、应用/会话绑定与任务选用分离；任务锁定版本，不把所有启用技能全文注入。
- 可不选技能直接调用模型；显式选中技能不可用时不得静默忽略，需用户确认后继续。
- 详细安全、更新、卸载与副本规则统一引用 V1-FR-002 第 4 节。

**MCP（原边界不变）**：使用 Model Context Protocol 连接工具服务器；不因本次 Skills 重定义改变 MCP 协议或执行边界。

### 6.4 模块系统规则

**模块生命周期**（引用 **D004**）：
- 使用 Module Federation 实现运行时动态加载，无需重启应用；V1 只加载宿主发布器验证过的本地模块包，不加载任意远程 JS（D025/D028）
- 模块卸载：清理内存和事件监听器
- 模块热重载：更新后自动加载新版本

**权限模型**（引用 **D006**）：
- V1 采用粗粒度模块级权限：`providers.call`、`skills.execute`、`mcp.call`、`storage.read`、`storage.write`、`network.local`
- 授权时机：模块安装时用户一次性授权，官方模块自动授予所有权限
- 模块更新增加权限时需要用户重新授权
- D016 补充：模块权限不自动授予所加载的 Skill；工具动作仍经宿主授权，禁止自动执行下载脚本

**设计系统强制**（引用 **D008**）：
- 所有模块必须使用统一设计系统 `@dgos/ui`（FR-005，尚未创建），禁止 inline styles 或自定义 CSS 覆盖主题变量
- 主题切换（亮色/暗色）全局生效
- CI 检查：扫描模块代码，禁止出现 `style={{}}` 或自定义 CSS 变量
- 模块审核时检查视觉一致性

### 6.5 本地用户管理规则

**用户创建与隔离**：
- 本地用户无需邮箱，只需用户名和密码
- 密码使用 bcrypt 或 Argon2 哈希存储
- 用户数据隔离，不能跨用户查询（当前所有数据在单个 `dgos.db` 中按 `user_id` 隔离，身份由宿主派生，D023；是否改为每用户独立目录在 FR-008 设计时决定）

**登录与会话**：
- 登录成功后生成 JWT Token，有效期 24 小时
- Token 到期前自动刷新，登出时清除 Token

**边界约束**：
- V1 不支持云端账号（V3 起，D040）、邮箱验证、OAuth 登录、2FA

### 6.6 局域网协同规则

**服务启动**（引用 **D007**）：
- 桌面应用启动时自动启动 HTTP 服务，监听 `0.0.0.0:3000`（端口可配置）
- 只监听局域网，不暴露到公网
- macOS 首次启动时会弹窗询问防火墙权限

**认证与权限**（引用 **D013**）：
- 使用主机生成的随机访问凭据换取会话（D053 取代 D013 的用户名/密码、Basic Auth 与 JWT 表述）；远程会话使用主机的 `default-user` 数据
- 无认证不能访问任何接口
- 远程设备只读模式，不能修改 Provider 配置（引用 **D007**）
- 远程设备可以使用主机的 Provider、Skills、MCP，可以发起对话和查看历史记录

**实时状态**（引用 **D013**）：
- 使用 WebSocket 连接维持实时通信，心跳检测每 30s
- 断线重连：客户端自动重连，最多重试 5 次
- 主机显示实时在线用户列表（用户名、IP、连接时间），可强制断开某个用户

**边界约束**：
- V1 不支持实时协同编辑（V4）、画布协同（V2 画布之后）、HTTPS（局域网内认为安全）

### 6.7 画布相关预留设计

虽然无限画布在 V2 才实现（原计划 V1.2–V1.5），但 V1 需要预留架构接口（引用 **D009**）：

**从老项目学习**：
- 保留交互逻辑（拖拽、连线、缩放手感）
- 重做架构（避免单文件巨石，限制每个节点文件 < 200 行）

- 节点类型注册机制：模块可以注册自定义节点类型

## 7. V1.0 状态机与异常处理

### 7.1 Provider 状态机

```
[创建] → [测试连接]
         ├─ 成功 → [启用] ← 用户可禁用/启用
         └─ 失败 → [配置错误]

[启用] → [调用中]
         ├─ 成功 → [空闲]
         ├─ 401 错误 → [API Key 无效]（不重试）
         ├─ 429 错误 → [速率限制] → 重试（1s、2s、4s）
         ├─ 5xx 错误 → [服务器错误] → 重试（最多 3 次）
         └─ 网络错误 → [网络异常] → 重试
```

**重试策略**：
- 可重试错误：429 速率限制、5xx 服务器错误、网络超时
- 不可重试错误：401 认证失败、400 参数错误、404 未找到
- 重试次数：默认 3 次（可配置）
- 重试间隔：指数退避（1s、2s、4s）

### 7.2 Skills 内容与任务状态

```text
[目录项] → [确认来源/许可] → [固定修订下载暂存] → [安全校验] → [发布本地版本]
                             └─ 失败/中断 → [清理或恢复]，不产生错误就绪状态
[本地版本] → [用户启用] → [应用/会话选择] → [依赖/权限校验] → [任务版本锁定]
                                                   └─ 失败 → [提示并等待用户处理]
[任务版本锁定] → [按需上下文准备] → [模型消费/受控工具动作] → [记录与释放引用]
[更新确认] → [新版本校验发布]；旧任务继续旧版，更新失败保留旧版
[卸载] → [检查活动引用] → [无引用时清理下载包]；内置资源仅可禁用
```

不得用数据库事务替代文件发布恢复设计；完整规则见 V1-FR-002。

### 7.3 MCP 连接状态机

```
[未连接] → [连接中]
           ├─ 成功 → [已连接] → [获取工具列表]
           └─ 失败 → [连接失败]

[已连接] → [心跳检测]（每 30s）
           ├─ 正常 → [已连接]
           └─ 超时 → [断线] → [自动重连]（最多 5 次）
```

> 上图为早期草图。D021 冻结后的实施基线见 [FR-003 §3.3–3.4](../../03-功能规格/V1/01-底层能力/03-MCP管理系统.md)：ping 最长等待 5 秒，可恢复错误最多重试 3 次，手动断开后不自动重连。

### 7.4 模块加载状态机

```
[未加载] → [加载中]
           → [验证权限]
           → [加载代码]
           ├─ 成功 → [运行中]
           └─ 失败 → [加载失败]（显示错误信息）

[运行中] → [卸载]
           → [清理资源]
           → [已卸载]

[运行中] → [热重载]
           → [卸载旧版本]
           → [加载新版本]
           → [运行中]
```

### 7.5 异常处理原则

**网络超时**：
- Provider 调用：默认 30s，失败后重试
- 技能来源请求：超时与重试参数在技术设计确定，故障不阻塞本地浏览；选中技能加载失败则停止任务准备，用户确认才可无技能继续
- MCP 连接：握手超时 30s；仅曾成功连接且错误可恢复时自动重连（D021，详见 FR-003）

**数据完整性**：
- 使用记录必须保存：即使调用失败也要记录（success=false）
- 流式输出中断：保存已接收部分到数据库，避免用户看到的内容丢失
- 模块权限检查：未授权调用返回 403 错误

**用户友好错误**：
- API Key 无效（401）：提示"请检查 API Key 是否正确"
- 网络错误：提示"网络连接失败，请检查网络设置"
- 速率限制（429）：提示"请求过于频繁，请稍后重试"
- 模块权限不足（403）：提示"该功能需要授权，请前往设置授权"
