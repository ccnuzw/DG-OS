# V1 基础框架：版本总览

本文档冻结 DGOS 第一版本的交付范围。若 V1 子文档之间出现表述不一致，以本文档的范围口径为准；接口、数据表、架构和验收细节分别见同目录下的专项文档。

## 1. 版本定位

DGOS V1 建立本地优先的 AI 应用开发框架最小闭环：提供 Provider 适配、Skills/MCP 管理和模块系统基础能力，验证框架可扩展性。无限画布等核心价值功能分多版本完成，不阻塞 V1 交付。

### 1.1 架构基线

DGOS 是本地优先的可扩展 AI 应用框架。它提供统一的 Provider 适配、Skills/MCP 管理和模块热更新能力；桌面端与局域网 Web 端共用同一套前端应用包、设计系统和版本化 API。本地数据存储在 SQLite，云端服务为可选增强。Skills 和 MCP 使用现有标准，DGOS 只负责管理和调用，不重新实现协议。

### 1.2 核心原则

- **本地优先**：SQLite 单文件数据库，完全离线可用，云端为可选增强
- **强制模块化**：单文件不超过 1000 行，按领域拆分 crate，CI 自动检查
- **标准协议**：使用现有 Skills/MCP 标准，不重新发明轮子
- **热更新**：应用模块独立构建、动态加载，无需重启主程序
- **统一设计**：所有模块强制使用统一 Design System，禁止自定义样式

### 1.3 技术栈

| 层级 | 技术选型 | 版本 | 理由 |
|------|----------|------|------|
| 桌面容器 | Tauri 2 | 2.0+ | 轻量、跨平台、Rust 生态 |
| 后端语言 | Rust | 1.75+ | 性能、安全、强制模块化 |
| Web 框架 | Axum | 0.7+ | 异步、类型安全 |
| 数据库 | SQLite | 3.45+ | 零配置、单文件 |
| ORM | SeaORM | 0.12+ | 类型安全、异步 |
| 前端框架 | React 18 | 18.3+ | 生态成熟 |
| 前端语言 | TypeScript | 5.0+ | 类型安全 |
| 构建工具 | Vite | 5.0+ | 快速、HMR |
| 模块加载 | Module Federation | - | 动态加载、独立构建 |
| 状态管理 | Zustand | 4.0+ | 轻量、简单 |
| UI 组件 | Shadcn/ui | - | 无依赖、可定制 |

明确不采用：QuickJS/Node.js（Skills/MCP 自己运行）、PostgreSQL（本地优先）、Redis（单机不需要）、MinIO/S3（文件系统足够）。

## 2. V1 交付范围

### 2.1 底层能力框架（核心）

**V1-CAP-001 Provider 适配框架**
- 统一 Provider 接口定义（Rust trait）
- 模型列表获取与缓存
- 模型分类标签（文本/图片/视频/音频）
- OpenAI 兼容适配器实现
- 支持配置多个同类型 Provider
- Provider 排序与默认选择机制

**V1-CAP-002 Skills 管理系统**
- 从远程仓库获取 Skills 列表
- Skills 安装/卸载/启用/禁用
- Skills 配置管理（API Key 等）
- Skills 调用接口（HTTP/CLI）
- Skills 使用记录

**V1-CAP-003 MCP 管理系统**
- MCP 服务器连接管理
- 工具列表获取与缓存
- MCP 工具调用接口
- 连接状态监控

**V1-CAP-004 模块系统**
- 模块动态加载/卸载
- 模块热更新机制
- 模块权限管理（粗粒度）
- Module Federation 集成

**V1-CAP-005 统一设计系统**
- 主题系统（亮色/暗色）
- 色彩规范
- 字体规范
- 间距规范
- 基础 UI 组件库（10+ 组件）
- 所有模块强制复用

### 2.2 基础应用模块

**V1-APP-001 AI 工作台**
- 简单对话界面
- Provider 选择
- 历史记录查看
- Prompt 输入与提交
- 流式响应展示

**V1-APP-002 系统设置**
- Provider 管理界面
- Skills 管理界面
- MCP 管理界面
- 模块管理界面
- 主题切换
- 用户管理（本地用户）

### 2.3 运行模式

**单机模式（必须）**
- SQLite 本地存储
- 完全离线可用
- 简单用户隔离
- 本地 Provider 配置

**局域网模式（必须）**
- HTTP API 服务（始终开启）
- 端口可配置（避免冲突）
- 简单认证机制
- 远程设备只读使用
- 实时连接状态显示

**云端增强模式（V2.0）**
- 账号系统登录
- 官方 Provider 调用（积分）
- 应用市场下载
- 跨设备数据同步

### 2.4 明确不包含（后续版本）

| 功能 | 计划版本 | 原因 |
|------|---------|------|
| 无限画布完整版 | V1.2-V1.5 | 核心价值但复杂，分步实现 |
| 协同编辑（实时同步） | V2.0 | 需要 CRDT/OT，复杂度高 |
| 应用市场审核系统 | V1.5+ | 人工审核，后续完善 |
| 云端数据同步 | V2.0 | V1 本地优先 |
| Windows 支持 | V1.1 | 先保证 macOS 稳定 |
| 移动端应用 | V3.0+ | 焦点在桌面端 |

## 3. 核心流程

### 3.1 Provider 调用流程

```
用户发起调用
  ↓
选择 Provider（或使用默认排序第一个）
  ↓
权限检查（模块权限）
  ↓
Provider Adapter 调用
  ↓
返回结果 / 流式输出
  ↓
记录使用日志
```

### 3.2 Skills 使用流程

```
用户在应用模块中选择 Skills（可选）
  ↓
Skills Manager 查找已安装 Skills
  ↓
调用 Skills API（HTTP/CLI）
  ↓
Skills 自己运行并返回结果
  ↓
应用模块接收并展示结果
```

### 3.3 模块加载流程

```
应用启动
  ↓
读取已安装模块列表（SQLite）
  ↓
验证模块签名（V2.0）
  ↓
Module Federation 动态加载
  ↓
检查并授予权限
  ↓
模块注册到系统
  ↓
模块可用
```

### 3.4 局域网协同流程

```
主机启动 DGOS
  ↓
自动启动 HTTP 服务（可配置端口）
  ↓
远程设备访问 http://主机IP:端口
  ↓
简单认证（用户名/密码）
  ↓
远程设备使用主机的 Provider/Skills
  ↓
实时显示连接用户
```

## 4. 数据模型概要

### 4.1 核心实体

```
用户（users）
  ├── 本地用户（无需云端账号）
  ├── 可选绑定云端账号
  └── 创建时间、最后登录

Provider（providers）
  ├── 配置信息（名称、类型、base_url）
  ├── API Key（加密存储）
  ├── 启用状态
  └── 排序权重

模型（models）
  ├── 所属 Provider
  ├── 模型 ID
  ├── 能力标签（文本/图片/视频/音频）
  └── 同步时间

Skills（skills）
  ├── 名称、版本、类型
  ├── 端点配置
  ├── 分类标签
  └── 启用状态

MCP 服务器（mcp_servers）
  ├── 连接配置
  ├── 工具列表
  └── 连接状态

已安装模块（installed_modules）
  ├── 模块 ID、版本
  ├── 入口点
  ├── manifest 配置
  └── 启用状态

模块权限（module_permissions）
  ├── 模块 ID
  ├── 权限类型
  └── 授予状态

项目数据（projects）
  ├── 项目名称、类型
  ├── 数据（JSON）
  └── 所有者
```

详细 Schema 见 [V1 数据模型](../../04-技术架构/当前版本/V1-数据模型.md)。

## 5. 接口概要

### 5.1 Tauri Commands（桌面端）

```rust
// Provider
list_providers() -> Vec<Provider>
call_provider(id, model_id, request) -> Response

// Skills
fetch_skills_registry() -> Vec<SkillInfo>
install_skill(config) -> Result<()>
call_skill(skill_id, params) -> Result<Value>

// MCP
connect_mcp(config) -> Result<()>
call_mcp_tool(server_id, tool_name, params) -> Result<Value>

// 模块
load_module(manifest) -> Result<()>
reload_module(module_id) -> Result<()>
```

### 5.2 HTTP API（局域网）

```
POST /api/v1/auth/login          # 认证
GET  /api/v1/providers           # Provider 列表
POST /api/v1/providers/:id/call  # 调用 Provider
GET  /api/v1/skills              # Skills 列表
POST /api/v1/skills/:id/call     # 调用 Skill
GET  /api/v1/mcp/tools           # MCP 工具列表
POST /api/v1/mcp/call            # 调用 MCP 工具
```

详细 API 见 [V1 接口契约](../../04-技术架构/当前版本/V1-接口契约.md) 和 [V1 OpenAPI](../../04-技术架构/当前版本/V1-openapi.yaml)。

## 6. 关键决策

| 决策编号 | 决策内容 | 依据 |
|---------|---------|------|
| D001 | 使用 Rust 而非 Node.js | 强制模块化、性能、避免老项目单文件问题 |
| D002 | 使用 SQLite 而非 PostgreSQL | 本地优先、零配置、单文件 |
| D003 | 不使用 QuickJS/Node.js 运行时 | Skills/MCP 自己运行，我们只管理和调用 |
| D004 | Module Federation 实现热更新 | 成熟方案、独立构建、共享依赖 |
| D005 | Skills 和 MCP 使用现有标准 | 不重新发明轮子、生态兼容 |
| D006 | 权限模型粗粒度（模块级） | V1 简化实现，后续细化 |
| D007 | 局域网始终开启 | 简化配置，端口可调 |
| D008 | 统一设计系统强制复用 | 避免每个模块自定义样式 |
| D009 | 无限画布分多版本实现 | 不阻塞 V1，框架优先 |
| D010 | 应用市场人工审核 | V1.5+ 完善，暂不自动化 |

详细决策见 [V1 冻结决策](../../06-决策记录/V1-冻结决策.md)。

## 7. 验收标准

### 7.1 核心能力验收

- [ ] 可配置至少 1 个 Provider 并成功调用模型
- [ ] 可从远程仓库查看 Skills 列表
- [ ] 可安装至少 1 个 Skill 并成功调用
- [ ] 可连接至少 1 个 MCP 服务器并调用工具
- [ ] 可安装官方模块（AI 工作台、系统设置）
- [ ] 模块更新后无需重启即可生效
- [ ] 所有模块使用统一设计系统，无自定义样式

### 7.2 运行模式验收

**单机模式**
- [ ] 本地启动成功，无需网络
- [ ] SQLite 数据库正常读写
- [ ] 创建本地用户成功
- [ ] Provider 配置持久化

**局域网模式**
- [ ] HTTP 服务自动启动
- [ ] 远程设备可访问主机
- [ ] 简单认证通过后可使用
- [ ] 远程设备只读，不能修改配置
- [ ] 实时显示连接用户

### 7.3 性能验收

- [ ] 应用启动时间 < 2 秒
- [ ] 模块加载时间 < 1 秒
- [ ] API 响应时间（P95）< 200ms
- [ ] SQLite 数据库 < 1GB

### 7.4 质量验收

- [ ] 所有 Rust 文件 < 1000 行
- [ ] 所有 TypeScript 组件文件 < 500 行
- [ ] 零 P0/P1 安全漏洞
- [ ] 核心功能单元测试覆盖率 > 60%
- [ ] 文档覆盖率 > 80%

## 9. 风险与依赖

### 9.1 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Module Federation 不稳定 | 中 | 高 | 早期原型验证，准备降级方案 |
| SQLite 性能不足 | 低 | 中 | 限制数据量，优化索引 |
| Skills/MCP 调用失败 | 中 | 中 | 完善错误处理和重试机制 |

### 9.2 外部依赖

- Tauri 生态稳定性
- SQLite 兼容性
- Skills/MCP 远程仓库可用性

### 9.3 内部依赖

- 核心框架必须先完成
- Provider 框架是 Skills/MCP 的基础
- 统一设计系统必须在模块开发前完成
