### FR-004 第一阶段：runtime supervisor 与本地受信任加载

依据 [D033](../../06-决策记录/V1-冻结决策.md#d033-模块-runtime-supervisor-第一阶段本地受信任加载与热更新回滚)，技术设计见 [FR-004 §7.5](../../03-功能规格/V1/01-底层能力/04-模块系统与热更新.md#75-runtime-supervisor-第一阶段d033)。本阶段只完成 runtime supervisor 和本地受信任加载切片，**FR-004 整体未完成，AC01～AC15 均未通过**。

**已完成**

- 本地受信任加载：`ModuleLoader` 端口只接收 Publisher 构造的 `VerifiedModuleArtifact`；`runtime_handle` 改为 crate 内部，要求模块启用、pointer 与 DB 一致、存在 commit 写入的 `module_versions` 行且摘要一致；entry 收紧为包内 ASCII 相对路径，拒绝 scheme（`https:`/`data:`/`file:`）、`..`、绝对路径、反斜杠、查询/片段与百分号编码；canonical entry 必须仍在包内。`LocalArtifactLoader` 只做宿主侧 smoke 与 start 前摘要复核，不执行 JS。
- 在途请求：`ModuleRuntimeHandle::begin_request` 与状态转换同锁；`ModuleCapabilityDispatchService::dispatch` 统一执行准入 → 每请求新 request_id → `HostCapabilityService::authorize` → 操作 → 结算 `succeeded/failed/denied/interrupted`；删除 `authorize_handle`/`dispatch_handle` 捷径；drain 30 秒超时进入 `failed`，不取消、不重放，在途清零后释放加载器资源。
- 加载器释放 exactly-once：所有 `ModuleLoader::stop` 调用经 `release_runtime` → `ModuleRuntimeHandle::release_once`，同一 runtime 实例最多一次成功释放。后台释放（`report_failure`/drain 超时后）与显式 `stop` 并发时后者等待前者；失败或被取消的释放不记为已释放，runtime 保持 `failed`，下一次 `stop` 重试；已释放后 `stop` 为幂等 no-op；重复 `report_failure` 不产生第二次释放。状态机、请求终态、不重放与回滚语义不变。
- 热更新/回滚：stage → staged smoke → commit → 新 handle start → 切换 → drain 旧 runtime；启动失败按 commit 前快照 CAS 回滚指针、版本、摘要、manifest 与 entry，并记录 `activation`/`rolled_back` 事件；回滚失败时旧 runtime `failed`、`is_enabled=false`、移除 pointer 并记录 `disabled`；smoke 失败记录 `load_smoke` 且不改变指针/DB。无新 migration、IPC 或错误码。

- 供给原子性：`commit_with(FirstPublish{official:true, enabled:false})` 在首次插入的同一事务内写入；旧版本遗留的“与 pin 相同但非 official”的行被修复；中断提交遗留的版本目录被接管或重做；`uninstall` 对 official 返回 `1004023`。
- 崩溃可靠性：宿主先记 runtime failed 再写日志；自动禁用取数据库与进程内窗口较大值，被拒时后台退避重试直到被受理；`enforce_on_startup` 在自动加载前评估；页面端上报用同一 `call_id` 有界重试 3 次。
- React 精确版本：`HOST_REACT_VERSION` 由 `build.rs` 从 `package-lock.json` 取得（当前 `19.3.1`，此前手写的 `19.1.0` 与锁文件已不一致），锁文件缺失或版本非精确 semver 时构建失败；`contracts:check` 与 `npm run build` 前置检查已安装 react/react-dom 等于锁文件版本。
- 发布构建门禁：`npm run release:build`（`tauri:build` 同入口）在构建后对产物内实际资源目录运行 `verify_release_bundle`；`npm run release:verify -- <目录>` 供流水线使用。
