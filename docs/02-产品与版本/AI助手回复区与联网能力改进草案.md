# AI 助手回复区与联网能力改进草案

> 状态：已批准的设计输入（2026-11-11），实施边界以[D147](../06-决策记录/V7-冻结决策.md#d147-ai-助手回复执行体验与受控联网)、[FR-006 AC42～AC44](../03-功能规格/V1/02-应用模块/06-AI工作台.md#ac42-回复内连续执行与可达操作)及[技术设计](../04-技术架构/当前版本/AI助手回复与联网技术设计.md)为准。下文现状为2026-11-10设计前快照，不作为当前实现事实；实现与验证只见[V1实现状态](当前版本/V1-实现状态.md)。

## 1. 结论与目标

用户判断成立：**工具执行是回复的一部分，折叠呈现可以同时保留能力感与阅读效率；“任务详情”不应是普通用户理解执行结果的必经入口。**

产品目标：AI 助手是使用 DG-OS 自身运行基础的独立智能体。用户在一个对话工作面内提出目标、查看执行进度、处理必要授权、阅读有依据的结果，并继续处理未完成事项。不要求用户理解任务 ID、回执 JSON 或内部运行状态机。

改进分为三部分，而不是一次按钮改名：

1. **呈现闭环**：实时活动、完成记录和历史回看采用同一个回复内执行视图，消除生成前后断层。
2. **联网闭环**：搜索、网页读取、来源与引用作为一等产品能力，不把“用户可以自行找一个 MCP”当成完整联网交付。
3. **运行基础增量**：复用现有唯一模型/工具循环，补事件一致性、跨轮内容分段、来源绑定及运行预算，不新建第二套 harness。

## 3. 回复区交互方案

### 3.1 一个回复，三个阅读层级

- **默认层**：回答正文、必要的当前状态、完成后的轻量操作摘要、来源和可用产物。普通问答没有工具时不出现空执行卡。
- **展开层**：本次搜索/读取/调用的顺序、目标、结果节选、时间、失败原因和下一步。用用户能理解的动作命名，不以内部 phase 枚举做标题。
- **诊断层**：任务/步骤 ID、schema 标识、脱敏的技术回执等，放在消息更多菜单中的“诊断详情”。不得新增泄露原始敏感数据的入口。

执行过程和正文同列、同一回复归属；不是把整份任务弹窗搬进消息。模型文本与宿主状态使用不同数据源：模型可以说明意图，但“已执行/已完成/已读取”必须由真实记录驱动。

### 3.2 折叠与注意力规则

| 场景 | 默认展示 | 展开或操作 |
| --- | --- | --- |
| 普通问答 | 正文流式生成 | 无空步骤、无任务卡、无假计划 |
| 正在执行 | 一行当前动作，例如“正在搜索资料” | 展开查看已完成和当前步骤；停止按钮始终可达 |
| 正常完成 | “已搜索并读取资料 · 查看过程”等事实摘要 | 默认折叠成功步骤；用户主动展开后不因新事件自动收起 |
| 等待批准 | 显式“需要你确认”及动作目标 | 完整参数可检查；批准/拒绝不能藏在折叠里；长参数独立滚动 |
| 部分失败 | “部分资料未能读取”等影响说明 | 失败项可见，保留成功结果；是否继续由执行策略决定，不静默冒充全部成功 |
| 工具结果不明 | “操作可能已执行，暂不能确认结果” | 优先核查结果；没有权威核查能力时明确人工核实，不出现盲目重试 |
| 回答中断且无未决工具 | 保留已生成内容，标明回答未完成 | “继续处理”带入来源进度和新的用户意图，提交前说明新请求与费用 |
| 历史记录缺失/过期 | “详细记录不可用” | 不补造过程，不把无记录解释成未执行 |

聚合只改变展示，不改变调用次数或批准粒度；一组 3 次搜索的展示不等于批准 3 次调用。普通模型阶段不算作用户完成的“操作”，不使用不可证明的完成百分比。

### 3.3 工具调用与授权

工具行优先展示“动作 + 对象 + 状态”，例如“查询日历 · 今天”“读取网页 · example.com”。工具友好名称由可信适配器映射；未知 MCP 工具显示服务/工具原名，不根据名称猜测“只读”“安全”或“不会修改”。

审批与对应回复有明确视觉归属，但仅有一个可提交的批准控制点：

- 回复处显示目标、原因与待确认状态；必要时提供“前往确认”。
- 复用输入区上方的固定审批区域展示完整参数、期限、允许一次和拒绝；不重复渲染两套能提交的按钮。
- 窄窗和长参数下操作区仍可达；进入审批时焦点策略保留，流式消息不抢焦点。
- 批准后同一工具步骤转为运行/完成/失败；过期和拒绝都有明确状态。折叠、切页、查看记录均不批准调用。

结果按已知内容类型渲染：搜索来源列表、文本节选、文件/资产卡、简单表格等。未知结构用有界文本与可展开技术值兜底，不从任意 JSON 猜出危险的可执行按钮。只展示实际返回并通过权限/格式校验的产物，不能因模型写了一个路径就生成“已保存文件”。

### 3.4 继续处理与历史入口

- 完成回复的“任务详情”退出常驻操作条；普通执行记录留在回复内，低频诊断进入更多菜单。
- 会话级“执行历史”保留，用于查看无对应消息的运行、异常核实与排障；不维护另一套用户可编辑任务状态。
- 回复的“继续处理”把来源任务与新意图带回现有输入区，显示可移除的来源标记；使用同一发送和确认路径，不在详情弹窗另放一套聊天输入。
- 新请求重新准入、重新批准；沿原有续跑祖先链防重放。该保护不等于跨所有新对话的全局 exactly-once。
- 存在 unknown 工具或审计阻断时，不允许通过普通“继续”绕过。人工核查结果始终标成用户报告，不覆盖原始证据。

### 3.5 视觉与可访问性

沿用现有 `@dgos/ui`、主题 token、阅读域和代码域设置，不再引入新主题或组件库；保持回复与输入最大 920px 的既有对齐规则。成功步骤以紧凑行和浅层分隔呈现，不给每一步套大卡片。颜色仅辅助状态，文字和图标必须独立可辨认。

折叠支持键盘和正确的展开语义；长 URL 换行、代码内部横向滚动，不能撑宽回复。流式更新不重置用户展开项、不抢滚动；用户离开底部后显示新进展入口而不是强制拉回。阶段级无障碍播报合并更新，不逐 token 朗读。动效遵守减少动态效果设置。

样例中的“推理链”不作为默认模块：只在 Provider 确实提供允许展示的摘要/内容时显示并标明性质，不从工具日志虚构模型内心过程。

## 4. 联网查询方案

### 4.1 产品入口与执行链

输入区提供可理解的“联网查询”能力入口，展示关闭、可用、未配置、不可用等真实状态，显示实际搜索服务和可能的外发/费用说明。启用只改变本次可用能力，不立即发网络请求，也不等于已执行搜索或批准任意工具。

用户发送后，沿原有模型/工具循环完成：提出检索 → 宿主策略与授权 → 执行搜索 → 必要时读取具体网页 → 结果作为不可信资料供给模型 → 生成带可追溯引用的回答。简单事实不强制套完整研究流程；复杂查询是否继续搜索受次数、时间和内容预算约束。

### 4.2 接入方式与推荐取舍

| 方式 | 优点 | 限制 | 推荐定位 |
| --- | --- | --- | --- |
| 宿主受控 Search/Fetch 适配器 | 统一来源格式、网络边界、预算和交互；不要求用户理解 MCP 参数 | 需选定真实搜索服务，承担认证、价格、网络安全与解析实现 | 产品级默认能力的目标路径，复用现有执行核心和可信工具注册 |
| 已配置 MCP 搜索服务 | 可复用现有连接、审批、审计与工具调用 | 结果格式与安全质量不统一；宿主不能保证服务内部抓取的网络边界 | 保留为扩展后端；只有经过明确结果适配的服务才显示统一搜索/引用视图 |
| Provider 原生搜索 | 某些模型可直接搜索并返回原生引用 | 协议、计费、可见进度和取消支持不统一；当前适配器未接入 | 同一能力面下的独立后端，不用通用 function tool 冒充；按能力实测接入 |

推荐先交付一个真实、受控、可配置的搜索后端与网页读取链路，再扩展后端数量；不以三个空适配器代替闭环。D147已选定Brave官方API与用户独立密钥，公开HTTPS读取独立提供；外发和费用按请求级选择披露。普通用户获得的是明确的联网能力和配置指引，而不是“请自行安装某个 MCP”。

选择后端与执行授权是两回事：不静默跨服务降级，不因为某个服务超时就把用户查询发送给另一个服务。失败时说明实际使用的后端和下一步。

### 4.3 授权与隐私

当前所有 MCP 调用仍逐次完整参数确认，不能以 UI 优化为由修改。

建议为**受信任的专用搜索/读取适配器**另行评审“明确范围的一次联网授权”：绑定本次运行、选定服务、允许动作、公开网络范围与预算；在授权界面说明搜索词和指定 URL 将发往哪里。它不覆盖其他 MCP、登录态浏览器、私有网络、写操作或上传附件。模型、网页内容和 MCP annotations 均不能自授此权限。

未冻结该授权增量前，按现有逐次确认实现。若选择记住某一范围，必须另外明确存储、撤销和生效规则，不能把“记住工具选择”偷换成长期批准。

不自动上传整个对话、附件或凭据；搜索仅发送用户授权的必要查询。网页是非可信数据，其文字不能提升工具权限或要求读取本地秘密。浏览器自动化、登录态抓取和私网访问不包含在公开网页查询中。

### 4.4 来源与引用不是普通超链接

由宿主生成稳定来源 ID，至少绑定：本次运行/调用、真实 URL、标题、服务、检索/读取时间、结果类型、可用片段与截断状态。正文引用只允许引用本次实际取得且仍可授权查看的来源，不允许模型任意生成 ID。

- 区分“搜索摘要”“已读取网页正文”“用户提供材料”，不把搜索命中等同全文阅读。
- 回答中的引用点击打开轻量来源预览，显示标题、域名、相关片段、取得时间与打开原网页入口。
- 来源数量来自记录去重，不来自模型声称；网页发布日期未知时不使用抓取时间冒充发布日期。
- 网页已变更/删除、内容过期或仅存截断片段时明确说明；不重新联网伪装成原始证据。
- 来源真实与结论正确是两回事：技术校验可保证 ID、URL 和片段归属，不能保证模型的解读或引用支持度；后者需要质量评测。
- 无证据的结论明确区分推断，不把模型生成的链接包装成“已联网验证”。

### 4.5 搜索/读取的网络边界

新增宿主 Fetch 必须有独立网络策略：默认只允许公开 HTTPS、阻断 loopback/私网/link-local/云元数据地址、解析与实际连接地址绑定、每次重定向重新检查、限制跳数/响应体/解压后大小/耗时。不能只校验最初 URL。拒绝危险 scheme、内嵌凭据和未经允许的身份信息转发。

正文抽取不执行网页脚本，不自动加载跟踪资源，不共享用户浏览器 Cookie；只接收受支持内容类型，错误明确可见。搜索服务凭据沿宿主凭据管理，不进 DTO、SQLite 内容、前端日志或工具回执。

现有 MCP 服务端点的 HTTPS/重定向规则不等于该服务内部有 SSRF 防护；对外部 MCP 只能如实标注信任与能力边界，不能声称宿主控制了其全部网络访问。

## 5. Harness 增量设计

### 5.1 保留的执行与数据归属

沿用 D136/D140/D141：ChatManager 持有会话事务，AiService 持有模块公开服务入口，二者复用执行核心。聊天消息与模块临时正文保留策略分开；不复制执行循环，不建立隐藏聊天会话来服务模块，不搬用 CLI 原生权限。

工具执行、授权、结果供给与运行事实都在宿主产生；前端只负责受控呈现和提交用户动作。长期记忆、多智能体、任意 Shell、无人值守调度并非本次产品目标的必要前置。

### 5.2 具体增量

| 增量 | 设计要求 | 用户得到什么 |
| --- | --- | --- |
| 回复级运行投影 | 实时步骤与终态快照汇入同一按账户/会话/任务绑定的展示状态；持久来源为准；普通消息不逐条全量查询运行详情 | 完成后过程不消失，重开历史仍能查看 |
| 有序事件与补读 | 聊天事件增加运行内单调序号/版本；订阅与快照合并去重，缺口以只读快照补齐；终态封口后拒绝旧事件回退状态 | 断线、切页与迟到事件不会把完成改回运行或串到其他回复 |
| 跨轮内容分段 | 区分中间说明、工具阶段和最终回答；每段绑定运行/模型轮次；分别执行累计大小限制，历史保存规则明确 | 不把多轮文本拼成一个字符串再在终态突然替换 |
| 工具结果标准化 | 统一状态与已知展示内容类型；通用 MCP 保留安全、有界的兜底；诊断信息独立 | 看得懂结果，而不是默认看 JSON |
| 来源与供给账本 | 搜索结果/网页片段绑定来源和版本；区分取得、实际供给、答案引用；资料初始供给与实时补读都有可查询投影 | 知道依据来自哪里，也知道没有读取什么 |
| 运行预算 | 沿用现有次数/时长/上下文限制；搜索数、读取字节、总轮次明确计入；累计 token 观测与保守准入分开 | 不因搜索循环无界增加等待和费用 |
| 取消、核实、继续 | 保留已有阻断与防重放；支持有权威只读核查能力的适配器；无此能力时不伪装自动恢复 | 停止语义可靠，失败后有安全下一步 |

聊天当前无事件序号/重放游标；模块公共 AI 事件有 seq，但没有与聊天完全等价的逐步活动协议。新增共享事件字段需要同步两个实际消费者，不能只改前端类型后声称运行基础已统一。

现有工具核心总操作上限为 8（包括部分本地读取/分页读取），新增搜索不能默默绕过或提高它。应在真实任务评测后再决定是否增加可配置预算。没有可靠的实时 usage 或价格时，不显示“精确剩余费用”，更不能声称金额硬上限；达到保守预算先停止下一次派发并解释。

### 5.3 状态一致性与恢复边界

- 工具 dispatch 必须先落账，外部调用在事务外；结果确认后才进入下一模型轮。沿用现有语义。
- 页面查看历史和补读事件只读，不调用模型或工具。重启恢复观察，不恢复旧执行。
- 单一运行内明确完成、失败、取消、结果未知等终态；步骤成功不能直接推导整个用户任务成功。
- 取消可能只停止等待或发送取消通知，不代表远端撤销成功。未知状态不能被绿色完成图标覆盖。
- 展示缓存按账户 epoch、session/task/message 和版本隔离；切账户清理，迟到响应不得写回新账户。
- 新增持久字段只能追加 migration；旧运行无新字段时显示现有事实，不回填伪造网页来源或步骤。
- 宿主/Provider 重试、网络读取重试和用户重新发起必须区分。未知结果与已派发副作用不自动重放；专用只读请求的有限重试也需在适配器契约内声明，不能靠“搜索通常安全”推断。

事件最小投影是回复闭环的前置；来源与授权契约是联网接入前置。可以按依赖分批实现，但不能把只有静态卡片、替身搜索或只改按钮文字当作产品闭环交付。

正式实施需集中更新 V1-FR-001/003/006、受影响公共 AI 接口/数据模型，以及 V2-FR-009 的回复呈现分篇；风险较高的联网、授权和事件/迁移语义单独冻结后再编码。不以 UI 草案自动提高 V2/V7 门禁。

## 8. 本次核对、待决策与权威边界

### 8.1 本次实际观察

已读取上述原型/UICK 图片与代码，启动原型并在 Chromium 操作：1440px 与 800px 下展开/收起执行记录；点击演示授权；打开引用预览。两种宽度观察到文档宽度与视口相同；800px 下执行记录收起后摘要行为高为 24px；浏览器错误列表为空。

这些证据只证明已有原型的交互表现。原型重渲染会重建部分 disclosure 状态，因此不能据此宣称用户展开偏好已持久化；正式产品设计要求另行实现。审批为模拟调用、引用为演示资料，未调用真实 Provider/MCP/搜索服务，未运行产品测试或产品 E2E。现有生产能力判断来自静态代码核对，不提升 [V1 实现状态](当前版本/V1-实现状态.md) 中的外部验证等级。

UI/UX 指南搜索未命中精确的折叠状态规则；本文的渐进披露建议基于项目原型、现有 UI 和通用可访问性原则，不称为指南数据库已验证的结论。

### 8.2 实施前真正需要裁决的事项

1. **联网服务与交付方式**：推荐宿主受控 Search/Fetch 为默认目标；具体搜索服务、用户自带凭据还是产品提供服务、地区/费用/隐私条款需要明确。此项影响实际接入，不能由原型推导。
2. **联网批准粒度**：保守方案是现有逐次确认；推荐另行批准限定本次运行和专用只读联网适配器的范围授权，以免一次检索被多次打断。两者不能未经决定混用。
3. **来源保留**：推荐最小必要片段与元数据、按账户/会话权限保存，不默认永久缓存整页；具体额度、期限与删除语义需要纳入契约。

回复区信息重排和技术详情降级不需要等待服务商选择；新的网络权限和公开契约必须在实施前确定。
