## 1. 范围与用户流程

现有 CLI Agent 工作面升级为项目开发入口：导入已有目录、创建新空目录、克隆 Git 到不存在的目录；项目/最近项目、重命名显示名、归档/恢复、解除关联、失效目录重新定位。任务保存目标、完成要求和状态，可包含多个 Codex/Claude 会话；D143/D144 新入口由后台建立必要归属，不要求先填写任务。切换仅改变选中投影，不关闭原运行。重启只读恢复元数据、选择及工作现场；用户继续操作时，在有效精确工作区授权下自动恢复原绑定，不自动发送。

阶段1本身不实现代码编辑器、终端、worktree、绘画、编排、Git写操作或依赖安装；后续增量沿各节范围实施。读取目录与 Git 状态不执行项目脚本。CLI 启动消费 D144 精确工作区 Agent 授权，不再重复确认；原生配置保持不变，加载可能执行 Hooks 或启动 MCP，terminal/service 仍独立授权。

D144 五项菜单组合独立的任务方式与执行权限；规划/深度施加原生受限执行策略，所选 permission 意图可仍为 default，不能据此放开写入；全自动点击仅授权本会话，不继承新会话、不批准已有 pending。原生映射、Claude 非 OS 沙箱范围及用量/压缩证据边界见[D136 §17](../../04-技术架构/当前版本/D136-CLI能力切换技术设计.md#17-d144-输入模式与原生用量增量)。响应语言/精简/建议作用后续回复，跟随修改/流式/高亮只改呈现，主题复用应用外观；偏好保存不产生执行权限。原生统计未知不补零，费用实际/可靠价格预估区分；压缩只调用已支持的原生能力，受理不等于完成，失败/未知不改占用、不重放。本文规则不是新增验证通过记录。

## 2. 数据模型与状态

追加主库migration `m20261104_000026_project_tasks`，不修改历史migration。实施时000023～000025已由并行工作占用，逻辑契约不变，采用未使用的000026。

| 表 | 字段及约束 |
| --- | --- |
| development_projects | id UUID主键、owner、name（1～200字符）、path（规范绝对目录）、directory_identity（设备/文件标识）、archived布尔、created_at、last_opened_at；owner+path唯一 |
| development_tasks | id UUID主键、owner、project_id、goal（1～8192字节）、requirements（1～16384字节）、status、created_at；项目复合归属外键 |
| development_agent_sessions | id UUID主键、owner、engine、native_id、workspace、executable、model、project_id/task_id可空；project/task必须同时有值或同时为空，复合外键防串账户/串项目 |
| development_selection | owner主键、project_id/task_id/session_id可空；所有引用在宿主校验；解除关联清空对应选择 |
| development_migrations | key主键，旧索引导入成功标记 |
| development_project_operations | id、owner、kind（create/clone）、path、status（pending/succeeded/failed/unknown）、project_id可空；先记意图再操作磁盘 |

任务状态：todo / in_progress / blocked / review / completed / cancelled。用户可显式切换任意状态，包括重新打开；Agent完成一轮不自动完成任务。项目只有活动/归档两种持久状态；目录missing/changed/inaccessible及Git状态现场探测，不把暂时失效写成项目删除。

会话运行状态继续D127；任务关联不可随引擎回复变更。历史无任务会话project_id/task_id为空，显示待归类。显式归类只允许相同规范目录的自有项目任务，活动会话不可改归属。解除关联删除该项目任务元数据、将原生会话引用留作待归类，不删除代码或CLI原生历史。归档保留全部关联，禁止新运行；恢复后可用。

全部命令沿用可信main窗口、Workbench/TasksRun及宿主SessionResolver派生owner；不接受renderer身份、任意SQL、Shell、argv或环境。

| create_development_project | input: {kind: import/create/clone, name, path, source?}；返回项目 |
| update_development_project | input: {project_id, action: rename/archive/restore/unlink/relocate, value?} |
| inspect_development_project | projectId；返回path_state、kind、repository_root、branch、changes（porcelain列表）、truncated |

管理操作和Agent准入共用manager admission互斥，目录探测与新运行前校验身份。归档、解除关联、重定位、归类遇到仍未closed的相关会话返回project_busy；先由用户关闭运行。跨账户相同真实目录也不能绕过活动目录冲突：同目录只允许一个未closed的DGOS会话。外部编辑器不受该锁约束。

选择状态可以只选项目/项目+任务；选会话必须匹配整条链，待归类允许仅session_id。所有操作失败保留当前已提交数据，前端错误不自动重发。账户epoch阻断旧响应回填；账户结束沿D131撤销lease。

## 4. 目录、Git与外部副作用

导入和重定位canonicalize并记录目录身份；每次探测/启动核对，路径不存在为missing，同路径被替换为changed，需显式重新定位认可。普通目录支持全部任务/会话能力。Git固定argv、GIT_OPTIONAL_LOCKS=0、禁用fsmonitor和hooks；status --porcelain=v1 -z、branch及根目录探测，限时10秒、输出最多1MiB，超限明确截断。不得把Git故障误报干净仓库。

create/clone要求父目录存在、目标不存在且路径非符号链接替身；创建用create_dir，克隆用固定git clone参数，禁用hooks/模板与递归子模块，非交互、不启用ext协议或自定义SSH命令。克隆限时120秒，失败/取消不自动重试，不自动删残留目录；操作表保留path供用户核查，可显式导入残留。账户lease撤销时停止所启动的克隆进程。事务不跨进程等待；运行中崩溃留下pending，启动收敛unknown，不自动续跑。

## 5. 旧索引迁移

AgentManager只通过SQLite读写新索引，原JSON只读。启动先查全局agent-json-v1标记：有标记只读SQLite，不因旧文件变化重导；无标记时完整读取并验证Vec<SessionRecord>的UUID唯一、owner非空、合法引擎、绝对workspace。缺失文件按空集迁移。事务中插入所有记录（关联为空）并写标记，提交后才开放Agent与项目入口；旧文件原字节保留。不双写，不自动删除备份或自动降级。

JSON解析/读取、约束或数据库提交失败：回滚全部导入，保留旧文件和新库原数据，关闭本域准入并返回session_index_invalid/session_index_unavailable/storage_failed；其他应用域仍可启动。修复故障后重启重试。新库格式不支持、错误标记或损坏行不得当成空数据覆盖。回退旧应用不能读取新项目任务或新会话，必须备份并使用支持本契约的应用；旧JSON不是新数据的回滚副本。

## 7. 阶段2增量契约：编程执行与代码变更审查

用户于2026-11-04明确授权本独立切片，扩展D134的阶段边界；不代表V7整体门禁，不进入阶段3。沿用阶段1API、task_id、账户lease和同一真实目录一个未closed会话的准入规则；000026不可修改，SQLite继续为唯一写源。

### 7.1 基线与变更

首次向任务发送执行请求前，宿主校验owner→task→project及目录身份，在原生执行之前持久化一次任务基线；后续轮次和重启不得覆盖。已有历史任务在首次采用本契约时捕获，标注捕获时间，不能声称恢复过去的任务起点。基线包含可安全读取文件的内容摘要、受限文本及当时只读Git状态；不写工作区、索引或原生配置。任务期间变化相对于基线比较，开始前已有Git修改单列；两者可以同时成立。

文件时间重合、工具提及路径和模型自述均不是作者证明。默认标记“任务期间变化，来源无法确认”；在无执行期间观察到的变化可以标为“执行间观察到的外部变化”，仍不推断具体编辑者。未捕获、被忽略、敏感、超限、二进制或扫描不完整必须显式显示，不能伪装完整审查或干净目录。diff基于宿主读取的真实内容，删除保留基线；Git索引只读，重命名允许以删除/新增表示。

### 7.2 文件与权限

新增只读IPC：list_development_files(input:{project_id,path,query,include_ignored})、read_development_file(input:{project_id,path})、read_development_review(taskId)、read_development_diff(input:{task_id,path})、list_development_runs(taskId)。身份只由可信main窗口Workbench/TasksRun派生；宿主重新校验账户lease、项目归属、目录身份和相对路径，不接受任意绝对路径。文件树/文件名搜索不执行项目脚本，默认尊重忽略规则；显式展示忽略项不构成外发授权。拒绝父级越界、符号链接穿越、特殊文件和.git内部读取；大文件与二进制返回明确不可预览原因。敏感文件不自动快照或加入模型上下文。读取存在竞争时失败，不以检查前的路径授权竞争后的外部目标。

### 7.3 事件、执行与记录保留

每次用户执行请求以原有UUID request_id作为run_id，绑定owner/project/task/session/engine。展示工具名、文件操作、命令/cwd、输出、退出码、错误和原生运行终态；进行中与已结束区分。Codex本地消息与原生echo只展示一次；历史恢复保留原生消息。原生审批和问题请求ID独立于展示事件保留，仅对当前会话pending响应；拒绝和迟到响应不可改为成功。

追加000027保存基线和有界执行投影，不保存凭据、完整敏感输入输出或可在重启后重放的pending。输出按已知凭据模式脱敏并有界；每轮最多2000条/16MiB、每任务保留最近50轮，界面明确显示保留上限。基线扫描最多10000项/8MiB文本（同时限制JSON编码后文本8MiB）、单文件256KiB；路径及元数据预算384KiB，先达到任一上限即标记审查不完整。观察记录数据库上限1MiB，累计外部路径编码预算256KiB，超限保守丢弃归属并标记不完整。只读查看同样限制单文件256KiB。原生历史仍由CLI保留。解除项目关联和账户删除同步清理本域记录，不删除磁盘代码。

执行记录保存起止时间、状态、摘要、失败/阻塞原因、命令结果和代码快照标识。运行完成只建议待审查，失败/等待人工可标阻塞，不自动completed，不覆盖用户已完成/取消状态。只有实际工具命令和可确认结果可作为命令证据；模型“测试通过”不能建立通过记录，代码变化须使旧证据明确过期；无可靠退出码时标未知。应用重启将未完成执行收敛unknown，保留记录并由用户显式恢复原生会话，不重发未知请求，不重放审批。

### 7.4 控制与验收分支

切换项目/任务立即移除旧会话、文件、diff与审批投影；旧运行继续存在，迟到结果以账户epoch和选择代次丢弃。中断不回滚文件；继续是新的显式请求；关闭回收进程，恢复仍需目录信任。文件失败使用file_access_denied/file_not_found/file_too_large/file_binary/file_changed/scan_limit等稳定类别，存储失败沿storage_failed，错误不触发自动重发。

## 8. 阶段3增量契约：直接编辑、运行验证与开发服务

用户于2026-11-04授权本独立切片，扩展D134，不提升V7整体门禁，不进入阶段4。SQLite唯一写源；000026、000027不改，仅追加000028。阶段1/2的“不实现编辑/终端”限定于各自切片。

### 8.1 保存与目录协调

读取继续返回UTF-8文本和内容hash。保存输入project_id、task_id、path、expected_hash、text；仅保存已存在、可预览的普通文件，256KiB上限，沿用敏感文件、相对路径、目录身份、符号链接及特殊文件拒绝规则。宿主在共享admission下先捕获不可变任务基线，再以capability目录和不跟随链接的文件描述符校验读取版本；内容不符返回file_changed且不写入。保存前后校验路径身份，失败不自动重试；磁盘写入结果未知不能宣称未写。保存不修改Git索引或原生配置。

编辑草稿只驻留当前账户内存。切文件、项目、任务、页签和工作面关闭前提供丢弃确认，取消保留草稿；保存失败保留草稿。冲突展示本地草稿与重新读取的磁盘内容，重新加载需明确丢弃草稿；无强制覆盖按钮。外部程序不遵守宿主锁，不承诺锁住外部编辑器或任意跨进程原子CAS。

2026-11-10 文件详情交互细化（沿 D143，用户确认）：文件默认浏览，顶部提供“编辑文件”、源码/预览和更多菜单中的“从磁盘重新加载”；正常浏览不显示只读警告。显式编辑时由系统关联必要任务，成功后才进入可编辑态，不因此启动 CLI 或发送消息；失败保留文件与位置，结果未知仍只核实原记录。底部固定“添加到对话”，支持整个文件、选中行及仅路径；添加只更新对话材料并聚焦输入框，保留原问题，实际发送仍由用户触发。有未保存修改时使用明确的“保存并添加”，保存失败不添加，成功后引用新磁盘版本。选区行号按完整行范围呈现。

关闭文件、取消编辑或重新加载涉及脏草稿时，提供“保存并继续”“放弃修改”“返回编辑”。保存失败或等待期间出现新编辑时不继续关闭/替换；冲突、恢复待校验及写入占用期间不允许借该入口绕过保存保护。文件标签切换保留各自草稿，持久化边界沿 D143 的账户私有工作现场；本段细化上述早期仅内存/丢弃确认口径。浏览、编辑、未保存与保存成功使用普通状态文字，只有真实失败与外部版本冲突使用警示。窄面板底部操作可换行，源码独立滚动，顶部与添加操作保持可达。

### 8.2 PTY、命令与服务所有权

统一宿主执行输入：request UUID、task_id、kind（terminal/command/service）、program、args数组、cwd项目相对目录、env引用（目标变量→宿主环境变量名）、trust_workspace；不得输入环境秘密值。显式shell通过program/args表达，不隐式拼接。项目命令配置只存程序/参数/相对cwd/环境引用；识别package.json scripts与Cargo测试/构建候选不运行、不安装。配置和执行DTO不返回环境值，引用的秘密值仅驻留运行时内存并从输出投影移除；其余输出沿已知凭据模式脱敏，有界保留并明确截断，不承诺识别任意秘密。

产品化第1轮收口：read_development_commands接收task_id，save_development_commands输入task_id与commands；宿主由任务绑定解析并校验实际目录，package.json/Cargo.toml发现与执行使用同一任务根。保存配置仍按owner/project复用，相对cwd以当前任务目录解释。open_development_external必须提供project_id和task_id，编辑器打开宿主校验后的任务根；preview还核对process的project/task归属。

真实PTY支持原始输入、尺寸调整、输出和退出码；账户/project/task/request实例绑定，切换后按实例重新读取，不重发输入。宿主执行复用development_runs模型，session_id可空，engine=host，source区分native_agent/host_terminal/host_command/host_service；不伪造原生Agent会话。执行详情包含实际命令、cwd、起止时间、退出码、取消结果、有界输出及代码指纹；配置为独立development_commands表。

进程只在本次启动实例中持有可回收child及独立session/进程组；停止只作用于当前持有的所属进程树，不用持久PID认领或杀进程。停止有宽限及强制回收；未确认回收显示unknown/cleanup_pending并保留目录占用。页面关闭/选择切换不停止；显式停止、账户lease撤销和应用shutdown停止所属PTY/命令/服务。应用重启未完成记录收敛unknown，不重放命令、输入或重启服务。此机制不是进程沙箱，显式setsid及双重fork脱离所属session的程序不在可保证回收范围内；不得以扫描到的旧PID追杀脱离实例的进程。

服务状态starting/ready/failed/exited；ready必须通过配置的loopback HTTP就绪探测（明确端口、path及超时），进程存活不算就绪。启动前探测端口冲突，失败不终止其他进程；HTTP探测前后核对监听者属于本次仍持有的session，避免将争抢端口的其他服务标ready。macOS依赖系统/usr/sbin/lsof，Linux读取/proc；无法确认归属时不标ready。探测超时/进程提前退出保存失败原因并清理本实例。仅ready实例提供外部浏览器预览，URL由宿主推导；不内嵌项目网页。外部编辑器采用宿主公开opener入口：用户明确输入编辑器应用名称/可执行文件路径，以该应用打开当前校验过的任务工作目录；不自动执行项目配置中的命令。

任务目标/要求、项目能力、交接摘要、workspace提交说明及命令配置草稿按当前账户epoch与所属对象驻留内存；内部标签和任务切换保留，账户切换清空。明确丢弃、替换命令草稿、工作面关闭及项目解除关联前确认受影响草稿；文件切换使用文件专属文案。命令首次保存派发前固定command ID，成功回执归并到原project/task草稿；再次保存更新原ID，迟到回执不覆盖后来内容或另选命令。

### 10.1 工作目录身份与并发

### 10.2 Git审查、写入与执行信任

宿主读接口分离浏览快照与写入审查：列表返回分支、HEAD、结构化逐文件索引/工作区状态、未合并项、合并头及 `snapshot_token`，不随列表读取索引或工作区完整补丁。点击文件沿既有逐文件 diff 入口读取；大文件、二进制或受保护文件的正文失败不阻断其他文件列表。写操作仍先读取严格 `GitReview`，要求完整索引及原始文件哈希/模式/目录身份，按同一 `snapshot_token` 核对用户所见状态后使用 `review_token`；读取不完整不能获得写入权限，不能用脱敏展示或截断内容授权。任务首次Git写操作前捕获初始索引树，已有暂存路径单列；commit必须明确确认完整索引及其中原有暂存内容，不能默认混入。stage/unstage只接受明确的普通文件相对路径；使用literal pathspec，禁止通配参数、越界、.git、符号链接和子模块递归。无add all入口。提交、推送、切分支、合并均为用户单独动作；不由任务完成或Agent回复自动触发。提交前按版本摘要重检全部索引，提交消息及引用作严格数据参数校验，不接收任意Git argv。

Git hooks、fsmonitor、自定义diff/textconv、签名、credential helper和仓库过滤器可执行项目配置，读取及默认写操作禁用；执行可能含外部传输的push须再次明确目录/网络信任，不在renderer存秘密。当前宿主Git交付不执行项目自定义hooks/过滤器，存在必需过滤器时拒绝，用户可在明确受信任终端中处理；不静默产生不同过滤内容。push仅允许已配置的合法remote及当前本地分支的显式非强制refspec，禁用ext与自定义SSH命令，不自动重试或强推。普通非Git项目继续编辑/执行，不自动git init。

切分支、合并要求目标目录无未提交/未跟踪内容且无活动执行，引用必须为已存在本地分支。合并失败后重读unmerged stages并保留现场；冲突可逐文件审查、编辑、暂存，再由显式提交完成。不自动abort、reset、checkout强制覆盖。

进行中合并允许索引树与HEAD相同（无已暂存文件差异）时显式提交，以完成合法合并；普通无MERGE_HEAD的空提交拒绝。提交可用性依据结构化索引变更及合并头，不依赖是否已加载补丁文本。未合并stages仍拒绝，完整索引审查、原有暂存确认和执行前版本校验保持。AI 提交信息仅在用户点击后读取最多65536 UTF-8字节的完整暂存补丁，检查快照一致性；超限只阻止该次生成，不阻止浏览或手写提交，未暂存的大量改动不参与生成输入。

### 10.3 外部操作与恢复

沿用development_project_operations保存request UUID、owner/project/task/workspace、kind、请求摘要、前置版本、预期引用及结果详情；扩充原表kind范围，不另建执行台账。pending意图先提交，Git在事务外运行，完成后记succeeded/failed/unknown；同UUID不同输入request_conflict，相同请求只返回原回执。Git输出最多1MiB，读操作10秒、写操作120秒；超时/撤lease/崩溃均保留unknown。重启pending收敛unknown，仅显式reconcile核实Git对象、worktree登记、索引、HEAD或远端引用，不重发外部动作。不能证明则仍unknown；外部执行不承诺恰好一次。

renderer在Git/worktree派发前以宿主项目owner及project/task持久保存请求UUID与kind，保存失败不得派发；只存定位信息，结果以既有宿主台账为准。任务workspace读取返回该任务全部Git/workspace操作回执（operations），覆盖create/import/select/remove。IPC结果未知、标签卸载和重启后按原ID只读核实，不自动重发；核实完成同步统一workspace状态，终态清除本地待核实身份，不恢复旧unknown。未找到宿主回执不能据此证明从未执行，继续保留未知定位信息。

### 10.4 安全恢复与移除

恢复输入task、明确文件列表、各文件expected_hash、任务基线版本及用户确认。仅允许基线完整、可预览且当前版本一致、无已有脏内容/原有暂存、无执行间外部变化的文件；来源不确定的Agent文件变化不能仅按时间归属，拒绝自动恢复。宿主直接编辑保存可持久记录本任务最后写入hash作为可靠归属，后续外部变化使归属失效。恢复不改索引、不运行全仓reset/clean；逐文件恢复与失败部分结果必须可见，不伪称跨文件原子事务。

移除仅限宿主创建且身份与创建回执匹配的managed worktree；先确认无活动Agent/PTY/服务、无未提交/未跟踪/未合并文件、当前HEAD为指定保留分支的祖先，且无其他仍需该目录的任务。只调用不带force的git worktree remove，保留分支；外部导入目录永不删除。失败/未知保留元数据与路径供核实，不递归删除残留。

### 10.5 跨引擎交接

## 13. D136 Git 历史与显式拉取

依据 D136 与整体计划 §12.2 P6，复用既有 GitOperationIntent、任务目录身份、操作 UUID 和 pending/unknown 核实；本节是实施契约，验证状态只记入 V1 实现状态。

### 13.1 只读历史

新增 `read_development_git_history(app, window, input)`，input 为 `{task_id, cursor?, limit}`，limit 1～100，缺省 30。返回 `{anchor, commits, next_cursor}`，commit 为 `{oid, parents, author, timestamp, subject}`；作者不返回 email，subject 最多 512 字符，所有文本按不可信纯文本显示。首次读取将当前 HEAD 固定为 anchor；后续 cursor 绑定 owner/task、真实目录与 common-dir 身份、anchor、遍历位置，不能将任意 revision 表达式送给 Git。采用固定 anchor 的 topo/date 顺序并跳过已读取数量，最多遍历 10000 条；超过上限明确提示，不能不设上限扫描。空仓返回空集，非 Git 目录明确分类，游标失效需显式刷新。

读取只用本地对象，禁止 fetch、hook、filter、credential helper、自动 maintenance 或 replace/graft 改写历史；禁用 Git 配置中的程序扩展，输出沿用 1MiB/10秒边界。对象缺失、非 UTF-8 或超限明确失败，不以部分解析冒充完整历史。

### 13.2 拉取预览与执行

新增 `preview_development_git_pull(app, window, input:{task_id,remote,branch})`，只读本地 remote 配置，返回 `{review_token,remote,branch,remote_ref,remote_display,preview_token}`。remote_display 必须脱敏，完整 URL 不投影。预览绑定账户、任务目录/common-dir身份、本地 branch/HEAD、index/worktree版本、远端实际 URL 与精确 `refs/heads/<branch>`，有效期10分钟；不联网、不自动选择 upstream。参数按既有 remote/ref 校验拒绝选项注入。

现有 `execute_development_git` 的 action 增加 `{kind:'pull',remote,branch,preview_token,trust_directory,trust_network}`，仍要求调用方生成 UUID 和 review_token。目录与网络信任均为 true 才可执行；宿主重验预览全部绑定，拒绝脏目录、未合并、detached/unborn、失效目录或活动进程冲突。旧预览不能因重登恢复授权。

执行分两阶段：先把 pending 意图持久化，再对批准 URL 和唯一精确 ref 执行 fetch；显式空 refmap、no-tags/no-recurse-submodules/no-auto-maintenance，不消费 remote 的额外 fetch refspec、uploadpack 或用户配置中的自动动作，不写全局 FETCH_HEAD。获取结果固定为本操作专用 ref/OID，持久化后再核对本地目录、branch/HEAD/index/worktree 与原预览一致。若目标已是本地祖先，记录 already_up_to_date；若本地是目标祖先，只允许 ff-only；分叉返回 git_pull_diverged，保留现场并引导既有显式 merge。绝不自动 stash、rebase、reset、强制覆盖或创建 merge commit。外部 Git 不受宿主锁约束，最终结果需重读证明；不能承诺无法实现的文件系统全局 CAS。

### 13.3 持久化与恢复

现有 operation kind CHECK 不接受 git_pull，实施必须追加新 migration 扩充该约束，保留全部已有行/字段/索引，不改000030及其他已使用 migration。序号以派发时实际迁移目录为准。details 记录 `phase: prepared|fetch_started|fetched|ff_started|completed`、目标ref/OID、本地前置版本及脱敏结果；阶段在对应副作用前后落账。秘密 URL/凭据不得进入普通 details，必要远端身份用摘要与重读校验；不新增平行操作台账。

同 UUID 同请求只返回原回执，不再次联网；不同输入 request_conflict。超时/撤权/进程丢失保留 unknown 和已发生的对象获取；同一请求不得作为重试入口。`reconcile_development_git` 对 pull 只读取原操作、本地专用ref和当前目录事实，不 fetch/merge；prepared/fetch_started 或缺乏目标证据时不能仅凭 HEAD 未变判成功。只有已持久化 fetched/ff_started/completed 与目标、branch、index/worktree证据一致才能确认预期效果；外部变化保持 unknown。专用ref仅在终态已核实后清理，清理失败不冒充业务失败；unknown保留核实材料。
