# V2 画布系统：版本规划

> 状态：规划中，2026-11-01 起进入“门禁准备”（[D100](../../06-决策记录/V2-冻结决策.md)）。尚未通过[版本进入开发门禁](../版本进入开发门禁.md)，不代表任何实现状态。门禁准备期间可以分配 V2-FR 编号、编写 Draft 功能规格，版本层文档放 `后续版本/V2/`，本文件仍是 V2 规划主文档。版本顺序和边界以[版本路线图](../版本路线图.md)为准；跨版本能力增量以[功能演进矩阵](../功能演进矩阵.md)为准。

## 版本目标

提供无限画布核心能力。画布是 DGOS 的核心价值功能，V2 以完整画布系统交付。

历史文档中的 V1.2–V1.5 画布计划对应本版本。

## 交付范围

- 画布视口：缩放、拖拽、平移。
- 完整节点类型（10+ 种），包括 Image、Prompt、LLM、Generator、Loop、Conditional、Transform 等；LLM 节点可选择 Skills。`Function`（执行任意用户代码）不在 V2，另行决策；`Transform` 是内置变换和声明式表达式，不执行用户代码（2026-10-31 选定）。
- 节点连线、增量运行（只重跑变化部分，便宜节点自动预览，模型与工具节点在用户运行时执行）、循环节点（for-each 容器，图保持无环）（D104）。
- 工作流 JSON 格式定义、导入导出、自动排版和模板库。
- 图片生成与图片输入能力：Provider 层的图片生成调用与模块侧的图片生成能力，供 Generator 节点使用；LLM 节点接受图片输入（视觉理解）；Generator 不做图生图（D103、D106，见 [V2-FR-010](../../03-功能规格/V2/01-底层能力/10-图片能力.md)）。
- 只交付桌面画布；局域网、互联网设备使用画布所需的浏览器端模块加载器在 V4（D103）。

功能编号见 [V2 需求编号](../../03-功能规格/V2/00-V2需求编号.md)（V2-FR-001～010）；版本范围草案见 [V2 版本总览](V2/V2-版本总览.md)，两者冲突时以版本总览为准。

## 依赖与进入条件

- V1 必须稳定，且模块系统验证通过。
- 模块系统不稳定会导致画布无法独立开发。
- 下文“V2 门禁前要定的决策”中尚未完成的事项，进入开发前完成决策或写明延后理由。D082～D084 已于 2026-10-31 冻结。
- 产品设计与 UI/UX 改版（D097）在画布开工前完成；未完成不进入画布开发。

## 明确不包含 / 边界说明

- 画布系统作为一个完整版本交付，不拆分子版本；内部可以分阶段开发。
- 可选兼容老项目工作流格式以便用户迁移；不复制老项目单体架构或耦合设计，画布应为独立模块。

## 技术方案（草案，未冻结）

本节是规划，没有经过原型验证。进入开发门禁时拆成功能主文档和技术设计。标“未验证”的内容只来自文档或外部资料，没有在本项目运行过。

### 1. 定位

- 画布是官方应用模块，也是第三方模块开发者的样板。它只使用公开、带版本、需要声明权限的 SDK 能力，不使用第三方拿不到的宿主私有能力。
- 画布本身也是一个平台：对外提供节点扩展点、命令接口和工作流格式。节点类型会持续增加，并且可以由其他模块提供（[V8](V8-开发者生态.md) 的组件市场包含节点类型）。

### 2. 分层

| 层 | 内容 | 归属 |
| --- | --- | --- |
| 平台层 | 模块加载器（桌面与浏览器）、模块构建流程（D084）、`host.ui`、协同文档服务 `host.docs`、资产服务 `host.assets`、运行服务（D082、D083）、扩展注册表、身份与在线状态 | 宿主，所有应用共用；画布是第一个使用者，见[总体架构 §10](../../04-技术架构/总体架构.md) |
| 应用层 | 渲染引擎、文档到视图的映射、命令层、节点扩展点的定义 | 画布模块 |
| 扩展层 | 节点包（声明式或带代码） | 其他模块，经宿主的扩展注册表登记 |

### 3. 渲染（约 500 个节点）

- 引擎自研。D045 禁止模块 import react-dom，所以 React Flow、Radix 都不能打进模块；节点里的表单用 `host.ui`。
- 节点是 DOM；平移缩放由单个变换容器承载；连线画在单层 Canvas2D；用四叉树裁剪视口外的节点；缩小到阈值后换成简化占位，不挂载节点组件。
- 拖拽过程中直接改几何，不经过 React 协调；松手时才提交到文档。几何写入经宿主的 `host.dom`，画布自己的静态样式放在随包的 `entry.css`，由宿主安装（D091）。
- 画布根元素建立自己的层叠上下文（`isolate`），内部只用 `z-0`～`z-49`（FR-005 §4.8）；节点内弹出的 Select、Tooltip 经 portal 渲染，仍在全局 `z-popover`。
- Canvas2D 读不到 CSS 变量，换主题时要读计算样式后重画。外观控制器目前没有对外的变化订阅接口，需要补一个，或者监听 `html[data-theme]`。
- 画布内的节点尺寸使用画布单位，不随界面缩放（密度）变化；工具栏、参数面板照常随密度变化。否则密度设置不同的协作者看到的布局会不一样。

### 4. 文档与同步

- Yjs 文档：节点、连线是以稳定 id 为键的 `Y.Map`；提示词是 `Y.Text`；位置存成整体值；撤销用 `Y.UndoManager`。
- 同步协议从 V2 起就使用 y-protocols（sync、update、awareness），经一层抽象传输：桌面走 Tauri IPC，局域网和云端走 WebSocket。y-crdt 的说明称它与 Yjs 保持二进制协议兼容，宿主侧可用 Rust 实现 yrs（未验证）。
- 宿主持久化 Yjs 更新和定期快照；gc 保持开启，版本历史依靠中转存的快照。宿主用 `yrs` 解码并合并更新，但不以自己的身份写入内容；文档存 SQLite，资产存内容寻址文件；读写都沿用 `storage.*` 权限（D095）。
- 不进入文档的内容：
  - 密钥和 Provider 配置。
  - 图片、视频等大文件：按内容哈希引用 `host.assets`。
  - 拖拽过程中的位置：走 awareness，松手才写入。
  - 运行状态和进度：走运行服务的事件。
- 节点存“能力需求”（模型类型、协议），不存某台主机本地的 Provider id；执行时由执行方解析成自己的 Provider。
- 允许图暂时不合法：并发编辑可能产生悬空连线或环。引擎要能显示这种状态，执行前校验，由中转清理悬空连线。
- 文档带 `schemaVersion`，只做新增式变更；未知节点类型原样保留并显示占位；迁移必须幂等，由中转执行。

### 5. 节点系统与扩展

- 节点类型 id 写成 `发布者.包名/节点名`；主版本变化就是新类型。
- 两级定义：
  - 声明式：JSON，包括端口、参数 schema（自动生成 `host.ui` 表单）和执行绑定。任何人都可以写，不含代码。
  - 带代码：自定义节点主体。V2～V3 只限首方，第三方要等隔离方案（D051 方案 C：第三方代码需要独立 WebView 或进程）。
- 节点接口按“能跨进程”设计：只传可序列化数据，调用一律异步，不传对象引用，不直接操作 DOM 或 Yjs。首方节点也用同一套接口，否则引入第三方时要重写。
- 节点包是一种模块：manifest 用 `kind: "extension"`，经 `contributes` 声明贡献的节点、经 `dependencies` 声明依赖画布；声明式节点包可以没有入口、不执行代码。扩展 manifest 需要摘要 v3（D092）。
- 端口类型：基础类型由画布定义，节点包可以注册带命名空间的新类型并声明转换规则。
- 执行绑定是可扩展的类型：V2 只有“调用宿主能力”（Provider、Skills、MCP）；V8 再加“调用 API 市场的服务”。
- 权限按节点包计：运行服务执行某个包贡献的节点时，用该包的发布身份检查准入、声明与用户授予，画布自己不需要持有这些能力（D094）。在同一个 JS 环境里这只是记账和审计，不是安全措施：模块代码能直接调用宿主命令（`src-tauri/src/host.rs` 注明“不是沙箱”）。只有对隔离环境中的第三方包才有约束力。
- 注册表：扩展点的所有者为每个扩展点提供 JSON Schema，宿主在贡献者启用时校验；只有所有者能经 `host.extensions.list` 查询自己扩展点的有效贡献，变化时收到 `extensionsChanged`。V2 中其他模块只能贡献数据，带代码的节点主体只能写在画布源码里（D094）。
- 节点组件按需加载；每个节点包有体积和渲染耗时预算。

### 6. 执行

- 由宿主执行，客户端只发运行请求。生命周期见 D082，MCP 授权见 D083。
- 照搬聊天的模式（D074）：每次运行一个事件通道，先回执再推事件，客户端请求 id 保证幂等，只有一个终止事件，如实标“结果未知”。不直接复用聊天服务：聊天命令拒绝模块调用（D073）。
- 事件结构独立于传输（Tauri Channel、WebSocket），带递增序号。
- 模块目前唯一的能力 `providers.call` 入参是聊天请求。图片、视频生成需要新增模块能力；Provider 层是否已经支持图片接口未核实。

### 7. 命令层与对外格式

- 界面、撤销、协同、Agent（V7）和其他模块都调用同一套类型化命令：加节点、连线、改参数、批量应用。
- 导出的工作流 JSON 是对外契约，独立于内部的 Yjs 格式，带版本，并列出所需节点包。市场模板（V3）和 Agent 生成工作流（V7）都依赖它。

### 8. 运行环境与发布

- 引擎只依赖一个 `CanvasHost` 接口（文档传输、资产、运行请求、UI），桌面、局域网、互联网、移动端各写一个适配器。
- 局域网和互联网的浏览器端需要浏览器侧模块加载器：经 HTTP 取入口、校验摘要、用 Blob 导入。这是全新能力；FR-010 目前是草案、进度 0%，仓库里没有服务端代码。
- 构建与发布见 D084。画布源码不 import 仓库的 `src/`，只依赖一个只含类型的 SDK 包。
- 画布入口受[产品蓝图](../产品蓝图.md) §6.2“模块加载 < 1 秒”约束。

### 9. 互联网协同（V4 实现，影响 V2 的接口）

- 权限做到文档级（查看、编辑、运行），由中转执行；只读连接发来的更新丢弃；更新有大小和频率上限。V4 的“编辑锁”只能是经 awareness 广播的软锁。
- 运行请求可以派给文档所有者的主机、发起人自己的主机，或 V4 的官方 Provider；结果以资产引用写回文档。
- 身份：局域网会话没有用户身份（D053），光标标设备名；互联网使用 V3 账号（D040）。
- 文档共享到云端前要求用户明确同意；端到端加密与“中转要看到内容才能鉴权、存快照”冲突，V4 二选一。
