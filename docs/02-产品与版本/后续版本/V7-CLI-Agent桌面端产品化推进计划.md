## 1. 产品目标与范围

让 CLI Agent 从“带界面的 CLI 启动与执行管理入口”成为能保存工作现场、自然继续工作的桌面产品。

核心体验：

- 新项目：打开项目的活动工作区 → 选择 Provider / 模型 → 输入并发送；宿主按 D144 自动建立该精确工作区的 Agent 信任。
- 熟悉的项目：打开项目 → 新建会话 → 直接输入并发送，沿用有效默认配置。
- 旧会话：点开即看到历史、原配置和草稿，输入下一条即可继续；仅在确有异常时处理阻塞。
- 开发闭环：描述需求 → 查看执行和改动 → 运行测试 / 启动预览 → 根据结果继续修改。
- 隔日继续：重新打开应用，回到上次项目和会话的阅读、输入与文件现场，不重复设置，不重放执行。

覆盖 Codex 与 Claude 两条真实运行路线。统一交互入口，不伪造相同底层能力；能力缺失必须局部说明，不把整个产品退回配置表单。

不新增第二执行器，不将 CLI Agent 与内置 AI 助手混为同一产品；不引入云同步、远程开发容器、多 Agent 自治编排或应用退出后的无人值守守护进程。既有终端、文件、Git、Skills/MCP 管理与跨引擎交接能力继续复用。

### 2.3 必须先收口的产品规则

这些规则沿 D143/D144 冻结口径实施；D144 取代活动精确工作区的独立 Agent 授权确认及旧模式限制，terminal/service 等其余边界不变。只更新直接受影响的权威设计，不为普通布局另立决策；本表不构成实现或验收通过记录。

| 主题 | 目标规则与保守取舍 | 与既有行为的衔接 |
| --- | --- | --- |
| 项目信任 | 进入已打开项目的活动精确 workspace，由宿主校验当前账户、项目、task/workspace、实际目录身份及修订后幂等建立 agent 授权；输入区无授权按钮或二次确认 | 不扩大到父目录、terminal/service 或隐藏标签；手动撤销持久拒绝，仅显式“重新启用 Agent”直接授予。目录替换须重新定位，旧身份不转移 |
| 信任与权限 | Agent 信任允许加载该工作区原生配置及 Hooks/MCP；权限说明在项目设置可查。工具批准和直接 Shell 执行仍独立 | 自动信任不批准 pending；terminal/service 保留各自明确授权，不能从 Agent 模式推导 |
| 自动准备 | 对已授权目录，在用户选定模型或进入需要原生能力的活动草稿时自动准备；不启动所有隐藏标签，不发送占位消息或付费探测 | 自动准备仍可能加载 Hooks / MCP，不能称为无副作用扫描；与旧显式启动要求的变化需记录 |
| 双路线默认 | 唯一可用路线自动选；多路线先用会话 / 项目明确偏好，再用应用偏好，缺省优先可用 Codex，再选唯一其他可用路线 | 首次模型选择不增加强制引擎选择步骤；平台侧栏筛选、Provider 选择及底部高级路由入口分别表达。已绑定会话失败不静默改路线 |
| 配置继承 | 已有会话配置 > 项目默认 > 应用默认。提供显式“设为项目默认”，临时改会话不偷偷修改全局 | 原 Provider / 模型引用失效时保留历史快照并提供处理入口，不自动替换。快照不保存秘密 |
| 会话恢复 | 先只读恢复展示；继续发送或调用需连接的能力时，在有效授权下自动恢复原会话。不强制再点一次“恢复” | 重新校验身份、目录、Provider 和能力；无法恢复时明确“携带摘要新开”，不假装原生上下文完整 |
| 模式与权限 | 一个菜单保留手动确认、自动编辑、规划、深度、全自动五项，组合独立任务方式与执行权限；推理强度独立。规划/深度必须施加原生受限执行策略，不能仅靠提示词 | 原生缺少的项给简短不可用原因。全自动点击本身明确授权当前会话，无二次确认，不继承为其他项目或新会话默认、不批准已有 pending；原生映射与证据边界见[D136 §17](../../04-技术架构/当前版本/D136-CLI能力切换技术设计.md#17-d144-输入模式与原生用量增量) |
| 生命周期 | 切换、隐藏、关闭标签不停止；停止只针对本轮；结束会话、归档、删除分别操作。应用退出沿现有规则停止自有进程，退出前清楚提示 | 本轮不新增脱离应用的常驻模式；重启核实旧状态，不重发消息、不恢复旧批准、不凭旧 PID 认领进程 |
| 任务与完成 | 后台归属保留，默认侧栏以项目 / 会话为主；目标管理可选。执行状态自动更新，目标完成仍依据明确验收 / 用户确认 | 隐藏任务表单不删除数据；模型结束回复、进程退出零均不能单独证明目标完成 |
| 编辑与运行共存 | 不再把所有 Agent 与宿主进程一概互斥，按实际冲突和明确授权协调 | 开发脚本也可能写文件，不能按 `dev` 名称当只读；必须先定义受控共存、验证失效与无法约束的外部写入边界 |
| 草稿与内容保留 | 文本、引用、技能选择及支持的附件恢复到正确账户 / 项目 / 会话；缺失、过期、敏感内容不静默替代 | 当前内存图片等不能直接承诺跨重启可用；需定义账户私有存储、限额、清理与删除，历史省略范围如实显示 |

## 4. 分阶段实施

### CLI-DESK-0：产品规则与高风险契约收口

**目标：后续每阶段交付完整用户流程，不靠先堆界面、再补权限和恢复。**

实施内容：

1. 对 S01～S23 逐项核对当前实现，复用已有导航、标签、队列、原生能力管理和运行工具；将实质差距登记到唯一实现状态。
2. 定稿 §2.3 中的授权范围、自动启动时机、默认路由、配置持久化、草稿内容边界及退出语义；沿既有权威文档记录增量，不另建并行规格体系。
3. 为信任持久化、恢复 / 迁移和目录并发建立可测试的状态与失败规则；需要数据库变更时只追加迁移。
4. 确定信息架构：项目 / 会话为主导航，文件 / Git 为工作区工具，运行与预览为结果入口，终端为可展开工具，目标管理按需进入。
5. 核对两家真实验收环境、凭据安全入口、允许的模型与调用范围、隔离项目和安装包路径；缺少外部前提不阻塞独立本地切片，但不能免除最终真实验证。

**退出条件：** 授权、恢复、关闭和并发不再存在相互矛盾的产品规则；所有范围有主责阶段和验收路径。普通布局由实现者选择，不反复请求用户确认；确有不可兼得的产品取舍才集中提问。

### CLI-DESK-1：会话工作现场与配置持久化

**用户结果：旧会话点开即有内容和原配置，重启后找得到昨天的工作。**

实施内容：

- 持久化有效会话配置与用户待应用意图，区分“用户选了什么”和“原生实际生效什么”；补全三级默认继承及显式设为项目默认。
- 历史读取与启动 CLI 解耦；离线、Provider 失效时仍可看已有消息、工具 / 审批记录、计划、改动和验证记录的可保留投影。缺失内容显示来源与缺口，不编造原文。
- 保存每个项目 / 会话独立草稿及引用、技能和支持附件；阅读位置以稳定消息定位，恢复文件 / 详情展开状态。未保存编辑遵循既有草稿保护，不能为恢复视图覆盖磁盘内容。
- 持久化目录授权及撤销版本，恢复时重新检查有效性。凭据只保留引用和安全快照，不复制秘密到会话记录或普通日志。
- 升级旧数据：有快照沿用，缺字段显示实际缺省或待核实，不补造历史配置；失效授权不复活。迁移失败原数据可保全，恢复不重复导入。
- 明确正常关闭和崩溃时的保存边界；显示保存失败，不以“自动保存”承诺任意断电瞬间零损失。

**依赖：** CLI-DESK-0。

**退出条件：** 两个不同配置会话切换、应用正常退出 / 重启后，各自配置、正文、草稿和阅读位置正确；离线能读；账户间不串数据；修改项目默认不会改变旧会话。

### CLI-DESK-2：选好模型即可开始与继续

**用户结果：没有独立连接 / 恢复步骤，缺前提时才提供针对性引导。**

实施内容：

- 进入已打开项目的活动精确工作区即由宿主幂等建立 Agent 授权，不重复弹窗；撤销后只显示停用及直接重新启用入口。目录身份变化须重新定位，terminal/service 不被自动授予。
- 模型选择沿兼容目录自动路由，按既定默认处理双路线；Provider / 模型名称不能代替兼容事实。
- 选定有效模型后为活动草稿自动准备并发现能力；输入仍可编辑，状态轻量显示。不为每次键盘筛选启动进程，不启动全部历史标签。
- 准备途中更换模型、项目或账户时使旧结果失效并处理自有预备实例，保留草稿且不留下占目录的孤立空会话。
- 首发点击形成一次发送意图；准备成功后只发送原确认目标的内容。切换目标或启动失败不迟到发送；未知结果只核实原请求，不重新创建或派发。
- 旧会话读取即展示；用户继续发送时自动衔接有效原会话。不可恢复、绑定失效或需要另一引擎时走显式交接，不静默降级。
- 移除常驻信任勾选和“连接并配置”按钮；CLI 安装、凭据设置、目录重新定位提供就地入口，返回保留原会话与草稿。

**依赖：** CLI-DESK-1；复用既有启动、恢复和 Provider 绑定链路。

**退出条件：** 已授权且环境就绪时，新会话选模型后直接发送；旧会话输入下一条直接继续。默认流程不出现连接表单；准备失败、快速切换和双击不导致串会话或重复消息。

### CLI-DESK-3：输入框、技能与运行控制产品化

**用户结果：高频操作都在输入框附近完成，不必先理解引擎协议。**

实施内容：

- 输入区采用附件 / 偏好设置与模式 / 模型 / 推理 / 用量 / 发送的紧凑布局；首发前后保持同一套操作位置。发送、停止使用图标并提供当前动作的可访问名称；模式和模型选后关闭，偏好及推理离散滑杆调整后保留弹层，Esc/外点关闭并恢复焦点。
- 工作模式使用 D144 五项菜单；规划/深度施加原生受限执行策略，深度不自动改推理档位。全自动点击明确授权本会话，不再二次确认；支持情况、保存意图与实际执行策略分别处理，正常界面移除协议/回执长说明，失败就地简短反馈。
- `/` 弹出当前可显式调用的技能与命令，分组、搜索、说明、来源、重名区分，支持上下键、Enter / Tab、Esc；选择只加入输入意图，发送后才执行。不得拦截普通路径、代码块或中文输入法的正常输入。
- Codex 仍提交结构化 Skill 引用，Claude 按原生命令和可见性规则提交；未向用户开放调用、未启用或来源无法确证的项不能伪装可用。切引擎后重验已选项，不静默删除或退成普通文本。
- `@` 文件及选中内容、图片粘贴、引用 chips 与长文本展开编辑协同；管理 Skills / MCP / Provider 后回到原输入位置。
- 偏好提供响应语言、精简程度、下一步建议、跟随修改、流式展示和代码高亮；主题复用应用外观。响应偏好作用于后续回复，呈现开关不改变原生请求、审批、取消或失败；保存失败还原已确认值，管理往返保留现场。
- 运行中允许编辑下一条；“补充当前任务”和“加入下一条”区分，沿真实 steering / 队列能力执行。无对应能力时保留草稿并说明，不冒充成功。排队何时执行明确显示，不偷偷发送未提交文字。
- 用量环展开原生上下文占用/容量、累计输入输出/缓存、命中率、费用和耗时；缺失显示未知，累计不冒充占用，实际与可靠价格预估明确区分。压缩仅在当前身份/代次、空闲与能力检查后调用原生操作；受理不等于完成，失败/未知不改占用、不自动重发，统计规则与能力限制见 D136 §17。

**依赖：** CLI-DESK-1、2；静态布局可在 CLI-DESK-0 后先设计，能力生效与验收不可绕过依赖。

**退出条件：** 两家均能在首条消息前设置支持的选项、从 `/` 选择真实技能并发送；五项模式按各自原生能力开放，规划/深度受限、全自动仅限显式选择的会话；偏好影响后续回复或对应呈现，用量和压缩不造数。键盘全流程可用，模型切换和管理往返不丢输入，未授权的扩大能力不派发。

### CLI-DESK-4：多会话导航、生命周期与任务降噪

**用户结果：像桌面工作区一样自由切换，随时找回工作，不担心关闭错对象。**

实施内容：

- 以项目分组会话为主导航，复用已有置顶、归档与搜索；补齐搜索命中消息定位、可读标题和重命名。标题默认本地取首条需求，不为命名偷偷调用模型。
- 会话显示进行中、等待用户、失败、空闲等可核实状态及未读标记；明确“本轮结束”与“目标完成”区别。
- 关闭标签仅收起界面，停止本轮、结束原生会话、归档、删除分别操作；删除保留明确确认与范围说明，不删除项目代码，不删除 OS 用户共享的原生历史。活跃对象和未知请求不得失去核实入口。
- 切换页面 / 项目不停止已启动任务；后台审批、失败和完成通过会话标记与通知触达，通知点击定位原对象。系统通知按用户许可启用，默认不泄露消息、凭据或项目敏感内容。
- 阅读旧消息不强制滚到底部，有新内容可跳转；日志和工具详情按需展开，保留展开与阅读位置。
- 默认移除独立任务入口和空任务表单说明；会话详情承载目标 / 完成要求，项目更多入口承载可选目标管理，允许已有多个会话按目标查看，不重建第二套归属。
- 退出前展示自有活动执行，按既定停止 / 清理规则处理；重启区分已完成、已中断和待核实，不留永久假运行状态。

**依赖：** CLI-DESK-1、2；运行中输入与通知衔接 CLI-DESK-3。

**退出条件：** 多项目多会话并行使用时，切换、收起、关闭标签均不误停；能从后台提醒找到待审批会话；旧任务记录仍可访问但日常对话不需维护任务。

### CLI-DESK-5：运行、预览、终端与安全共存

**用户结果：点击即可运行项目和查看效果，也能随手进入真实终端。**

实施内容：

- 默认入口改为“运行与预览”，基于项目真实脚本 / 保存命令展示可执行操作；程序、参数、cwd、环境引用、探测设置移入高级配置。保留实际命令的查看途径。
- 识别单一明确脚本后提供直接运行；多应用 / 多脚本首次选择并记住偏好。未识别时提供配置或带上下文的 Agent 求助入口，不虚构命令、不自动安装依赖。
- 运行、测试、构建显示与其语义相符的状态和结果；退出零只表示对应命令成功，不直接代表全部需求通过。构建产物仅在路径可核实、允许访问时提供入口。
- 服务显示启动、就绪、失败、访问地址、输出和停止；重复点击打开已有实例。重启须先确认原实例停止，再启动新实例，未知时不另起副本；不杀端口上的外部进程。
- 一步打开终端，默认当前会话实际工作区，无会话时为项目根；授权不足才提示。输出搜索、复制粘贴、清屏与面板展开可用；清屏不停止进程、不偷偷删除历史。
- 切换不销毁有效 PTY；同一存活进程重新挂载不重放输入。应用退出后可读旧输出，但明确新开终端不是恢复旧进程。
- 实施目录共存契约：允许经过明确授权的开发服务与 Agent 编辑协作，保留真实冲突协调、外部文件变化检测和未保存保护。不能简单删除全部目录锁，也不能把任意终端或脚本声明为只读。
- 测试 / 构建期间代码变化时标注证据不再对应当前代码；必要的排他操作说明对象和原因，提供结束冲突执行的入口。

**依赖：** CLI-DESK-0 的并发契约、CLI-DESK-1 的授权 / 偏好，以及 CLI-DESK-4 的生命周期。脚本展示与终端布局可提前独立实现，安全共存不得跳过契约。

**退出条件：** 从真实项目启动预览并打开，在 Agent 编辑期间服务可按已定策略持续运行；测试结果随代码变化正确失效；打开终端无需填写表单；停止、端口占用、失败和重启不会影响外部进程。

### CLI-DESK-6：对话到开发结果闭环与异常恢复

**用户结果：知道做了什么、结果如何、接下来能做什么，出错不用重新开始。**

实施内容：

- 对话完成区按实际结果提供查看改动、运行测试、启动 / 打开预览；不以模型文本声称替代真实文件、命令和结果。
- 将失败命令和经过敏感信息处理的有界输出，经用户预览 / 选择后作为草稿交回正确会话；不自动发出，不把日志内容当宿主授权。
- 运行记录链接回相关会话和工作区；无法证明独占归属的改动不全部归给当前 Agent。沿既有 Git 审查确认，不自动提交、推送或丢弃用户文件。
- 按异常给出直接入口：凭据更新、CLI 安装 / 更新指引、目录重新定位、模型替换交接、重连、核实原操作。处理后回到原位置，保留草稿和可读历史。
- 启动 / 发送 / 终端输入未知只核实；确定未派发才允许明确重试。局部能力失败仅阻塞相关操作；缺少 MCP、技能或推理能力不无条件封锁普通对话。
- 审批贴近对应操作，说明动作、对象和授权范围；拒绝后可以解释要求继续讨论。过期请求、旧账户及旧代次的审批不可复用。

**依赖：** CLI-DESK-2～5；复用原生审批、文件 / Git 和宿主运行记录。

**退出条件：** 完成“需求 → 修改 → 预览 → 测试失败 → 交回修复 → 测试通过 → 审查改动”的真实闭环；其中断线、配置失效和审批拒绝均可恢复且不重放外部副作用。

### CLI-DESK-7：完整桌面体验与安装验收

**用户结果：日常长时间使用、重启、升级和异常恢复均可信，而不是一次演示能跑通。**

实施内容：

- 完成本计划 §6 全部用户旅程；Codex 与 Claude 分别留证，不能用一家的通过替代另一家。
- 旧数据升级、正常退出、强制退出、CLI 崩溃、断线、凭据撤销、目录移动 / 替换、账户切换以及磁盘保存失败等边界分层验证。
- 验证长历史按需加载、快速切换、多标签及长日志，不将全部内容同步灌入首屏。记录代表性数据量、设备及操作时延；具体预算在本阶段测试前固定，不以体感“很快”验收。
- 对实际界面核对中英、明暗主题、窄窗、大字号、键盘、焦点恢复、输入法及辅助技术标记；通知不抢焦点，敏感信息不出现在普通日志和通知预览。
- 实际安装包验证 bridge / CLI 接线、资源分发、历史恢复、预览、终端和退出清理；平台证据单列，macOS 通过不声称 Windows / Linux 通过，平台范围沿既有发布边界。
- 删除已被本轮新流程取代的旧入口、重复配置路径和失效说明；保留必要的数据迁移兼容，不长期维持新旧两套执行 / 状态来源。

**依赖：** CLI-DESK-1～6。设计质量与基本验证贯穿各阶段，本阶段做跨阶段集成，不把所有验证拖到最后。

**退出条件：** 范围 S01～S23 均有实现和对应等级的证据；必要真实验收、安装 / 平台覆盖不足必须在实现状态中保留未完成项，不能以“核心完成”宣布整体完成。

## 5. 顺序与协作方式

默认推进顺序为 CLI-DESK-0 → 1 → 2 → 3 → 4 → 5 → 6 → 7。先保证“记得住、回得来、能直接聊”，再完成高频交互、工作组织和开发结果闭环。

可以并行的部分仅限共享契约已明确后的独立切片：

- 持久化 / 宿主授权与输入区视觉设计可以独立推进，真实接线等待契约完成。
- 会话导航与运行 / 终端呈现可在各自所需生命周期规则明确后分别推进。
- 两家引擎适配分别实现，各自验证；共享 DTO、状态与 composer 由同一个集成负责人负责，避免两套 UI 状态来源。
- Claude 专项的真实协议缺口沿原 §14 继续推进，本计划消费其结果，不建立重复专项，也不将缺失能力伪装成统一支持。

每个阶段按“定位现有依据 → 补齐直接相关契约 → 一组实现 → 定向验证 → 集中回写”完成。不先写完所有未来细节再编码；也不在权限、迁移、并发未明确时先改 UI 绕过限制。

本轮不承诺未经拆解的日历工期、不按代码量计算进度。阶段完成以可操作旅程和退出条件判断；局部阶段交付不缩减完整范围。

### 8.3 必须收口的实现规则

1. **身份与输出权威性**：采用现有原生 message/item/block/task 身份和 run/parent 作用域，不以文字相等消除合法重复。最终输出字段缺失、明确为空、完整替换三种情况分别按原生契约处理；无完整快照时保留已收集的增量。展示序号不兼任排序与消息身份，定位优先匹配 sources。后台事件保留原任务归属，不因当前 active_run 改变而改写旧归属。
2. **状态与未知数据**：区分等待用户、执行中、工具业务失败、拒绝、取消、未知、回复结束。MCP 调用结束不代表 result 成功。未知事件只保留经白名单/脱敏、有大小限制的诊断摘要；私有思考、签名、凭据、认证回调不得为了“完整覆盖”进入普通历史。未知请求仍不能自动批准或执行。
3. **审批和表单**：待办区沿既有 session/generation/request 身份提交；持久权限扩大保留明确确认，不改变原生 availableDecisions。支持的 JSON Schema 约束既给字段级解释又在可信边界验证；不支持的必需约束明确拒绝接受，可选不支持字段按协议允许省略时才省略。URL 打开使用既有受控外链路径；打开浏览器不等于授权完成，不伪造 verification proof。
4. **消息操作**：整条正文复制输出完整 Markdown；引用到草稿保留用户现有内容和来源，不自动发送。若加入“再次提问”，必须是用户可编辑的新请求，不能直接重放旧工具链。没有反馈收集用途时不添加装饰性的赞踩。
5. **内容访问**：网页 citation 必须绑定当前原生来源记录，不把任意 Markdown URL 升格为可信证据。输出图片和产物只读取获准来源；本机文件复用工作区授权/目录身份与读取限额，远程读取须有单独的超时、大小、重定向、取消和访问策略。需要新增 IPC、持久化或迁移时，先更新直接权威契约及必要决策，不以 UI 实现隐式扩大权限。
6. **富文本安全与兼容**：Markdown 原始 HTML 保持惰性文本；图解/公式采用禁脚本、禁外链、输入和计算量有界的 renderer，失败时保留可复制源码并说明。表格排序仅作用于展示副本，原输出及顺序可恢复，导出不得引入公式执行。共享 Markdown 的普通 AI 会话消费者必须同步核对，避免 CLI 优化改变其来源信任或链接规则。
7. **能力差异**：Codex 的公开 summary/phase/Plan 和 Claude 的块流/Todo/工具许可分别适配，不强行伪造等价功能。TaskCreate/TaskUpdate、后台停止、图片输入等逐项按实际支持版本登记；不存在的能力提供明确边界，不用按钮或假结果补齐。上游新增能力纳入登记后才进入“已覆盖”口径。
