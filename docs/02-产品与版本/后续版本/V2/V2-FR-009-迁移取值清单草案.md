## 3. 组件施工约束

- 颜色保持单向源→角色→Tailwind映射；已有surface别名必须按调用点清查后统一，不得同名循环或维护第二套字面色。控件边界用完整语义配对求解，不把某个静态V1边框色当所有预设固定值。
- Button/Input/Select等一起完成紧凑角色、hover/active/focus/disabled/loading；组件内统一appearance/border/font，不用全局preflight影响旧页面和模块。
- 外层工作区tab、内层会话tab、设置分类、普通Tabs分别定义视觉和焦点行为。关闭只发意图，由对象生命周期决定是否确认、取消或detach，不能概括为“所有标签只detach”。
- Settings、Launcher、确认框共用成熟焦点原语，但dismiss策略各自明确；不能把现有400～600px确认Modal直接充当设置浮层。
- 资源卡网格、服务列表—详情、设置分类—资源—详情需要不同产品模式；现有业务行为复用，布局重新编排。
- 五套明暗/三域/持久化、标签列表与命令面板均在统一切换范围；随包provider-console也必须迁移host.ui外观并更新摘要/pin。画布引擎、云市场等依赖按整体方案逐项裁定，不由本清单宣告延期。
