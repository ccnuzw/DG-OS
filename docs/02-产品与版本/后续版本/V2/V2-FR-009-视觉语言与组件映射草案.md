## 2. 设计语言摘要

建议将参考风格暂称为 **Quiet Precision Desktop（安静、精密的桌面工作台）**。名称用于交流，不是品牌定稿。

1. **中性表面做底**：画布、侧栏、内容面板和输入区域用细微表面差异分层，避免大面积高饱和色。
2. **边界优先于阴影**：静态内容用细边框、分隔线和对齐关系组织；阴影主要用于浮层和需要脱离文档流的界面。
3. **强调色服务于交互**：主色用于主要操作、焦点和选中态；状态色用于健康、待处理、错误等语义，不互相代用。
4. **信息密度有层级**：标题、正文、说明、技术值各自有稳定字号、字重和行高；路径、模型 ID、端口及指标可以使用等宽字。
5. **桌面工具的空间感**：使用清楚的工作区边界、分栏、可收起的辅助栏和固定操作区域；具体页面是否采用这些模式由 IA 与任务设计决定。
6. **控件边界清楚**：输入、选择、开关、按钮和选中项要能快速辨认，状态不能只靠颜色表达。
7. **图标是辅助识别**：图标可置于低饱和色块中，保持统一的线条重量和尺寸；颜色不应让每个图标都争夺主视觉。
8. **动效克制且有因果**：仅在展开、选择、提交或运行状态变化时表达反馈；尊重减少动态效果偏好。

## 3. 视觉参考与当前实现的映射

| 设计维度 | 参考中观察到的做法 | DG-OS 当前基础 | 后续设计处理 |
| --- | --- | --- | --- |
| 表面层级 | 暖白/浅灰画布、稍深侧栏、白色内容面板、浅色输入井 | `--color-bg-primary/secondary/tertiary` | 收敛成语义层级；避免组件直接引用页面色值 |
| 强调色 | Stitch 原型偏靛蓝/紫；补充截图偏蓝；不同页面代码也有不同色值 | 现行 `--color-primary` 为蓝色，深浅主题已配对 | 主色仍待明确选择；不得把两套原型色混成两个主色 |
| 状态色 | 绿、琥珀、红分别表达健康、待处理、危险/失败 | 已有 `success/warning/error/info` 令牌及文字前景令牌 | 维持语义映射；检查状态点、淡色底和文字的对比度 |
| 结构边界 | 细边框和分隔线明显，普通面板阴影轻或无 | 已有 `border`、`border-control`、`divider` 和阴影 token | 区分装饰边界与控件边界，不靠阴影表达所有层级 |
| 字体 | Stitch 手册建议 Inter 与 JetBrains Mono；部分原型代码使用系统字体栈 | `--font-family-base`、`--font-family-mono`；根字号 14px 并支持 5 档密度 | 定义中英 UI 回退栈与技术值角色；保留现有密度内核，按角色映射字号 |
| 控件形状 | 控件约 8px 圆角，面板更大，状态标签胶囊形 | 已有统一 radius token；Button/Input/Select/Switch 已使用 `@dgos/ui` | 用组件级变体控制形状，避免任意组合圆角 |
| 图标容器 | 常见 28–40px 淡色图标底，主要用于列表项或设置行 | 有状态图标，通用图标体系按 V2 规划 | 只在有识别价值时采用；图标集合与功能分类另行设计 |
| 固定操作区 | 设置参考图有固定底栏、内容独立滚动 | 页面布局由页面自行实现 | 形成可复用布局模式候选；固定区须考虑窄窗口和键盘焦点 |
| 侧栏 | 展开时图标加文字、分组间距；收起时可保留图标轨道 | 当前主界面使用顶部导航，暂无统一侧栏模式 | 作为可选模式探索，不据此决定全局导航或信息架构 |

## 4. 令牌口径待收敛项

参考资料本身存在多套实现值，以下仅记录冲突，不代表已选定新值：

| 项目 | 当前材料中的差异 | 后续需确定的内容 |
| --- | --- | --- |
| 中性背景 | `DESIGN.md` YAML 使用 `#FBF9F9`，正文描述 `#F7F7F6`；部分原型代码使用 `#F8F9FA` | DG-OS 的 canvas、sidebar、panel、inset surface 语义及亮暗配对值 |
| 主色 | YAML `#4233CC`；正文 `#5B50E5` / `#6366F1`；页面代码还出现 `#4F46E5`；用户补充截图更偏蓝 | 选择蓝或靛蓝为唯一主交互色，随后校准 hover、active、focus、on-primary 和容器色 |
| 文字色与边界 | YAML 与正文使用不同的 `on-surface`、`muted` 和 outline 值 | 基于现行对比度测试重建语义配对，不能只按截图取色 |
| 字体 | 设计手册使用 Inter；HTML 有系统中文字体、Inter 与等宽栈的不同组合 | 中文/英文字体回退、技术值字体、数字等宽特性；避免网络字体成为运行依赖 |
| 字号 | 手册给 11–13px 的高密度刻度；现行系统有 11px 最小有效字号与密度缩放 | 按 UI 角色映射到现有字号 token，并在五档密度验证，不直接改变 root 尺寸 |
| 暗色主题 | 参考图片以浅色为主，没有完整暗色规范 | 为每个语义 surface、状态色、边界和选中态补齐暗色配对 |

任何实际令牌改值都属于对 FR-005 的范围/验收影响；进入代码前依 D097 先修订对应规格并更新令牌对比度测试，不能以本草案作为绕过路径。

2026-11-02 用户进一步明确需要主题套装、区域覆盖及字体/字号精细设置；完整规则与默认行为建议见[外观主题与作用域设计](../../../03-功能规格/V2/03-产品设计/外观主题与作用域设计.md)。本草案中“唯一主色”指默认套装及每个解析后主题内部保持单一交互色，不排除用户选择其他套装或自定义强调色；系统状态色保持独立语义。

## 5. 组件与模式候选

### 5.1 现有基础组件的视觉复核

首轮复核范围建议限定在以下组件，不预设必然新增组件：

| 组件 | 复核重点 |
| --- | --- |
| Button | 主/次/幽灵/危险变体，尺寸与状态层级，图标间距，窄窗口下是否可读 |
| Input、Select | 控件高度、描边、背景、focus ring、错误/禁用/成功状态，图标槽和密钥遮蔽 |
| Switch、Checkbox、RadioGroup | 选中态和标签对齐，触控/鼠标目标，键盘状态反馈 |
| Card、Divider | 减少“全部内容卡片化”；明确面板、分区和分隔线何时使用 |
| Tabs | 选中态是否适用于局部视图切换；不将其默认扩展为全局导航 |
| Modal、Toast、Tooltip | 与独立设置窗口、浮层、页面内提示区分职责；保留焦点与无障碍契约 |

### 5.2 产品级模式候选

这些是待原型验证的视觉/交互模式，不是已经批准的组件 API：

- `SettingsWindowFrame`：独立设置窗口的标题区、关闭入口、可滚动内容与固定操作区；是否由宿主窗口、独立 Webview 或 Dialog 承载另行决定。
- `CollapsibleSidebar`：展开导航与窄图标轨道的视觉状态、分组、当前项、键盘焦点和提示；不定义具体导航条目。
- `ResourceListItem`：图标、主标题、辅助说明、状态点、选中态和可选尾部数据。
- `SettingsRow`：设置名称、解释、控件/值区域以及可选的二级说明。
- `StickyActionBar`：保存、取消、恢复等操作的固定区布局及未保存状态；操作内容按页面行为确定。
- `SurfacePanel`：面板、嵌套内容和分隔层级的统一边界语法；避免无差别地把每个 section 包成卡片。

## 6. 不从视觉稿推导的内容

- 不依据参考图的菜单标签、分组名称或图标推导 DG-OS 的产品分类和信息架构。
- 不把原型里的指标、设备、账号、版本、遥测、沙箱能力或业务流程视为 DG-OS 已存在功能。
- 不要求所有页面使用三栏布局、资源列表—详情布局、固定侧栏或固定底栏。
- 不复制 HTML 中的 CDN Tailwind 配置、硬编码色值、任意固定窗口尺寸、全局 `select-none` 或未验证的低对比文字。
- 不把 Stitch HTML 作为可直接合并的生产组件；任何可复用片段都要先映射到 DG-OS 令牌、组件 API、技术边界与测试。
- 不把独立设置窗口等同于网页 Dialog。窗口类型、生命周期和宿主实现属于后续技术设计。

## 7. 后续设计检查点

在把本草案转为正式 V2-FR-009 规格之前，应完成以下视觉验证：

1. 明确蓝色与靛蓝/紫色的主色取舍，并整理一套唯一的浅色语义表和暗色配对表。
2. 提供中英字体回退和技术值字体规则，验证 75%–175% 五档密度及中文长文案。
3. 至少检查亮/暗主题、键盘焦点、状态色对比度、减少动态效果和 800px 窗口下的组件表现。
4. 以设置窗口框架、可折叠侧栏、资源列表项和固定操作栏制作独立的组件原型；原型内容使用中性占位文案，不借用参考图的功能分类。
5. 将被采纳的样式与交互逐项映射到 `src/ui/tokens/`、`src/ui/components/` 或产品模式层，并标记哪些属于 V1-FR-005 规格修订、哪些留在 V2-FR-009。
