# V2-FR-009 组件视觉原型与令牌候选

> 状态：视觉探索工作稿，非冻结规格。用途是把现有 Stitch 参考收敛为可比较、可带回的组件原型；不确定义产品功能分类、导航 IA、业务流程或生产组件 API。
>
> 设计语言来源与映射边界见[视觉语言与组件映射草案](V2-FR-009-视觉语言与组件映射草案.md)。V1 现行令牌仍以 [V1-FR-005](../../../03-功能规格/V1/01-底层能力/05-统一设计系统.md) 为准；任何代码落地前仍须遵循 D097 的规格修订要求。

## 1. 本轮目标

当前不是让 Stitch 再设计一套产品功能，而是拿同一组中性组件样本，比较视觉语言与桌面界面元素，回答：

1. 蓝色强调与靛蓝强调哪一种更像 DG-OS，且能满足文字和状态对比度？
2. 暖中性色与偏冷中性色哪一种更适合长时间桌面使用？
3. 面板、边界、圆角、图标底、输入和固定操作栏的比例如何组合？
4. 独立设置窗口和可折叠侧栏分别采用什么视觉规则？
5. 一套视觉语言在亮色、暗色、中英文和窄窗口下是否仍然成立？

本轮只比较视觉和组件呈现；先不讨论组件应该属于哪个功能、主导航放什么、用户旅程怎么走。

## 2. 比较方式

使用同一份组件样本和同一屏幕尺寸生成 3 个变体，避免不同页面内容干扰风格判断。

| 变体 | 强调色方向 | 中性色方向 | 用途 |
| --- | --- | --- | --- |
| A：Clear Blue | 保留 DG-OS 现行蓝色角色（现行主色候选 `#2563EB`） | 中性、略偏冷的灰白层次 | 与现有令牌连续，作为迁移成本较低的基线 |
| B：Quiet Indigo | Stitch 参考中的靛蓝方向（建议原型主色 `#4F46E5`；避免把 `#6366F1` 用作小号白字按钮底） | 中性偏暖石色 | 验证 Stitch 的选中态与操作强调语言 |
| C：Warm Neutral + Blue Signal | 使用现行蓝色作为唯一主操作/焦点色 | 暖白、浅石色、低对比背景层次 | 验证用户补充设置截图中的温和表面与蓝色操作信号 |

A/B/C 必须共享相同布局、文案、数据、图标和控件状态；只有色彩温度和主强调色允许变化。不要混合两种主操作色。状态色维持同一语义：绿=正常，琥珀=待处理/注意，红=错误/危险。

## 3. Stitch 原型样本范围

每个变体只生成一张组件样本板，板上包含以下区域：

1. **Surface & Type**：画布、侧栏、主面板、浅色内嵌区域、边界、标题/正文/辅助文字/技术值。
2. **Controls**：主/次/幽灵/危险按钮；文本输入、搜索输入、选择器、开关、分段选择；默认、hover、focus、disabled、error、selected 状态。
3. **Reusable Rows**：设置行（名称+说明+右侧控件）、资源列表项（图标底+名称+副标题+状态点+选中态）、状态提示条。
4. **Independent Settings Window**：独立窗口外框、顶部标题/关闭操作、左侧中性类别占位、滚动内容、底部固定操作栏。类别仅用“类别 A/B/C”等占位，不生成产品功能分类。
5. **Collapsible Sidebar**：展开态与收起图标轨道并排展示，使用“区域 A/B”“项目 1/2”等无业务含义标签；重点比较选中态、分组、图标底和收起后的提示表达。
6. **Density Check**：将主组件板缩窄到约 800px 窗口，并另示意放大密度；不要求 Stitch 准确模拟真实 WebView 缩放，只检查长标签、控件和操作栏是否有合理重排空间。
7. **Theme Check**：主板为亮色；同一组件小样另附暗色表面和选中态色板，作为后续暗色设计输入，而非暗色最终稿。

不在本轮生成完整 Workbench、Provider、Skills、MCP 等业务页面，也不要求 Stitch 根据截图复刻任何功能流程。

## 4. 可直接用于 Stitch 的主提示词

分别生成 A、B、C 三次。每次复制同一份提示词，只将 `{VARIANT}` 替换成下方对应的一段方向描述；不要把 A/B/C 三个方向同时放进一次生成请求。

```text
Create a desktop UI component specimen board for DG-OS, a local-first AI desktop application.

This is a visual language and reusable UI-elements study only. Do not design product information architecture, feature categories, navigation taxonomy, user journeys, or real business functionality. Do not infer functions from reference screenshots. Use neutral placeholder labels such as “Section A”, “Section B”, “Item 01”, and generic descriptive content.

Visual direction: “Quiet Precision Desktop” — calm, precise, desktop-native, information-dense but readable. Use neutral surfaces, crisp 1px boundaries, restrained shadows only for floating/elevated surfaces, deliberate spacing, clear type hierarchy, and small purposeful state accents. Avoid generic SaaS card grids, glassmorphism, decorative gradients, oversized headings, and excessive badges.

Variant: {VARIANT}
Keep layout, copy, icons, data, and control states identical across A/B/C. Only change the accent hue and neutral temperature. Use green only for healthy/success, amber for pending/attention, and red for errors/danger. Never use color as the only state indicator.

Show these generic reusable elements on one coherent specimen board:
1. Surface hierarchy: app canvas, sidebar surface, main panel, inset/input surface, separators, primary and secondary text.
2. Buttons: primary, secondary, ghost, danger; show default, hover, keyboard focus, disabled, and busy states.
3. Fields: text input, search field, select, segmented choice, and switch; show focus, error, disabled, and selected states.
4. A generic settings row with title, one-line explanation, and a right-aligned control.
5. A generic resource-list row with a softly tinted icon tile, title, subtitle, status dot plus text, and a distinct selected state.
6. A status notice with icon, concise message, and one recovery action.
7. An independent settings-window visual: top title/close bar, neutral placeholder category rail, scrollable content area, and a pinned bottom action bar with secondary and primary actions. This is a separate window, not the main application shell and not a modal dialog overlay.
8. A collapsible sidebar shown expanded and collapsed side-by-side. Use placeholder labels only; show grouping, active item, icon-only rail, tooltip affordance, and keyboard focus.
9. A compact dark-theme swatch strip for canvas, panel, inset, border, text, selected state, and semantic statuses.

Typography: use a practical UI sans-serif with good Chinese glyph fallback; use a restrained monospace only for a sample technical value. Keep hierarchy compact: page title around 22–24px, section title 15–18px, body around 13–14px, helper text no smaller than 11px. Prioritize Chinese readability; do not depend on a remote font download.

Geometry: controls about 34–36px high; 6–8px radius for controls; 10–14px radius for panels; pill radius only for compact status chips. Use 4px-based spacing. Keep borders crisp and low-noise. Show visible keyboard focus.

Platform constraints: Tauri desktop UI, should remain plausible at 800px wide; do not draw fake macOS traffic-light controls because the native window chrome is not part of this specimen. Do not assume all pages use a sidebar, three columns, cards, or a fixed footer. The settings window and collapsible sidebar are independent component/layout patterns.

Output: one high-fidelity component specimen board, not a marketing page or a complete product dashboard. Use consistent placeholder copy, realistic control proportions, coherent alignment, and no invented product features.
```

`{VARIANT}` 的替换内容（每次只用一段）：

```text
A / Clear Blue: use a clear blue interaction accent close to #2563EB with neutral slightly-cool whites and grays.
```

```text
B / Quiet Indigo: use one indigo interaction accent close to #4F46E5 with restrained warm-stone neutrals. Do not use #6366F1 with small white text on a button.
```

```text
C / Warm Neutral + Blue Signal: use warm whites and pale stone surfaces with the same clear blue interaction accent as A.
```

建议在 Stitch 中创建同一项目下的三个独立 screen，分别命名 `A - Clear Blue`、`B - Quiet Indigo`、`C - Warm Neutral + Blue Signal`。若 Stitch 支持以已有 screen 为参考，先生成 A，再复制/引用 A 作为 B、C 的布局基准，并在提示词中明确“只改强调色与中性色温，其余保持一致”；如果生成器无法稳定保持布局，则分别用完整基线提示词生成，再做人工对比。

如果当前重点是沿用已认可的整体风格并补齐组件，而不是继续选择主色，可跳过 A/B/C 色彩对照，直接使用下一节的扩展组件提示词。A/B/C 是可选的色彩探索，不是后续组件原型生成的前置条件。

## 5. 扩展组件原型提示词

### 5.1 是否需要继续生成

首轮样本已覆盖表面层级、常见控件、设置行、资源行、独立设置窗口和折叠侧栏，足以初步判断整体风格；但还没有把常见的组件状态、反馈方式、数据密度和工作台内容组件拆开验证。若目标是趁这次设计阶段降低后续返工和组件维护成本，建议再补一组**按组件职责分屏**的视觉样本，而不是继续扩写一张塞满所有组件的总览板。

建议优先补齐：

1. 原子控件及标签/状态标记的变体；
2. 列表、筛选、批量操作和表格等分子组合；
3. 空、加载、错误、确认、运行中等状态与反馈层；
4. 对话、代码、工具结果等工作台内容组件；
5. 侧栏、树形分组与辅助检查面板的可组合样式。

这不是要求穷举所有产品页面，也不表示上述模式都会进入 DG-OS。它们是有代表性的视觉/交互候选，最终采用范围仍由产品场景与正式规格决定。以下提示词固定沿用现有参考风格，不再生成 A/B/C 配色对照。

### 5.2 Stitch 使用方式

- 在 Stitch 同一项目中，每次新建一个独立 screen；从下面选择一个专项提示词，单独生成，不要把几组提示词合并成一张板。
- 若可选择参考 screen 或图片，把已认可的原型作为**风格参考**。明确要求沿用其色彩温度、表面层级、边界、字重、图标质感与圆角；不要复刻参考图的功能标签、页面布局或产品分类。
- 每个专项提示词都是单独的一屏任务描述；为了保持跨图一致，每次先把“共用约束”附在所选专项提示词前，再一起提交，组合后即为一条完整提示词。提示词英文为便于 Stitch 稳定理解，样例界面文案要求中英并列。
- 建议先生成 01–05，再生成 07、09、10；06 与 08 是按未来页面需要选做的布局模式。若某一屏仍把组件画得过小，可要求 Stitch 仅拆分该组，不要重新设计整套风格。
- 命名建议依次使用章节中的英文短名，如 `07 - Navigation & Command Overlays`、`09 - Files & Attachments`。所有 screen 应从同一已认可的风格参考派生。

### 5.3 共用约束（每次与一个专项提示词组合）

```text
Extend the established DG-OS desktop UI visual language shown in the selected Stitch reference. Treat the reference as a style source only: preserve its calm, precise, neutral-surface desktop character, restrained interaction accent, crisp boundaries, typography hierarchy, icon treatment, and component proportions. Do not copy its feature names, information architecture, page structure, or business content, and do not invent a new visual direction or alternate color theme.

Create one focused, high-fidelity reusable-component specimen screen for a local-first desktop application. Use neutral placeholder labels and sample values only. Include Chinese-first labels with short English equivalents where space allows, plus one deliberately long Chinese label and one long English label to reveal wrapping and truncation behavior. Do not imply that sample labels or data are real DG-OS features.

Keep the specimen visually coherent with the reference and readable at desktop scale. Show realistic component proportions, clear hierarchy, restrained spacing, and only the states relevant to this screen. Include visible keyboard focus and never communicate status by color alone. Avoid marketing copy, decorative gradients, glassmorphism, excessive cards, invented navigation taxonomy, and fake native window controls.

This is a visual prototype, not a final token specification, accessibility certification, responsive implementation, product IA, or approved component API. Do not add hex color codes, claim contrast compliance, or invent functionality. Use the established reference style consistently; do not create A/B/C variants.
```

### 5.4 专项提示词

#### 01 — Controls & Labels（原子控件与标签）

```text
Design a component atlas organized as a compact, clearly labeled grid of reusable controls, not as a product page. Cover: icon-only buttons with accessible-name tooltip examples; a small set of button hierarchy examples; text, search, password-masked, and number-stepper fields; a searchable select/combobox; checkbox, radio, switch, segmented choice, and a slider; tag/chip and removable-token examples; status badges with icon plus text; avatar and softly tinted icon tile; keyboard shortcut keycaps; and a compact progress indicator.

Show a useful subset of default, hover, keyboard-focus, selected, disabled, busy, and invalid states beside the relevant controls. Make field labels, helper text, optional markers, and inline validation visibly distinct. Keep examples small but legible and leave enough room to compare the shape, border, icon alignment, and state treatment. Use neutral sample text such as “显示名称 / Display name”, “输入关键词 / Enter a term”, “标签 A / Tag A”, and “正在处理 / In progress”. Do not fill the board with redundant color swatches or create a full settings form.
```

#### 02 — Rows & Toolbars（分子行与操作工具栏）

```text
Design a reusable interaction-pattern sheet focused on rows and compact toolbars. Show several distinct but related molecules: a settings row with title, helper line, optional secondary metadata, and a right-aligned control; a resource row with icon tile, title, subtitle, status label, trailing value, selection, and overflow action; a selectable row with checkbox and keyboard focus; and a compact filter/search toolbar with query field, neutral filter chips, sort control, view toggle, and clear-filters action.

Add a narrow bulk-action strip that appears only when multiple rows are selected, and a small tab/segmented-control example for local view switching. Show normal, selected, hover, focus, and disabled variants where relevant. Include one long label and one two-line helper so truncation and wrapping can be judged. Use neutral placeholders (“项目 A / Item A”, “辅助说明 / Supporting detail”, “状态 / Status”, “3 项已选 / 3 selected”) and do not turn this into a real feature list or global navigation design.
```

#### 03 — Data Views（表格、列表与时间线）

```text
Design a data-presentation specimen with three clearly separated, reusable patterns: a compact sortable table, a dense event/log list, and a simple chronological timeline. Use generic columns and entries only, such as “名称 / Name”, “类型 / Type”, “状态 / Status”, “最近更新 / Updated”, and timestamps. Include row selection, selected-row treatment, sort direction, a status icon plus text, one truncated long value with a tooltip affordance, and a restrained pagination/footer example.

Show a small density comparison for the same table rows (comfortable and compact), without shrinking text to illegibility. In a small inset area, show how the table region looks while loading and when it has no matching results; do not create three complete pages. Make column alignment, separators, hover/focus affordances, and scanning rhythm the focus. Avoid charts, fabricated metrics, feature-specific columns, or a dashboard layout.
```

#### 04 — Feedback States（状态、反馈与浮层）

```text
Design a reusable feedback-pattern board that clearly distinguishes persistent inline feedback from transient overlays. Include: a neutral info notice, success/attention/error banners with icon and text, inline field validation, an empty state with a simple restrained illustration or icon and one action, a skeleton/loading example, a determinate progress state with a cancel affordance, and a compact success/error toast pair.

Also show a tooltip, a small anchored popover/menu, and a focused destructive-action confirmation dialog with cancel and destructive actions. Label the dialog as a compact overlay; it is not an independent settings window. Use concise neutral Chinese/English sample messages and show the same message structure at two different text lengths. Distinguish status using iconography and wording as well as color. Do not invent real product errors, recovery workflows, or feature categories; keep hierarchy, placement, and dismissal affordances visually clear.
```

#### 05 — Workbench Components（工作台内容组件）

```text
Design a focused specimen of reusable content components for an AI-oriented desktop workbench, without composing a complete application screen or defining a user journey. Show a generic user message and assistant response with compact metadata; a streaming/thinking indicator; a composer with multiline input, attachment/token chip, secondary utility icon, and primary submit/stop control; a code block with language label and copy affordance; a generic tool/action result card with pending, running, completed, and failed visual states; and a permission/confirmation card with a clear description and explicit allow/deny actions.

Add a small diff or structured-output panel to demonstrate technical content hierarchy. Keep component boundaries, spacing, typography, code contrast, status semantics, and keyboard focus visible. Use non-sensitive placeholder content such as “示例内容 / Sample response” and “操作摘要 / Action summary”; do not use real credentials, real prompts, invented tool names, or claims about DG-OS capabilities. Do not turn these elements into a chat-page layout or product taxonomy.
```

#### 06 — Sidebar & Inspector（可选：辅助面板组合）

```text
Design a reusable shell-pattern specimen showing an expanded sidebar, a collapsed icon rail, and a contextual inspector panel as independent composable patterns. Use generic groups and entries only (“区域 A / Group A”, “项目 01 / Item 01”). Show group collapse, active and hover items, a count/status marker that does not rely on color alone, keyboard focus, tooltip affordance on the collapsed rail, and a clear expand/collapse control.

Beside these examples, show a narrow inspector panel with a title, close/collapse affordance, section headings, a few generic property rows, one editable field, and a subtle divider hierarchy. Include a constrained-width variation to illustrate which labels wrap, truncate, or move into a secondary region. This is a component/layout-pattern board, not the DG-OS global shell: do not invent real navigation items, require every page to use a sidebar, or define application information architecture.
```

#### 07 — Navigation & Command Overlays（导航原子与命令浮层）

```text
Design a reusable navigation-and-overlay component specimen, not a complete application shell. Show compact breadcrumb navigation, local tabs, a generic navigation item in default/active/hover/focus states, a contextual overflow menu, a nested submenu, and a command-palette style quick switcher with a search field, grouped neutral results, keyboard shortcut hints, highlighted match text, and an empty-result state.

Demonstrate clear keyboard navigation and focus movement without relying only on color. Keep popovers anchored to their trigger and visually distinct from a dialog or independent window. Use placeholder labels (“最近项目 / Recent items”, “操作 A / Action A”, “返回 / Back”) and generic shortcut keycaps. Do not define global navigation categories, real commands, or product workflows. Focus on alignment, surface elevation, separators, selected-result treatment, and compact desktop proportions.
```

#### 08 — Hierarchy & Resizable Panes（树形层级与可调分栏）

```text
Design a desktop layout-pattern specimen focused on hierarchical navigation and adjustable work areas. Include a compact tree/list with two nesting levels, disclosure controls, item icons, selected and hover states, keyboard focus, a disabled child, and a neutral count marker. Alongside it, show a two-pane split view and a three-region composition with draggable resize dividers, clear min-width behavior, and a collapsed secondary pane affordance.

Add a small drag-reorder example with a visible insertion indicator and a keyboard-accessible alternative affordance; do not imply that dragging is the only way to reorder. Include one long item name and a narrow-width example to show truncation and tooltip placement. Use generic labels (“文件夹 A / Group A”, “条目 01 / Entry 01”). Treat these as optional composable patterns, not a required global layout or actual file/product taxonomy.
```

#### 09 — Files & Attachments（文件选择与附件状态）

```text
Design a reusable file-and-attachment component board for a desktop application. Show a restrained drop zone in idle and drag-over states; a compact file row with generic file icon, name, type/size metadata, and remove action; a selected attachment chip; and upload/transfer rows in queued, in-progress, completed, paused, and failed states. Include progress, retry, cancel, and remove affordances only where appropriate to each state.

Show a small preview tile for a generic image/document and a neutral unsupported-file state, but do not create a file manager page. Use harmless placeholder names such as “示例文档.pdf / Sample document.pdf” and fictional sizes. Ensure long filenames wrap or truncate cleanly, status is communicated with icon and text as well as color, and keyboard focus is visible. Do not suggest actual DG-OS file-handling capabilities or invent permissions and data-retention behavior.
```

#### 10 — Typography & Microcopy Patterns（文字层级与界面文案样式）

```text
Design a visual specimen for reusable interface typography and concise product microcopy patterns. Demonstrate page and section headings, body text, secondary/help text, technical identifiers in monospace, inline links, form labels with optional/required markers, character-count hint, inline validation, a short neutral notice, a confirmation message, and a concise empty-state title/body/action hierarchy.

Show the same semantic message in concise Chinese and English, plus one intentionally long bilingual label and paragraph to inspect wrapping, line height, punctuation spacing, and truncation. Include examples at normal and compact density while keeping helper text comfortably legible. Use neutral sample content and avoid marketing slogans, invented product terms, or prescriptive workflow copy. Focus on readable hierarchy and consistent tone rather than decorative typography or large display text.
```

#### 11 — Project Shell & Interaction Prototype（项目整体框架与交互原型）

本组已改为 **Bytro 布局参考版**，替换原先较泛化的整体框架提示词。2026-11-02 经用户授权直接查看本机运行中的 Bytro：工作台、会话页、侧栏收起态、设置的通用页与模型配置页。仅参考空间组织、控件呈现和可观察的交互，不复制实际项目名、聊天内容、账户、连接信息和功能分类。

布局提炼：

- **主框架**：左侧浅灰分组导航，上方是工作区切换，底部是账户与侧栏收起入口；细分隔线连接右侧大面积内容区，而非再叠一层全局顶栏。
- **工作台**：内容顶部左侧为上下文、标题和少量元信息，右侧为紧凑操作；下方宽主区域搭配较窄辅助区域，再接最近条目等次级内容，大小有别而非等宽卡片铺满。
- **会话页**：主内容顶端是紧凑上下文栏，其下为局部标签带；正文限制阅读宽度居中，底部输入区与正文对齐，输入框内的下缘安排轻量工具及发送操作。
- **侧栏收起态**：变成窄图标轨道，保留分组分隔、当前项、底部账户和展开入口，而不是整个消失。
- **设置弹窗**：实际观察为遮罩上的居中弹窗，包含标题/关闭、左侧分类、滚动内容和固定操作区；复杂类别内部再增加资源列表，简单类别保持双栏。它不是独立系统窗口，也不是主应用内的常驻设置页。

本组按最新参考将设置呈现为**独立于主工作区的居中弹窗**，取代旧版第 11 组“禁止弹窗、必须独立窗口”的提示。其他章节的独立窗口样本仍是单独的设计探索，不因此冻结最终宿主实现。Bytro 的紫色渐变、营销/邀请模块、统计图与工程专用入口不直接带入；视觉样式以已认可的 DG-OS 原型为准，功能分类与正式 IA 仍待产品设计。
