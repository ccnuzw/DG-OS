> 2026-11-01 起草，门禁准备阶段（D100）。本文是 V2 范围的权威草案，**尚未冻结**：范围在通过[版本进入开发门禁](../../版本进入开发门禁.md)时由用户确认后冻结，之后的变更走门禁文档 §5.2 的流程。V2 规划主文档仍是 [V2-画布系统](../V2-画布系统.md)；两者冲突时以本文为准，并回写规划。

## 1. 版本定位

V2 交付 DGOS 的核心价值功能：无限画布。用户把模型、技能与工具节点连成工作流，在桌面上编辑、运行、保存和分享。画布是官方应用模块，也是第三方模块开发者的样板，只使用公开、带版本、需要声明权限的宿主能力（V2 规划 §1）。

### 1.1 架构基线

- V1 的底层能力（Provider、Skills、MCP、模块系统与权限、设计系统、本地账户）保持不变，V2 在应用框架层新增运行服务、协同文档与资产服务、扩展注册表、模块构建与样式、图片生成能力（[总体架构](../../../04-技术架构/总体架构.md) §10）。
- 画布引擎打进画布模块，节点是 DOM，连线画在 Canvas2D；画布文档使用 Yjs，宿主只处理更新字节（D095）。
- 运行归宿主持有，离开页面不取消（D082）。

### 1.2 核心原则

- **不开后门**：画布用到的宿主能力都是公开 SDK 接口。
- **不花冤枉钱**：只重跑变化的部分，调用模型和工具的节点只在用户运行时执行（D104）。
- **对外格式稳定**：工作流文件独立于内部文档格式，带版本，只做新增式变更（V2-FR-008）。

## 3. 核心流程

```mermaid
flowchart LR
  A[打开画布] --> B[从模板新建或空白画布]
  B --> C[添加节点并连线]
  C --> D[改参数：便宜节点自动预览]
  D --> E[点运行：只执行变化部分]
  E --> F[查看结果、强制重跑单个节点]
  F --> G[保存，导出工作流文件]
```

## 6. 验收标准

### 6.1 核心能力验收

各功能的 AC 以其功能主文档为准。版本层的验收场景：

- [ ] 从三个内置模板各新建一张画布，配置 Provider 后运行成功（V2-FR-008）。
- [ ] 改 Prompt 后 Transform 自动预览、LLM 标为已过期且没有调用；点运行后只重跑变化部分（V2-FR-007）。
- [ ] Loop 对列表逐项执行，结果顺序正确；超过上限时不运行（V2-FR-007）。
- [ ] Generator 节点生成图片，结果保存为资产并可在下游使用；Image 连到 LLM 时模型能理解图片（V2-FR-010）。
- [ ] 运行中离开页面，返回后看到结果（D082）。
- [ ] 导出 → 导入 → 导出往返一致（V2-FR-008）。
- [ ] V1 的全部页面已按 V2-FR-009 的设计迁移。

### 6.2 性能验收

- [ ] 约 500 个节点时平移、缩放、拖拽保持 60fps（测量条件在门禁时定义，预计登记为 V2-NFR）。
- [ ] 画布模块加载 < 1 秒（产品蓝图 §6.2）。
- [ ] 自动预览延迟（参数变化到预览更新）的目标值在 500 节点原型后确定。

### 6.3 质量验收

沿用 [V1 版本总览](../../当前版本/V1-版本总览.md) §7.4 的质量指标。

### 6.4 发布门禁

- [ ] 所有 V2 P0 功能验收通过
- [ ] 性能与质量指标达标（§6.2、§6.3）
- [ ] 从 V1 升级：V1 用户库迁移到 V2 后数据完整、V1 功能正常
- [ ] macOS 安装包构建成功，全新环境安装测试通过
- [ ] 用户文档、开发者文档（画布节点包开发）完成度 > 80%

## 7. 时间线

V2 规划的“2 个月、8 周”是初始估算，没有计入自研渲染引擎与平台能力，进入门禁时按 500 节点原型的结果重估。V2 开发要等 V1 通过发布门禁（路线图 §8.3）且 V2-FR-009 完成（D097）。

## 8. 风险与依赖

- 渲染引擎在 500 节点下达不到 60fps：先做原型（V2 规划“相关风险”）。
- 图片生成与图片输入的上游行为未验证（OpenAI 兼容与 Anthropic 的图片内容格式不同）：V2-FR-010 门禁前要有真实上游调用证据（D103、D106）。
- 平台能力多、彼此依赖：开发顺序在门禁时按依赖排定（运行服务、文档与资产服务、扩展注册表先于画布）。
- 依赖 V1：模块系统、权限、Provider、Skills、MCP 稳定；V1 发布门禁通过。
