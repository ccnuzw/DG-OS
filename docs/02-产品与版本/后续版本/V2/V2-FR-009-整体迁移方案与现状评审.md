> 设计评审工作稿，2026-11-03。阶段1已补设计基线、迁移矩阵、契约提案、范围冲突与阶段2/3任务（§9～§12）；用户要求当前原型完整迁移后一次切换。本文不将推荐提升为冻结接口/生产准入，不修改生产行为。§6/§8为前轮历史运行证据，本轮证据单列§12；状态仍在版本实现状态文档维护。

## 1. 结论与依据

本次目标是把现有工程界面完整转换成 `prototypes/product-design/` 当前呈现的产品体验。保留领域服务、真实业务规则和可复用的行为原语；重做页面编排、工作面生命周期、主题解析和组件视觉。现有 `@dgos/ui` 是承载新设计的实现基础，不是限制目标外观的模板。

完整主题编辑器、三域排版、工作区标签、应用启动台、标签列表、命令面板、设置浮层、资源列表—详情、对话阅读区与输入区，都属于同一交付包。FR-005/FR-009 是技术归属，不能成为主题或交互延期交付的理由。内部按依赖分步实现、验证；对用户只有一次完整切换，不交付“新外壳 + 旧工程内容”的过渡状态。

本次复核纠正首轮方案：不再把静态暖色与单一蓝色当完整主题，不再沿用旧清单的 172px/860px 尺寸作为原型最终值，不再默认将命令面板留后续。最新原型运行结果作为视觉与空间基线；原型内部矛盾和模拟能力分别列出，不直接复制其错误或假数据。

## 3. 已确认的问题与修法

优先级：P1 为应先处理的用户可见故障或集成风险；P2 为迁移一致性与可用性问题。未发现可据本轮证据认定的账户越权 P0。

### R01 / P1：浅色主题控件边框令牌循环引用

- 位置：`src/ui/tokens/colors.css:44,62`；`src/ui/tailwind.css:44`；使用者如 `src/ui/components/Checkbox.tsx:33`、Input/Select。
- 原始颜色声明是 `--color-border-control: #7b8494`，新角色 `--border-control` 指向它；Tailwind 映射又将 `--color-border-control` 定义为 `var(--border-control)`。编译后的浅色 root 形成闭环。
- 浏览器实测：浅色 `getComputedStyle(document.documentElement).getPropertyValue('--color-border-control')` 为空；MCP 未选中 Checkbox 的边框为白色。深色由非 theme 层的显式 `#788291` 覆盖，表现不同。
- 临时诊断：只在评审页设置 root 的 `--color-border-control: #7b8494` 后，Checkbox 边框立即变成 `rgb(123, 132, 148)`；移除诊断覆盖后恢复白色。没有修改生产文件。
- 修法：移除冲突的同名反向映射；颜色只保留一个源，必要角色只能单向引用。不要靠给 Checkbox 写死颜色绕过问题。清查所有 Tailwind namespace 与既有 token 同名的映射。
- 验证：构建后真实 CSS 的浅/暗主题控件边界、focus、selected、disabled；检查 computedStyle 非空和实际颜色配对。只读取源码色值的对比度测试不足以捕获该问题。

### R02 / P1：工作区标签保留，未保存表单却随切页丢失

- 位置：`src/App.tsx:118` 的 Routes；`src/workspace/useWorkspaceTabs.ts:10` 明确尚未 keep-alive；`src/pages/McpManagement.tsx:67` 的局部 config 状态。
- 复现：MCP → 新增名称填入 `migration-unsaved` → 设置 → 点击仍在外层标签栏的 MCP → 名称变为空；无放弃提示。本轮已在真实 React 页面、mock IPC 下复现。
- 修法：为已打开的工作面提供稳定挂载与隐藏；关闭才释放。表单脏状态参与关闭保护，设置覆盖层不卸载背景。密码/token 输入仍按安全要求及时清理，不把所有输入持久化到磁盘。
- 验证：资源选择、搜索、非敏感草稿、滚动位置跨页保留；明确关闭时确认；账户切换后清空；取消保存/失败不假装成功。
- 限定：不能推导为聊天也丢数据。聊天状态已在独立 chatStore 中保留，需按消费者分别核对。

### R03 / P1：外层关闭没有运行确认，预备 reducer 也未接入生产

- 位置：`src/workspace/TabBar.tsx:68` → `src/workspace/useWorkspaceTabs.ts:52`；`src/App.tsx:86,113` 只传路由标签 hook。
- 外层关闭直接删 ID 并导航，没有查询运行/脏状态；技术设计 `closeAiWorkspace` 要求运行中先确认。现有内层会话关闭确认不能覆盖外层入口。
- 修法：将确认与执行放在统一工作面关闭协调入口，TabBar 仅发意图。区分“切换”“关闭外层视图”“关闭内层会话”“停止任务”“卸载模块”。FR-009 主规格状态与生命周期要求：AI 外层关闭遇运行会话先确认停止；应用外层关闭只 detach、不停止实例。不能给所有标签套同一种关闭行为。
- reducer/model 可作为基础，但必须通过真实 App/store/runtime 接线后再计入行为完成；不要继续维护两套彼此独立的生产标签状态。
- 验证：AI 运行时关闭外层、取消确认、确认后重新打开恢复状态；内层关闭取消失败；模块关闭只 detach，实例继续由宿主管理。本轮只确认代码缺口，没有执行真实生成或模块操作。

### R04 / P2：共享按钮仍带原生立体边框

- 位置：`src/ui/styles.css:2` 明确不引入 preflight；`src/ui/components/Button.tsx:11` 的基础样式未消除原生 border/appearance。
- 浏览器实测：MCP 的“保存 Server”为 `border: 2px outset rgb(0,0,0)`、`appearance: auto`；外壳按钮额外写了 `border-0`，因此同一应用呈现两种控件质感。
- 修法：在受控的共享组件内显式统一 appearance、基础边框、字体继承，secondary/danger/focus 状态按 token 赋值。不要直接全局引入 preflight 影响尚未迁移页面与模块。
- 验证：同屏 primary/secondary/ghost/disabled/loading、Input/Select/Checkbox/Switch，亮暗两套；以浏览器截图和 computedStyle 为证据。

### R05 / P2：窄窗口与高密度下侧栏未按方案让出空间

- 位置：`src/workspace/AppShell.tsx:93`、`src/ui/tokens/geometry.css:18`；取值清单 §4.5 约定 1120/800 两个断点。
- 本轮 799px 宽实测：100% 密度侧栏 172px；175% 密度侧栏 301px，仍是展开状态。页面无 document 横向溢出，但主工作区被明显挤压；“无横向滚动”不能作为布局完成的唯一判断。
- 修法：区分用户折叠偏好与当前 viewport 派生状态，窄窗自动图标化，恢复宽窗后恢复用户偏好；内容最小可用宽度优先。组件的局部重排可用容器条件，但须记录与两个产品断点的关系。
- 验证：799/800、1119/1120 边界，75/100/175 密度，手动折叠再变宽，长中文与英文；主操作始终可见或可滚动到达。

### R06 / P2：外层 tab 使用 roving tabindex，却没有方向键行为

- 位置：`src/workspace/TabBar.tsx:54-59`。非选中 tab 为 `tabIndex=-1`，没有 Arrow/Home/End 处理。
- 实测：打开 MCP 与技能两个外层标签，聚焦技能标签并按 ArrowLeft，焦点和选中状态仍在技能；MCP 的主 tab 为 -1。
- 修法：采用既有 Tabs 的键盘模式或完整实现 roving focus；若手动激活，方向键移动焦点、Enter/Space 激活，并滚动显示焦点。关闭后焦点回相邻标签，特殊页无 active tab 时仍应可进入标签组。
- 不宜只让所有 tabIndex=0 来绕过，也不将内层会话与外层工作面混成一组。

### R07 / P2：专注布局快照会被覆盖，属于接线前必须修复的潜在缺陷

- 位置：`src/workspace/reducer.ts:173-182`；对应技术设计的 toggleFocus 伪代码也有同样覆盖风险。
- 首次专注保存原布局；专注 A 后切专注 B 又保存当时已隐藏的布局，丢失原快照；退出返回 `restored-layout` 时 state 内快照直接清空，调用方还需有明确的恢复载荷/读取协议。关闭专注面也要覆盖恢复分支。
- 本轮直接执行 reducer 观察到快照从全 true 变成全 false，退出只留下 null。该 reducer 尚未接到实际 App，所以不将其描述为当前用户已遇到的专注故障。
- 修法：只在未专注→专注时保存原布局；专注目标切换保留它；退出/关闭返回可应用的恢复数据。同步修技术设计及既有行为测试。

### R08 / P2：取值草案、原型与生产约定尚未收敛

- 取值清单开头写“非冻结”，§5.1/§7 又写“权威/唯一出处”；且 §3.1 要求不引入 `surface-*` 第二命名，生产已经引入整套别名。
- 清单声明状态色采用原型值，但 `colors.css:20-32` 仍为现有状态色；不能据此称对比度失败，应先明确保留还是改色。
- 清单标准按钮 32px，V1 默认 Button/Input 为 36px，而当前原型工作区按钮约 25–28px。完整迁移应建立紧凑角色，并迁移全部调用点，包括随包模块；是否保留旧默认 API 按模块契约处理，不能让旧默认外观继续决定产品页布局。
- Input 当前固定 `h-9`，尚无明确紧凑变体契约；三作用域字号别名仍依赖密度，不能宣称内容字号独立。
- 命令面板在取值清单写后续，但主规格 AC16 已要求 Cmd/Ctrl+K 打开启动台，原型也已提供搜索与键盘执行；按本次用户目标纳入整体切换。市场原型自身标 V3 预研；该版本边界与普通导航交互区别处理。
- 修法：正式数值与组件契约回到 FR-005，产品 IA/关闭行为回到 FR-009，方案文档只引用；对冲突建立一次具体裁定，不让后续开发者从不同文档自行挑选。本文建议保留五档与 11px 下限，禁止为贴图恢复 9/10px 字号。

## 4. 一次完整切换的实施方案

### 4.1 交付范围与实施方式

“一次到位”指一个完整产品结果，不是一次性提交未经运行的大改。开发中可以有多个小切片，但所有页面、主题、模块宿主和关键旅程通过后才切换；不发布新旧两套 UI，也不长期保留旧路由页面实现。

- **必须一起交付**：五套明暗主题与三域排版、外观预览/应用/恢复/持久化、全局壳、两层标签、启动台与固定、标签列表与命令面板、设置浮层、全部既有用户页面、真实模块工作面、全局空/错/加载/权限状态。
- **后端尽量复用，但允许必要增量**：完整主题偏好、工作区应用目录读取、多视图宿主属于本次依赖。不能以“只做 UI”为由省掉这些真实实现。
- **已有业务能力不减少**：Provider 凭据、Skills 导入/版本/只读、MCP 审批/未知结果、账户隔离、LAN 配对撤销、任务取消等保留。主界面用产品文案，技术诊断按需展开。
- **原型中的独立业务增量不隐去**：画布、云市场、CLI 配置、存储清理、语音/附件/结构化产物均列到 §7.6，说明已有契约、缺口、版本归属和闭环条件。范围冲突未裁定前不能宣称全原型功能完成。

### 4.2 七阶段推进计划

以下七阶段取代原 W0～W6 工作包的执行顺序；阶段编号用于调度，不代表新功能编号或已获开发准入。目标是完成一个统一切换的迁移版本。阶段完成必须同时满足“真实行为 + 原型视觉 + 对应证据”，不能仅按文件数量或测试数量计算进度。

#### 阶段 1：设计基线与迁移契约收口

- 以 §7 的最终渲染为依据确定默认预设、侧栏/阅读列/设置浮层尺寸、字号角色、交互状态；同步修订直接冲突的 FR-005/009、外观分篇与取值清单，不再新建另一套数值表。
- 建立“原型入口 → 生产页面/组件 → store/宿主接口 → 验收场景”清单，覆盖所有用户可达页面，包括模块内部与远程页面。
- 一次收口主题快照/revision/受支持schema与损坏恢复、受控主题变量写入、Settings路由、工作区目录读权限、模块视图贡献和运行关闭策略；旧偏好兼容按D126不提供。
- 对 §7.6 的市场、画布、CLI路径、存储、附件/语音/结构化产物逐项确认范围、真实数据来源和依赖。已有决定覆盖的直接执行；只有未决产品范围/安全契约集中裁定。未纳入必须有明确结论，不能由实施者自行删减。
- 整理可回退的代码与偏好数据基线；复用仍适用的验证，必要的当前快照基线按D097和受影响领域补齐。

**阶段产物**：可直接施工的迁移矩阵、设计/契约增量和验证清单。这个阶段只收口本次冲突，不扩展为全库文档整顿。

#### 阶段 2：修复基础缺陷，完成主题与组件体系

- 优先修 R01 token循环与 R04 原生立体边框；检查 Tailwind 同名映射、语义颜色引用和编译后计算样式。
- 完成五预设×明暗、三域覆盖/排版、预览/应用/恢复、非法配色校验、revision冲突及宿主原子保存；按D126使用新安装默认值，不提供旧偏好升级映射。主题内核和保存能力本阶段完整实现，不推迟到页面迁完之后。
- 为 Button/Input/Select/Checkbox/Switch/Tabs 等补齐原型紧凑外观、状态、尺寸与字体；统一图标、分类色容器、Popover/Menu、焦点和动效。
- 保持14px换算与五档兼容；正文/代码显式字号独立。组件内部消除UA差异，避免全局reset破坏未迁模块。
- 使用真实组件组合观察表单、菜单、确认框、阅读/代码区域在各预设中的表现；组件检查页仅作开发校准，不作为用户页面交付。

**完成条件**：主题修改可取消、保存失败可恢复、应用后重启仍正确；实际CSS值有效；默认/hover/active/focus/disabled/loading状态统一；主题不能只在设置预览区生效。

#### 阶段 3：工作区、模块标签与任务生命周期

- 整合现有路由标签hook与预备reducer，形成唯一surface状态；路由负责导航投影，业务store不复制到标签模型。
- 修 R02 切页丢草稿、R03 外层关闭绕过确认、R07 专注快照覆盖；Agent/单任务运行控制与组件卸载解耦。验证晚到ack、停止失败、审批过期和账户切换。
- 复用ModuleSlot/runtime-owned容器；完成工作区只读目录、显示元数据与权限状态；真正定义多文档view归属，不复制实例或把同一DOM同时挂到两个面板。
- 内置资源页/AI/单任务/Agent/动态模块各有明确关闭策略。后台运行事件持续消费，隐藏页面不抢焦点；账号reload后旧状态消失。

**完成条件**：切到其他标签或设置不丢草稿、不隐式停止；关闭需确认时可以取消；模块视图关闭不发stop；重复打开不产生第二实例；撤权/停用/热更新能正确更新视图。

#### 阶段 4：完整外壳、设置浮层与全局交互

- 按原型实现品牌和分组侧栏、淡色分类图标、选中细标、账户区和彩色折叠；窄窗自动收起与用户折叠偏好分开。
- 完成外层标签、AI内层标签、运行/未保存标记、完整标题、关闭按钮、溢出列表、方向键/Home/End及关闭后的焦点落点。
- 完成工作区内悬浮启动台：动态图标网格、搜索、外点/Esc关闭、焦点恢复、拖拽/P键/长按固定及最多3个限制。
- 完成Cmd/Ctrl+K命令面板，与侧栏、桌面、标签菜单共用导航动作目录。
- 设置改为主窗口浮层；分类、内容列、固定操作区按原型组织；保留背景工作面、dirty guard、深链和返回历史。Launcher/Settings/确认框分别采用适当的遮罩与关闭语义。

**完成条件**：从任意工作面可完成设置、切换、搜索应用、固定和专注/恢复；不出现重复标题栏或额外模式层；800px/高密度下主操作和菜单可达。设置分类里的业务内容在下一阶段全部迁完。

先完成三个可对照原型的代表页面，校准后在本阶段内迁完其余页面：

#### 阶段 6：跨页面集成与原型能力补齐

- 本阶段收口阶段1已确认纳入的业务增量。接口设计和提供给页面的真实数据必须提前安排在其消费者之前；不能到此阶段才发现主题/模块目录等前置缺失。
- 对附件、多Skills、结构化执行记录/Diff/产物、CLI配置与存储等，依照范围结论接真实契约与状态。未通过版本裁定的云市场/画布引擎不做假实现，也不能据此宣布“全原型业务已完成”。
- 连贯运行：桌面→会话→模型/技能/工具→审批/结果→设置调主题→取消/应用→回到仍运行的工作面→资源→模块→专注→关闭/重开→账户切换。
- 集中处理跨页重复请求、隐藏状态、旧路径、权限撤销、系统主题变化、保存失败、偏好冲突、任务取消失败和运行未知结果。
- 收齐中英文文案、tooltip、键盘、窄窗、大字号、减少动效及滚动细节。

**完成条件**：全旅程无状态断裂，后台操作与界面一致；本期已承诺能力全部真实可执行；没有演示成功提示、硬编码业务数据或无法恢复的失败。

#### 阶段 7：整体验收、清理与统一切换

- 按 §5/§7.7 在同尺寸、同预设、同角色字号、同等数据长度下对照原型；五预设明暗检查基础控件，关键页面覆盖视口/密度/字号/中英组合。
- 运行受影响前端回归、构建、契约/Rust目标与真实Tauri WebView；完整产品验收时执行约定的全量前端回归，真实外部服务与跨平台证据分开报告。
- 删除已被替代的页面实现、旧样式、冗余alias和临时fixture。旧URL仅保留明确导航映射，不保留第二套UI；保留无关用户改动。
- 按D126验证受支持schema、损坏恢复及新安装默认值，不恢复旧两键偏好升级/兼容；核对账户隔离、模块撤权/热更新和失败恢复。数据恢复按[离线备份恢复规程](../../../01-项目概览/工程与本地环境.md#64-本地开发数据库损坏)执行，回退二进制不等于回滚数据库和资源。
- 集中更新权威规格/状态和证据，正式入口切到唯一新结构。

**完成条件**：范围内所有目标页面与关键交互通过；无数据丢失、越权、误取消、无法停止运行等阻塞缺陷；视觉与功能共同验收，不能用编译或测试通过替代实际界面对照。

#### 推进依赖与阶段汇报

阶段1先收口共享契约。阶段2与阶段3中不共享文件和接口的实现可并行；阶段4依赖它们形成可用基础。阶段5按三类样板校准后分页面推进；阶段6收口真实业务与跨页场景；阶段7统一验收切换。不得把宿主依赖留给最终验收兜底。

每个阶段结束提供四项：已交付页面/行为、对照原型的运行截图、实际验证结果、剩余阻塞及归属。状态写入既有实现状态文档，不在本计划维护勾选完成率。可独立的小修复无需反复等待确认；涉及未决产品范围、公开契约或权限边界的决定按阶段1集中处理。

本轮仅完成阶段1文档与契约交接；阶段2/3按§11依赖、§12准入结论另行执行，不因本方案的推进顺序自动启动代码迁移。主题、工作区与页面始终同包，样板不能替代整体交付。

## 5. 验证和交付标准

### 每个页面的完成判定

- 设计：目标布局与原型空间层级一致；允许为生产字号下限、密度和真实数据调整，不逐像素照抄 12px 根字号。
- 功能：真实接口、加载/空/失败/禁用/权限拒绝/处理中/结果未知齐全；危险操作有明确结果与取消边界。
- 状态：跨标签、打开/关闭设置、关闭/重开、账户切换、刷新与热更新分别有预期。
- 可用性：默认宽屏与窄窗、亮暗、75/100/175 密度、长英文、键盘焦点；需要对照保存后的真实界面，不仅跑 jsdom。
- 集成：已影响的调用者权限、模块生命周期或流式路径在真实 Tauri 中验证；Mock 只证明前端行为。

### 7.5 发现的真实契约差距

1. **模块单实例不等于多视图**：`moduleRuntimeHost.ts:123-130,548-582` 只有一个container和Component，ModuleSlot移动这个container保留根。需真正定义view/document桥，不复制runtime。
2. **Agent/单任务取消与页面卸载耦合**：`AgentWorkbench.tsx:31-40`、`SingleTaskWorkbench.tsx:101-109`。本轮真实前端mock IPC复现：启动Agent后点设置，收到`cancel_agent_run`且没有dialog，返回prompt为空。这是整体导航迁移的P1，修复应落runner与关闭策略。
3. **主题两字段API不足**：Rust AppearancePreferences仅theme/density，Patch拒绝未知字段；repository两键事务。完整主题必须升级DTO/持久化/初始化，不是多加几个CSS变量。
4. **全部原型状态不可直接作为契约**：原型safeGo运行时离开会停止；主规格要求切标签不取消。原型应用关闭提示“后台继续”，confirmCloseApp却把appRunning置false。生产遵循明确产品语义，修原型矛盾，不复制模拟状态机。
5. **设计检查通过不等于渲染正确**：当前stylelint规则检查var是否定义，不查依赖环；token测试的部分断言仅锁别名文本。新验收以编译后computedStyle、状态颜色配对和主题切换结果为准，删除锁实现文本的断言，不把错误alias重新固定成测试期望。
