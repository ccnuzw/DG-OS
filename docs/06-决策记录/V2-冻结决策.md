## D104 画布执行语义、循环、内置节点清单与工作流格式

- 状态：已冻结（2026-11-01 用户逐项选定，四项均与助手推荐一致）。第 5 项是助手由 D082 推出的接口后果，2026-11-01 由用户在 D106 第 1 项确认。
- 日期：2026-11-01
- 背景：
  - V2 规划与版本路线图写“实时执行（用户操作立即执行）”，与 D082“运行归宿主持有”的关系没有定义；按字面，每次改字都会触发 LLM、图片生成等计费调用。
  - “循环节点（LoopNode）”没有语义；V2 规划要求“执行前校验，允许图暂时不合法”。
  - 节点类型只有名字（“10+ 种”），没有清单。
  - 工作流 JSON 只有原则；“兼容老项目工作流格式（可选）”没有结论，仓库里也没有老项目格式的说明。
- 备选方案：
  - 执行：A（推荐）增量运行 + 便宜节点自动预览；B 改参数后防抖自动重跑全部受影响节点（含 LLM）；C 只有手动全图运行。
  - 循环：A（推荐）for-each 容器，图保持无环；B 允许环 + 退出条件；C for-each 容器 + 受限重试。
  - 节点：A（推荐）10 个可执行节点 + Note；B 去掉 MCP 节点。
  - 格式：A（推荐）自有格式，资产按哈希引用并可打包，V2 不兼容老项目；B 另加老项目导入；C 资产 base64 内嵌。
- 决定（四项均为 A）：
  1. **执行**：运行以用户点“运行”为主。运行只执行“变化的节点及其下游”，输入与参数都没变的节点复用上次结果。确定性、无外部调用的节点（Prompt、Transform、Conditional、Merge）在参数变化后自动预览；调用模型或外部工具的节点（LLM、Generator、MCP 工具）只在用户运行时执行，参数变化后标为“已过期”。用户可以对单个节点强制重跑。
  2. **循环**：画布的图始终是有向无环图，不允许连成环。Loop 是容器节点，对输入列表逐项执行内部子图，“按次数循环”即对 1..N 逐项执行；有最大迭代数与并发上限。连线不能跨越容器边界，只能经容器声明的端口进出。
  3. **内置节点**（`dgos.core` 包）：输入类 Prompt、Image；AI 类 LLM（可选 Skills）、Generator（图片生成，V2-FR-010）、MCP 工具（授权按 D083）；逻辑类 Transform（声明式表达式）、Conditional、Loop、Merge；输出类 Output。另有不参与执行的 Note。`Function` 节点不在 V2。
  4. **工作流格式**：自有格式 `dgos.workflow`，带 `schemaVersion`，列出依赖的节点包与版本；图片等资产按内容哈希引用；导出分“仅 JSON”与“JSON + 资产”的打包两种；老项目格式不在 V2。
  5. **自动预览走宿主**（由第 1 项与 D082 推出）：自动预览不在页面里计算，而是以“预览”范围发给宿主运行服务，该范围只包含确定性节点，宿主拒绝其中出现外部调用节点。这样页面与宿主只有一套节点实现，结果不会分歧。
- 不变：D082（运行归宿主持有，离页不取消）、D083（MCP 运行范围授权）、D094（节点调用权限算在贡献它的包上）、D095（文档与资产存储）。
- 风险：
  - 增量运行依赖可靠的缓存键；键漏掉某个输入会返回过期结果。缓解：缓存键由宿主计算，包含节点类型与主版本、参数、全部输入的哈希；V2-FR-001 技术设计中给出。
  - 自动预览每次往返宿主，在大图上可能有延迟。缓解：防抖；500 节点原型时一并测量。
  - LLM 结果不确定，复用缓存可能不是用户想要的。缓解：强制重跑。
- 影响：
  - 文档：V2 版本总览（新建）、V2-FR-007 节点系统（新建）、V2-FR-008 工作流格式与模板（新建）、V2 规划、版本路线图 §5.3 与 §8.2、功能演进矩阵 V2 行；V2-FR-001 运行服务需要“预览”范围与缓存键。
  - 代码、数据、错误码：不涉及（错误码在 V2 接口契约阶段分配）。
- 落实：
  - [x] 用户确认第 1～4 项（2026-11-01）
  - [x] 用户评审第 5 项（2026-11-01，D106 确认）
  - [x] 文档同步（2026-11-01）

## D106 自动预览走宿主、LLM 图片输入、CEL 表达式、初值复核与 V2 实现状态表

- 状态：已冻结（2026-11-01 用户逐项选定，五项均与助手推荐一致）。确认 D104 第 5 项；修订 D100 第 1 项中“门禁通过前不写实现状态”；修改 V1-FR-001 §2.3 中“图片输入 → 路线图未分配（D062）”的归属。
- 日期：2026-11-01
- 背景：D104 第 5 项待用户评审；V2-FR-007 留下图片输入与表达式语言两个待决项和一组助手选定的初值；`docs:check` 对没有出现在实现状态表中的 V2 功能报 ST001。
- 备选方案：
  1. 自动预览：A（推荐）走宿主运行服务；B 页面里用 JS 计算；C 页面里用与宿主同源的 WASM 计算。
  2. 图片输入：A（推荐）LLM 接受图片输入，Generator 不做图生图；B 两者都做；C 都不做。
  3. 表达式：A（推荐）CEL（Rust `cel` 0.15.0）；B JMESPath（Rust `jmespath` 0.5.0）；C 自定义小语言。
  4. 初值：A（推荐）先接受，500 节点原型后复核；B 现在逐项调整。
  5. ST001：A（推荐）建 V2 实现状态表，只写“规划中”；B 保留警告并在门禁文档写理由；C 在配置中忽略 ST001。
- 决定（五项均为 A）：
  1. **自动预览走宿主**：确认 D104 第 5 项。预览以“预览”范围交给宿主运行服务，只含 `pure` 节点；画布模块不包含节点的执行实现。
  2. **LLM 图片输入**：LLM 节点增加可选的 `image` 输入（可多张），由宿主把资产作为图片内容发给支持视觉输入的模型；模型不支持时节点校验不通过（`node_capability_unresolved`）。Generator 只接受文本提示词，图生图不在 V2。该能力并入 V2-FR-010，V2-FR-010 的名称改为“图片生成与图片输入能力”，编号不变；V1-FR-001 §2.3 的“图片输入”改为指向 V2-FR-010。
