## D104 画布执行语义、循环、内置节点清单与工作流格式

- 状态：已冻结（2026-11-01 用户逐项选定，四项均与助手推荐一致）。第 5 项是助手由 D082 推出的接口后果，2026-11-01 由用户在 D106 第 1 项确认。
- 日期：2026-11-01
- 背景：
  - V2 规划与版本路线图写“实时执行（用户操作立即执行）”，与 D082“运行归宿主持有”的关系没有定义；按字面，每次改字都会触发 LLM、图片生成等计费调用。
  - “循环节点（LoopNode）”没有语义；V2 规划要求“执行前校验，允许图暂时不合法”。
  - 节点类型只有名字（“10+ 种”），没有清单。
  - 工作流 JSON 只有原则；“兼容老项目工作流格式（可选）”没有结论，仓库里也没有老项目格式的说明。
- 备选方案：
  - 执行：A（推荐）增量运行 + 便宜节点自动预览；B 改参数后防抖自动重跑全部受影响节点（含 LLM）；C 只有手动全图运行。
  - 循环：A（推荐）for-each 容器，图保持无环；B 允许环 + 退出条件；C for-each 容器 + 受限重试。
  - 节点：A（推荐）10 个可执行节点 + Note；B 去掉 MCP 节点。
  - 格式：A（推荐）自有格式，资产按哈希引用并可打包，V2 不兼容老项目；B 另加老项目导入；C 资产 base64 内嵌。
- 决定（四项均为 A）：
  1. **执行**：运行以用户点“运行”为主。运行只执行“变化的节点及其下游”，输入与参数都没变的节点复用上次结果。确定性、无外部调用的节点（Prompt、Transform、Conditional、Merge）在参数变化后自动预览；调用模型或外部工具的节点（LLM、Generator、MCP 工具）只在用户运行时执行，参数变化后标为“已过期”。用户可以对单个节点强制重跑。
  2. **循环**：画布的图始终是有向无环图，不允许连成环。Loop 是容器节点，对输入列表逐项执行内部子图，“按次数循环”即对 1..N 逐项执行；有最大迭代数与并发上限。连线不能跨越容器边界，只能经容器声明的端口进出。
  3. **内置节点**（`dgos.core` 包）：输入类 Prompt、Image；AI 类 LLM（可选 Skills）、Generator（图片生成，V2-FR-010）、MCP 工具（授权按 D083）；逻辑类 Transform（声明式表达式）、Conditional、Loop、Merge；输出类 Output。另有不参与执行的 Note。`Function` 节点不在 V2。
  4. **工作流格式**：自有格式 `dgos.workflow`，带 `schemaVersion`，列出依赖的节点包与版本；图片等资产按内容哈希引用；导出分“仅 JSON”与“JSON + 资产”的打包两种；老项目格式不在 V2。
  5. **自动预览走宿主**（由第 1 项与 D082 推出）：自动预览不在页面里计算，而是以“预览”范围发给宿主运行服务，该范围只包含确定性节点，宿主拒绝其中出现外部调用节点。这样页面与宿主只有一套节点实现，结果不会分歧。
- 不变：D082（运行归宿主持有，离页不取消）、D083（MCP 运行范围授权）、D094（节点调用权限算在贡献它的包上）、D095（文档与资产存储）。
- 风险：
  - 增量运行依赖可靠的缓存键；键漏掉某个输入会返回过期结果。缓解：缓存键由宿主计算，包含节点类型与主版本、参数、全部输入的哈希；V2-FR-001 技术设计中给出。
  - 自动预览每次往返宿主，在大图上可能有延迟。缓解：防抖；500 节点原型时一并测量。
  - LLM 结果不确定，复用缓存可能不是用户想要的。缓解：强制重跑。
- 影响：
  - 文档：V2 版本总览（新建）、V2-FR-007 节点系统（新建）、V2-FR-008 工作流格式与模板（新建）、V2 规划、版本路线图 §5.3 与 §8.2、功能演进矩阵 V2 行；V2-FR-001 运行服务需要“预览”范围与缓存键。
  - 代码、数据、错误码：不涉及（错误码在 V2 接口契约阶段分配）。
- 落实：
  - [x] 用户确认第 1～4 项（2026-11-01）
  - [x] 用户评审第 5 项（2026-11-01，D106 确认）

## D106 自动预览走宿主、LLM 图片输入、CEL 表达式、初值复核与 V2 实现状态表

- 状态：已冻结（2026-11-01 用户逐项选定，五项均与助手推荐一致）。确认 D104 第 5 项；修订 D100 第 1 项中“门禁通过前不写实现状态”；修改 V1-FR-001 §2.3 中“图片输入 → 路线图未分配（D062）”的归属。
- 日期：2026-11-01
- 背景：D104 第 5 项待用户评审；V2-FR-007 留下图片输入与表达式语言两个待决项和一组助手选定的初值；`docs:check` 对没有出现在实现状态表中的 V2 功能报 ST001。
- 备选方案：
  1. 自动预览：A（推荐）走宿主运行服务；B 页面里用 JS 计算；C 页面里用与宿主同源的 WASM 计算。
  2. 图片输入：A（推荐）LLM 接受图片输入，Generator 不做图生图；B 两者都做；C 都不做。
  3. 表达式：A（推荐）CEL（Rust `cel` 0.15.0）；B JMESPath（Rust `jmespath` 0.5.0）；C 自定义小语言。
  4. 初值：A（推荐）先接受，500 节点原型后复核；B 现在逐项调整。
  5. ST001：A（推荐）建 V2 实现状态表，只写“规划中”；B 保留警告并在门禁文档写理由；C 在配置中忽略 ST001。
- 决定（五项均为 A）：
  1. **自动预览走宿主**：确认 D104 第 5 项。预览以“预览”范围交给宿主运行服务，只含 `pure` 节点；画布模块不包含节点的执行实现。
  2. **LLM 图片输入**：LLM 节点增加可选的 `image` 输入（可多张），由宿主把资产作为图片内容发给支持视觉输入的模型；模型不支持时节点校验不通过（`node_capability_unresolved`）。Generator 只接受文本提示词，图生图不在 V2。该能力并入 V2-FR-010，V2-FR-010 的名称改为“图片生成与图片输入能力”，编号不变；V1-FR-001 §2.3 的“图片输入”改为指向 V2-FR-010。

## D120 工作区标签、应用启动台、AI 会话多标签与单窗口边界

- 状态：已冻结（2026-11-03，用户确认工作区/应用宿主建议组合、应用启动台与 AI 会话多标签；标签与应用宿主技术设计仍待补）。
- 日期：2026-11-03
- 背景：
  - FR-009 当前仍是页面式结构：Workbench 只有聊天/单任务两个页面内模式，模块使用与模块管理混在设置子路由，应用入口依赖硬编码或动态顶层链接；模块数量增长后无法扩展。
  - 原型会话内容锁在 720px，顶部有顶栏、页面标题栏、会话标签三层；用户要求主工作区更大，并要求 AI 会话内支持多会话标签、不设左侧会话列表。
  - 现有模块宿主按模块实例管理，模块 DOM 由稳定容器承载（D044），但缺少“工作区标签/应用视图/单实例多视图”的产品模型；V2 画布需要全幅应用宿主与最大化。
  - 用户明确询问独立应用窗口：当前模块运行时在同一 WebView/JS realm，独立 OS 窗口会引入第二套模块宿主、窗口身份、权限与状态同步，不能按普通布局改动处理。
- 备选方案：
  - A. 保持页面式与每应用一个导航项，AI 会话保留左侧列表：改动小，但应用增长后导航不可维护，主工作区继续被列表和窄内容限制；不选。
  - B. 外层工作区标签 + 应用启动台 + AI 会话内层多标签 + 单主窗口：应用可同时打开、切换、最大化，AI 会话保持多标签；不需要多 WebView；选用。
  - C. 现在引入多 OS 窗口/分屏/多实例：视觉上最自由，但窗口身份、模块宿主、后台运行、权限与账户隔离均需重做，超出 V2 FR-009 的边界；不在 V2 引入。
- 决定：
  1. **工作区标签按工作表面组织**：外层标签承载 AI 会话组、画布文档、应用视图等工作表面；全局只保留一层工作区标签，不默认给每个应用再加“应用标签 + 文档标签”两层。AI 会话是唯一带内层会话标签的工作表面。
  2. **AI 会话内多会话标签**：AI 会话内部支持多个会话标签；不设永久左侧会话列表；历史通过标签溢出、历史下拉或搜索进入；新建、切换、关闭、溢出均可用；切换会话保留草稿与滚动位置，运行中的会话关闭前确认停止。外层切换到应用再返回时保留会话标签集合。
  3. **应用启动台**：在主窗口内提供独立的应用启动器覆盖层，不作为独立 OS 窗口或普通页面。入口为左侧“应用”、桌面“打开应用”和 Cmd/Ctrl+K；内容包含搜索、固定、最近、全部应用和状态；固定应用最多 3 个进入左侧导航；应用数据来自已安装模块，不硬编码示例应用；应用管理仍留在设置 → 应用与扩展。
  4. **一个应用一个实例**：一个模块/应用全局只允许一个实例；一个实例可以承载多个视图或文档标签；再次从启动台打开同一应用时聚焦已有视图，不创建第二个实例；实例与视图的归属由宿主登记，不靠前端路由推断。
  5. **单主窗口边界**：V2 只在主窗口内提供工作区标签；不同应用可以同时作为后台标签打开；不引入独立 OS 应用窗口、分屏或一个应用多实例。分屏与 OS 多窗口列为后续独立决策/技术设计，本轮只保留 workspace/window 抽象，不实现窗口创建。
  6. **切换、关闭与运行**：切换标签保留会话、应用和文档状态；关闭应用标签只关闭视图，不停止宿主后台运行；关闭运行中的会话先确认停止；关闭 AI 会话外层标签时保留会话标签集合与历史，运行中的会话先确认；账户切换、权限撤销、应用停用或崩溃时清理相关状态。
  7. **最大化 = 工作区专注模式**：隐藏左导航、检查器和历史列表，保留细标签条与应用切换入口；Esc 或显式操作恢复之前的布局；布局记忆以当前会话为界；OS 全屏另设，不把“最大化”等同于窗口全屏。
  8. **应用宿主布局**：manifest/contribution 声明应用视图为 document 或 full-bleed；宿主只提供最小外框与状态，full-bleed 应用（画布）占满工作区，表单类应用保留合理内容宽度；应用管理入口仍打开设置浮层，不在应用宿主内重复管理页。
  9. **单任务归属**：单任务是 AI 会话内的一种模式，不占主导航，不保留“单任务测试”作为独立产品入口；示例应用不硬编码进导航。
  10. **空间原则**：去掉重复的页面标题栏；会话目标宽度为 860–920px，右侧检查器可选，应用/画布全幅；不恢复永久左侧会话列表；具体像素与断点为设计方向，不是生产接口。
  11. **桌面仍为独立首页**：桌面承接固定/最近应用、最近会话、运行中与权限/更新提示；工作区作为常驻层，回到桌面不卸载已打开的工作区标签；不把桌面并进工作区标签。
  12. **设置形态不变**：D119 的主窗口悬浮设置继续有效；应用使用在工作区，应用管理在设置；不创建独立 OS 设置窗口。
- 理由：
  - 模块数量增长后，启动台 + 外层标签是可扩展入口；每应用一个导航项会持续膨胀。
  - 一个实例 + 多视图符合现有模块宿主，避免为标签引入多实例和第二套模块运行时。
  - AI 会话多标签但不设左列表，既满足用户明确要求，也把宽度留给主工作区。
  - 单主窗口避免在 FR-009/门禁前引入窗口身份、权限与多 WebView 的 L3 风险。

  - 关闭标签、后台运行和账户切换的语义如果实现不一致，会丢失状态或误停任务。缓解：先补工作区/应用宿主技术设计与 AC15～AC20。

## D122 启动台改为悬浮窗口，点击外部关闭，移除关闭按钮

- 状态：已冻结（2026-11-03，用户直接要求）。
- 日期：2026-11-03
- 背景：D121 的启动台覆盖整个主工作区，仍像一个整页界面；用户要求点击“应用”后只出现一个悬浮窗口，不占满右侧工作区，点击其他空白区域即关闭，不再提供右上角关闭按钮，接近 Apple 启动器的轻量感。
- 备选方案：
  - A. 保持全工作区图层 + 右上角关闭按钮：视觉完整，但遮挡工作区，关闭按钮多余；不选。
  - B. 居中悬浮面板 + 轻量遮罩，点击面板外或 Esc 关闭，不显示关闭按钮；选用。
  - C. 独立 OS 浮动窗口：跨窗口焦点和拖拽固定复杂，超出 V2 边界；不选。
- 决定：
  1. 启动台表现为主工作区内的居中悬浮面板，宽度约 760px（窄窗自适应），不占满右侧工作区；周围保留可见、可点击的工作区。

  4. 左侧导航保持可见，拖拽固定行为与 D121 相同；拖拽落点仍为导航区域。
