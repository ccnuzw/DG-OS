# ADR-0001 模块到宿主能力调用通道

- **状态**: Accepted（范围限于 V1 内置、经 D041 准入的首方模块，传输方案、限值与错误映射见 [D051](../V1-冻结决策.md#d051-模块能力调用通道的传输采用-adr-0001-方案-a限值与错误映射)；由助手按任务指令采用，仓库与会话中没有用户的逐条评审记录，评审结果待定。边界与语义由 [D050](../V1-冻结决策.md#d050-模块到宿主能力调用通道的边界与语义) 冻结）
- **日期**: 2026-10-29
- **决策者**: 助手起草并推荐，评审结果待定（仓库与会话中没有用户对本条的评审记录）
- **关联**: D026、D028、D033、D034、D041、D042、D044、D046、D048、D050、D051、V1-FR-004

## 背景

D048 让持有 supervisor 句柄的宿主 Rust 代码能调用 `providers.call`，但模块页面里的 JS 没有任何路径触发它：D042 的 `host` 对象只含 `React`、`apiVersion`、`moduleId`、`version`。要让模块真正使用宿主能力，必须新增一条模块到宿主的通道。约束如下。

- D028/D034/D046：不开放通用模块 IPC；不得新增携带 `module_id` 的普通 Tauri command；桥接命令只服务页面生命周期。
- D026/D029：身份不由 renderer、模块或模型自报；授权每次调用前检查。
- D042：模块与宿主共享同一个 JS realm，能读写宿主页面持有的一切，也能直接 `invoke` 窗口 ACL 允许的任何命令。**同 realm 不是安全沙箱**，D041 的固定准入清单是唯一的执行准入边界。
- D044：回执和附着已绑定 `attachment_id`、页面代次、`ticket`，宿主不接受页面声明的 runtime 或 module。

因此，通道不能靠“模块拿不到的秘密”来证明身份：任何放在页面里的值，同 realm 的脚本都能读到。通道能做的是让**宿主一侧**的绑定可验证、可撤销、可审计，并把调用限制在具体的、类型化的能力方法上。

## 决策

推荐方案 A，范围限于 V1 内置、经 D041 准入的首方模块：

1. 宿主在 runtime 变为 `ready` 且仍在当前附着内加载时，为该 runtime 签发一个**路由键**（`ModuleCallRoute`，随机、不持久化、不跨附着/代次/runtime）。路由键只用于定位 runtime，不含也不代表 module、用户、权限或能力。
2. 每个能力对应一条**类型化**的桥接命令（例如未来的 `module_call_provider`），入参只有宿主下发的 `attachment_id`、路由键和该能力的业务字段。命令不接受 `module_id`、`runtime_id`、用户、版本、摘要、URL、权限或能力令牌，也不存在“能力名 + 任意 JSON”的通用入口。
3. 每次调用，宿主先做通道准入（`ModuleCallRouter::admit`）：路由键存在、`attachment_id` 与签发时一致且仍是窗口的当前附着、页面代次未变、runtime 仍为 `ready`；通过后才 `begin_request`，由此得到宿主生成的 `request_id`。随后由 `ModuleCapabilityDispatchService` 逐次授权（D048），最后执行能力。路由键本身不授予任何东西。
4. 本 ADR 已按 D051 采用：接口契约、`contracts:check` 规则与错误码映射随实现同步更新；本 ADR 的“遵守方式”在命令落地前即已生效。

本 ADR 采用后实现的内容见 D051 与 FR-004 实现状态；取消命令、其他能力（`mcp.call`、`skills.execute`）与方案 C 仍未实现。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 类型化的逐能力桥接命令 + 宿主签发的 runtime 路由键 | 命令表面明确、可被 `contracts:check` 静态约束；绑定全在宿主侧（附着、代次、runtime 状态）；撤权、重载、停止立即使路由失效；复用 D044/D046 的附着与门禁模式 | 路由键放在页面里，同 realm 的另一个模块可以读到并冒用，造成混淆代理（confused deputy）；每增一种能力就多一条命令 | 采用，仅限首方、已准入模块；纳入第三方代码前必须改用 C |
| B. 一条通用 `module_call(capability, payload)` 命令 | 实现最少、扩展最快 | 实质上是通用模块 IPC，违反 D028/D046；契约检查无法约束 payload；能力名成为字符串协议；审计与脱敏难以按能力收紧 | 不采用 |
| C. 每个模块独立 WebView 或独立进程，宿主以 WebView label / 进程身份识别调用者 | 身份由宿主从调用来源派生，不依赖页面里的任何值；可以隔离同 realm 冒用；是纳入不受信代码的前提 | 需要多窗口/多 WebView 的生命周期、per-label ACL、渲染集成与资源开销；D042 已明确本阶段不引入 | 暂不采用，列为第三方代码的前置条件 |

## 后果

- 正面：宿主能把每次调用归因到具体 runtime、`(module_id, version, integrity)`、附着、页面代次和 `request_id`；撤权、停止、页面重载、热更新切换都在下一次调用前生效；没有通用 IPC。
- 负面：同 realm 的恶意或有缺陷的代码可以冒用另一个模块的路由键，或绕过通道直接 `invoke` 窗口 ACL 允许的命令。通道提供**归因与按模块授权**，不提供隔离。
- 风险与缓解：
  - 混淆代理 → V1 只运行 D041 清单内的首方代码；任何第三方或用户导入模块之前必须采用方案 C 并新增决策。
  - 路由键泄漏到日志 → `ModuleCallRoute` 的 `Debug` 输出已脱敏；日志、审计、错误文本不得写入路由键。
  - 无并发上限 → 实现前必须为每个 runtime、每种能力定义在途上限，超限返回可重试错误；具体数值在实现时登记，不在本 ADR 中猜测。
  - 页面重载后在途调用的结果无人接收 → 见 D050，按“已结算但未送达”记录，不重放。

## 遵守方式

- 新增模块桥接命令前，`scripts/check-host-contracts.mjs` 必须先有对应规则：入参白名单只含 `attachment_id`、路由键与该能力的业务字段，并禁止 `module_id`、`runtime_id`、`user_id`、版本、摘要、路径、URL、权限、令牌类参数；在规则落地前新增此类命令视为违反本 ADR。
- 评审检查项：命令是否类型化；是否引入通用转发；是否在通道准入之后、能力执行之前逐次授权；拒绝是否统一映射为 `1004004` 而不泄露原因；是否有取消、超时与未知结果的测试。
- 本 ADR 被接受后，若改为方案 C 或放宽任何一条，新建 ADR 并把本条改为 `Superseded by ADR-{NNNN}`。
