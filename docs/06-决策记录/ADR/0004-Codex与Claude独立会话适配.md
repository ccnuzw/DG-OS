# ADR-0004 Codex与Claude独立会话适配

- **状态**: Accepted
- **日期**: 2026-11-03
- **决策者**: 用户确认分别定制适配并授权实施；具体接口由助手选定
- **关联**: D127、[CLI 适配设计](../../02-产品与版本/后续版本/V7-AI-Agent-CLI适配设计.md)

## 背景

原宿主只支持只读单次任务，关闭 stdin、关闭持久化和配置发现，不能提供持续会话与审批。用户明确仅先接入 Codex 与 Claude，Gemini 延后。本次为获授权的独立技术任务，不代表 V7 整体门禁通过。

## 决策

Codex 用 Rust 驱动本机 App Server；Claude 用 Rust 监管官方 TypeScript Agent SDK 辅助进程，SDK 指向本机 claude。辅助进程随桌面打包，CLI 不打包。两者分别维护原生协议、权限、恢复、中断和事件投影。共用宿主用户归属、可信工作区确认、可执行路径发现、进程监管和基础显示组件。

会话绑定引擎。网页卸载不停止会话；账户撤销和应用退出清理进程。中断当前轮次与关闭会话分开。所有恢复入口先查宿主用户归属，不允许 renderer 随意恢复其他人的 native ID。DGOS 持久化仅保存宿主归属和 native ID/目录/引擎的索引，历史由原引擎保存和读取。原生历史不自动导入所有本机会话。原生运行配置可以读取可信工作区配置，但不接受 renderer argv、任意环境或原始 RPC 转发。

先展示并确认工作区信任，再启动引擎，因为配置、Hooks、MCP 可能在首条提示前运行。审批仅负责原引擎要求人类回答的请求，不宣称所有操作都经过 DGOS。Codex 默认 workspace-write/on-request；Claude 使用自身权限模式与 canUseTool。配置权限不是 OS 用户隔离；同一 OS 账户的 CLI 登录态与文件权限并不随 DGOS 账户变成独立身份。凭据不进入前端与会话索引。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 两家统一为单次运行协议 | 少量代码 | 丢失原生会话/审批能力 | 不采用 |
| 两家都手写底层协议 | 无 JS 辅助进程 | Claude 控制协议维护负担大 | 不采用 |
| Codex App Server + Claude 官方 SDK，分别适配 | 保留能力差异，使用官方接口 | Claude 增加辅助进程与 SDK 版本兼容成本 | 采用 |

## 后果

- 单次 runner、旧 IPC 和旧页面状态机在迁移后删除，不维持双轨。
- 原生事件先做展示字段投影，不转发配置、认证、stderr；命令与文件内容可在用户自己的会话界面显示，不写普通日志。
- 消息提交不确定时不自动重发。审批响应关联原 pending ID，过期响应拒绝。
- 支持能力以实际版本接口与验证为准，不承诺官方客户端全部功能。Claude 第三方产品认证与发布条款需独立核对，不通过直接 CLI 绕开判断。

## 遵守方式

分别验证多轮、恢复、审批允许/拒绝、工具/文件事件、中断、进程异常、用户隔离；真实模型 smoke 在临时工作区进行。静态契约、协议 fixture、真实 CLI 握手和真实模型调用分别记证据。
