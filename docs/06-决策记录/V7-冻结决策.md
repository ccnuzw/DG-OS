## D132 绘画Agent的批次授权、资料范围与作品归属

- 状态：已冻结（用户确认三项推荐方案）
- 日期：2026-11-04
- 背景：D127 独立 CLI 会话之后，需要明确绘画业务集成的执行权限、资料范围和结果归属；现有会话索引不能替代业务资产管理。
- 备选方案：仅提供提示词建议；按明确批次授权实际生成；开放式自动迭代。采用按批次授权实际生成，先交付用户驱动迭代，自动评价和追加生成后续另定轮数及消耗上限。
- 决定（执行）：Agent 可分析需求、整理参考资料、编写提示词、调整方案并调用实际绘画能力。默认先展示可编辑方案，再按用户授权执行；用户明确要求按指定参数生成指定数量即构成本批授权，不重复确认。展示模型、提示词、参考图、尺寸、数量及有可靠依据的费用估计；无法准确估价时显示数量与限制。追加数量、更换收费模型或增加迭代轮数超出原范围时重新授权。结果未知不自动重发；停止只阻止后续调度，不能保证撤回已提交请求或费用。
- 决定（资料与工具）：默认仅提供当前任务需求、参数、选定作品版本及用户加入的参考资料；其他项目资料需显式选择，跨项目文件、任意目录和联网搜索按需授权。外发图片时明确对应服务和资料。DGOS 宿主校验资料范围、外发与业务执行授权，凭据留在宿主；初始工具覆盖模型参数查询、生成提交、进度查询、停止后续执行、结果读取和保存到当前项目。CLI 工作区信任与原生 Shell/MCP 批准不替代 DGOS 业务授权；DGOS Skills/MCP 不自动同步到 CLI 配置。
- 决定（归属）：作品归属绘画项目；生成任务保存已确认方案、参数快照、执行状态、错误及可取得的消耗信息；作品版本关联来源任务与父版本。结果自动保存，修改后再生成创建新任务和新版本，不覆盖原作品；部分成功保留成功图片并标明失败项。临时创作进入“未归档创作”，支持后续命名归档。会话仅关联业务对象，关闭或更换 Agent 不影响作品管理；用户可直接编辑参数和生成。参数可追溯不等于图片可精确复现。删除、覆盖外部文件或发布另行确认。
- 理由：形成真实出图闭环并使消耗可控；资料和执行权限可验证；作品不依赖单一会话或引擎。
- 影响：[V7 规划](../02-产品与版本/后续版本/V7-AI-Agent.md) 的绘画业务集成阶段及后续正式功能设计。尚未分配绘画 Agent 功能编号、IPC、错误码或 migration，不把产品决策写成已实现 API。
- 边界：本次冻结产品边界并批准继续独立会话交互验收、Claude 扩展兼容与 CLI 对照；不代表绘画集成实现或 V7 整体门禁已通过。正式实现前补齐授权批次、外发确认、资产写入与失败恢复的技术设计。

## D136 双运行时分工与统一能力管理

- 状态：已冻结
- 日期：2026-11-07
- 背景：D135 将 DG-OS Provider、Skills 和宿主 MCP 同时注入 CLI。用户现已明确 DG-OS AI 是可独立运行、供模块复用的平台能力；CLI Agent 使用 CLI 原生能力体系，仅共享 DG-OS Provider。统一 Skills/MCP 管理界面不改变运行时归属。
- 来源：用户逐项同意可复用 AI 服务、共享 Provider、依赖检测、配置范围、生效与生命周期推荐方案；要求未完成的 AI 服务复用能力纳入本次实施。具体工程拆分由助手选定，沿用现有安全边界。
- 备选方案：A. 延续 D135 混合能力注入，复用已有网关但增加两套审批与能力来源的耦合；B. 双运行时各自加载 Skills/MCP，统一管理入口与 Provider 来源。采用 B。
- 决定（平台服务）：复用现有 Provider、Skills、MCP、ChatManager、WorkbenchManager 与应用服务，补齐不依赖聊天页面或 CLI 的公开宿主 AI 服务。模块调用者、上下文及权限由宿主派生，每次执行校验；不得继承聊天会话授权。业务资产由所属模块保存。服务抽取与至少一个真实模块调用闭环属于本次范围。
- 决定（Provider）：新 CLI 会话显式引用 DG-OS Provider、模型和配置修订，按 CLI 版本及协议验证兼容性。不可用时拒绝，不静默回退 CLI 原生订阅账号；原生账号来源留待后续独立设计。凭据仍由宿主管理，按适配方式提供给可信 CLI，不进入前端、仓库或普通日志；不预先建设通用协议代理。旧会话按迁移计划处置。
- 决定（Skills/MCP）：在现有管理页统一选择 DG-OS AI、Codex 或 Claude 及其支持范围。DG-OS 继续自己的内容校验、固定版本、连接、工具审批和审计；CLI 技能发现/加载、MCP 连接/调用、认证和审批遵循原生规则。DG-OS 可显式管理 CLI 原生配置，不自动注入 DG-OS 技能或 MCP 网关，不把原生事件标成宿主已执行或已审计。同源资源跨运行时安装/配置需显式选择、兼容检查和目标预览，不继承凭据或授权。
- 决定（依赖与范围）：提供 CLI、解释器、MCP 程序和技能工具依赖检测与配置指引，不隐式安装、执行脚本或启动服务。DG-OS 资源沿账户隔离；CLI 用户级配置标明当前操作系统用户共享，项目级配置显示实际目录及可能影响范围，不声称 DG-OS 账户切换隔离了原生环境。原生配置写入必须保留未知字段、检测外部修改，冲突拒绝覆盖；插件或包管理器所有的资源遵循其管理方式。
- 决定（生效与撤销）：区分已安装/已配置、检测通过、当前会话实际加载/连接、待生效和不可读取。检测成功不能冒充 CLI 已连接；不声称冻结无法控制的原生配置。DG-OS 可控配置固定引用与内容，权限和可用性仍实时重验。CLI 按版本验证刷新/重建要求；正常保存不擅自重启会话。Provider 禁用或撤销后阻止后续宿主准入，已发给 CLI 的凭据无法靠数据库撤销收回，须停止受影响进程并如实记录未确认清理及外部结果。
- 决定（生命周期）：沿用 D130/D131：切换、隐藏和收起不停止；显式关闭运行中的 CLI 会话确认后等待进程退出，失败/超时/未知保留归属和核实入口；账户结束先失效租约再有界清理。应用退出停止自己拥有的运行与子进程，不停止外部 CLI 或共享服务；重启不自动发送模型请求、重放批准或工具操作，不凭旧 PID 杀进程。恢复原会话需重新校验授权、目录和配置；不可恢复时明确新建并交接，不伪造原历史。AI 会话标签关闭继续遵循自身既有策略，不把 CLI 进程关闭规则机械套用到聊天视图。
- 理由：平台 AI 可独立复用，CLI 可保留原生能力；统一入口降低操作分散，同时保留真实的配置、身份、权限与进程边界。
- 影响：替代 D135 的目标能力接入模式；D127 原生适配、D130/D131 生命周期、D132 业务授权及 V1 Skills/MCP 安全原则继续有效。涉及 V1-FR-001/002/003/004/006、工作台及项目能力契约；分阶段交付、迁移和验证入口见[整体实施计划](../02-产品与版本/后续版本/V7-编程项目工作台方案草案.md#12-双运行时与统一能力管理实施计划)。不修改已执行 migration，不在此分配新 IPC/错误码或宣称 V7 整体门禁通过。
- 落实：本次记录产品契约和实施计划；各阶段实施前补齐受影响功能文档、接口和高风险技术设计，完成后集中回写唯一实现状态。既有混合注入代码、测试和历史记录不因本决策自动视为已迁移。

## D140 AI会话持续完善与受控能力增量

- 状态：已冻结（用户明确授权完成持续完善方案全部批次；具体保守实现取舍由助手选定）
- 日期：2026-11-09

- 决定（范围）：实施独立技术任务CHAT-CONTINUOUS，覆盖CHAT-P1～P6；不提升V7整体门禁，不复制CLI原生运行时。原ChatManager持有聊天事务，公共执行器保持唯一模型/工具循环，Provider、Skills与MCP仍各自管理资源。

- 决定（技能）：保留默认空技能与显式手选；用户可选择固定已安装/启用的授权集合并开启按需消费。模型仅能在该集合内发现、读取正文和受支持包内资源，每次读取重验pin/归属/边界。候选推荐不等于授权；不自动安装、更新、运行脚本或获得MCP许可。
- 决定（工具）：两种协议增加真实工具流式与过程事件；完整参数和schema验证通过后才允许逐次审批。工具选择偏好可保留，但每轮重新校验且不得保存批准。大结果有界读取并明确省略，未知外部结果与审计失败阻断自动推进。
- 决定（恢复）：允许有界批量保存部分正文、内容无关步骤身份及账户chat域内明确截断的工具结果回执；不写通用审计。重启只读核实，不自动执行。用户明确继续时创建新请求、重新验证配置和租约，不复活旧审批，不重放已完成副作用。无可核实回执的工具动作保留unknown并阻断；无通用只读查询能力时，可显式记录用户在应用外核实的报告，保留原unknown并标注“用户报告”，不得伪装权威成功。Provider计费/输出未知不等于工具副作用未知：原消息仍未知，只允许用户以新意图继续已保存进展，不自动重发或重新生成原请求；审计异常仍阻断。
- 决定（不变量）：每账户一个活动生成槽，摘要和继续同样占槽；身份由宿主派生，账户结束先失效；敏感内容不进入一般审计或日志。真实收费模型验收需要明确端点和额度授权，替身证据不得升格。
- 取代范围：D074的仅终态保存部分正文、D075的仅整轮淘汰、D018的聊天仅显式正文技能、D022的工具轮非流式/不保留选择偏好，在本独立技术任务中分别按上述增量修订；旧条目保留为历史，其他权限、幂等、取消、无自动重放与数据边界继续有效。单任务与LAN不因聊天新入口自动获得权限。
- 影响：V1-FR-001/002/003/006、聊天IPC与账户隔离的chat持久数据；仅追加migration。规范与追踪见[AI工作台增量](../03-功能规格/V1/02-应用模块/06-AI工作台.md)、[技术设计](../04-技术架构/当前版本/AI会话持续完善技术设计.md)和[推进方案](../02-产品与版本/AI会话持续完善方案草案.md)。实现状态及实际验证只在V1实现状态维护。

- 决定（证据）：宿主来源ID关联实际URL、标题、取得时间、类型、节选与截断；区分搜索摘要、正文读取与实际供给。只有匹配该运行真实来源的引用可打开来源预览，普通模型链接不升级为证据。最小节选随账户聊天运行保存、会话删除清理，不默认永久缓存整页，不把来源真实等同模型结论正确。
- 决定（运行基础）：沿现有ChatManager/公共执行核心增加事件序号、终态封口、只读快照补齐、模型轮次分段和累计输出边界；模块消费者同步受影响的核心事件，不自动取得联网权限。重启只恢复观察；工具unknown和审计失败继续阻断重放，取消不冒充远端回滚。
- 理由：将执行可见性、可追溯依据和异常处理交还产品主流程，同时保持独立智能体的真实能力和可验证权限边界。
- 取代范围：仅细化FR-006“任务详情”主入口及D140受控本地能力种类；新增专用联网请求授权，不修改任意MCP逐次批准、账户隔离、单活动槽和副作用防重放。D136/D141双运行时保持；不新增任意Shell、多智能体、跨会话记忆或后台调度。
- 影响：V1-FR-001/003/006、V2-FR-009、聊天IPC与共享执行事件、联网凭据生命周期；接口与技术边界集中回写，实际验证只在V1实现状态维护，不提升整体版本门禁。

## D148 AI 助手上下文用量与显式压缩

- 状态：已冻结（2026-11-11 用户批准分阶段方案并要求全部实施；具体保守工程取舍由助手选定）
- 日期：2026-11-11
- 背景：现有上下文面板说明过多，只统计已加载回复；Provider 日志随配置删除，运行 ID 又不能区分工具循环里的多次模型调用，不能直接改名为会话总计。
- 备选方案：A. 只换紧凑皮肤并沿用分页累计；B. 紧凑展示、真实逐调用事实和会话聚合；C. 复用 CLI 原生计量与压缩。采用 B，实施[CTX-P0～P5](../02-产品与版本/AI助手上下文与用量设计草案.md#6-分阶段实施方案)，不混用运行时。
- 决定（展示）：环形入口、上下文卡片、会话六项统计与二级详情；预算为预估输入加输出预留，图片不重复计量，未知模型窗口不算百分比，宿主独立字节限制不取消。
- 决定（计量）：输入包含缓存，输出包含协议定义的推理子集；缓存读取不再加入总计，命中率仅使用同组完整回报的输入集合。逐字段记录回报存在性，明确回报零有效，缺失为未知；这细化 D074/D081 的零值处理，不把历史全零行反推为已回报。
- 决定（持久化）：每个实际派发的模型调用拥有宿主唯一尝试 ID，运行 ID 仅关联；重复终态不重复累计，真实再次调用独立计量。聊天拥有数值用量事实，Provider 配置删除不减少保留会话累计；会话/账户删除清理其统计，原有审计边界不扩大。Provider 审计与聊天事实来自同一次规范化，不将两者相加；无回报、取消、崩溃和审计失败保持未知覆盖，不自动重发。

- 决定（耗时）：累计实际模型调用执行时长，排除用户思考、工具和审批等待；无可靠结束计时保留未知，不用会话年龄代替。
- 决定（压缩）：沿用现有摘要执行器，用户明确确认额外模型调用与可能费用；宿主判定资格并在提交复验。原消息保留，成功以摘要安装为准；预算和统计独立刷新，失败或结果未知不自动重试，非历史输入变化时不展示前后比较。
