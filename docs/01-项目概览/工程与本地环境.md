# 工程与本地环境

本文档说明 DGOS 项目的环境要求、本地开发环境搭建、项目结构和常用开发命令。内容以仓库当前的 `Cargo.toml`、`package.json` 和 `src-tauri/tauri.conf.json` 为准；规划中的模块不在此列出。

---

## 1. 环境要求

### 1.1 必需环境

| 工具 | 版本要求 | 说明 |
|------|---------|------|
| **Rust** | 1.90+ | Tauri 2.12 依赖声明的最低版本 |
| **Node.js** | 22.22.2+、24.15.0+ 或 26+ | jsdom 30 的 `engines`（`package-lock.json`）：`^22.22.2 \|\| ^24.15.0 \|\| >=26.0.0`；Vitest 5 的要求更低 |
| **npm** | 随 Node.js | 项目使用 `package-lock.json` |
| **Bun** | 支持 `bun build --compile` 的版本 | `agents:build` 将 Claude SDK bridge 编译为本机可执行资源；桌面开发/发布前置步骤均调用 |
| **Xcode Command Line Tools** | - | macOS 编译 Tauri 所需 |
| **操作系统** | macOS | V1 首发平台；Windows 在 V1 发布门禁后补齐，Linux 计划 V2 |

### 1.2 可选环境

| 工具 | 用途 |
|------|------|
| Node.js MCP 官方包（临时目录安装） | 运行 MCP 官方兼容测试（默认 ignored，见 4.3） |
| VS Code + rust-analyzer | 推荐 IDE |

## 2. 本地开发环境搭建

### 2.1 安装工具链

```bash
# Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustc --version

# Node.js（示例：Homebrew）
brew install node
node --version

# macOS 编译工具
xcode-select --install
```

### 2.2 克隆与安装依赖

```bash
git clone https://github.com/ccnuzw/DG-OS.git
cd DG-OS
npm install
```

Rust 依赖在首次 `cargo build` 或 `npm run tauri:dev` 时下载。

### 2.3 启动开发环境

```bash
npm run tauri:dev
```

该命令先执行 `npm run agents:build`（通过 npm ci 安装 bridge 锁定依赖，再由 Bun 编译），再启动 Vite（`http://localhost:1420`，端口固定，被占用时启动失败），最后编译并打开 Tauri 桌面窗口。LAN 远程页面是独立入口 `lan-web/index.html`，由宿主 LAN HTTP 服务提供；`npm run build` 同时生成主应用 `dist/` 与远程 `dist-lan/`。

### 2.4 数据库

- 不需要手动初始化。应用启动时连接系统应用数据目录下的 `dgos.db`（macOS 为 `~/Library/Application Support/com.dgos.app/`），并自动执行全部 SeaORM migration。
- migration 定义在 `crates/dgos-db/src/migrations/`；没有独立的 migrate 命令行。
- 已执行的 migration 不修改，只追加兼容迁移（见 [AGENTS.md](../../AGENTS.md)）。
- 测试使用内存 SQLite 或临时目录，不读写正式数据库。

## 3. 项目结构

```

├── src/                       # React 前端
│   ├── pages/                 # Providers / Skills / Workbench / MCP / 设置 / 模块管理页面
│   ├── components/            # Provider 表单与列表、聊天组件、MCP 连接提示
│   ├── ui/                    # 统一设计系统（Shadcn/ui + Radix + Tailwind，别名 @dgos/ui，D066）
│   ├── modules/               # 页面侧模块运行时（Blob URL 动态 import，D042）
│   ├── accounts/              # 本地账户登录与切换（FR-008）
│   ├── stores/                # Zustand store（provider / skills / mcp / chat）
│   ├── App.tsx                # 路由
│   └── main.tsx
├── src-tauri/                 # Tauri 宿主（Rust 包名 dgos）
│   ├── src/commands/          # Tauri commands：provider / skills / workbench / chat / mcp / modules / accounts / appearance
│   ├── src/host.rs            # 宿主派生的调用上下文，用户由 session.rs 的会话解析器给出（D087）
│   ├── src/capabilities.rs    # 模块能力授权服务（内部，非 command）
│   ├── src/provider_credentials.rs  # 系统钥匙串凭据
│   └── tauri.conf.json
├── crates/                    # Rust 领域 crate
│   ├── dgos-types/            # 共享类型与错误码
│   ├── dgos-db/               # SeaORM 实体、migration、仓储
│   ├── dgos-providers/        # Provider 适配与调用
│   ├── dgos-skills/           # 技能中心与官方内容包
│   ├── dgos-workbench/        # 工作台任务编排
│   ├── dgos-mcp/              # MCP 客户端与管理
│   ├── dgos-modules/          # 模块包发布与恢复、页面加载协议
│   └── dgos-application/      # 跨 command 的用例服务（账户、模块管理与能力调用）
├── skills/                    # 官方技能内容包源文件（打包为应用资源）
├── bundled-modules/           # 随包模块（当前只有 provider-console）
├── scripts/                   # 技能目录校验、IPC 契约检查、样式检查、发布构建、文档工具
├── tests/                     # 前端 Vitest 测试
├── docs/                      # 项目文档
├── Cargo.toml                 # Rust workspace
└── package.json               # npm 脚本与前端依赖
```

### 3.1 Rust crate 说明

| crate | 说明 | 主要入口 |

### 4.1.1 开发组件与页面预览

运行 `npm run dev:ui`，打开 `http://127.0.0.1:5197/`。独立入口在 `tools/ui-preview/`，复用生产控件、PagePatterns、设置外壳/CLI和聊天组件；产品 `src/main.tsx` 与构建配置不引用它。`npm run check:ui-preview`检查预览及其生产依赖的类型。

工具栏可选择基础控件、长表单Modal、资源成功/首次失败/刷新失败保留旧数据/空/未确认、设置、聊天长正文代码/运行中快照/审批/错误；切换中英文、明暗、75–175%密度、UI/阅读/代码独立字号和380/520/800/1280px容器。设置故障选择仅影响设置fixture：首次读取、检测、保存未知结果或冲突。可编辑草稿、检测、保存、重读与关闭保护仍由生产组件处理。任一参数切换或“重置当前场景”重新创建iframe，清除草稿、浮层和保存结果。

预览Vite将Tauri导入替换为白名单内存fixture；没有真实账户、数据库、CLI执行或Provider/MCP连接，未知命令拒绝。CSP限制外部网络，外链打开拒绝。聊天流式场景使用固定delta快照与真实store通道，审批和停止走fixture回执，不代表外部服务或持续流式验收。MCP样板、xterm离屏辅助树仍阻塞；VoiceOver和物理输入仍待验。

完整App外壳可导航到未提供fixture的页面；这些页面的非白名单命令会明确失败，不代表该页面已获预览支持。侧栏收起等已支持偏好在当前iframe内保存并读回，重建后恢复初始值；“设置故障”不改变聊天流式或审批场景。iframe重置不清理同源持久存储；生产组件可能保存布局偏好，需验证首次访问时使用独立浏览器配置或手动清除此入口的站点数据。

添加场景时，在`tools/ui-preview/shell.tsx`的`scenes`与`names`注册稳定ID和名称；在`ComponentScenes.tsx`组合现有生产控件，或在`frame.tsx`挂载现有生产页面。不要复制生产布局/CSS或重写业务状态机。数据和必要命令只添加到`host.ts`白名单，使用固定时间、合成名称和路径；禁止真实凭据、私人会话、网络或进程副作用。沿用现有`initAppearance`/`applyTheme`出口，不直接写主题变量。iframe重建是场景隔离边界，不向产品入口加入mock开关。

新增永久视觉用例只针对可见风险：在`visual/cases.mjs`加入最小组合，在`visual/probes.mjs`检查实际行为或几何；先运行`npm run check:ui-preview`及相关既有测试，再按下述流程记录、审图和接受基线。失败先区分环境漂移、已批准的视觉变化和产品回归；产品回归先修生产实现，不能以重录基线消除失败。预览页的只读证据链接提供当前实现状态与xterm最小复现源码；源码以`text/plain`返回，不执行诊断。要运行既有xterm复现，另启仓库`npm run dev`后手动打开`/tests/fixtures/terminal-accessibility.html`并点击运行，默认预览不加载或运行它。

视觉回归使用本机Chrome、Node 22+和锁定的pngjs/pixelmatch，不下载浏览器。先启动预览，再运行：

```sh
npm run test:ui-visual                  # 默认只比较已接受基线
npm run test:ui-visual -- --record      # 生成candidate，逐张检查全部5张图片
npm run test:ui-visual -- --accept      # 显式接受已审阅candidate
npm run test:ui-visual -- --prove-detection # 临时注入过宽Modal，验证几何和像素均检出
```

五个场景覆盖长Select/三域字体、窄Modal键盘、175%设置分类焦点、窄聊天输入与审批。基线及环境manifest位于`tools/ui-preview/visual/baseline/`；candidate/results忽略，不自动覆盖基线。manifest固定Chrome版本/二进制哈希、OS、Node、字体栅格、DPR1、UTC、窗口、数据时钟和比较参数。环境漂移退出2；视觉/几何失败退出1；缺少前提退出3。Chrome或系统更新后先记录和审图，再显式接受新环境候选；不能把漂移当产品回归。此入口仅提供Chromium合成输入和截图证据，不替代原生WKWebView、VoiceOver或人工键鼠验收。

已接受环境以`visual/baseline/manifest.json`为准，当前记录为macOS arm64、Chrome 157.0.8103.38、Node v22.23.0；路径探测支持其他已安装Chromium二进制不等于已验证其他系统或最低浏览器。默认比较不改基线；本轮集成修复只改内存fixture，不需要重录或接受候选。检查环境漂移时应保留退出2及环境信息，不把它改成可忽略警告。


ESLint 与 Stylelint 只用于 `design:check` 的样式合规门禁（D068），不是通用 lint 配置；项目没有 Prettier 配置，也没有独立的 E2E 测试框架。真实 WebView 冒烟见 4.4。

### 4.4 Tauri

```bash
npm run tauri:dev           # 开发模式
npm run tauri:build         # 构建桌面安装包（经 scripts/release-build.mjs：模块包校验、IPC 契约检查、tauri build、发布包核对，D061）
npm run release:verify -- <.app 或 bundled-modules 目录>   # 检查安装资源与模块准入；目录模式仅检查模块
npm run tauri -- info       # 查看 Tauri 环境信息
```

`release:build`（`tauri:build` 的同一入口）只在本地执行：先校验随包模块与 IPC 契约，Tauri 的 `beforeBuildCommand` 再构建 bridge、主应用与 LAN 页面，最后检查本次生成的 macOS `.app` 及存在的 `.dmg` 内的模块 pin、主可执行文件和 bridge 权限，以及 skills、bridge、LAN 资源与本次源码构建输入的一致性。单独核对安装包：

```bash
npm run release:build -- --bundles app
npm run release:verify -- "target/release/bundle/macos/DG-OS.app"
```

显式传 `--target <triple>` 时产物位于 `target/<triple>/release/bundle/`。脚本只扫描仓库 `target/` 与 `src-tauri/target/`，自定义 `CARGO_TARGET_DIR` 时需对实际 `.app` 运行 `release:verify`；直接传 `bundled-modules` 目录仍只执行 D049 模块准入校验。安装包模式额外校验主可执行文件、Claude bridge 存在且可执行、skills/bridge/LAN 页面资源与本次构建输入一致。该检查不启动程序，不证明主可执行文件的二进制来源，不验证 CLI 兼容/ Finder 环境、生命周期、代码签名、公证、签名清单、安装器字节一致性或 Windows/Linux 包。构建成功不等于安装验收通过。

桌面 UI 只有 `index.html → src/main.tsx → AccountGate → App` 一个正式入口；旧 `/providers`、`/account`、`/settings/skills`、`/settings/mcp` 只导航到现行页面，旧模块路径只导航到 `/apps/:moduleId`。远程 LAN SPA 与受准入控制的动态模块是独立消费者，不是旧版桌面入口。

本地验收必须避开日常账户数据。下述 WebView smoke 使用各自临时目录/测试库，优先通过它们执行真实 IPC 旅程。手动启动发布包时使用另一个 macOS 测试账户的图形登录会话或一次性 VM，在其终端执行 `"<验收应用路径>/DG-OS.app/Contents/MacOS/dgos"`；该账户中创建全新测试数据、使用显式测试凭据。生产宿主固定使用系统 `app_data_dir`，没有 `DGOS_DATA_DIR` 或 `--data-dir` 开关；仅换工作目录、直接运行 `target/release/dgos`、改 `HOME` 或换 bundle identifier，均不能作为数据库与系统钥匙串完整隔离的证明。发布模式还需要应用内的 `skills/`、`bundled-modules/`、`agent-bridge/` 与 `dist-lan/` 资源，因此不要把裸二进制启动当发布包验收。

真实 WebView 冒烟（macOS，需要图形会话，会弹出窗口）先执行 `npm run build`，再以 `webview-smoke` feature 运行 `src-tauri/tests/webview_smoke*.rs`：

```bash
npm run smoke:tauri         # Provider、模块、外观、能力、账户等冒烟
npm run smoke:tauri:chat    # 聊天工作台冒烟（V1-E2E-06 fixture 级）
npm run smoke:tauri:ui      # 设计系统冒烟（V1-E2E-05）
npm run smoke:tauri:lan     # 局域网协同冒烟（V1-E2E-10，三次真实进程启动，会占用本机私网 IPv4 上的端口）
```

命令存在不代表已通过，结果见 [V1 实现状态](../02-产品与版本/当前版本/V1-实现状态.md)。

## 6. 常见问题

### 6.1 Apple Silicon 上 Rust 链接失败

**现象**：`cargo test` / `cargo check` 在链接阶段报 `xcrun` SDK 架构不匹配（x86_64 与 arm64 混用），常见于在 Rosetta 终端中运行。

**解决**：为命令显式指定 arm64 工具链（只影响当前命令，不修改全局配置）：

```bash
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk \
CARGO_TARGET_AARCH64_APPLE_DARWIN_LINKER=/Library/Developer/CommandLineTools/usr/bin/clang \
CC=/Library/Developer/CommandLineTools/usr/bin/clang \
AR=/Library/Developer/CommandLineTools/usr/bin/ar \
cargo test --offline --workspace
```

这类失败属于工具链问题，与代码测试失败分开记录。

### 6.2 前端依赖安装失败或测试启动报引擎错误

先确认 `node --version` 满足 1.1 节要求，再重新安装：

```bash
rm -rf node_modules
npm ci
```

### 6.3 `npm run tauri:dev` 启动失败

- 端口 1420 被占用：结束占用进程（Tauri 要求固定端口）
- 缺少编译工具：`xcode-select --install`

### 6.4 本地开发数据库损坏

先停止应用及所有使用该数据目录的宿主/测试进程，保留故障现场，再判断是外观单行损坏还是数据库打开/迁移失败。不要把删除数据库当恢复；删除后重建会丢失本地配置、历史与账户元数据，系统钥匙串中的凭据仍可能存在。

- **外观偏好**：按[D126](../06-决策记录/V2-冻结决策.md#d126-v2主题快照事务默认映射与受控变量出口)，schema 2的合法字段可读取，坏字段仅在渲染时回退；无法解析或revision损坏的原行保留，常规保存拒绝。显式恢复须先读取宿主签发的一次性token，再恢复为出厂快照revision 0；恢复写入失败后重新读取，不能重放旧token。未来schema拒绝保存和恢复，只能使用支持该schema的应用。旧两键偏好不升级、不双写、不提供无损降级。
- **升级前备份**：在应用完全关闭、全部SQLite连接关闭后，保存整个应用数据目录的同一时点副本（包含数据库、仍存在的WAL/journal伴随文件、Skills、模块版本/指针、安装操作文件和Agent索引），另记录对应应用版本。不能对正在写入的`dgos.db`单文件直接复制并假定一致；无法停机时需要另行验证SQLite在线备份与文件资源的一致性，本工程没有提供该工具。备份含账户私有数据，须按原有访问权限保存。
- **数据库/迁移失败恢复**：先完整保存失败现场，保留最后一份升级前备份；在独立恢复目录或隔离系统账户中成套恢复数据库与同一时点资源，用支持该备份schema的应用启动并执行前向迁移。核对账户、偏好、消息/资产引用、模块版本/指针及安装状态，再决定是否替换工作副本。迁移失败可能已执行部分DDL，不能仅删除迁移记录、调用`down()`或更换旧二进制继续使用失败库。恢复到备份时点会舍弃备份后的提交，须明确接受该恢复点。
- **凭据和外部资源边界**：OS钥匙串不在数据目录备份内；凭据轮换/删除后的旧引用可能已经无法使用，恢复库不等于恢复凭据，须重新配置并校验。原生CLI历史、项目磁盘文件和远程副作用也不由SQLite备份恢复；旧`agent-sessions.json`不包含迁移后的新项目/会话数据，不能作数据库的降级副本。备份恢复不恢复运行lease、会话进程或已发生的外部效果。

迁移只前进；回退二进制不等于数据回滚。没有升级前的一致备份时保留原件，不承诺无损恢复。现有隔离回归入口与覆盖边界见[整体迁移方案§11.4](../02-产品与版本/后续版本/V2/V2-FR-009-整体迁移方案与现状评审.md#114-阶段7数据与生命周期定向验收)，实际运行结论只登记于[V1实现状态](../02-产品与版本/当前版本/V1-实现状态.md)。
