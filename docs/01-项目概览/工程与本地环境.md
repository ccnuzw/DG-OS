# 工程与本地环境

本文档说明 DGOS 项目的环境要求、本地开发环境搭建、项目结构和常用开发命令。内容以仓库当前的 `Cargo.toml`、`package.json` 和 `src-tauri/tauri.conf.json` 为准；规划中的模块不在此列出。

---

## 1. 环境要求

### 1.1 必需环境

| 工具 | 版本要求 | 说明 |
|------|---------|------|
| **Rust** | 1.90+ | Tauri 2.12 依赖声明的最低版本 |
| **Node.js** | 22.22+ 或 24.15+ | Vitest 5 / jsdom 30 的 `engines` 要求 |
| **npm** | 随 Node.js | 项目使用 `package-lock.json` |
| **Xcode Command Line Tools** | - | macOS 编译 Tauri 所需 |
| **操作系统** | macOS | V1 首发平台；Windows 在 V1 发布门禁后补齐，Linux 计划 V2 |

### 1.2 可选环境

| 工具 | 用途 |
|------|------|
| Node.js MCP 官方包（临时目录安装） | 运行 MCP 官方兼容测试（默认 ignored，见 4.3） |
| VS Code + rust-analyzer | 推荐 IDE |

## 2. 本地开发环境搭建

### 2.1 安装工具链

```bash
# Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustc --version

# Node.js（示例：Homebrew）
brew install node
node --version

# macOS 编译工具
xcode-select --install
```

### 2.2 克隆与安装依赖

```bash
git clone https://github.com/ccnuzw/DG-OS.git
cd DG-OS
npm install
```

Rust 依赖在首次 `cargo build` 或 `npm run tauri:dev` 时下载。

### 2.3 启动开发环境

```bash
npm run tauri:dev
```

该命令先执行 `npm run dev` 启动 Vite（`http://localhost:1420`，端口固定，被占用时启动失败），再编译并打开 Tauri 桌面窗口。当前没有局域网 HTTP 服务。

### 2.4 数据库

- 不需要手动初始化。应用启动时连接系统应用数据目录下的 `dgos.db`（macOS 为 `~/Library/Application Support/com.dgos.app/`），并自动执行全部 SeaORM migration。
- migration 定义在 `crates/dgos-db/src/migrations/`；没有独立的 migrate 命令行。
- 已执行的 migration 不修改，只追加兼容迁移（见 [AGENTS.md](../../AGENTS.md)）。
- 测试使用内存 SQLite 或临时目录，不读写正式数据库。

## 3. 项目结构

```
DG-OS/
├── src/                       # React 前端
│   ├── pages/                 # Providers / Skills / Workbench / MCP 页面
│   ├── components/            # Provider 表单、列表、MCP 连接提示
│   ├── stores/                # Zustand store（provider / skills / mcp）
│   ├── App.tsx                # 路由
│   └── main.tsx
├── src-tauri/                 # Tauri 宿主（Rust 包名 dgos）
│   ├── src/commands/          # Tauri commands：provider / skills / workbench / mcp
│   ├── src/host.rs            # 宿主派生的调用上下文（固定本地用户）
│   ├── src/capabilities.rs    # 模块能力授权服务（内部，非 command）
│   ├── src/provider_credentials.rs  # 系统钥匙串凭据
│   └── tauri.conf.json
├── crates/                    # Rust 领域 crate
│   ├── dgos-types/            # 共享类型与错误码
│   ├── dgos-db/               # SeaORM 实体、migration、仓储
│   ├── dgos-providers/        # Provider 适配与调用
│   ├── dgos-skills/           # 技能中心与官方内容包
│   ├── dgos-workbench/        # 工作台任务编排
│   ├── dgos-mcp/              # MCP 客户端与管理
│   └── dgos-modules/          # 模块包发布与恢复（FR-004 前置）
├── skills/                    # 官方技能内容包源文件（打包为应用资源）
├── scripts/                   # 技能目录校验、IPC 契约检查、文档浏览器生成
├── tests/                     # 前端 Vitest 测试
├── docs/                      # 项目文档
├── Cargo.toml                 # Rust workspace
└── package.json               # npm 脚本与前端依赖
```

### 3.1 Rust crate 说明

| crate | 说明 | 主要入口 |
|------|------|---------|
| `dgos-types` | 共享 DTO、`DgosError` 错误码、执行上下文 | `src/error.rs`、`src/execution.rs` |
| `dgos-db` | 实体、migration、Provider/模型/模块权限仓储 | `src/migrations/`、`src/repositories/` |
| `dgos-providers` | OpenAI 兼容适配器、重试、凭据边界 | `src/manager.rs`、`src/adapters/openai.rs` |
| `dgos-skills` | 官方内容包校验、目录与用户状态 | `src/content_manager.rs` |
| `dgos-workbench` | 单任务文本/工具任务 | `src/lib.rs`、`src/tools.rs` |
| `dgos-mcp` | stdio / Streamable HTTP / legacy SSE 传输与管理 | `src/manager.rs`、`src/transport.rs` |
| `dgos-modules` | 本地模块包暂存、校验、发布、启动恢复 | `src/lib.rs` |
| `dgos`（`src-tauri`） | Tauri 宿主、commands、启动流程 | `src/lib.rs` |

## 4. 常用开发命令

所有命令在仓库根目录执行。

### 4.1 前端

```bash
npm run dev                 # 仅启动 Vite
npm test                    # Vitest（tests/**/*.test.tsx）
npm test -- --run tests/providers.test.tsx   # 单个测试文件
npm run build               # 技能包校验 + tsc + vite build
npm run skills:check        # 校验官方技能包与目录哈希
npm run skills:catalog      # 重新生成技能目录（修改 skills/ 后）
npm run contracts:check     # 桌面 IPC 宿主契约静态检查
```

项目尚未配置 ESLint、Prettier 或 E2E 测试框架。

### 4.2 Rust

```bash
cargo check --offline --workspace --all-targets
cargo test --offline --workspace
cargo test --offline -p dgos-providers           # 单个 crate
cargo test --offline -p dgos-mcp --test manager  # 单个集成测试文件
cargo fmt --all -- --check
cargo clippy --workspace
```

`--offline` 要求依赖已下载；首次构建去掉该参数。

### 4.3 需要显式开启的测试

以下测试默认 `#[ignore]`，只在触及对应边界时运行：

| 测试 | 开启方式 |
|------|---------|
| macOS 钥匙串：Provider 凭据 | `DGOS_TEST_PROVIDER_OS_VAULT=1 cargo test --offline -p dgos provider_credentials::tests::provider_os_vault_normal_lifecycle -- --ignored --exact` |
| macOS 钥匙串：MCP token | `cargo test --offline -p dgos --lib os_keychain_roundtrip_for_isolated_synthetic_token -- --ignored` |
| MCP 官方兼容（`crates/dgos-mcp/tests/official_compat.rs`） | 在临时目录安装官方包，设置 `DGOS_OFFICIAL_FILESYSTEM_SERVER`、`DGOS_OFFICIAL_MCP_SDK_PREFIX` 后加 `-- --ignored` |
| 真实 Provider smoke（`crates/dgos-workbench/examples/`） | 显式设置 `DGOS_SMOKE_*` 环境变量后 `cargo run --example <name>`，会产生真实调用费用 |
| 真实聊天 smoke 与预算校准（`crates/dgos-workbench/examples/real_chat_smoke.rs`） | `cargo run -p dgos-workbench --example real_chat_smoke --offline -- [--base-url URL] [--only openai\|anthropic] [--stub]`；密钥在终端隐藏输入，不接受参数，回车跳过；会产生真实调用费用。完整参数见文件头注释 |

具体命令与最近一次结果见 [V1 实现状态](../02-产品与版本/当前版本/V1-实现状态.md)。

### 4.4 Tauri

```bash
npm run tauri:dev           # 开发模式
npm run tauri:build         # 构建桌面安装包
npm run tauri -- info       # 查看 Tauri 环境信息
```

## 5. 开发工作流

1. **创建分支**：`git checkout -b feature/<功能ID>-<描述>`
2. **开发**：后端改对应 crate，前端改 `src/`；L2/L3 变更先确认功能 ID 或决策（见 [AGENTS.md](../../AGENTS.md)）
3. **验证**：先跑受影响的测试或 crate，再按风险扩大范围
4. **提交**：遵循 [Git 提交信息规范](Git提交信息规范.md)，只暂存相关文件
5. **推送并创建 PR**

完整流程见 [功能开发流程](../03-功能规格/功能开发流程.md)。

### 5.1 调试技巧

```bash
# 详细日志（宿主使用 tracing_subscriber::fmt）
RUST_LOG=debug npm run tauri:dev
```

- WebView 开发者工具：macOS 上 `Cmd+Option+I`
- 前端状态：React Developer Tools

## 6. 常见问题

### 6.1 Apple Silicon 上 Rust 链接失败

**现象**：`cargo test` / `cargo check` 在链接阶段报 `xcrun` SDK 架构不匹配（x86_64 与 arm64 混用），常见于在 Rosetta 终端中运行。

**解决**：为命令显式指定 arm64 工具链（只影响当前命令，不修改全局配置）：

```bash
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk \
CARGO_TARGET_AARCH64_APPLE_DARWIN_LINKER=/Library/Developer/CommandLineTools/usr/bin/clang \
CC=/Library/Developer/CommandLineTools/usr/bin/clang \
AR=/Library/Developer/CommandLineTools/usr/bin/ar \
cargo test --offline --workspace
```

这类失败属于工具链问题，与代码测试失败分开记录。

### 6.2 前端依赖安装失败或测试启动报引擎错误

先确认 `node --version` 满足 1.1 节要求，再重新安装：

```bash
rm -rf node_modules
npm ci
```

### 6.3 `npm run tauri:dev` 启动失败

- 端口 1420 被占用：结束占用进程（Tauri 要求固定端口）
- 缺少编译工具：`xcode-select --install`

### 6.4 本地开发数据库损坏

开发环境下可先备份，再删除应用数据目录中的 `dgos.db`，下次启动会重新执行 migration。该操作会丢失本地 Provider 配置、任务记录等数据；系统钥匙串中的凭据不会随之删除。

## 7. 开发规范

- **Rust**：`cargo fmt`、`cargo clippy`；单文件不超过 1000 行
- **TypeScript**：`tsc` 严格模式（`strict`、`noUnusedLocals`）；单组件文件不超过 500 行
- **提交**：见 [Git 提交信息规范](Git提交信息规范.md)
- **文档**：功能规格、冻结决策和实现状态的维护规则见 [AGENTS.md](../../AGENTS.md) 与 [文档中心](../README.md)
