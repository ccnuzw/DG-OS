# V7 AI Agent：第三方 CLI 适配设计草案

> 状态：草案。V7 尚未通过开发门禁；本文是实现前的架构输入，不代表 V7 功能已进入正式开发或已完成验收。

## 1. 范围

当前宿主切片提供 Codex 与 Claude Code 两个固定适配器；以下默认参数描述 Codex，Claude Code 边界见 §6.1：

- 调用 `codex exec --json`，消费 JSONL 事件。
- 运行目录由用户选择，但必须是已存在的 Git 工作区。
- 默认 `read-only`、`--ephemeral`、`--ignore-user-config`、`--ignore-rules`。
- 只接受封闭枚举 adapter、提示词和工作区，禁止 renderer 提交 executable、argv、环境变量、MCP 配置、sandbox 放宽项或自定义配置文件。
- 不保存完整提示词、stdout、stderr、文件内容、工具参数或 CLI 凭据。
- 一次只允许一个 Agent 运行；运行以宿主生成的 `run_id` 标识。

不在第一阶段：写入工作区、任意 CLI 注册、Codex App Server、会话恢复、MCP 透传、Skills 自动选择、多 Agent 协作和画布工作流生成。

## 2. 分层

```text
Workbench
  -> Tauri command + Channel
  -> host::context(Workbench, TasksRun)
  -> AgentManager
  -> Codex / Claude Code adapter + shared runner
  -> tokio::process::Command
  -> fixed CLI + JSONL events
```

`dgos-agents` 只处理适配器协议、进程生命周期和公共事件；身份、页面准入和宿主能力由 `src-tauri` 处理。Codex、Claude Code 各自构造命令与解析事件，封闭枚举静态分派；Gemini CLI 尚未接入。

宿主基础能力切片（用户已授权，不依赖 UI 迁移）：`lib.rs` 保留管理器与公共 DTO，`runner.rs` 负责有界 JSONL 读取、进程生命周期和取消，`codex.rs` 负责命令构造、事件解析和退出结果判定，`probe.rs` 负责安装与参数探测。运行器通过静态分派的内部 `Protocol` 接口调用解析和完成判定，不识别 Codex 事件名称，不引入动态插件注册或异步装箱。单运行、页面卸载取消和通道关闭取消语义保持不变。

## 3. 公共状态和事件

运行状态：

```text
starting -> running -> succeeded
                   -> failed
                   -> result_unknown
```

以下情况进入 `result_unknown`：进程在没有可靠 `turn.completed` 终态时退出、读取中断、外部超时，或进程启动后的取消。取消会终止直接子进程，但不声称撤销模型请求或副作用；该状态不自动重试。

公共事件：

- `run_started`：宿主生成的 run ID 与 adapter ID。
- `thread_started`：CLI 提供的会话引用，只在当前运行内展示，不持久化。
- `turn_started`。
- `message_delta`：规范化的 Agent 文本片段。
- `progress` / `tool_activity`：脱敏的阶段摘要，不包含完整命令或参数。
- `run_failed`：错误类别和 retryable 诊断，不是终态；失败或运行开始后的取消先发送该事件，再且仅再发送一个 `run_completed`。成功仅发送 `run_completed`。

CLI 原始事件只在 adapter 内存中解析，不直接转发给 renderer。

## 4. 安全边界

- executable 由封闭 adapter 枚举固定为 `codex` 或 `claude`，参数由对应适配器构造，不经过 shell；下列 Codex 专属参数与事件规则不套用到 Claude Code（见 §6.1）。
- 子进程环境先清空，仅恢复 `PATH`、`HOME`、`TMPDIR`；不把 DGOS Provider secret 或其他进程环境传入。
- `--ignore-user-config` 跳过用户 config.toml，`--ignore-rules` 跳过 execpolicy `.rules`；不将这两个参数宣称为禁用所有项目指令、插件或 MCP 的隔离保证。认证由 Codex 自己处理。
- `--sandbox read-only` 是 CLI 的执行策略，不等于 DGOS 的 OS 级沙箱；DGOS 不把该运行宣称为不受信代码隔离。
- 工作区只允许已有目录和 `.git` 目录；不接受任意文件路径作为输入，不创建临时工作树，不自动安装 CLI。
- stdout 单行上限 4 MiB（包括 CR/LF）、总输出上限 16 MiB、最多 100000 个 JSONL 事件。按块读取并在追加缓冲前检查上限，缓冲重复使用；无换行尾行仍须通过 JSON/UTF-8 校验。
- 取消、超时、协议错误或接收端关闭会终止并回收直接子进程；`kill_on_drop` 兜底。清理完成才释放单运行槽位，终态投递最多等待 2 秒，断开通道不能保证收到终态。未实现后代进程树隔离，不宣称撤销上游副作用。
- 模块不能调用 Agent；模块 SDK 未来必须新增独立的、带授权的 `agents.run` 能力，不能复用通用 JSON 转发入口。
- 提示词使用 `codex exec ... -` 的 stdin 输入并关闭管道，不拼入 argv，不作为 CLI 选项解析。
- 已知事件缺少必需字段、无 type 的 JSON、重复终态或终态后的事件均拒绝；未知且带 type 的事件忽略，不能建立成功。仅 `turn.completed` 加成功退出码判定成功；非零退出且无成功终态记为 `process_failed`，冲突或缺失终态记为 `result_unknown`。
- 超时与启动后的取消均不可自动重试；错误诊断不转发 stderr、CLI 原始 error 或异常文本。无法稳定识别认证错误时显示通用运行失败并引导用户检查 CLI 登录，不猜测认证状态。

## 5. Tauri 契约

- `start_agent_run({ input: { request_id, adapter, prompt, workspace }, onEvent }) -> { run_id, status }`；request_id 为客户端生成并保留的 UUID，adapter 必须为 `codex` 或 `claude_code`。无隐式默认，不接受任意程序名称。原 Codex 页面仅迁移请求字段，不增加选择器或自动恢复交互。
- `cancel_agent_run({ runId }) -> boolean`。
- 命令不接收 `user_id`、caller、adapter executable、sandbox、MCP 或 credential 参数。
- 仅 `main` 窗口、可信来源、Workbench caller、`TasksRun` capability 放行。
- 提供当前进程内的运行状态快照查询，不提供持久化历史；重启后内存句柄与快照消失，不自动恢复或重放。
- 启动输入错误及运行控制错误返回稳定 snake_case 类别。界面只显示白名单类别对应的中英提示；未知错误显示通用提示，不显示原始异常。
- 每次启动独立维护 attempt 身份；迟到 ack/事件不能覆盖下一任务，卸载后收到启动确认会取消该任务；活动列表仅保留最近 200 条。

### 5.1 本地 CLI 探测

`probe_agent_adapter({ adapter }) -> AgentProbeReport`，adapter 为 `codex` 或 `claude_code`，沿用 Workbench / TasksRun 宿主准入；前端不能指定可执行文件、参数或环境。UI 迁移期间不扩展旧页面。

| 字段 | 契约 |
| --- | --- |
| `adapter` | `codex` 或 `claude_code` |
| `version` | 识别出的三段数字版本，可带预发布后缀；未识别时为 `null` |
| `status` | `available` / `not_found` / `unsupported` / `probe_failed` / `busy` |
| `authentication` | 固定 `unknown`；不检查凭据或推断登录状态 |
| `missing_options` | 缺少的必要参数名称；沙箱未声明只读值时为 `--sandbox=read-only` |
| `diagnostic` | `null` 或 `spawn_failed` / `timeout` / `invalid_output` / `process_failed` |

按适配器执行版本与 help：Codex 为 `codex --version`、`codex exec --help`，Claude Code 为 `claude --version`、`claude --help`；复用各自运行时的环境白名单。不发起模型请求、不安装软件、不缓存结果。每个进程最多 5 秒，stdout 最多 128 KiB，stdin/stderr 关闭；异常时终止并回收直接子进程，future 丢弃时由 `kill_on_drop` 兜底。两个适配器共享一个探测槽位，竞争调用返回 `busy`，不占用 Agent 任务槽位。

只解析 help 的 Options 声明。Codex 要求 `--json`、`--ephemeral`、`--ignore-user-config`、`--ignore-rules`、`--sandbox`、`--cd` 及沙箱声明中的 `read-only`；Claude Code 要求 §6.1 使用的全部显式参数声明。未知 help 格式保守返回 `unsupported`（只表示本适配器无法确认支持，CLI 也可能支持未公开的参数）；版本格式无法识别返回 `probe_failed / invalid_output`。不返回原始输出、异常文本或本机路径。

`available` 仅说明本机 CLI 声明了当前启动所需参数，不代表已登录、模型可访问、真实 JSONL 兼容性或 OS 隔离已验证；不以未经验证的版本区间作兼容承诺。探测不会自动启动任务、放宽执行策略或改变既有 start/cancel 契约。

验收边界：可识别版本和全部必要声明时返回 `available`；缺少声明或只读值时返回 `unsupported` 与缺失项；说明文本中的参数名不能建立支持；超时、超量、非 UTF-8、退出失败与缺少可执行文件有稳定分类。对应验证见第 7 节。

### 5.2 运行状态快照与归属

用户授权的下一切片：新增 `get_agent_run({ runId }) -> AgentRunSnapshot`。查询、启动和取消均从宿主 context 派生用户；前端不传身份。未知、已淘汰或不属于当前用户的 ID，查询统一返回 `run_not_found`，取消统一返回 `false`，不暴露其他用户任务。

快照字段为 `run_id`、`adapter`、`status`、`cancel_requested`、`error`（稳定类别及 retryable，或 null）。两个适配器共享一个活动任务槽位与全局最近 32 个终态，按完成顺序淘汰；不保存 prompt、workspace、输出、thread ID 或凭据。不提供列表、事件重放、重新订阅或持久化。

注册时为 `starting`；直接子进程成功 spawn 后为 `running`，不依赖 renderer 接收事件。取消仅设置 `cancel_requested` 并请求清理，不提前伪造终态；启动前取消为 `cancelled`，启动后取消沿用 `result_unknown`。只有运行器返回后才写终态并释放单运行槽位，随后投递终态事件；终态写入后不会被迟到取消覆盖。完成/未知任务取消返回 `false`。

页面卸载和通道关闭的取消行为保持不变；查询不会使任务脱离页面生命周期。应用退出不承诺结果可恢复或上游副作用回滚，后代进程树隔离仍不在当前范围。

验收：活动/完成任务均可由所属用户查询；跨用户查询与取消不能命中；快照在收到 run_started 前已为 running，在收到 run_completed 前已为终态；取消请求和最终结果分开；重复取消不改写终态；终态保留上限、淘汰和单运行槽位复用有确定性验证。

#### 会话结束与应用退出

账户会话每次状态切换均撤销旧 Agent lease；身份与 lease 在同一读锁下取得，启动前核对宿主 context，运行任务使用 lease 的子取消令牌。切换、退出登录、改密失效和删除流程复用 HostSessionPort 的 set_state → release 顺序，不接受 renderer 提交 lease。即使同一用户重新登录，旧 lease 也不能恢复。

事件转发监听 lease 撤销，并在与会话失效共享的锁下检查后投递；set_state 返回后不再向旧 Channel 排入新事件。已在切换前交给 WebView 的消息不能撤回；新 UI 仍需沿用运行实例隔离。旧输出不会自动转接到新会话。

HostSessionPort.release 调用 `cancel_user`，只取消对应用户的活动任务，最多等待 4 秒回收；失败记录不含敏感数据的警告，不把超时说成清理成功。结束后保留原有有界快照，运行中的取消沿用 result_unknown，cancel_requested 标记为 true。未回收前单运行槽位不释放。

ExitRequested 首先撤销会话 lease 并调用 AgentManager.close 永久关闭启动准入，再与现有宿主清理并行执行 shutdown，纳入现有 5 秒整体退出窗口。其他 manager 缺失时仍独立清理 Agent。shutdown 幂等，最多等待 4 秒；未完成返回 false 并记录警告。该能力不提供后台续跑、退出结果恢复、后代进程树隔离或上游副作用回滚。

验收覆盖：旧 lease 拒绝启动、会话撤销终止直接子进程、跨用户 release 不误取消、同用户新 lease 可重新运行、shutdown 幂等且永久拒绝新任务、失效后不调用旧事件投递闭包。应用强杀和操作系统崩溃不属于正常退出清理保证。

#### 启动确认丢失与请求去重

`get_agent_request({ requestId }) -> AgentRunSnapshot` 按当前宿主用户查询。客户端应在发送前保留 UUID；启动确认丢失时先查询，不自动生成新 ID 重试。无效 UUID 返回 invalid_request_id，未知或其他用户请求返回 run_not_found。run_not_found 不能证明请求从未执行（可能未登记、仍在传输或宿主已经重启）。

首次登记、去重检查与单运行准入共用一把锁。同用户同 UUID 的重复启动，如果 adapter/prompt/workspace 原始字节一致，返回原 run_id 与当前状态，不执行第二个进程、不重发事件、不替换原 Channel；不同输入返回 request_conflict。原 Channel 断开仍会取消原任务，重复提交不能让任务脱离原生命周期。

内存请求凭据最多 1024 条（全局），仅包含用户、UUID、run_id 和分字段长度编码的 SHA-256 输入摘要，不保存完整输入、不落盘、不输出摘要。快照仍只保留最近 32 个终态；快照淘汰后凭据继续阻止重跑，查询/重复启动返回 request_expired。凭据不自动淘汰，容量满后新请求返回 request_capacity，已有请求仍可查询/去重。重启清空凭据，不能跨重启承诺恰好执行一次；这些错误均不可自动重试。

会话撤销与 shutdown 优先于重复启动返回；新的显式用户任务必须生成新 UUID。工作区有效性在首次接受时验证，重复查询已接受请求不因工作区后来消失而重新执行。启动失败也保留凭据；修复原因后显式重新运行需使用新 UUID。前端新恢复交互留待 UI 迁移完成，本批旧页面只增加一次启动一个 UUID 的字段。

验收：并发重复只登记一个运行；相同请求可在确认缺失时查询；跨用户不可查询；三种输入字段冲突均拒绝；重复请求不接管通道；已淘汰终态不会重新执行；无效 ID 和凭据容量满不启动进程。

### 5.3 宿主能力目录

`list_agent_adapters() -> AgentAdapterDescriptor[]` 无输入，沿用 Workbench / TasksRun 准入。返回静态目录，不启动 CLI、不访问凭据、不探测安装，不占用任务或探测槽位。安装与参数支持仍通过 `probe_agent_adapter` 查询，认证仍为 unknown。

| 字段 | 含义 |
| --- | --- |
| `adapter` | `codex` 或 `claude_code`，可直接用于探测和启动 |
| `execution_policy` | Codex 为 `codex_read_only_sandbox`；Claude 为 `claude_restricted_read_tools`，描述宿主请求的 CLI 策略，不承诺 OS 隔离 |
| `operations` | 当前开放 `probe`、`run_once`、`stream_events`、`cancel`、`query_run`、`query_request`；未列出的操作不视为开放 |
| `requires_git_workspace` | 两者均为 true |
| `max_prompt_bytes` | 16384，UTF-8 字节数，复用运行输入校验的常量 |

目录描述 DGOS 当前接口能力，不是上游 CLI 的完整功能、安装状态或验证等级。`stream_events` 表示事件通道，不能推断逐 token 输出。目录不授予权限，也不接受动态注册；共享单运行槽位与页面取消语义沿用 §5.2。前端选择器待 UI 迁移后接入；本切片不修改页面。

验收：即使 PATH 无可执行 CLI，目录仍可读取；序列化为稳定 snake_case 字段及枚举；两种执行策略区分明确，输入字节上限与运行器一致。采用公开 API 临时 smoke 和宿主编译/契约验证，不新增仅重复静态元数据的永久测试。

## 6. 其他 CLI 适配

未来适配器必须先声明能力：

| Adapter | 第一阶段状态 | 计划协议 |
| --- | --- | --- |
| Codex | 实现 `exec --json` | JSONL 事件；后续再评估 app-server |
| Claude Code | 接入受限单次运行，验证边界见 §7 | `--print --output-format stream-json --verbose` |
| Gemini CLI | 未实现 | headless JSONL |

适配器必须按版本检测能力并忽略未知事件；不能仅凭 CLI 名称假设支持会话恢复、审批、工具调用或文件变更。

### 6.1 Claude Code 受限运行

固定 executable 为 `claude`，cwd 为已验证的 Git 工作区，提示词仅通过 stdin 发送并关闭管道。不传 resume/continue，不传 partial-messages，不注入 DGOS Provider 凭据；环境先清空，仅恢复 PATH/HOME/TMPDIR，认证由 CLI 自行处理，探测报告始终为 unknown。

宿主固定参数：`--print --output-format stream-json --verbose --no-session-persistence --restricted --safe-mode --strict-mcp-config --mcp-config '{"mcpServers":{}}' --tools Read,Glob,Grep --allowedTools Read,Glob,Grep --disallowedTools 'mcp__*' --permission-mode dontAsk --permission-prompts none --disable-slash-commands --no-chrome --settings '{"disableAllHooks":true}'`。

只开放读取/查找工具，不启用 Bash、编辑、写入、Skills、Agent 子任务或 MCP；不使用 bypassPermissions。restricted 限制文件工具工作目录并跳过用户/项目设置；safe-mode 禁用自定义内容并保留 CLI 认证；显式 settings 请求禁用 hooks。管理员策略仍可能优先生效，CLI 仍可能维护自身非会话运行数据；不将这些参数宣称为 OS 沙箱、不写任何本机文件或完全隔离策略。使用已安装可信 CLI，旧版本不支持参数时不能降级放宽策略。

事件映射：`system/init.session_id` → thread_started + turn_started；完整 `assistant.message.content` 中 text → message_delta，tool_use → 固定类别摘要，不传名称/参数；thinking、user、原始诊断不转发。未请求 partial-messages，因此结果中的重复答案不再次展示。`result` 必须有 `subtype=success`、`is_error=false` 和字符串 result，加成功退出才成功；错误结果映射 process_failed，缺失/冲突终态映射 result_unknown，缺字段、重复终态和终态后事件拒绝。复用有界读取、超时、取消、归属与快照生命周期。

协议依据：[官方 CLI 参数](https://code.claude.com/docs/en/cli-reference)、[非交互与 stream-json](https://code.claude.com/docs/en/headless)，以及本机 `claude --help`（2.1.317）。本机 help 与真实请求支持是不同证据，真实模型调用尚未验证。
