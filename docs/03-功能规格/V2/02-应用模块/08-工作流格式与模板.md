# V2-FR-008：工作流格式、导入导出与模板

## 目标

用户把画布导出成一个文件，在另一台机器或另一个账户里导入，得到同样的图；也可以从内置模板开始一张新画布。

## 功能边界

包含：

- 工作流文件格式 `dgos.workflow`（D104 第 4 项）与版本规则。
- 导出：仅 JSON；JSON + 资产的打包文件。
- 导入：校验、未知节点与缺失节点包、能力需求解析、缺失资产。
- 内置模板库（至少 3 个，V2 规划“完成判定”）。

不包含：

- 老项目工作流格式的导入（原因：D104 第 4 项，仓库里没有该格式的说明）。
- 合并导入到已有画布（原因：V2 只支持导入为新画布；合并涉及 id 冲突与协同，另行设计）。
- 模板市场、分享与云端存储（原因：V3 应用市场、V4 云端）。
- 自动排版（原因：V2-FR-006）。

## 需求说明

### 用户故事

作为画布用户，我希望把调好的工作流导出给同事，对方导入后配置自己的 Provider 就能运行，以便复用和分享。

### 文件格式 `dgos.workflow` v1

```json
{
  "format": "dgos.workflow",
  "schemaVersion": 1,
  "id": "wf_…",
  "name": "…",
  "description": "…",
  "createdWith": { "app": "DGOS", "version": "2.x.y" },
  "packages": [{ "id": "dgos.core", "version": "1.0.0" }],
  "nodes": [
    {
      "id": "n_…",
      "type": "dgos.core/llm",
      "typeVersion": "1.0.0",
      "parent": null,
      "position": { "x": 0, "y": 0 },
      "label": "…",
      "params": {}
    }
  ],
  "edges": [{ "id": "e_…", "from": { "node": "n_…", "port": "out" }, "to": { "node": "n_…", "port": "prompt" } }],
  "assets": [{ "hash": "sha256:…", "mime": "image/png", "size": 12345, "name": "…" }],
  "viewport": { "x": 0, "y": 0, "zoom": 1 }
}
```

字段的完整 JSON Schema 在进入开发前写入 V2 接口契约（`04-技术架构/后续版本/V2/`，D100）。

### 业务规则

1. **对外契约**：本格式独立于内部 Yjs 文档（V2 规划 §7）；导出时由宿主从文档生成，导入时由宿主写成新文档。
2. **版本**：`schemaVersion` 只做新增式变更；读到比自己新的 `schemaVersion` 时拒绝导入并提示升级 DGOS。旧版本的迁移必须幂等（V2 规划 §4）；V2 只有 v1，没有迁移。
3. **不含机密与本机配置**：文件中不出现 API Key、Provider id、MCP 凭据、本机路径；LLM、Generator 只存能力需求（V2-FR-007 业务规则 12）。
4. **资产**：图片等按内容哈希引用（D095）。
   - “仅 JSON”导出只含 `assets` 清单；
   - “打包”导出是一个 zip（扩展名 `.dgosflow`），内含 `workflow.json` 与 `assets/<hash>` 文件，单文件上限 200 MB（助手选定的初值）。
5. **导入只校验、不执行**：导入的文件是不可信输入。宿主校验格式与 JSON Schema、每个节点的参数 schema、节点数上限（与画布上限一致，暂定 2000）、字符串长度、资产哈希；任一项失败就拒绝整个文件，不创建半成品画布。导入后不自动运行任何节点。
6. **导入为新画布**：总是创建新画布；文件里的节点与连线 id 原样保留（新画布内唯一即可）。
7. **未知节点类型**：所属包未安装或类型不存在时，节点作为占位节点导入，保留原始数据；该节点不能运行，导出时原样写回。
8. **缺失节点包**：导入结果列出缺少的包与版本；包含它们的节点为占位节点。
9. **能力需求解析**：导入后，LLM、Generator 节点按能力需求匹配本机 Provider 与模型；匹配不到的节点标为“需要配置”，不阻止导入。
10. **缺失资产**：“仅 JSON”导入时，本机没有对应哈希的资产，引用它的节点显示缺失，运行前校验不通过。
11. **资产哈希不符**：打包文件中资产内容的哈希与清单不一致时，拒绝整个文件。
12. **模板**：内置模板是只读的 `dgos.workflow` 文件，随画布模块发布；“从模板新建”等于导入为新画布。至少包括：
    - 文本改写：Prompt → LLM（选择一个官方 Skill）→ Output；
    - 批量生成：Prompt（列表）→ Loop（内部 LLM）→ Merge → Output；
    - 条件路由：Prompt → LLM（分类）→ Conditional → 两个 LLM 分支 → Output。
    三个模板都只用文本节点，不依赖图片输入（待决项见 V2-FR-007）。

### 主流程

1. 导出：用户选择“导出”→ 选“仅 JSON”或“打包”→ 宿主生成文件 → 用户选择保存位置。
2. 导入：用户选择文件 → 宿主校验 → 通过则创建新画布并打开，显示导入报告（缺失包、需要配置的节点、缺失资产）→ 不通过则显示原因，不创建画布。
3. 从模板新建：用户在模板列表中选择 → 同导入流程。

### 异常与边界

- 文件不是 JSON 或 zip 损坏：拒绝，提示格式错误。
- `schemaVersion` 高于当前支持：拒绝，提示升级。
- 文件超过上限：拒绝，不读取全部内容。
- 导入过程中磁盘写入失败：不留下半成品画布与孤立资产。

### 页面与交互

导出、导入与模板列表的入口在画布编辑器（V2-FR-006），视觉按 V2-FR-009 的设计稿。

## 接口契约

宿主命令（导出、导入、列出模板）在 V2 接口契约中定义，本节只列需要的错误键。

### 错误矩阵

错误码在 V2 接口契约阶段分配。

| 错误键 | 场景 |
| --- | --- |
| `workflow_file_invalid` | 不是合法 JSON 或 zip，或缺少必填字段 |
| `workflow_schema_unsupported` | `schemaVersion` 高于当前支持 |
| `workflow_too_large` | 文件或节点数超过上限 |
| `workflow_params_invalid` | 某个节点的参数不符合其 schema |
| `workflow_asset_mismatch` | 打包资产的哈希与清单不一致 |
| `workflow_import_failed` | 写入新画布或资产时失败，已回滚 |

## 数据与事务

### 读写数据

| 数据 | 操作 | 字段 |
| --- | --- | --- |
| 画布文档（D095） | R（导出）/ W（导入） | 节点、连线、参数、位置、视口 |
| 资产（D095） | R（导出）/ W（导入） | 内容与哈希 |

### 约束与事务

- 导入时画布文档与资产要么全部写入、要么全部不写；写入机制属于 V2-FR-002，本功能要求它提供“新建文档 + 一批资产”的原子写入或可补偿清理。

### 状态与生命周期

不适用：导入与导出是一次性操作，没有持久状态。

## 验收标准

#### AC01 导出 JSON 的内容

Given 一张含 Prompt、LLM（已配置本机 Provider 与 API Key）、Image 的画布。

When 以“仅 JSON”导出。

Then 文件含 `format`、`schemaVersion`、`packages`、`nodes`、`edges`、`assets`；不含 API Key、Provider id、本机路径；LLM 节点只有能力需求。

#### AC02 打包导出包含资产

Given 画布引用 2 个图片资产。

When 以“打包”导出。

Then zip 内有 `workflow.json` 与 2 个 `assets/<hash>` 文件，文件内容的哈希与清单一致。

#### AC03 导入为新画布且不执行

Given 一个合法的工作流文件。

When 导入。

Then 创建一张新画布，节点、连线与位置与文件一致；没有任何节点被执行，没有外部调用。

#### AC04 往返一致

Given 一张画布。

When 导出 → 导入 → 再导出。

Then 两次导出的 `nodes`、`edges`、`params`、`assets` 一致（忽略画布 id 与时间字段）。

#### AC05 未知节点保留为占位

Given 文件中有一个类型为 `acme.pkg/foo` 的节点，本机没有该包。

When 导入后再导出。

Then 该节点在画布上为占位节点，不能运行；导入报告列出缺少 `acme.pkg`；再次导出时该节点的数据原样保留。

#### AC06 能力需求匹配不到

Given 文件中 LLM 节点要求的模型类型在本机没有可用 Provider。

When 导入。

Then 导入成功，该节点标为“需要配置”；运行前校验报 `node_capability_unresolved`。

#### AC07 拒绝非法文件

Given 分别是：损坏的 JSON、`schemaVersion` 为 2、超过节点数上限、某节点参数不符合 schema、参数 schema 中含远程 `$ref`。

When 逐个导入。

Then 每个都被拒绝并给出对应原因；没有创建任何画布或资产。

#### AC08 资产哈希不符

Given 打包文件中一个资产文件被改动，哈希与清单不一致。

When 导入。

Then 整个文件被拒绝（`workflow_asset_mismatch`），不创建画布。

#### AC09 仅 JSON 导入时缺资产

Given 一个“仅 JSON”文件引用的资产在本机不存在。

When 导入并运行。

Then 导入成功并在报告中列出缺失资产；引用它的节点运行前校验不通过。

#### AC10 导入写入失败不留残留

Given 导入过程中资产写入失败（注入故障）。

When 导入。

Then 返回 `workflow_import_failed`；没有新画布，没有孤立资产。

#### AC11 内置模板

Given 画布模块已启用。

When 打开模板列表并分别从三个模板新建。

Then 每个模板都创建新画布，通过运行前校验（Provider 配置齐全时）；模板文件本身不变。

#### AC12 模板只读

Given 从“文本改写”模板新建并修改了画布。

When 再次从同一模板新建。

Then 新画布与原模板一致，不包含上次的修改。
