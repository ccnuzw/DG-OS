## 目标

画布用户把内置节点连成一张无环图，点“运行”后只重算有变化的部分；不花钱的节点在改参数时自动给出预览，调用模型和工具的节点只在用户运行时执行。

## 功能边界

包含：

- 节点类型的定义方式：端口、参数 schema、执行类别、类型 id 与版本。
- 端口类型与连线规则。
- 内置节点包 `dgos.core` 的 10 个可执行节点与 Note（D104 第 3 项）。
- 执行语义：运行前校验、运行范围、增量运行与缓存复用、自动预览、强制重跑、失败传播、条件分支、循环、外部调用确认（D104 第 1、2 项）。
- LLM 节点选择 Skills（功能演进矩阵“V2 画布集成”）。

不包含：

- 运行的生命周期、持久化、事件通道、缓存存储与取消（原因：V2-FR-001）。
- 画布上的拖拽、连线手势、撤销、自动排版（原因：V2-FR-006）。
- 工作流文件的导入导出（原因：V2-FR-008）。
- 第三方节点包的注册与贡献校验（原因：V2-FR-003）；带代码的第三方节点（原因：等隔离方案，D051 方案 C）。
- `Function` 节点（原因：执行任意用户代码，不在 V2，另行决策）。
- 允许成环的循环（原因：D104 第 2 项）。

## 需求说明

### 用户故事

作为画布用户，我希望把 Prompt、LLM、图片生成等节点连起来，改一处只重跑受影响的部分，以便快速迭代而不重复付费。

### 节点类型的定义

每个节点类型声明下列内容，宿主与画布只认这些声明：

| 字段 | 说明 |
| --- | --- |
| 类型 id | `发布者.包名/节点名`，内置节点为 `dgos.core/<名>`；主版本变化就是新类型（V2 规划 §5） |
| 版本 | 语义化版本；缓存键只取主版本 |
| 输入端口 | 名字、端口类型、是否必填 |
| 输出端口 | 名字、端口类型 |
| 参数 | JSON Schema（自动生成 `host.ui` 表单）；不接受 `$ref` 到远程或文件（D094） |
| 执行类别 | `pure`（确定性、无外部调用）、`external`（调用模型、工具或网络）、`container`（Loop）、`inert`（Note，不执行） |

### 端口类型与连线规则

1. 基础端口类型：`text`、`number`、`boolean`、`json`、`image`（资产引用，D095）、`list<T>`，以及只用于输入的 `any`。节点包可以注册带命名空间的新类型（V2 规划 §5），转换规则由 V2-FR-003 定义。
2. 输出类型与输入类型相同、或输入为 `any` 时可以连线；`list<T>` 不会隐式拆成 `T`，拆分只能经 Loop。
3. 一个输入端口最多一条连线；一个输出端口可以连到多个输入。
4. 图必须无环（D104 第 2 项）。编辑时拒绝会成环的连线；并发编辑后仍可能出现环或悬空连线（V2 规划 §4），由运行前校验拦下。
5. Loop 容器内的节点只能和同一容器内的节点相连，进出只经容器端口。

### 内置节点（`dgos.core`）

| 节点 | 类别 | 输入 | 输出 | 主要参数 | 执行类别 |
| --- | --- | --- | --- | --- | --- |
| Prompt | 输入 | 可选：变量（`json`） | `text` | 模板文本，`{{变量}}` 占位 | pure |
| Image | 输入 | 无 | `image` | 选择或上传的资产 | pure |
| LLM | AI | `text`（提示词）；可选 `text`（系统提示）；可选 `image`，可多张（D106） | `text` | 能力需求（模型类型、协议、是否需要视觉输入，不存本地 Provider id）、Skills（固定版本）、温度、最大输出长度 | external |
| Generator | AI | `text`（提示词） | `image` | 能力需求（图片生成）、尺寸、数量 | external |
| MCP 工具 | AI | `json`（参数） | `json` | 服务器与工具、配置时固定的工具 schema | external |
| Transform | 逻辑 | `any` | `any`（由表达式结果决定） | CEL 表达式（D106） | pure |
| Conditional | 逻辑 | `any`（值） | `true`、`false` 两个输出，类型同输入 | 返回布尔的 CEL 表达式（D106） | pure |
| Loop | 逻辑 | `list<T>` 或 `number`（次数） | `list<U>` | 最大迭代数、并发上限、单项失败策略 | container |
| Merge | 逻辑 | 多个同类型输入 | `list<T>` | 输入端口数 | pure |
| Output | 输出 | `any` | 无 | 显示方式 | pure |
| Note | 注释 | 无 | 无 | 文本 | inert |

### 业务规则

1. **运行前校验**（依据：V2 规划 §4）：运行开始前检查环、悬空连线、端口类型、必填输入、参数 schema、未知节点类型；任何一项不通过就不运行，逐节点列出原因。
2. **运行范围**：全图运行；或“运行到此节点”，只执行该节点及其上游。
3. **增量运行**（D104 第 1 项）：节点的缓存键 = 类型 id + 主版本 + 规范化参数 + 全部输入的哈希。键与上次成功结果相同的节点直接复用结果，不执行；其余节点按拓扑序执行。缓存的存储与淘汰属于 V2-FR-001。
4. **自动预览**（D104 第 1、5 项）：`pure` 节点的参数或上游预览变化后，防抖 300 毫秒，以“预览”范围交给宿主运行服务执行，只包含 `pure` 节点；遇到 `external` 节点即停止，该节点与其下游标为“已过期”。
5. **强制重跑**：用户对某个节点选择“重新运行”时，该节点忽略缓存执行一次，下游按新结果判定是否变化。
6. **外部调用确认**：一次运行将要执行的 `external` 调用数（含 Loop 展开后的次数）超过 20 次时，运行前显示调用数并要求用户确认；阈值是助手选定的初值，可在设置中调整（待 V2-FR-006 设计设置项）。
7. **失败传播**：节点失败时，只有依赖它的下游标为“已跳过”；与它无关的分支继续执行并保留结果。外部调用结果未知时（D074 的口径）节点标为“结果未知”，下游同样跳过，不自动重试。
8. **条件分支**：Conditional 只把值送到一个输出；未选中的输出及其独占下游标为“已跳过”，不算失败。Merge 忽略已跳过的输入，按端口顺序合并其余输入；全部输入都跳过时 Merge 也跳过。
9. **循环**（D104 第 2 项）：
   - Loop 对输入列表逐项执行内部子图，子图内可用 `item` 与 `index`；输入为 `number` 时等于对 `1..N` 逐项执行。
   - 输出列表与输入顺序一致，与并发完成的先后无关。
   - 列表长度超过“最大迭代数”时运行前校验不通过，提示实际长度与上限，不截断。默认最大迭代数 100，默认并发 4，均为助手选定的初值。
   - 单项失败策略：`stop`（默认）取消其余项，Loop 失败；`skip` 跳过失败项，输出只含成功项，并报告失败数量。
   - V2 不支持嵌套 Loop（助手选定，避免组合爆炸；需要时另行决策）。
10. **Skills**（D016、D017）：LLM 节点选择的 Skill 记录固定版本；运行开始时按该版本装配，Skill 版本变化不影响已固定的节点，用户可以手动升级。
11. **MCP 工具**（D083）：工具 schema 在配置节点时固定；运行前发现服务器上的 schema 已变化，节点校验不通过，需要用户重新配置。MCP 授权在运行开始时按运行范围一次性取得。
12. **能力需求**：LLM、Generator 存“能力需求”（模型类型、协议），不存本机 Provider id（V2 规划 §4）；执行时由宿主解析为本机可用的 Provider 与模型，解析不到时节点校验不通过并提示配置。
13. **Note** 不参与校验、执行与缓存。

### 节点结果状态

`空闲 → 已过期 → 排队 → 运行中 → 成功 / 失败 / 已跳过 / 已取消 / 结果未知`；成功的节点在参数或输入变化后回到“已过期”。这些是节点在画布上的显示状态，运行本身的状态机在 V2-FR-001 定义，两者的映射在 V2-FR-001 技术设计中对齐。

### 异常与边界

- 并发编辑留下环或悬空连线：运行前校验拦下，画布上标出问题节点。
- 运行中用户修改了参数：本次运行不变（D082 运行归宿主持有），结束后受影响节点标为“已过期”。
- 运行中关闭页面：运行继续（D082）；重新打开时显示结果。
- Loop 列表为空：Loop 成功，输出空列表。
- Conditional 表达式求值出错：节点失败，按失败传播处理。

### 页面与交互

节点卡片显示状态、最近一次结果的预览与耗时；“已过期”的节点有明显标记。交互细节属于 V2-FR-006，视觉按 V2-FR-009 的设计稿。

## 验收标准

#### AC01 内置节点目录

Given 画布模块已启用。

When 用户打开节点目录。

Then 显示 Prompt、Image、LLM、Generator、MCP 工具、Transform、Conditional、Loop、Merge、Output 与 Note，每个节点的端口与参数和“内置节点”表一致。

#### AC02 端口类型与单入边

Given 一个 Prompt（输出 `text`）与一个 Generator（输入 `text`），另有一个 Image（输出 `image`）。

When 用户把 Image 连到 Generator 的提示词输入，再把 Prompt 连到同一输入。

Then 第一条连线被拒绝并提示类型不匹配；第二条连线成功；该输入只有一条连线。

#### AC03 拒绝成环

Given A → B → C 三个节点已连接。

When 用户尝试连接 C → A。

Then 连线被拒绝，图保持无环。

#### AC04 运行前校验阻止运行

Given 图中有一个未连接必填输入的 LLM 节点，另一个节点的类型不存在。

When 用户点“运行”。

Then 运行不开始，没有任何外部调用；两个节点分别标出 `node_input_missing` 与 `node_type_unknown`。

#### AC05 增量运行只重算变化部分

Given Prompt → LLM → Output 已成功运行一次。

When 用户只修改 Output 的显示方式并再次运行。

Then LLM 不再调用上游（复用缓存），Output 更新。

#### AC06 便宜节点自动预览，模型节点标为已过期

Given Prompt → Transform → LLM，均已成功运行。

When 用户修改 Prompt 文本，不点运行。

Then 约 300 毫秒后 Transform 显示新的预览；LLM 标为“已过期”，没有发出模型调用。

#### AC07 强制重跑

Given LLM 节点已成功运行，输入与参数未变。

When 用户对该节点选择“重新运行”。

Then 发出一次新的模型调用，下游按新结果更新。

#### AC08 失败只影响下游

Given 一个 Prompt 同时连到 LLM-A 与 LLM-B，LLM-A 的下游是 Output-A。

When 运行时 LLM-A 调用失败。

Then LLM-A 为失败，Output-A 为已跳过；LLM-B 正常完成并保留结果。

#### AC09 条件分支与合并

Given 值 → Conditional，`true` 与 `false` 各接一个 Transform，两者再接同一个 Merge。

When 条件为真时运行。

Then `false` 分支的 Transform 为已跳过；Merge 输出只含 `true` 分支的结果。

#### AC10 循环逐项执行并保持顺序

Given Loop 输入 `["a","b","c"]`，并发 4，内部子图把 `item` 转成大写。

When 运行。

Then 输出为 `["A","B","C"]`，顺序与输入一致。

#### AC11 超过最大迭代数不运行

Given Loop 的最大迭代数为 100，输入列表长度为 150。

When 用户点“运行”。

Then 运行不开始，提示 `loop_limit_exceeded`，并显示实际长度 150 与上限 100。

#### AC12 循环单项失败策略

Given Loop 输入 3 项，第 2 项会使内部节点失败。

When 分别以 `stop` 与 `skip` 运行。

Then `stop`：其余项被取消，Loop 失败；`skip`：输出 2 项，报告失败 1 项。

#### AC13 外部调用数确认

Given Loop 输入 30 项，内部有 1 个 LLM 节点，确认阈值为 20。

When 用户点“运行”。

Then 运行前显示将发出 30 次外部调用并要求确认；用户取消时不发出任何调用。

#### AC14 Skills 版本固定

Given LLM 节点选择了 Skill X 的 1.2.0 版本，之后本机把 X 更新到 1.3.0。

When 运行该节点。

Then 按 1.2.0 装配；节点上提示有新版本，用户确认升级后才改用 1.3.0。

#### AC15 MCP 工具 schema 变化

Given MCP 工具节点配置时固定了工具 schema，之后服务器上该工具的参数 schema 变化。

When 用户运行。

Then 该节点校验不通过（`mcp_tool_schema_changed`），不调用工具，提示重新配置。

#### AC16 Note 不参与执行

Given 图中有一个 Note。

When 运行全图并做运行前校验。

Then Note 不出现在校验结果、执行顺序与缓存中。

#### AC17 LLM 图片输入

Given Image 节点（一张已上传的图片资产）与 Prompt 节点同时连到 LLM；本机配置了一个支持视觉输入的模型和一个不支持的模型。

When 分别选择这两个模型运行。

Then 支持视觉输入的模型收到图片与提示词并返回文本；不支持的模型在运行前校验不通过（`node_capability_unresolved`），不发出调用。
