## 目标

画布和其他受控模块可以按模型能力需求调用图片生成，并把结果以内容寻址的资产引用交给后续节点；LLM 节点可以把已存在的图片资产作为视觉输入发送给支持视觉能力的模型，同时保持 Provider、凭据、文件路径和原始响应不泄露给调用方。

## 功能边界

包含：

- Provider 适配器的图片生成统一接口和 `image-generation` 模型能力校验。
- OpenAI Images 兼容端点的首个适配画像；其他供应商只有在独立画像和真实调用证据完成后才能启用。
- LLM 请求中的一个或多个图片资产输入，支持模型视觉理解。
- 面向官方画布模块的 `providers.image_generate` 宿主能力和结果资产引用。
- 图片结果的大小、MIME、内容哈希、尺寸和资产原子提交校验。
- 超时、取消、重复提交、Provider 配置变更、外部结果未知和审计告警语义。

不包含：

- Generator 图生图、图片编辑、局部重绘、ControlNet 或多图融合（原因：D106 明确 Generator 只接受文本提示词）。
- 图片、视频或音频生成 CLI；第三方 CLI Agent 由后续 Agent 功能单独定义。
- 视频生成、音频生成、Embedding 和图片 OCR（原因：尚未分配的能力）。
- 把任意本地路径、任意 URL、data URL 或原始二进制交给模块（原因：宿主资产边界和路径安全）。
- 局域网远程画布调用（原因：D103，画布浏览器端模块加载器移到 V4）。

## 需求说明

### 用户故事

作为画布用户，我希望用 Generator 生成图片，或把已有图片交给 LLM 理解，以便在同一张画布中完成视觉创作和文本处理；我希望结果可复用、可追踪，并且取消或失败时不会被系统误报为成功。

### 业务规则

1. Generator 只保存模型能力需求，不保存本机 Provider ID、凭据引用或 endpoint。运行时由宿主从当前用户可用的启用 Provider 和模型中解析；解析不到时不发起外部请求（依据：V2-FR-007、D106）。
2. 图片生成模型必须由宿主从模型目录得到 `model_type=image-generation`；前端或模块提交的模型分类、能力提示和 Provider 身份不可信，不能覆盖宿主计算结果（依据：V1-FR-001）。
3. 首个兼容画像只接受 Provider 明确支持的 OpenAI Images 兼容响应：内嵌 `b64_json`，或经宿主校验后获取的 HTTPS 图片 URL。原始 URL 不返回给模块或页面。
4. Provider 返回的每一张图片都必须经过 MIME、字节上限、内容哈希和可解码性校验；校验或资产提交任一步失败，整次生成不返回部分成功资产。
5. 图片生成请求默认最多生成 4 张图片，单张资产最大 8 MiB，提示词最大 16 KiB；这些是 V2 初值，进入开发门禁后按真实 Provider 证据复核。超限时拒绝，不截断、不拆分、不自动降低数量。
6. LLM 图片输入只能使用宿主已经登记的 `AssetRef`，支持的 MIME 初值为 `image/png`、`image/jpeg`、`image/webp`；模块不能提交文件路径、data URL 或任意外部 URL。
7. LLM 图片输入要求目标模型的 `capabilities.vision=supported`。能力为 `unknown` 或 `unsupported` 时运行前拒绝，错误为 `image_vision_unresolved`，不把一次失败请求交给上游试探。
8. Generator 不接受图片输入；即使请求同时包含文本和图片资产，宿主也必须在外部调用前拒绝。
9. 生成外部调用在数据库事务外执行。宿主不会因页面离开、超时、进程重启或取消而自动重放图片生成；已经发送但未观察到终态的调用按 `image_result_unknown` 处理。
10. 取消在外部调用派发前到达时，调用终结为 `cancelled` 且上游请求次数为零；派发后取消只停止等待和资产提交，不能声称远端调用被撤销。
11. 同一宿主用户、同一运行任务和同一节点的重复 `request_id` 只允许一次受理。已受理请求再次提交返回原运行状态或重复请求错误，不以重复提交作为外部幂等保证。
12. Provider 配置或模型缓存 revision 在任务绑定后发生变化，不影响已经派发的请求，但尚未派发的节点必须终止为 `provider_revision_changed`，不静默切换到新 Provider。
13. 资产写入采用暂存后原子提交；数据库、文件系统或哈希校验失败不得留下可被后续运行引用的孤立资产。
14. 使用记录只保存用户、Provider、模型、任务/节点引用、请求哈希、图片数量、字节数、耗时、结果类别和用量是否未知；不保存 API Key、完整提示词、原始图片 URL、完整返回正文或图片二进制。
15. Provider 适配器的重试策略不能把已接受的图片生成请求自动重发。若无法判断请求是否已被上游接受，必须返回 `image_result_unknown`，由用户显式决定是否创建新的请求。
16. `providers.image_generate` 是新增的模块能力声明；它只允许受信任宿主准入的官方模块使用。授予 `providers.call` 不自动授予图片生成，图片输入仍受 `providers.call` 和模型视觉能力检查共同约束。

### 主流程

1. 用户在画布配置 Generator 的图片生成能力需求、尺寸、数量和提示词。
2. 运行服务冻结节点参数、输入、Provider 配置 revision 和任务引用。
3. 宿主检查当前用户、节点参数、模型能力、数量、Provider 状态与 `providers.image_generate` 授权。
4. 宿主在事务外调用图片适配器，读取并规范化响应。
5. 宿主把响应内容写入用户作用域的资产暂存区，校验哈希和元数据后原子提交。
6. 运行服务发布 `AssetRef[]` 和脱敏用量结果；画布下游节点只消费资产引用。

### 异常与边界

- 能力需求没有匹配 Provider 或模型：运行前失败，不产生上游请求。
- 请求超过提示词、数量或尺寸限制：运行前失败，不截断。
- Provider 返回不支持的 JSON、无效 base64、非 HTTPS URL、私网 URL、超限响应或无法解码内容：失败且不发布资产。
- 资产提交失败：运行失败，不返回部分资产；可清理暂存目录，不能自动重发请求。
- 取消或超时发生在派发前：`cancelled`；发生在派发后：`result_unknown`。
- 页面离开或画布标签关闭：运行继续，由 V2-FR-001 持有；重新打开通过运行事件和资产引用查看结果。
- Provider 版本变化：未派发节点失败；已派发调用按原快照完成或进入未知结果。
- 同一图片生成请求并发提交：宿主按 `(user_id, run_id, node_id, request_id)` 防止重复受理；不同 `request_id` 是两个独立的、可能产生费用的调用。

### 页面与交互

图片能力不新增独立设置页。画布 Generator 和 LLM 节点显示：

- 能力需求、匹配状态和需要配置提示；不显示不属于工作流的 Provider 凭据。
- 生成中、取消中、成功、失败、结果未知和资产写入失败状态。
- 生成数量、尺寸和预计外部调用数量；超过运行服务确认阈值时由 V2-FR-001 统一确认。
- 成功结果的缩略图通过 `AssetRef` 读取；不直接渲染 Provider 返回 URL。

## 接口契约

V2 接口字段以 `04-技术架构/后续版本/V2/` 的增量契约为准；本节定义 V2-FR-010 必须提供的逻辑接口，具体 Tauri 命令和事件传输由 V2-FR-001、V2-FR-002 统一收敛。

### 接口清单

| 方法 | 路径 / 能力 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| `generate_image` | `host.providers.generateImage` / `providers.image_generate` | 当前宿主用户 + 模块能力 + 运行上下文 | 生成图片并提交为资产引用 |
| `call_vision` | `host.providers.call` | 当前宿主用户 + `providers.call` + Provider/模型能力 | 发送包含图片资产引用的 LLM 请求 |
| `read_asset` | `host.assets.read` | 当前宿主用户 + 资产归属 | 读取图片资产用于预览或 Provider 请求 |
| `cancel_run` | V2-FR-001 运行命令 | 当前宿主用户 + 任务归属 | 取消尚未派发的图片调用，或停止等待已派发调用 |

### 请求字段

| 字段 | 位置 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| `request_id` | 运行请求 | string | 是 | 宿主生成或绑定；1～64 字符；重复请求不再次受理 |
| `run_id` | 运行上下文 | string | 是 | 由运行服务生成；调用方不能伪造其他用户任务 |
| `capability` | Generator 参数 | object | 是 | 至少包含 `kind=image-generation`；不含本机 Provider ID |
| `prompt` | Generator 参数 | string | 是 | UTF-8 ≤ 16 KiB；空字符串拒绝 |
| `count` | Generator 参数 | integer | 是 | 1～4；不接受截断或自动降级 |
| `width` / `height` | Generator 参数 | integer | 是 | 必须在适配画像允许的尺寸集合内；不支持的尺寸运行前拒绝 |
| `asset_refs` | 视觉请求 | AssetRef[] | 否 | 仅 LLM 图片输入使用；每项属于当前用户且为允许的图片 MIME |
| `model_requirement` | LLM/Generator 参数 | object | 是 | 能力、协议和可选模型约束；不含凭据、endpoint 和本机资源 ID |

### 成功响应

```json
{
  "run_id": "run_…",
  "status": "succeeded",
  "assets": [
    {
      "ref": "sha256:…",
      "mime": "image/png",
      "bytes": 123456,
      "width": 1024,
      "height": 1024
    }
  ],
  "usage": {
    "image_count": 1,
    "reported": false
  },
  "audit_warning": false
}
```

`AssetRef` 是内容寻址引用，不含本地绝对路径、Provider URL 或凭据。LLM 视觉调用的文本响应沿用 V1 Provider 响应契约，图片输入只作为请求上下文，不把图片二进制放入普通响应 DTO。

### 错误矩阵

V2 错误码尚未分配；以下稳定错误键必须在 V2 接口契约阶段映射为数字错误码。

| 错误键 | 场景 | 是否产生上游请求 | 处理 |
| --- | --- | --- | --- |
| `image_capability_unresolved` | 没有匹配的图片生成模型或 Provider | 否 | 标记节点需要配置 |
| `image_generation_unsupported` | Provider/画像不支持图片生成 | 否 | 不降级为文本调用 |
| `image_prompt_invalid` | 提示词为空或超过上限 | 否 | 拒绝请求 |
| `image_count_invalid` | 数量不在 1～4 | 否 | 拒绝请求 |
| `image_size_unsupported` | 尺寸不在适配画像允许集合 | 否 | 拒绝请求 |
| `image_vision_unresolved` | LLM 模型不支持或未知视觉能力 | 否 | 运行前失败 |
| `image_asset_invalid` | 资产不存在、越权、MIME 不允许或损坏 | 否 | 拒绝请求 |
| `image_response_invalid` | Provider 响应结构、base64 或内容不可解析 | 可能 | 失败，不发布资产 |
| `image_response_too_large` | 单张或总响应超过上限 | 可能 | 失败，清理暂存 |
| `image_asset_write_failed` | 暂存、哈希或原子提交失败 | 已可能 | 失败，不自动重发 |
| `image_generation_timeout` | 达到宿主期限 | 可能 | 已派发时按未知结果处理 |
| `image_generation_cancelled` | 派发前取消或停止等待 | 可能为否 | 不自动重试 |
| `image_result_unknown` | 已派发但未观察到可靠终态 | 是 | 用户显式创建新请求 |
| `image_request_duplicate` | 同一请求标识重复受理 | 否 | 返回原状态或拒绝重复 |
| `provider_revision_changed` | 尚未派发时 Provider 快照失效 | 否 | 重新配置后重试 |
| `image_permission_denied` | 模块未获 `providers.image_generate` | 否 | 宿主拒绝，原因不交给不受信模块 |

## 数据与事务

### 读写数据

| 数据 | 操作 | 字段 |
| --- | --- | --- |
| `providers` / `models` | R | 当前用户的启用状态、模型 kind、能力提示、配置 revision |
| V2 运行任务 | R/W | `run_id`、节点引用、状态、请求哈希、Provider 快照引用 |
| V2 资产存储 | R/W | 内容哈希、用户归属、MIME、字节数、尺寸、暂存/提交状态 |
| Provider 使用记录 | W | Provider、模型、任务引用、图片数量、字节数、耗时、结果类别、用量未知标志 |
| 模块权限与审计 | R/W | `providers.image_generate` 的声明、授权和脱敏审计 |

### 约束与事务

- Provider 配置、模型能力和模块授权由宿主查询；前端只提交能力需求和 AssetRef。
- 任务绑定、Provider revision 和请求去重记录在短事务中提交；网络请求和图片下载不持有数据库事务。
- 资产必须先写用户作用域暂存区，完成 MIME、哈希和解码校验后，在同一提交操作中发布元数据和可读引用。
- 任何中间步骤失败都不能发布半成品 `AssetRef`；清理失败必须进入可观测的暂存清理状态，不把调用报告为成功。
- 图片正文、完整提示词、secret、Provider URL 和原始响应不进入 SQLite 普通字段、日志或错误消息。

### 状态与生命周期

```text
queued
  → resolving
  → staging
  → dispatching
  → receiving
  → committing
  → succeeded

resolving / staging / dispatching / receiving / committing
  → failed
  → cancelled
  → result_unknown
```

- `cancelled`：确认外部调用尚未派发，或宿主只停止等待且明确按取消结算。
- `result_unknown`：请求可能已经被上游接受，但宿主没有可靠终态；不得自动重放。
- 终态不可被后续事件改写；迟到的 Provider 响应只能进入丢弃或脱敏诊断路径。

## 验收标准

#### AC01 图片生成能力需求解析

Given 当前用户启用了一个模型目录中 `model_type=image-generation` 的 Provider。

When Generator 以图片生成能力需求运行。

Then 宿主解析到可用 Provider 和模型，调用使用冻结的配置 revision；请求和工作流文件都不包含本机 Provider ID、凭据或 endpoint。

#### AC02 图片生成结果提交为资产

Given Provider 返回一张合法的 PNG 图片。

When Generator 完成调用。

Then 宿主校验 MIME、字节数、解码结果和 SHA-256，原子提交一个 `AssetRef`，下游只收到该引用；页面和日志不显示 Provider 原始 URL。

#### AC03 不支持的图片能力在上游调用前失败

Given 当前匹配到的模型不是 `image-generation`，或 Provider 没有首个兼容画像。

When 用户运行 Generator。

Then 返回 `image_capability_unresolved` 或 `image_generation_unsupported`，上游请求次数为零，没有创建资产。

#### AC04 请求预算拒绝且不截断

Given 用户输入超过 16 KiB 的提示词、数量为 0 或超过 4，或选择适配画像不支持的尺寸。

When 用户运行 Generator。

Then 返回对应校验错误，原始提示词不被截断，Provider 请求次数为零。

#### AC05 LLM 使用图片资产输入

Given 当前用户拥有一个合法的 PNG 资产，且目标 LLM 的视觉能力为 `supported`。

When LLM 节点把该资产作为图片输入运行。

Then 宿主读取资产并转换为目标协议所需的图片内容格式；模型收到图片输入，模块和 Provider 不收到本地路径或资产存储路径。

#### AC06 未知或不支持视觉能力时拒绝

Given 目标模型的视觉能力为 `unknown` 或 `unsupported`。

When LLM 节点包含图片输入并运行。

Then 返回 `image_vision_unresolved`，不向上游发送请求，也不把图片输入降级为文本 URL。

#### AC07 非法或越权资产被拒绝

Given 请求包含不存在、属于其他用户、MIME 不允许或内容哈希不匹配的 AssetRef。

When LLM 节点运行。

Then 返回 `image_asset_invalid`，上游请求次数为零，其他用户的资产信息不泄露。

#### AC08 Provider 响应异常不发布部分资产

Given Provider 返回非法 JSON、无效 base64、非 HTTPS 图片 URL、私网 URL、无法解码的内容或超过大小上限的内容。

When 宿主处理响应。

Then 返回 `image_response_invalid` 或 `image_response_too_large`，所有暂存内容被清理或标记待清理，没有任何可引用的成功资产。

#### AC09 取消和未知结果不自动重放

Given 图片请求已经进入外部调用，用户取消或宿主达到超时，且没有可靠的 Provider 终态。

When 运行结算。

Then 状态为 `result_unknown`；宿主不再发起第二次图片请求，不把结果显示为成功，用户必须显式创建新的 request_id 才能重试。

#### AC10 派发前取消不产生外部请求

Given 图片请求仍在解析、授权或暂存阶段。

When 用户取消运行。

Then 状态为 `cancelled`，Provider 请求次数为零，没有发布资产。

#### AC11 重复提交不重复受理

Given 同一用户、运行、节点和 request_id 已经受理。

When 页面再次提交相同 request_id。

Then 宿主返回原运行状态或 `image_request_duplicate`，不创建第二个外部调用；使用新的 request_id 才能创建新的用户意图。

#### AC12 Provider revision 绑定

Given 运行已经绑定 Provider 配置 revision，用户随后修改 endpoint、凭据或模型缓存。

When 尚未派发的图片节点继续执行。

Then 节点终止为 `provider_revision_changed`，不静默切换到新配置；已经派发的请求继续按原快照结算。

#### AC13 模块图片生成权限

Given 一个模块声明 `providers.image_generate`，但当前用户尚未授予该权限。

When 模块调用 `host.providers.generateImage`。

Then 宿主拒绝调用，不启动 Provider 请求；授予 `providers.call` 不能替代图片生成权限。

#### AC14 使用记录脱敏和用户隔离

Given 两个用户分别完成图片生成或视觉输入调用。

When 任一用户查询使用记录和资产列表。

Then 只能看到自己的脱敏记录和资产引用；记录不包含 API Key、完整提示词、原始 URL、图片正文或其他用户信息。

## 技术设计

详见 [10 图片生成与图片输入能力 - 技术设计](10-图片能力-技术设计.md)。

### 单元契约

| 函数 | 前置条件 | 返回 / 后置条件 | 副作用 |
| --- | --- | --- | --- |
| `resolve_image_capability(requirement, user, revision) -> ProviderSnapshot` | 用户会话有效；能力需求合法 | 返回唯一可用快照，否则返回能力解析错误 | 无外部调用 |
| `generate_image(snapshot, request, cancel) -> ImageGenerationResponse` | 快照有效；调用未取消 | 返回规范化图片内容或稳定错误 | 一次受控外部调用；不负责发布资产 |
| `commit_image_assets(user, run, response) -> AssetRef[]` | 响应内容已校验 | 原子发布全部资产或全部失败 | 写暂存文件、资产元数据和审计引用 |
| `call_vision(snapshot, messages, assets) -> ChatResponse` | 模型视觉能力为 supported；资产已授权 | 返回文本响应；图片只作为上游请求内容 | 一次受控外部调用；写脱敏使用记录 |

### 伪代码

```text
FUNCTION run_image_generation(ctx, request):
  validate_request(request)                                      // B10-01
  existing = find_request(ctx.user, request.request_id)          // B10-02
  IF existing: RETURN existing OR image_request_duplicate        // B10-03
  snapshot = resolve_capability(ctx.user, request.capability)    // B10-04
  IF snapshot missing: RETURN image_capability_unresolved        // B10-05
  BEGIN TRANSACTION
    bind_run_and_revision(ctx.run_id, snapshot.revision)           // B10-06
    reserve_request(ctx.user, request.request_id)                 // B10-07
  COMMIT
  IF cancelled_before_dispatch(): settle_cancelled()             // B10-08
  response = adapter.generate_image(snapshot, request)             // B10-09
  IF response is unknown: settle_result_unknown()                 // B10-10
  validate_all_outputs(response)                                  // B10-11
  staged = stage_assets(ctx.user, response)                        // B10-12
  IF staging fails: cleanup_staging(); settle_asset_write_failed   // B10-13
  committed = commit_all_assets_atomically(staged)                // B10-14
  IF commit fails: cleanup_or_enqueue_cleanup(); settle_failed     // B10-15
  write_redacted_usage_and_finish(committed)                      // B10-16
  RETURN succeeded(committed)
```

## 实现与验证

### 工程落点

- Provider 类型与适配器：`crates/dgos-types`、`crates/dgos-providers`；需要新增图片请求/响应和视觉消息的共享类型。
- 宿主应用服务：`crates/dgos-application`；负责 capability、运行上下文和 Provider revision 绑定。
- 运行服务：V2-FR-001；负责任务生命周期、事件通道、取消和未知结果。
- 资产服务：V2-FR-002；负责暂存、内容寻址、元数据和原子发布。
- 模块能力命令：V2-FR-004 / V2-FR-001 接口增量；新增 `providers.image_generate`，不使用通用 JSON 转发入口。
- 测试：V2 进入开发后建立 fake Provider、回环 HTTP、故障注入和真实上游 smoke；本规格阶段不创建测试替身。

### 当前差距

- `ProviderAdapter` 当前只有文本同步、工具和流式接口，没有图片生成方法。
- `ChatMessage.content` 当前是字符串，不能表达图片资产输入；需要新增跨协议的视觉消息模型，并分别由 OpenAI 兼容和 Anthropic 适配器转换。
- V2 `host.assets`、运行服务、V2 增量接口契约和 V2 错误码尚未建立。
- Provider 模型已能分类为 `image-generation`，但分类不等于图片生成请求已实现。
- 首个 OpenAI Images 兼容画像、图片响应 URL 获取策略和真实上游证据尚未创建。
