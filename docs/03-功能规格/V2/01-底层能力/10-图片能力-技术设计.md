# 10 图片生成与图片输入能力 - 技术设计

来源：[需求](10-图片能力.md#需求说明) · [接口](10-图片能力.md#接口契约) · [数据](10-图片能力.md#数据与事务) · [验收](10-图片能力.md#验收标准)

> V2 门禁准备阶段设计。具体迁移、公开 Tauri 字段和错误数字码要在 V2 接口/数据契约建立后冻结；本文先冻结内部边界、事务、状态和失败语义，不代表代码已实现。

## 风险与对策

| 风险 | 严重程度 | 对策 | 关联决策 |
| --- | --- | --- | --- |
| 图片生成请求可能已经计费但宿主未观察到结果 | 高 | 不对图片生成做自动重试；终结为 `image_result_unknown`，要求用户用新 request_id 显式重试 | D082、D106 |
| Provider 返回 URL、base64 或 MIME 不可信 | 高 | 只接受允许的协议/来源，限制响应大小，解码后重新检测 MIME 与尺寸，再暂存和哈希 | D103 |
| 资产写入与运行结果不一致 | 高 | 暂存、校验、元数据发布采用原子提交；失败不发布 AssetRef，清理失败进入可观测清理队列 | D095 |
| 多用户或模块越权读取资产/Provider | 高 | 用户由宿主派生；每次校验资产归属、运行归属和模块能力；不接受 user_id、Provider ID 或路径作为可信身份 | D023、D051、D094 |
| Provider revision 在运行期间变化 | 高 | 任务绑定配置快照和 revision；未派发的调用发现漂移即失败，已派发调用只按原快照结算 | D082、D106 |
| 同一请求重复提交造成重复费用 | 高 | 在短事务中登记 `(user_id, run_id, node_id, request_id)` 唯一键；重复返回已有状态，不作外部 exactly-once 承诺 | D074、D106 |
| 图片输入跨协议转换泄露本地路径 | 高 | 资产服务只返回受控 bytes/stream；适配器自行编码为协议内容块，禁止 file URL、绝对路径和原始 AssetRef 出现在上游请求 | D095 |

## 单元契约

| 函数 | 前置条件 | 返回 / 后置条件 | 副作用 | 幂等 |
| --- | --- | --- | --- | --- |
| `resolve_image_capability(user, requirement, revision) -> ProviderSnapshot` | 当前宿主会话有效；需求为允许的能力格式 | 返回唯一启用 Provider、模型和配置快照；无匹配时返回稳定错误 | 只读数据库 | 是；同一快照读取不改变状态 |
| `reserve_image_request(user, run, node, request_id, snapshot) -> Reservation` | 运行归属正确；request_id 合法 | 首次提交创建唯一登记；重复返回已有登记 | 短事务写运行绑定和去重登记 | 是；唯一键 |
| `generate_image(snapshot, request, cancel) -> ExternalImageResult` | 快照已绑定；未超过外部调用期限 | 返回完整规范化内容、明确失败或 unknown | 一次 Provider 外部调用 | 否；不得由宿主重放 |
| `validate_image_output(result) -> Vec<ValidatedImage>` | 响应未超过大小和数量上限 | 每张内容可解码、MIME 与声明一致；否则整批失败 | 内存读取 | 是；纯函数 |
| `stage_assets(user, run, images) -> StagedAssets` | 所有图片已验证 | 用户作用域暂存文件及哈希元数据 | 文件系统写入 | 可重复清理；不发布引用 |
| `commit_assets(staged) -> Vec<AssetRef>` | 暂存完整且数据库/文件路径有效 | 全部资产可引用，或整体失败 | 原子发布资产元数据和文件指针 | 是；同一 staging id 不二次发布 |
| `encode_vision_input(user, asset_refs, profile) -> VisionContent` | AssetRef 属于当前用户且 MIME 允许；模型视觉能力 supported | 返回协议画像所需的图片内容块 | 读取资产 bytes；不写入图片正文日志 | 是；纯转换 |
| `settle_image_run(run_id, outcome) -> ()` | 运行仍未终结 | 只允许一次终态写入，迟到事件被丢弃 | 短事务写状态/脱敏审计 | 是；终态保护 |

## 伪代码

要求：每个关键判断和副作用标注分支 ID `// B10-序号`；外部调用放在事务外。

```text
FUNCTION start_image_run(ctx, request) -> Result:
  require_host_session(ctx)                                        // B10-01
  validate_prompt_count_size(request)                              // B10-02
  validate_capability_shape(request.model_requirement)              // B10-03

  existing = find_request(ctx.user_id, ctx.run_id, ctx.node_id, request.request_id)
  IF existing exists:
    RETURN existing_or_duplicate(existing)                         // B10-04

  snapshot = resolve_image_capability(
    ctx.user_id, request.model_requirement, request.expected_revision
  )
  IF snapshot missing:
    RETURN image_capability_unresolved                              // B10-05

  authorize_image_generation(ctx.module, ctx.user_id, snapshot)     // B10-06
  BEGIN TRANSACTION
    verify_run_owned_by_user(ctx.run_id, ctx.user_id)               // B10-07
    verify_provider_revision(snapshot)                              // B10-08
    reserve_unique_request(ctx, request.request_id, snapshot)       // B10-09
    write_running_state(ctx.run_id, snapshot.revision)              // B10-10
  COMMIT

  IF cancellation_requested():
    settle_image_run(ctx.run_id, cancelled)                         // B10-11
    RETURN cancelled

  external = adapter.generate_image(snapshot, request, deadline)    // B10-12
  IF external is Unknown:
    settle_image_run(ctx.run_id, result_unknown)                     // B10-13
    RETURN result_unknown
  IF external is Error:
    settle_image_run(ctx.run_id, map_external_error(external))      // B10-14
    RETURN mapped_error

  IF cancellation_requested_after_dispatch():
    discard_or_finish_without_publish(external)                      // B10-15
    settle_image_run(ctx.run_id, result_unknown)                     // B10-16
    RETURN result_unknown

  validated = validate_image_output(external)                        // B10-17
  staged = stage_assets(ctx.user_id, ctx.run_id, validated)           // B10-18
  IF staging failed:
    cleanup_or_enqueue_staging_cleanup(staged)                       // B10-19
    settle_image_run(ctx.run_id, image_asset_write_failed)           // B10-20
    RETURN image_asset_write_failed

  committed = commit_assets(staged)                                  // B10-21
  IF commit failed:
    cleanup_or_enqueue_staging_cleanup(staged)                       // B10-22
    settle_image_run(ctx.run_id, image_asset_write_failed)           // B10-23
    RETURN image_asset_write_failed

  write_redacted_usage(ctx, committed, external.usage)               // B10-24
  settle_image_run(ctx.run_id, succeeded(committed))                 // B10-25
  RETURN succeeded(committed)
```

```text
FUNCTION build_vision_request(ctx, request) -> Result:
  require_host_session(ctx)                                         // B10-26
  model = resolve_text_model(request.model_requirement)              // B10-27
  IF model.capabilities.vision != supported:
    RETURN image_vision_unresolved                                  // B10-28
  IF request.asset_refs is empty:
    RETURN build_text_request(request)                               // B10-29

  assets = read_and_authorize_assets(ctx.user_id, request.asset_refs) // B10-30
  IF any asset invalid:
    RETURN image_asset_invalid                                      // B10-31
  IF any asset.mime not in allowed_image_mimes:
    RETURN image_asset_invalid                                      // B10-32

  content = encode_for_profile(assets, model.profile)                // B10-33
  IF content exceeds request/model budget:
    RETURN image_input_too_large                                    // B10-34
  RETURN provider_request_with_content(request, content)             // B10-35
```

## 并发控制

| 场景 | 冲突点 | 控制方式 | 失败策略 |
| --- | --- | --- | --- |
| 同一 request_id 并发提交 | 去重登记 | `(user_id, run_id, node_id, request_id)` 唯一约束；先登记再外部调用 | 竞争失败读取首次登记，不能启动第二次调用 |
| 同一运行多个 Generator | Provider 与运行额度 | 由 V2-FR-001 的运行服务控制运行范围和外部调用并发；图片服务不自行扩展无限并发 | 超过运行额度返回可重试的运行资源错误，不发起请求 |
| 同一用户同时写资产 | 文件名/引用冲突 | 内容寻址路径 + 原子 rename；元数据唯一键为 `(user_id, hash)` | 已有同哈希资产复用，不重复写正文 |
| Provider 配置变更与运行 | 快照漂移 | 运行绑定 revision；写配置递增 revision，调用前重验未派发节点 | 返回 `provider_revision_changed`，不切换 Provider |
| 取消与完成并发 | 终态竞争 | 终态条件更新；只有第一个终态写入者成功 | 已观察到成功则保留成功，否则按实际观察到的取消/unknown 结算 |
| 资产提交与清理并发 | staging 被误删 | staging lease/状态标记；提交前持有短期清理保护 | 清理任务跳过 active staging；过期 staging 才可清理 |

死锁预防：所有事务先锁运行登记，再锁 request 去重登记，最后锁资产元数据；数据库事务内不做网络请求、图片下载或解码；每个事务只持有用户作用域的短行锁。

## 事务边界

- **请求受理事务**：校验当前归属后的运行绑定、Provider revision 快照引用、request_id 去重登记和 `running` 状态在同一短事务中提交。
- **外部调用阶段**：完全在事务外，带独立超时和取消 token；不持有数据库锁。
- **资产提交阶段**：图片先写用户作用域 staging，再做完整性校验；元数据发布和 staging→published 指针切换必须原子完成。
- **结算事务**：使用记录摘要、运行终态和资产引用在可行时同一短事务提交；审计写入失败不能把已完成外部调用改报为未执行，必须返回 `audit_warning` 或进入补偿队列。
- **隔离级别**：沿用 SQLite/SeaORM 当前事务默认值；依靠唯一约束和条件更新保护并发，不在事务中进行外部 I/O。
- **失败回滚**：请求受理失败不留下活动登记；资产发布失败不留下可读引用；外部调用失败不触发数据库重试。

## 幂等与重试

- 幂等键：`(user_id, run_id, node_id, request_id)`；`request_id` 由运行服务生成或绑定，不能由不可信模块伪造运行归属。
- 去重登记保存运行状态和最终脱敏结果引用，至少覆盖当前进程生命周期；跨重启的恢复策略属于 V2-FR-001，不能在图片服务中自行重放。
- 重复请求：运行中返回已有状态；已成功返回同一 AssetRef；已失败返回稳定失败类别；已 unknown 不自动重放，页面必须生成新 request_id。
- 图片生成外部请求不自动重试。网络连接在请求尚未交给上游前失败可判定为未派发；无法判断是否已接受时必须按 unknown。
- 图片 URL 下载如属于响应处理的一部分，只允许在已验证 HTTPS、无重定向或逐跳仍在允许来源范围内执行；下载失败不重试整次生成，不重新发起生成请求。
- 视觉 LLM 请求沿用 V1 Provider 的重试政策，但请求中的图片资产读取失败和协议转换失败属于本地最终错误；若上游请求可能已接受，沿用 Provider 的未知结果语义。

## 外部调用与补偿

### Provider 图片生成

- 首个适配器以 OpenAI Images 兼容画像为边界；图片生成请求和响应字段由适配器独立解析，不复用文本 `ChatRequest` 的伪字段。
- 适配器必须在发送前确认模型 kind、数量、尺寸和请求大小；响应体采用总大小上限，单项采用单张大小上限。
- 原始响应只在内存中短暂存在。解析失败只记录错误类别和响应大小，不记录完整响应正文。
- `b64_json` 直接解码后进入统一校验；URL 结果必须符合 HTTPS、无用户信息、无 fragment、无私网地址和允许的重定向策略，下载后按 bytes 校验。
- Provider 传输超时、进程退出、连接断开和取消都区分“未派发”和“可能已派发”；后者统一为 `image_result_unknown`。

### 资产补偿

- staging 目录按 `(user_id, run_id)` 隔离，路径由宿主生成，不能从请求字段拼接。
- 启动恢复扫描过期 staging；有已提交元数据的 staging 可安全删除，无元数据的 staging 删除正文并记录类别。
- 数据库提交成功而文件清理失败时保留可读资产并写 `audit_warning`；文件提交成功而数据库失败时不发布引用，加入清理队列。
- 补偿任务只清理 staging，不重发 Provider 请求，不修改已终结的运行结果。

## 安全与日志

- 敏感字段：API Key、credential_ref 对应的 secret、完整提示词、图片正文、原始响应、Provider URL、资产本地路径不进入普通 DTO、SQLite 日志、tracing 字段或错误消息。
- 资产权限：读取资产前检查宿主用户、运行归属和模块上下文；不接受模块自报 user_id、文件路径或 Provider ID。
- 模块权限：`providers.image_generate` 单独声明、单独授予、单独审计；不提供 `capability + arbitrary JSON` 的通用 invoke 入口。
- 网络：图片 URL 响应只允许适配画像规定的 HTTPS 来源；禁止自动跟随到不受信任的主机、私网地址或本地文件协议。
- 日志：只记录 request_id、run_id、Provider/模型的稳定非秘密标识、结果类别、耗时、数量、字节数和 `usage_unknown`；提示词和响应仅记录哈希或长度。
- 供应商错误正文不直接透传给模块；统一为稳定错误键和用户可理解的固定文案。

## 发布与回滚

- 前置条件：V2-FR-001 运行服务、V2-FR-002 资产服务、V2 Provider 增量类型/错误契约、至少一个 fake Provider 和一个真实 OpenAI Images 兼容 smoke。
- 功能开关：图片生成和视觉输入分别受能力注册/版本开关控制；开关关闭时能力解析失败，不影响 V1 文本 Provider。
- 回滚方式：关闭图片能力开关；正在运行的任务按现有生命周期结算，不自动重放；已提交资产保留为可读历史引用，不执行破坏性删除。
- 数据回滚：新增资产元数据和 staging migration 采用向后兼容追加；回滚代码时保留历史资产并由旧版本忽略未知能力记录，不修改已执行 migration。
- 监控指标：能力解析失败率、图片生成成功/失败/unknown 比例、Provider 延迟、响应大小拒绝数、资产提交失败数、staging 清理积压、审计告警数、重复 request_id 次数。
- 发布门禁：至少覆盖 OpenAI 兼容 b64 和 URL 两种响应之一；真实调用不得把 API Key 或完整提示词带入测试输出；取消、超时和 Provider 配置变化必须有本地故障注入证据。
