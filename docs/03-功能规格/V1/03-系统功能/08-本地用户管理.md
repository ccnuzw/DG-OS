## 2. 功能概述

### 2.1 一句话描述

提供本地用户的创建、登录、切换和删除功能，支持密码认证和数据隔离，让多个用户可以在同一台电脑上独立使用 DGOS。

### 2.2 详细说明

本地用户管理是 DGOS 的基础功能，让不同用户的数据完全隔离。V1 只实现本地用户（无需云端账号）；云端账号在 V3 提供，绑定本地用户和跨设备同步在 V4（D040）。

**核心价值**：
- 数据隔离：每个用户有独立的配置、历史、模块
- 隐私保护：用户之间看不到彼此的数据
- 多用户支持：同一台电脑多人使用
- 简单认证：用户名 + 密码

**用户价值**：
- 个人用户：隐私保护
- 家庭用户：多人共享一台电脑
- 企业用户：不同员工使用同一台设备

**与云端账号（V3 起）的区别**：
- V1 本地用户：数据只在本地，无需注册
- 云端账号：V3 用于应用市场；V4 绑定本地用户后数据云端同步，跨设备使用

### 2.3 功能边界

**包含**：
- 用户注册（用户名 + 密码）
- 用户登录（验证密码）
- 用户切换（切换到其他用户）
- 用户注销（退出登录）
- 用户删除（删除用户和所有数据）
- 修改密码
- 密码单向哈希存储（Argon2id，D087）
- 数据隔离（基于 user_id）
- 首次启动引导（创建第一个用户）
- 记住上次登录用户

**不包含**（明确说明原因）：
- ❌ 找回密码 → V1 无邮箱，无法找回
- 两步验证 → V2 安全增强
- 用户头像 → 后续版本（路线图未分配）
- ❌ 用户权限管理 → V1-FR-009 独立功能
- ❌ OAuth 登录 → 云端账号（V3 起，D040）
- ❌ 云端同步 → V4 跨设备同步

### 2.4 身份边界收口（2026-10-31）

共用身份模型见 [服务与领域边界 §3.5](../../../04-技术架构/服务与领域边界.md#35-auth统一身份与安全边界fr-008009010)，本节只记录本功能的结论，来源是冻结决策（含 2026-10-31 冻结的 [D087](../../../06-决策记录/V1-冻结决策.md#d087-本地账户首个账户承接-default-userargon2id-与退避会话只在内存删除账户可恢复地清理)）与当前代码。§3～§9 的旧草案与本节冲突时以本节为准，冲突逐项见 §2.4.2。

#### 2.4.1 已确认

1. **不是前置**：D023 下 FR-001～FR-007 不依赖本功能；FR-009 的授权已按宿主派生的 `user_id` 隔离，FR-010 的远程会话不使用本功能的账户（D053），两者都不以本功能为前置。
2. **接入方式**：只替换宿主会话解析器，即 `src-tauri/src/host.rs` 的 `LOCAL_USER` 与 `HostSession::local_default()` 这一处出口。已注册命令的签名不变，仍不携带用户身份；新增的账户命令同样经 `host::context`，并纳入 `contracts:check`。
3. **请求不能选择用户**（D023、D025）：§6.1 草案中的 `delete_user(user_id, …)`、`change_password(user_id, …)`、`set_last_login_user(user_id)`、`logout(session_token)`、`verify_session(session_token)` 不按原签名实现。删除、改密只作用于当前会话用户；会话令牌不交给 renderer。`login`、`create_user` 中的 `username` 是与密码一起验证的账户选择器，不是身份声明。
4. **`user_id` 保持 TEXT**：现有数据全部归 `default-user`，所有表没有指向用户表的外键（D023、D065、D072）。§4.1 草案的 UUID `id` 与 [V1 数据模型](../../../04-技术架构/当前版本/V1-数据模型.md) 的 INTEGER `id` 都不能直接套用；用户表由新增 migration 追加，已执行的 migration 不修改。
5. **没有 `ON DELETE CASCADE`**：§3.5、§4.2 与 AC10 的“级联删除”只能由应用层逐领域清理实现。D072 已为聊天登记 `purge_user_chat(user)`，其他领域需要同类入口。
6. **删除账户的清理面**（按 2026-10-31 的 migrations 核对，实施前再对照 `crates/dgos-db/src/migrations/mod.rs`）：
   - 表：`providers`、`provider_usage_logs`（及遗留 `usage_logs`）、`provider_credential_cleanup`、`skill_user_states` 与技能使用日志、`mcp_servers`、`mcp_usage_logs`、`mcp_connection_logs`、`workbench_tasks`、`chat_sessions`、`chat_messages`、`module_permissions`、`module_permission_audits`、`module_crash_logs`、`system_settings`。`modules` 是全局表，不随用户删除。
   - 外部资源：OS vault 中该用户的 Provider 与 MCP 凭据。vault 账户名是含 `user_id` 的哈希，不能按用户枚举，必须先从数据库取得 `credential_ref` 再删 vault 项；清理失败沿用 D023 的持久 outbox 重试，不把未删除的 vault 项报告为已删除。
7. **敏感数据**：密码、会话令牌不写日志、不进普通 DTO 或错误消息；密码只存单向哈希（D023）。
8. **账户不用于局域网**：远程会话没有独立用户身份，`/api/auth/login`、`/api/users` 不开放（D053）。
9. **用户切换不能让旧用户的能力继续服务新用户**：模块 runtime 句柄在 start 时绑定用户（`HostExecutionContext::for_module_session`），资源服务按用户校验归属（D023）。切换、注销、删除、改密的顺序见 §2.4.3“桌面会话”；远程会话绑定签发者，该用户注销、切换或被删除时撤销其远程会话（D088）。
10. **JWT 不用于本功能**：D087 规定桌面会话只在宿主内存，令牌不交给 renderer；D053 排除远程的 JWT 登录。PRD §6.5 的“JWT 24 小时”与 §7.1 的 bcrypt cost 12 作废。

#### 2.4.3 已决（D087）

| 项 | 规则 |
| --- | --- |
| default-user 承接 | 首个账户的 `user_id` 就是 `default-user`，现有行与 vault 项原样归属，不改写任何数据；第二个账户起使用 UUID 文本。首个账户创建前宿主仍以 `default-user` 运行，没有密码门禁；创建后启用登录 |
| 密码哈希与暴力破解限制 | Argon2id，参数随哈希串保存，登录成功时可按新参数重算；在阻塞线程池计算。口令 8～128 字符，用户名 1～32 字符。每账户失败次数持久化，连续 5 次失败后指数退避（30 秒起，最长 15 分钟），成功登录后清零，不永久锁定 |
| 桌面会话 | 只在宿主内存，令牌不交给 renderer、不写数据库；重启后重新登录，“记住上次登录”只预选用户（AC11）。切换、注销、删除、改密的顺序：停止全部模块 runtime（D086）→ 取消在途任务与待确认的工具调用 → 撤销该用户签发的远程会话（D088）→ 切换会话解析器 → 页面重新加载用户数据。改密后需要重新登录 |
| 删除账户与外部资源清理 | 只能删除当前登录的账户，需要再次输入密码。先写持久删除标记，再逐领域删除（§2.4.1 第 6 条），先取 `credential_ref` 再删 vault 项，失败走 D023 的持久 outbox；中途崩溃由启动恢复继续，完成前不能登录。可以删除最后一个账户，之后回到首次引导；权限审计一并删除 |
| 宿主级设置存放 | 新表 `host_settings`（新 migration），存放上次登录的用户、局域网开关与端口等；删除账户只清除指向该用户的“上次登录”值 |

接口契约见 [V1 接口契约 §9](../../../04-技术架构/当前版本/V1-接口契约.md#9-用户管理接口)，实现方式见[技术设计](08-本地用户管理-技术设计.md)。两者在 D087 之外的取舍由 [D090](../../../06-决策记录/V1-冻结决策.md#d090-fr-008-账户命令契约与实现取舍独立账户入口未登录-1008007退避-1008011可恢复删除与-mcp-凭据-outbox) 冻结（2026-11-01）。

## 4. 数据模型

### 4.1 涉及的数据表

> 历史草案：表结构以 migration 为准，与 §2.4 的冲突见 §2.4.2（`user_id` 为 TEXT、无外键、不持久化明文会话令牌、`app_config` 表不存在）。

**users 表**（核心表）：
```sql
CREATE TABLE users (
    id TEXT PRIMARY KEY,              -- UUID
    username TEXT UNIQUE NOT NULL,    -- 用户名（唯一）
    password_hash TEXT NOT NULL,      -- 密码哈希（bcrypt）
    display_name TEXT,                -- 显示名称（可选，默认为 username）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_login_at TIMESTAMP,          -- 最后登录时间
    is_active BOOLEAN DEFAULT TRUE    -- 是否激活
);

CREATE INDEX idx_users_username ON users(username);
```

**user_sessions 表**（会话管理）：
```sql
CREATE TABLE user_sessions (
    id TEXT PRIMARY KEY,              -- UUID
    user_id TEXT NOT NULL,
    token TEXT UNIQUE NOT NULL,       -- 会话 token
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP,             -- 过期时间（可选）
    device_info TEXT,                 -- 设备信息（可选）
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX idx_sessions_token ON user_sessions(token);
```

**app_config 表**（应用配置）：
```sql
CREATE TABLE app_config (
    key TEXT PRIMARY KEY,
    value TEXT
);

-- 存储"上次登录用户"
INSERT INTO app_config (key, value) VALUES ('last_login_user_id', '...');
```

### 4.2 数据隔离策略

**所有用户数据表都包含 user_id 字段**：
```sql
-- 示例：Provider 表
CREATE TABLE providers (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,            -- 关键：用户隔离
    name TEXT NOT NULL,
    ...
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 查询时必须过滤
SELECT * FROM providers WHERE user_id = ?;
```

**级联删除**：用户删除时，所有关联数据自动删除（`ON DELETE CASCADE`）。

### 4.3 读写关系

**读操作**：
- 获取所有用户：`SELECT id, username, display_name, last_login_at FROM users WHERE is_active = TRUE`
- 查询用户：`SELECT * FROM users WHERE username = ?`
- 获取上次登录用户：`SELECT value FROM app_config WHERE key = 'last_login_user_id'`

**写操作**：
- 创建用户：`INSERT INTO users (id, username, password_hash) VALUES (?, ?, ?)`
- 更新密码：`UPDATE users SET password_hash = ? WHERE id = ?`
- 删除用户：`DELETE FROM users WHERE id = ?`（级联删除所有关联数据）
- 记录登录：`UPDATE users SET last_login_at = ? WHERE id = ?`
- 保存会话：`INSERT INTO user_sessions (id, user_id, token) VALUES (?, ?, ?)`

// B08-01: 密码加密
pub fn hash_password(password: &str) -> Result<String> {
    // 使用 bcrypt，默认 cost = 12
    let hashed = hash(password, DEFAULT_COST)?;
    Ok(hashed)
}

pub fn verify_password(password: &str, hash: &str) -> Result<bool> {
    let valid = verify(password, hash)?;
    Ok(valid)

### 7.2 用户注册实现

```rust
// 规划 crate（未创建）：crates/dgos-auth/src/service.rs

pub struct AuthService {
    db: DatabasePool,
}

impl AuthService {
    // B08-03: 创建用户
    pub async fn create_user(
        &self,
        username: String,
        password: String
    ) -> Result<User> {
        // B08-04: 验证用户名唯一性
        if self.db.user_exists(&username).await? {
            return Err(Error::UserAlreadyExists);
        }
        
        // B08-05: 验证密码强度
        if password.len() < 6 {
            return Err(Error::PasswordTooShort);
        }
        
        // B08-06: 密码加密
        let password_hash = hash_password(&password)?;
        
        // B08-07: 保存到数据库
        let user = User {
            id: Uuid::new_v4().to_string(),
            username: username.clone(),
            display_name: None,
            created_at: Utc::now().to_rfc3339(),
            last_login_at: None,
        };
        
        self.db.insert_user(&user, &password_hash).await?;
        
        Ok(user)
    }
    
    // B08-08: 用户登录
    pub async fn login(
        &self,
        username: String,
        password: String
    ) -> Result<Session> {
        // B08-09: 查询用户
        let user = self.db.get_user_by_username(&username).await?
            .ok_or(Error::UserNotFound)?;
        
        // B08-10: 验证密码
        let password_hash = self.db.get_password_hash(&user.id).await?;
        if !verify_password(&password, &password_hash)? {
            return Err(Error::InvalidPassword);
        }
        
        // B08-11: 创建会话
        let session = Session {
            token: Uuid::new_v4().to_string(),
            user: user.clone(),
            expires_at: None, // 草案；会话有效期须结合安全设计确认
        };
        
        self.db.insert_session(&session).await?;
        
        // B08-12: 更新最后登录时间
        self.db.update_last_login(&user.id).await?;
        
        // B08-13: 记录为上次登录用户
        self.db.set_config("last_login_user_id", &user.id).await?;
        
        Ok(session)
    }
    
    // B08-14: 删除用户
    pub async fn delete_user(
        &self,
        user_id: &str,
        password: String
    ) -> Result<()> {
        // B08-15: 验证密码（确认身份）
        let password_hash = self.db.get_password_hash(user_id).await?;
        if !verify_password(&password, &password_hash)? {
            return Err(Error::InvalidPassword);
        }
        
        // B08-16: 删除用户（级联删除所有数据）
        self.db.delete_user(user_id).await?;
        
        Ok(())
    }
}
```
