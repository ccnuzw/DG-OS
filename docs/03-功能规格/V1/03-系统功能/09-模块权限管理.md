## 2. 功能概述

### 2.1 一句话描述

提供粗粒度的模块权限管理，定义 6 种权限类型（Provider、Skills、MCP、文件读写、网络），在运行时拦截模块调用并检查权限，记录权限日志。

### 2.2 详细说明

模块权限管理是 DGOS 的安全基石，确保模块只能访问授权的资源。V1 实现粗粒度权限（6 种类型），V2 再实现细粒度权限（RBAC、资源级别）。

**核心价值**：
- ✅ 安全保障：防止模块越权访问
- ✅ 用户知情：安装时明确告知权限
- ✅ 可审计：所有权限操作都有日志
- ✅ 可撤销：用户可以随时撤销权限

**用户价值**：
- 开发者：清晰的权限申请流程
- 最终用户：知道模块能做什么，安心使用

**粗粒度 vs 细粒度**：
- V1 粗粒度：6 种权限类型，简单直观
- V2 细粒度：具体到某个 Provider、某个文件路径

### 2.3 功能边界

**V1 权限类型（6 种）**：

1. **providers.call**：访问 Provider（调用 AI 模型）
2. **skills.execute**：访问 Skills 能力
3. **mcp.call**：访问 MCP（调用 MCP 工具）
4. **storage.read**：读取存储
5. **storage.write**：写入存储
6. **network.local**：访问本地网络

旧名称仅用于追溯（D024），不得写入：

| 旧名称 | D006 规范值 |
| --- | --- |
| `provider_access` | `providers.call` |
| `skills_access` | `skills.execute` |
| `mcp_access` | `mcp.call` |
| `file_read` | `storage.read` |
| `file_write` | `storage.write` |
| `network` | `network.local` |

**包含**：
- ✅ 权限定义和存储
- ✅ 模块安装时权限申请（manifest.json）
- ✅ 用户授权界面（安装时显示权限列表）
- ✅ 运行时权限检查（拦截器）
- ✅ 权限授予/撤销
- ✅ 权限日志记录
- ✅ 权限查询（查看模块有哪些权限）
- ✅ 权限拒绝错误处理

**不包含**（明确说明原因）：
- ❌ 细粒度权限（具体 Provider、文件路径） → V2 实现
- ❌ 角色权限（RBAC） → V2 实现
- ❌ 动态权限申请（运行时申请） → V2 实现
- ❌ 权限组（权限集合） → V2 实现
- ❌ 临时权限（时间限制） → V2 实现

### 2.4 四层权限模型与生命周期语义（2026-10-31）

共用身份模型见 [服务与领域边界 §3.5](../../../04-技术架构/服务与领域边界.md#35-auth统一身份与安全边界fr-008009010)。本节结论来自冻结决策与当前代码；生命周期补充规则由 [D086](../../../06-决策记录/V1-冻结决策.md#d086-模块权限生命周期更新时撤销不再声明的授权启用全局授权按用户未知权限拒绝整个包) 冻结（2026-10-31）。§3～§9 的旧草案与本节冲突时以本节为准。

#### 2.4.1 四层模型（已确认）

一次模块能力调用必须逐层通过，任一层失败即拒绝（fail-closed）；层与层之间互不替代、互不隐含。

| 层 | 内容 | 作用域 | 检查时机 | 失败 | 依据与代码 |
| --- | --- | --- | --- | --- | --- |
| 1 准入（pin/admission） | 包的 `(module_id, version, integrity)` 在编译进宿主的 `BUILTIN_PINS` 中；`v2:` 摘要覆盖 manifest 与全部文件 | 宿主构建，全局 | 预检、start、更新 commit 之前 | `1004021` | D041、D047、D052、D057；`crates/dgos-modules/src/admission.rs` |
| 2 manifest 上限 | 当前已发布 manifest 声明的、属于 D006 六个规范值的权限集合 | 每个已发布版本，全局 | 授予时与每次调用时 | 授予与调用都为 `1004004` | D024、D029；`manifest_requests_permission` |
| 3 用户授权 | `module_permissions` 中该用户逐项授予且未撤销的行 | 每用户 × 模块 × 权限 | 每次调用前重新读库，不缓存 | `1004004`，写 `denied` 审计 | D026、D048、D050；`ModulePermissionRepository::check` |
| 4 runtime 状态 | 模块 `is_enabled`；runtime 为 `ready` 且句柄未被取代；路由与附着有效；`call_id` 未重复；在途 ≤ 8；总期限 120 秒 | 每个 runtime | 调用通道准入时 | `1004004`；超限 `1001005`；超时 `1001006` | D034、D051、D054、D055；`ModuleCallRouter::admit_once` |

有效能力 = 已准入 ∩ manifest 声明 ∩ 当前用户已授予 ∩ runtime 可受理。授权不构成准入（D041），准入不授予权限（D052），启用不授予权限（D055），LAN 会话不继承也不授予模块权限（服务与领域边界 §3.5.3）。

#### 2.4.2 生命周期语义（已确认）

| 操作 | 语义 | 依据 |
| --- | --- | --- |
| 供给（“安装”） | 随包模块经启动复核后发布，首次写入为 `is_official = true`、`is_enabled = false`，不授予任何权限；V1 没有从路径或 URL 安装 | D052、D055、D058 |
| 启用 | 只改全局启用标志，不启动 runtime、不授予权限；授予要求模块已启用。多用户下启用保持全局、授权按用户：其他用户看到已启用，但在各自授予前调用被拒绝；用户切换时停止全部 runtime，再以新用户会话重新自动加载已启用模块 | D055、D086；接口契约 §8.6 |
| 启用 + 授予的部分失败 | 管理页“确认启用”依次 `enable_module` → 逐项 `grant_module_permission`（每项独立事务，全部尝试）→ 全部成功才 `start_module`。任一授予失败：已成功的步骤保留、不回滚，不启动；页面列出未授予的权限与错误码，可逐项重试后用“重新加载”启动。未授予的能力仍按第 3 层拒绝 | D093 第 1 项 |
| 禁用 / 卸载 | 先停止 runtime 再改状态。卸载删除授权、模块存储、版本行、模块行与文件，保留更新历史与权限审计；随包模块只能禁用（`1004023`） | D055、D093 |
| 授予 | 入参只有 `module_id` 与 D006 字符串；宿主重新读取当前 manifest，未声明则拒绝并写 `denied` 审计；重复授予幂等 | D029、D055 |
| 撤权 | 下一次调用前生效，不取消在途调用；已派发的外部请求按原快照与未知结果语义结算，不伪报已撤销 | D026、D050 |
| 更新 | 目标版本必须有 pin；仍声明的权限沿用原授权；新增的权限没有授权，须用户另行授予；不再声明的权限在更新 commit 的同一事务中把所有用户的授权行标为撤销，并写 `revoked` 审计，以后的版本重新声明时须再次授予。激活失败回滚到旧版本时，按恢复后的 manifest 同样撤销。管理页在更新后比对前后的声明：列出新增（未授予，可直接授予）与被撤销的权限；结果为 `updated` 与 `updated_pending_release` 时都比对，后者只改变提示文案 | D029、D033、D052、D086、D093 第 9 项；`ModulePermissionRepository::revoke_undeclared_in` |
| 未知权限 | manifest 含非 D006 值时，暂存即失败，整个包无效（`1004015`）；授予命令收到未知字符串按拒绝处理（`1004004`）；旧名称（`provider_access` 等）不接受。§5.2 “忽略，安装成功”一行按本条理解为拒绝，AC 原文不改 | D024、D029、D086；`crates/dgos-modules/src/lib.rs`、`module_management.rs` |
| 能力接入范围 | 六项都有类型化调用命令：`providers.call`（D051）与 D093 的 `storage.read`/`storage.write`（每用户 × 每模块键值存储）、`network.local`（只回环 HTTP(S)）、`mcp.call`（每次由用户在宿主确认框批准）、`skills.execute`（只返回已安装技能的固定版本内容）。每次调用都按四层顺序检查；期限与限额见接口契约 §8.5。模块调用与 MCP 确认框都跨 SPA 路由工作：确认提交经 `main` 窗口与可信来源门禁，用户由宿主派生，只接受宿主签发且属于该用户的 confirmation ID（D093；同 realm 脚本可调用，D050 残余风险，不是隔离） | D048、D051、D093；接口契约 §8.5 |
| 权限审计 | 写入 `granted`、`revoked`、`denied`；只经 `list_module_permission_audits` 读取当前用户的行，新到旧分页；每用户保留最近 10000 条，宿主没有修改或删除单行的入口；删除账户时删除（D087），卸载时保留（D055） | D048、D093 第 2、3 项 |

`network.local` 是模块访问本地网络的能力，与 FR-010 局域网服务及其远程会话无关。

## 3. 核心流程

> 历史草案流程，保留用于追溯 AC 的来源。现行语义以 §2.4 为准：安装即“启用并确认权限”（D055），调用经类型化通道而非 `call_provider`（D051），授予与撤销经 §8.6 管理命令，权限不缓存。

### 3.1 模块安装时权限申请流程

```
用户安装模块（AI 工作台）
  ↓
系统读取 manifest.json：
  "permissions": {
    "providers.call": true,
    "skills.execute": true,
    "storage.read": true
  }
  ↓
显示权限确认对话框：
  "AI 工作台请求以下权限：
   - 访问 Provider（调用 AI 模型）
   - 访问 Skills（使用工具）
   - 读取文件
   
   是否授予这些权限？"
  ↓
用户点击"授予"
  ↓
保存权限到数据库：
  INSERT INTO module_permissions (module_id, permission, granted)
  VALUES ('ai-workbench', 'providers.call', TRUE)
  ↓
模块安装成功
```

### 3.2 运行时权限检查流程

```
AI 工作台调用 Provider
  ↓
前端调用：invoke('call_provider', { providerId, ... })
  ↓
Tauri Command 接收请求
  ↓
权限拦截器介入
  ↓
提取 module_id（从调用上下文）
  ↓
查询数据库：
  SELECT granted FROM module_permissions
  WHERE module_id = 'ai-workbench'
    AND permission = 'providers.call'
  ↓
（如果 granted = TRUE）放行，继续调用
  ↓
（如果 granted = FALSE 或不存在）拒绝
  ↓
记录权限拒绝日志
  ↓
返回错误：PermissionDenied
  ↓
前端显示："AI 工作台无权访问 Provider"
```

### 3.3 用户撤销权限流程

```
用户打开系统设置
  ↓
点击"模块"标签
  ↓
选择"AI 工作台"
  ↓
查看模块详情
  ↓
显示权限列表：
  ✓ 访问 Provider
  ✓ 访问 Skills
  ✓ 读取文件
  ↓
用户点击"撤销 Provider 访问"
  ↓
确认提示："撤销后，模块将无法调用 AI 模型"
  ↓
用户确认
  ↓
更新数据库：
  UPDATE module_permissions
  SET granted = FALSE
  WHERE module_id = 'ai-workbench'
    AND permission = 'providers.call'
  ↓
记录权限撤销日志
  ↓
显示"权限已撤销"
  ↓
（下次模块调用 Provider 时会被拒绝）
```

### 3.4 模块更新时权限变更流程

```
模块有新版本
  ↓
用户点击"更新"
  ↓
系统读取新版本 manifest.json
  ↓
对比权限变更：
  旧版本：providers.call, skills.execute
  新版本：providers.call, skills.execute, storage.write (新增)
  ↓
显示权限变更提示：
  "新版本请求额外权限：
   - 写入文件
   
   是否授予并更新？"
  ↓
用户确认
  ↓
保存新权限到数据库
  ↓
更新模块
```

## 4. 数据模型

### 4.1 涉及的数据表

**历史草案（物理结构以 migration 为准）**。现行结构见 [V1 数据模型](../../../04-技术架构/当前版本/V1-数据模型.md)：

```sql
CREATE TABLE module_permissions (
    id TEXT PRIMARY KEY,
    module_id TEXT NOT NULL,          -- 模块标识
    permission TEXT NOT NULL,         -- 权限类型
    resource_id TEXT,                 -- 资源 ID（V1 为空，V2 使用）
    granted BOOLEAN DEFAULT FALSE,    -- 是否授予
    granted_at TIMESTAMP,             -- 授予时间
    granted_by TEXT,                  -- 授予人（user_id）
    revoked_at TIMESTAMP,             -- 撤销时间（如果撤销）
    user_id TEXT,                     -- 所属用户
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    UNIQUE(module_id, permission, user_id)
);

CREATE INDEX idx_permissions_module ON module_permissions(module_id, permission);
```

**历史草案（物理结构以 migration 为准）**：当前审计表为 `module_permission_audits`，见 [V1 数据模型](../../../04-技术架构/当前版本/V1-数据模型.md)。

```sql
CREATE TABLE permission_logs (
    id TEXT PRIMARY KEY,
    module_id TEXT NOT NULL,
    permission TEXT NOT NULL,
    action TEXT NOT NULL,             -- 动作：granted, revoked, denied
    resource_id TEXT,                 -- 尝试访问的资源 ID（如 provider_id）
    user_id TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE INDEX idx_permission_logs_module ON permission_logs(module_id);
CREATE INDEX idx_permission_logs_time ON permission_logs(created_at);
```

### 4.2 读写关系

> 历史草案语句。现行读写见 `ModulePermissionRepository`：授予、撤销各在一个事务内更新授权行并写审计；调用检查只在拒绝时写 `denied` 审计（D048）；审计没有读取入口（§2.4.4）。

**读操作**：
- 检查权限：`SELECT granted FROM module_permissions WHERE module_id = ? AND permission = ? AND user_id = ?`
- 查询模块权限：`SELECT * FROM module_permissions WHERE module_id = ? AND user_id = ?`
- 查询权限日志：`SELECT * FROM permission_logs WHERE module_id = ? ORDER BY created_at DESC`

**写操作**：
- 授予权限：`INSERT INTO module_permissions ... ON CONFLICT UPDATE SET granted = TRUE, granted_at = ?`
- 撤销权限：`UPDATE module_permissions SET granted = FALSE, revoked_at = ? WHERE ...`
- 记录日志：`INSERT INTO module_permission_audits (module_id, permission, action, ...) VALUES (...)`

### 7.1 权限检查服务

```rust
// 历史草案（物理结构以 migration 为准；不创建 crate）：crates/dgos-permissions/src/service.rs

pub struct PermissionService {
    db: DatabasePool,
}

impl PermissionService {
    // B09-01: 检查权限
    pub async fn check_permission(
        &self,
        module_id: &str,
        permission_type: PermissionType,
        user_id: &str
    ) -> Result<bool> {
        // B09-02: 查询数据库
        let permission = self.db
            .get_permission(module_id, &permission_type.to_string(), user_id)
            .await?;
        
        // B09-03: 判断是否授予
        let granted = permission
            .map(|p| p.granted)
            .unwrap_or(false);
        
        if !granted {
            // B09-04: 记录拒绝日志
            self.log_permission(
                module_id,
                permission_type,
                PermissionAction::Denied,
                None,
                user_id
            ).await?;
        }
        
        Ok(granted)
    }
    
    // B09-05: 授予权限
    pub async fn grant_permission(
        &self,
        module_id: &str,
        permission_type: PermissionType,
        user_id: &str
    ) -> Result<()> {
        // B09-06: 插入或更新
        self.db.upsert_permission(
            module_id,
            &permission_type.to_string(),
            true,
            user_id
        ).await?;
        
        // B09-07: 记录授予日志
        self.log_permission(
            module_id,
            permission_type,
            PermissionAction::Granted,
            None,
            user_id
        ).await?;
        
        Ok(())
    }
    
    // B09-08: 撤销权限
    pub async fn revoke_permission(
        &self,
        module_id: &str,
        permission_type: PermissionType,
        user_id: &str
    ) -> Result<()> {
        // B09-09: 更新为不授予
        self.db.update_permission_granted(
            module_id,
            &permission_type.to_string(),
            false,
            user_id
        ).await?;
        
        // B09-10: 记录撤销日志
        self.log_permission(
            module_id,
            permission_type,
            PermissionAction::Revoked,
            None,
            user_id
        ).await?;
        
        Ok(())
    }
    
    // B09-11: 记录权限日志
    async fn log_permission(
        &self,
        module_id: &str,
        permission_type: PermissionType,
        action: PermissionAction,
        resource_id: Option<&str>,
        user_id: &str
    ) -> Result<()> {
        let log = PermissionLog {
            id: Uuid::new_v4().to_string(),
            module_id: module_id.to_string(),
            permission_type,
            action,
            resource_id: resource_id.map(|s| s.to_string()),
            created_at: Utc::now().to_rfc3339(),
        };
        
        self.db.insert_permission_log(&log, user_id).await?;
        
        Ok(())
    }
}
```

## 9. 非功能需求

### 9.1 安全需求

| 需求 | 实现方式 |
| --- | --- |
| 权限最小化 | 模块只申请必要权限 |
| 用户知情 | 安装时明确显示权限 |
| 可撤销 | 用户随时撤销权限 |
| 审计日志 | 授予、撤销、拒绝写入 `module_permission_audits`；允许的调用不写（D048） |
| 拒绝默认 | 未授予的权限默认拒绝 |

### 9.2 性能需求

> 下列性能目标只作参考，不作为验收门槛；授权结果不缓存，每次调用前读库（§2.4.3，D093 第 10 项）。

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 权限检查时间 | < 10ms | 单元测试 |
| 并发检查 | > 1000 QPS | 压力测试 |
| 日志查询 | < 500ms（1000 条） | 性能测试 |

### 9.3 可审计性需求

| 需求 | 实现方式 |
| --- | --- |
| 所有授予操作记录 | 写入 `module_permission_audits`（`granted`） |
| 所有撤销操作记录 | 写入 `module_permission_audits`（`revoked`） |
| 所有拒绝操作记录 | 写入 `module_permission_audits`（`denied`） |
| 日志不可篡改 | 宿主没有修改或删除单行的入口；只由保留规则（每用户最近 10000 条）和删除账户清理，见 §2.4.3 |
