## 风险与对策

| 风险 | 严重程度 | 对策 | 关联决策 |
| --- | --- | --- | --- |
| renderer 选择或伪造用户 | 高 | 命令不收 `user_id`、会话令牌或账户 ID；身份只来自宿主解析器；`contracts:check` 精确白名单 | D023、D025 |
| 用户切换后旧用户的能力继续服务 | 高 | 切换前停止全部模块 runtime、取消并等待在途工作、撤销远程会话；切换中所有命令返回 `1008007` | D086、D087、D088 |
| 删除账户漏表 | 高 | 清理清单由 schema 测试校验：库中每个含 `user_id` 列的表都必须登记一个清理入口，否则测试失败 | D087 |
| vault 项删除失败被报告为成功 | 高 | 先把 `credential_ref` 写入持久 outbox，再删行；结果带 `credential_cleanup_pending` | D023、D087 |
| 删除中途崩溃 | 中 | 持久删除标记；启动恢复继续；标记存在时账户不可登录，`default-user` 不被新账户占用 | D087 |
| 口令被暴力猜测 | 中 | Argon2id；每账户持久失败计数与指数退避；口令只在清零类型里，不进日志 | D087 |
| 口令或哈希泄露到日志、DTO、错误 | 高 | 输入结构自定义 `Debug`；DTO 不含哈希；错误为固定文本 | D023 |
| 同 realm 脚本调用账户命令（D042） | 中 | 删除、改密需要口令；登录页（`signed_out`）不能新建账户；首次引导前没有门禁是 D087 接受的状态 | D042、D087 |

## 物理模型（新增 migration）

```sql
-- users：首个账户 id = 'default-user'（D087）
CREATE TABLE users (
  id TEXT PRIMARY KEY NOT NULL,
  username TEXT NOT NULL,
  username_key TEXT NOT NULL UNIQUE,      -- Unicode 简单小写，用于唯一性与查找
  password_hash TEXT NOT NULL,            -- Argon2id PHC 串
  failed_attempts INTEGER NOT NULL DEFAULT 0,
  locked_until BIGINT,                    -- Unix 秒；退避截止
  last_sign_in_at BIGINT,
  deleting_since BIGINT,                  -- 非空即删除进行中（持久删除标记）
  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL
);

-- 宿主级设置：不属于任何用户（D087）
CREATE TABLE host_settings (
  setting_key TEXT PRIMARY KEY NOT NULL,  -- 如 'last_sign_in_user'、'lan.enabled'、'lan.port'
  setting_value TEXT NOT NULL,
  updated_at BIGINT NOT NULL
);

-- MCP 凭据清理 outbox（与 provider_credential_cleanup 同形）
CREATE TABLE mcp_credential_cleanup (
  credential_ref TEXT PRIMARY KEY NOT NULL,
  user_id TEXT NOT NULL, server_id TEXT NOT NULL, endpoint TEXT NOT NULL
);
```

不加指向 `users` 的外键：已执行的 migration 不改，现有表的 `user_id` 没有外键（D023、D065、D072）。

**用户作用域表（2026-11-01 按 migrations 核对，含 `user_id` 列）**：`providers`、`usage_logs`（遗留）、`provider_usage_logs`、`provider_credential_cleanup`、`skills`（遗留）、`skill_usage_logs`、`skill_user_states`、`mcp_servers`、`mcp_usage_logs`、`mcp_connection_logs`、`workbench_tasks`、`chat_sessions`、`chat_messages`、`module_permissions`、`module_permission_audits`、`module_storage`、`module_crash_logs`、`system_settings`，以及新增的 `mcp_credential_cleanup`。两个凭据 outbox（`provider_credential_cleanup`、`mcp_credential_cleanup`）不随账户删除：条目留到 vault 项删除成功才移除（`RETAINED_FOR_VAULT_RETRY`）。经父行删除的子表：`models`（`providers` 外键级联）、`mcp_server_tools`、`workbench_task_skills`、`workbench_task_tools`（按父 ID 删除）。全局、不随用户删除：`modules`、`module_versions`、`module_update_events`、`module_release_locks`、`skill_catalog`、`skill_versions`、`host_settings`（只清 `last_sign_in_user` 指向该用户的值）。

归属：`UserRepository` 与三张新表的 migration 在 `dgos-db`；`AccountService`、`UserPurge` 端口与各领域的清理实现登记在 `dgos-application`（D030：跨入口用例编排）；`SessionResolver`、`host::account_window` 与 `commands/accounts.rs` 在 `src-tauri`。不新建 `dgos-auth` crate。

| 函数 | 前置条件 | 返回 / 后置条件 | 副作用 | 幂等 |
| --- | --- | --- | --- | --- |
| `SessionResolver::current() -> Resolved` | 无 | `NoAccounts`（`default-user`）/ `SignedIn(user_id)` / `Unavailable` | 无；读锁只拷贝 user_id | 是 |

| `AccountService::sign_in(input) -> AccountState` | 模式为 `SignedOut` 或 `SignedIn` | 口令通过则为该用户会话 | 写失败计数、退避、`last_sign_in_at`；可能重算哈希；切换会话 | 同一账户已登录时为是 |

| `AccountService::delete(input) -> DeleteAccountResult` | `SignedIn` | 用户行与全部作用域数据已删 | 删除标记、outbox、各领域删除、vault | 中断后由恢复继续：是 |
| `AccountService::recover() ` | 启动时、命令开放前 | 所有 `deleting_since` 非空的账户完成删除 | 同 `delete` 的删除阶段 | 是 |
| `UserPurge::purge(user_id)`（各领域实现） | 该用户没有在途工作 | 本领域该用户的行全部删除 | 删除行；必要时写 outbox | 是 |

## 伪代码

账户操作全部在 `AccountService` 内由一把 `tokio::sync::Mutex` 串行；Argon2id 计算在 `spawn_blocking`。错误键对应接口契约 §9.3。

```text
FUNCTION resolve() -> Resolved:                                  // 每个命令入口
  state = RESOLVER.read()
  IF state == NoAccounts: RETURN Session("default-user")          // B08-19
  IF state == SignedIn(u): RETURN Session(u)                       // B08-20
  RETURN Err(session_invalid 1008007)                              // B08-21 signed_out / 切换中 / 删除中

FUNCTION create_account(input) -> AccountState:
  LOCK accounts
  IF mode NOT IN {NoAccounts, SignedIn}: RETURN Err(1008007)       // B08-22
  IF NOT valid_username(input.username): RETURN Err(1008003)       // B08-23
  IF NOT valid_password(input.password): RETURN Err(1008002)       // B08-24
  hash = spawn_blocking(argon2id_hash(input.password))             // B08-25
  id = mode == NoAccounts AND no row 'default-user' ? 'default-user' : uuid()   // B08-26
  BEGIN TRANSACTION
    INSERT users(id, username, username_key = lower(username), hash, ...)
      ON UNIQUE(username_key) CONFLICT: ROLLBACK; RETURN Err(1008001)          // B08-27
  COMMIT
  IF mode == NoAccounts: switch_to(SignedIn(id)); record_last(id)  // B08-28 首个账户自动登录
  RETURN state()

FUNCTION sign_in(input) -> AccountState:
  LOCK accounts
  IF mode == NoAccounts: RETURN Err(1008007)                       // B08-29
  row = SELECT users WHERE username_key = lower(input.username) AND deleting_since IS NULL
  IF row IS NONE:
    spawn_blocking(argon2id_verify(input.password, DUMMY_HASH))    // B08-30 不泄露是否存在，不计数
    RETURN Err(1008005)
  verify_with_throttle(row, input.password)?                        // B08-31～34
  IF mode == SignedIn(row.id): RETURN state()                      // B08-35 幂等
  IF mode == SignedIn(other): end_session()                        // B08-36 口令通过后才结束旧会话
  maybe_rehash(row, input.password)                                 // B08-37 参数升级
  UPDATE users SET last_sign_in_at = now WHERE id = row.id
  switch_to(SignedIn(row.id)); record_last(row.id)                  // B08-38
  RETURN state()

FUNCTION verify_with_throttle(row, password) -> Result:
  IF row.locked_until > now: RETURN Err(1008011, retry_after = row.locked_until - now)   // B08-31
  ok = spawn_blocking(argon2id_verify(password, row.password_hash))
  IF NOT ok:
    failed = row.failed_attempts + 1
    locked_until = failed >= 5 ? now + min(30 * 2^(failed - 5), 900) : NULL
    UPDATE users SET failed_attempts = failed, locked_until = locked_until            // B08-32 持久计数
    RETURN Err(1008005)                                                               // B08-33
  UPDATE users SET failed_attempts = 0, locked_until = NULL                           // B08-34
  RETURN Ok

FUNCTION end_session():                                             // 接口契约 §9.4
  RESOLVER.set(Switching)                                           // B08-39 之后所有命令 1008007
  modules.stop_all_and_wait()                                       // B08-40 D086
  chat.cancel_user(u); workbench.cancel_user(u); provider_streams.cancel_user(u)
  mcp.cancel_pending_confirmations(u); mcp.disconnect_user(u)       // B08-41 取消并等待
  lan.revoke_sessions_issued_by(u)                                  // B08-42 D088；FR-010 前为空操作
  RESOLVER.set(has_accounts ? SignedOut : NoAccounts)               // B08-43

FUNCTION change_password(input) -> AccountState:
  LOCK accounts
  IF mode != SignedIn(u): RETURN Err(1008007)
  verify_with_throttle(row(u), input.current_password)?             // B08-44
  IF NOT valid_password(input.new_password): RETURN Err(1008002)
  UPDATE users SET password_hash = spawn_blocking(argon2id_hash(new)), updated_at = now   // B08-45
  end_session()                                                     // B08-46 改密后重新登录
  RETURN state()

FUNCTION delete_account(input) -> DeleteAccountResult:
  LOCK accounts
  IF mode != SignedIn(u): RETURN Err(1008007)
  verify_with_throttle(row(u), input.password)?                     // B08-47
  BEGIN TRANSACTION
    UPDATE users SET deleting_since = now WHERE id = u              // B08-48 持久删除标记
    INSERT provider_credential_cleanup FROM providers WHERE user_id = u AND credential_ref IS NOT NULL
    INSERT mcp_credential_cleanup FROM mcp_servers WHERE user_id = u AND credential_ref IS NOT NULL   // B08-49 先入 outbox
  COMMIT
  end_session()
  RESOLVER.set(Deleting)                                            // 删除期间仍拒绝所有命令
  RETURN finish_delete(u)

FUNCTION finish_delete(u) -> DeleteAccountResult:                   // delete 与 recover 共用
  FOR purge IN USER_PURGES:                                         // 顺序：聊天→单任务→MCP→Provider→技能→模块授权、审计、存储与崩溃→设置
    purge.purge(u)?  ON ERROR: RETURN Err(1008009)                  // B08-50 标记保留，启动恢复继续
  DELETE host_settings WHERE key = 'last_sign_in_user' AND value = u
  DELETE users WHERE id = u                                         // B08-51
  pending = drain_credential_outboxes(u)                            // B08-52 vault 删除；失败留在 outbox
  RESOLVER.set(any users ? SignedOut : NoAccounts)                  // B08-53 删除最后一个账户 → 首次引导
  RETURN { state(), credential_cleanup_pending: pending > 0 }

FUNCTION recover():                                                 // 启动，命令开放前
  FOR u IN SELECT id FROM users WHERE deleting_since IS NOT NULL:
    finish_delete(u)                                                // B08-54
  drain_credential_outboxes(all)                                    // B08-55 取代 recover_credentials(LOCAL_USER)
  RESOLVER.set(any users ? SignedOut : NoAccounts)                  // B08-56 重启后重新登录
```

## 并发控制

| 场景 | 冲突点 | 控制方式 | 失败策略 |
| --- | --- | --- | --- |
| 两个账户操作并发（如双击登录、删除时登录） | 解析器状态、`users` 行 | `AccountService` 一把 `tokio::sync::Mutex`；Argon2id 在锁内的 `spawn_blocking` | 后到者等待；不排队重试 |
| 命令执行中发生切换 | 命令已取得的 `user_id` | 命令入口只在读锁内拷贝 `user_id`，不持锁执行；切换前取消并等待在途工作（B08-40～41） | 切换中新命令返回 `1008007` |
| 删除时有短命令已取得旧 `user_id` | 删除后又写入一行 | 删除期间解析器为 `Deleting`；各领域 purge 幂等 | 已知限制：极短窗口内的单行写入可能残留，启动时扫描无主行并告警（不自动删） |
| 同用户名并发创建 | `username_key` | 唯一约束 | `1008001` |

死锁预防：账户操作锁总是最先获取；结束会话时只调用各领域的取消与等待接口，不在账户锁内等待其他账户锁。

## 事务边界

- 创建：单条 `INSERT users`；唯一约束失败整体回滚。
- 登录失败计数、成功清零、`last_sign_in_at`：各自单条 `UPDATE`。
- 删除：事务一写删除标记与两个 outbox；之后的各领域 purge 是各自的事务（领域仓库各自持有事务，例如 `ChatRepository::purge_user`），因此整体不是一个事务，靠持久删除标记与 purge 幂等保证可恢复。
- 隔离级别：SQLite 默认（串行写），理由：单进程（D077 实例锁）且账户操作已串行。

## 幂等与重试

- 登录同一已登录账户：直接返回当前状态（B08-35）。
- `sign_out` 在非 `signed_in` 模式：返回当前状态。
- 删除：标记写入后的每一步都幂等；中断后由 `recover()` 重做，不会二次删除已删的行、不会重复删除 vault 项（outbox 按 `credential_ref` 主键）。
- 不提供客户端幂等键：账户操作串行且结果可由 `get_account_state` 查询。

## 外部调用与补偿

外部依赖只有 OS vault（Provider、MCP 凭据）。vault 删除在数据库事务之外执行；失败的项留在持久 outbox，启动时与之后的凭据操作重试（D023）。删除结果的 `credential_cleanup_pending` 如实反映是否还有未删的 vault 项。

## 安全与日志

- 口令：输入结构字段为清零类型，自定义 `Debug` 输出 `***`；不写日志、错误、审计或 panic 消息；哈希只在 `users` 表，不进任何 DTO。
- Argon2id 参数（D090）：m = 19 MiB、t = 2、p = 1（OWASP 推荐的最低档），参数随 PHC 串保存；登录成功时若参数低于当前值则重算（B08-37）。依赖为 RustCrypto `argon2`，引入时登记到工程依赖。
- 未知用户名：仍对固定的哑哈希做一次验证，避免以响应时间区分用户名是否存在。
- 日志只记账户操作的结果类别与内部 `user_id` 的短哈希，不记用户名、口令、`credential_ref`。
- 权限校验：命令入口 `host::account_window`（窗口与来源）→ 账户模式检查 → 口令（改密、删除、登录）。

## 发布与回滚

- 前置条件：新增 migration（`users`、`host_settings`、`mcp_credential_cleanup`）；`argon2` 依赖；`contracts:check` 规则（接口契约 §9.5）。
- 升级：现有数据库没有 `users` 行，启动为 `no_accounts`，行为与当前一致（`default-user`，无门禁）。
- 回滚：降级到不含本功能的版本时，旧版本忽略新表并继续以 `default-user` 运行；首个账户的数据仍在 `default-user` 下，其他账户的数据旧版本看不到但不丢失。已执行的 migration 不回退。
- 监控：启动日志记录删除恢复数、outbox 残留数、无主行数。

## 已决取舍（D090）

接口契约 §9.6 的六项与下列五项由 [D090](../../../06-决策记录/V1-冻结决策.md#d090-fr-008-账户命令契约与实现取舍独立账户入口未登录-1008007退避-1008011可恢复删除与-mcp-凭据-outbox) 冻结（2026-11-01，用户逐项确认）：

| 取舍 | 内容 |
| --- | --- |
| 删除不是单一事务 | 标记 + 逐领域幂等 purge + 启动恢复；理由是领域仓库各自持有事务，强行合并需要跨 crate 共享连接 |
| 短窗口残留 | 删除期间仍可能有已取得旧 `user_id` 的短命令写入一行，只扫描告警、不自动删除 |
| MCP 凭据 outbox | 新增 `mcp_credential_cleanup`，修改 `delete_server` 的失败处理（此前只记告警） |
| 切换时断开 MCP 连接 | 结束会话时断开该用户的全部 MCP 连接，新用户需重新连接 |
| Argon2id 参数 | m = 19 MiB、t = 2、p = 1 |

## 实现与偏差（2026-11-01）

实现状态与验证证据只在 [V1 实现状态](../../../02-产品与版本/当前版本/V1-实现状态.md)“FR-008 实现验收证据”一节维护。本节只记录实现与上文设计的差别；契约（接口契约 §9.2～§9.4）没有偏差。

| 设计 | 实际 | 原因 |
| --- | --- | --- |
| `SessionResolver` 在 `host.rs` | 在 `src-tauri/src/session.rs`；`host.rs` 的 `context`、`module_session`、`module_confirmation_session` 经私有 `resolved_session` 读取，取不到托管的解析器时也返回 `1008007`（失败即关闭） | 解析器还要实现 `dgos-application` 的 `SessionPort`，单独成文件；`host.rs` 只保留门禁 |
| `HostSession` 增加 crate 内受控构造 | `HostSession::for_user` 为公开函数；`local_default()` 保留作测试夹具。`contracts:check` 禁止宿主与 `dgos-application` 生产代码调用 `local_default()`，并要求 `context` 经解析器取用户；`host::LOCAL_USER` 只在 `cfg(any(test, feature = "webview-smoke"))` 下存在 | 跨 crate 无法用可见性限制调用方，改用静态检查 |
| 结束会话的取消接口 | `SessionPort::release`（`HostSessionPort`）按序：MCP 监视器作用域设为无人 → `ModuleOperationManager::stop_all`（等待每个停止完成，supervisor 的 30 秒排空）→ `ChatManager::cancel_user`（等待终态事务）→ `WorkbenchManager::cancel_user` → `ProviderStreams::cancel_owner("main")` → `ModuleMcpConfirmations::cancel_user` → `McpManager::disconnect_user`（取消在途调用、撤销待确认、关闭连接；不写“手动断开”标记）。然后 `RemoteSessionRevoker::revoke_issued_by`（FR-010 前为 `NoRemoteSessions` 空操作） | Provider 流按窗口登记而非按用户；桌面只有 `main` 一个窗口，属于正在结束的会话 |
| MCP 自动连接 | 新增 `McpManager::set_connection_scope`（`AllUsers`/`User`/`Nobody`）。`no_accounts` 为全部、`signed_in` 只连该用户、其余状态不连；`DesktopMcpPolicy` 改为与解析器当前用户比较 | 原监视器会连接所有用户的已启用服务器，多用户下会为未登录用户建立后台连接 |
| MCP outbox 只改 `delete_server` | `delete_server`、`update_server`（改端点）、`set_bearer_token`（换 token）都在与行更新同一事务中写 `mcp_credential_cleanup`，删除成功才确认；新增 `McpManager::drain_credential_cleanup` | 三处原本都是“删除失败只记告警” |
| `UserPurge` 各领域实现 | `UserPurge` 端口在 `dgos-application`；清单与 SQL 集中在 `dgos-db` 的 `UserDataDomain`（chat 复用 `ChatRepository::purge_user`）。schema 测试比较 `sqlite_master` 中含 `user_id` 的表与清单 | 一份清单同时供删除与 schema 测试使用，避免两处漂移 |
| 启动 `enforce_on_startup` | 账户恢复之后，对每个账户 id（无账户时为 `default-user`）各执行一次；`ensure_disabled` 改用该用户的会话 | 模块启用是全局的，任一账户的崩溃记录都应计入；原代码固定为 `default-user` |
| 附着后启动模块 | `attach_module_host` 只在解析器有会话（`signed_in`、`no_accounts`）时 `start_enabled`；页面在每次账户操作后整页重载并重新附着 | - |
| Provider 凭据恢复 | `recover_credentials` 对每个账户 id 执行（旧明文 key 迁移与 outbox 重试）；新增 `ProviderManager::drain_credential_cleanup` 返回剩余数 | 取代 `recover_credentials(LOCAL_USER)` |
| 未知用户名 | 先查 `username_key`（含删除中账户时不可见），未命中则对固定哑哈希做一次 Argon2id 验证；哑哈希在 `recover()` 时预先计算 | 首个未知用户名不应比后续慢 |
| 删除中途失败 | 解析器回到 `signed_out`（存在删除中账户时不进入 `no_accounts`），删除中账户不出现在列表中、不能登录，下次启动继续 | 与 D087“完成前不可登录、`default-user` 不被新账户占用”一致 |
| 前端 | 账户页为独立路由 `/account` 与导航栏 `AccountMenu`，不在 Settings 外壳内；`AccountGate` 包住 `App`（`src/main.tsx`）。所有账户操作成功后整页重载 | Settings 外壳（FR-007）正由其他工作修改，未加入新标签；账户命令门禁不看路由，放在哪个路由不影响安全 |
| 无主行 | `UserDataRepository::orphan_count` 在启动恢复时计数并告警，不删除 | D090 |

未实现（不属于本设计）：“保持登录”、找回密码、管理员接口；FR-010 远程会话撤销（端口已定义为空操作）。
