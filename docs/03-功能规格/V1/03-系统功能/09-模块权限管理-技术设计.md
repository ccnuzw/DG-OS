## 风险与对策

| 风险 | 严重程度 | 对策 | 关联决策 |
| --- | --- | --- | --- |
| 渲染进程伪造用户或模块身份 | 高 | 身份与调用者上下文由宿主派生，权限检查在 Host Capability API 内部逐次执行（D023/D026） | D023、D026 |
| 权限名新旧并存导致授权漂移 | 中 | 以 D006 规范值为准，旧名只用于追溯（见主规格映射表） | D006、D024 |
| 未声明或已撤销的能力被调用 | 高 | 未声明的能力在 grant 与实际 dispatch 两处 fail-closed；`ModulePermissionRepository` 只负责授权、撤销与脱敏审计 | D029 |
| 拒绝与授予无审计 | 中 | `module_permission_audits` 表记录授予、撤销与调用拒绝的脱敏审计（migration m20261028_000009）；只经 `list_module_permission_audits` 读取当前用户的行，新到旧游标分页，每用户保留最近 10000 条（D093 第 2、3 项） | D029、D048、D093 |
| 部分启用：启用成功而授予失败 | 中 | 已成功的步骤保留、不回滚、不启动；未授予的能力仍按第 3 层拒绝，不扩大权限；页面列出未授予项供逐项重试（D093 第 1 项） | D055、D093 |
