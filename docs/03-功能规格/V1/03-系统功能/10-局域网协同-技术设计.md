## 风险与对策

| 风险 | 严重程度 | 对策 | 关联决策 |
| --- | --- | --- | --- |
| 服务暴露到公网或非预期接口 | 高 | 只绑定一个私网 IPv4 接口地址，不监听 `0.0.0.0`、回环与 IPv6；对端再做私网校验 | D088 |
| DNS 重绑定、跨站请求伪造、跨站 WebSocket 劫持 | 高 | `Host` 必须等于绑定的 `IP:端口`；改变状态的请求与 WebSocket 升级要求同源 `Origin`；不返回任何 CORS 头；Cookie `SameSite=Strict` | D088 |
| 访问凭据被猜中或重放 | 高 | 128 位随机、单次有效、10 分钟过期、累计失败 10 次作废；配对限速；内存只存哈希 | D088、D099 |
| 会话令牌泄露（无 TLS，同网段嗅探） | 中 | 已知残余风险（D088）。缓解：`HttpOnly` Cookie、不进 JS 存储、会话绑定来源 IP、闲置 30 分钟 / 最长 12 小时、主机可随时断开 | D088 |
| 远程借会话越权到配置、账户、模块、文件、MCP | 高 | 路由逐项白名单；白名单外 404；LAN handler 只调用聊天与只读目标列表的 Application Service；不映射 Tauri command | D039、D088 |
| 用户切换后旧用户的远程会话继续服务 | 高 | 每个请求核对解析器当前用户与绑定用户；FR-008 结束会话第 4 步调用 `revoke_issued_by`；签发者结束会话时作废其未使用凭据 | D088、D090、D099 |
| 撤销与在途请求竞争，撤销后仍启动新生成 | 高 | 每会话读写锁：请求持读锁直到生成登记完成；撤销取写锁后再取消该会话窗口的全部生成 | D099 |
| 远程看到主机用户的全部聊天历史 | 高 | 本次配对创建的会话 ID 集合只在内存；列表、读取、发送、重新生成都按集合过滤 | D072、D088、D099 |
| 审计泄露凭据或正文 | 高 | 审计只有固定枚举、来源 IP、会话短标识、绑定用户与错误码；最多 500 条 | D099 |
| 审计被刷满 | 中 | 同一来源同一原因 60 秒内的拒绝合并为一行计数 | D099 |
| 访问凭据交到错误的人 | 中 | 只在主机设置页显示一次明文；二维码把凭据放在 URL fragment；设置页提示只在可信网络使用 | D053、D088 |

## 冻结的设计

### 1. 网络绑定、Host/Origin 与 CORS

- **接口选择**：枚举本机 IPv4 接口地址，只保留 10/8、172.16/12、192.168/16。优先默认路由所在接口的地址；默认路由不在私网时取枚举顺序中的第一个私网地址。没有私网地址时服务进入 `failed`，错误 `1010003`。设置页显示实际绑定的 `IP:端口`。
- **端口**：`host_settings` 的 `lan.port` 是用户设定的首选端口 P，没有这一行时为默认值 8635（D107）。启动时依次尝试 P、P+1……P+19（不超过 65535）。监听 socket 用 `socket2` 创建，不设 `SO_REUSEADDR`、`SO_REUSEPORT`；逐个端口直接 `bind` 加 `listen`，第一个成功的就是监听本身，不先探测再绑定。`EADDRINUSE` 视为被占用并试下一个端口，其他绑定错误不递增，服务进入 `failed`，错误 `1010001`。20 个都被占用时 `failed`，错误 `1010002`。回退得到的端口**不写回** `lan.port`，下次启动仍先试 P；运行中不切回 P；`LanStatus.port_fallback` 为真时设置页提示“首选端口 P 被其他程序占用，当前使用 Q”（D107 第 2 项）。不设 `SO_REUSEADDR` 是为了识别其他程序在通配地址上的监听；代价是服务刚停止时 P 可能处于 TIME_WAIT 而临时回退（D105 第 1 项）。
- **修改端口**：主机命令 `set_lan_port` 校验 1024～65535 且不是 Fetch 规范的 bad port，不合法返回 `1010012`，不保存。合法时保存；服务运行且新值不等于当前端口时，撤销全部会话（`port_changed`）、作废未使用的凭据、停止监听，再按上一条重新绑定；新值等于当前端口或服务未运行时只保存（D107 第 3 项）。
- **网络变化**：每 10 秒检查一次绑定地址是否仍在本机接口上。只有绑定地址消失时：撤销全部会话（原因 `network_changed`），作废未使用的访问凭据，停止监听，按上面的规则重新绑定。旧会话的 Cookie 与 `Origin` 绑定旧地址，所以必须重新配对。绑定地址仍在、只是首选地址改变（如开关 VPN、接入第二块网卡）时继续在原地址服务；首选地址只在下次启动服务时生效（D101 第 3 项）。
- **对端**：TCP 对端地址不是私网 IPv4 时返回 403 `1010007`。
- **Host**：必须逐字等于 `绑定IP:端口`（端口不可省略，不接受主机名）。不等返回 403 `1010007`。这同时阻断 DNS 重绑定。
- **Origin**：`POST`、`DELETE` 与 WebSocket 升级必须带 `Origin`，且等于 `http://` 加 `Host`；缺失、`null` 或不等返回 403 `1010007`。`GET` 带 `Origin` 时同样必须相等；不带时放行（导航请求）。
- **CORS**：不返回任何 `Access-Control-*` 头，也不处理 `OPTIONS` 预检（白名单外的方法返回 405）。

### 2. 访问凭据、Cookie 会话、过期与撤销

- **访问凭据**：主机设置页调用 `issue_lan_access_code` 时生成。D088 写“服务启动时生成首个”；凭据明文只能在生成时交给主机界面一次（内存只存哈希），启动时生成的凭据没有界面能显示，所以改为“打开设置页的局域网标签或点击‘重新生成’时生成”（D099 第 6 项）。同时只有一个未使用的凭据；新凭据使旧凭据作废。
  - 128 位 CSPRNG 随机值，Crockford Base32 编码为 26 个字符，按 4 个一组用 `-` 分隔显示。输入时去掉 `-` 与空白、转大写后解码；解码失败等同于不匹配。
  - 存 SHA-256(原始 16 字节)、签发者 `user_id`、过期时间（签发后 10 分钟）、失败计数。比较为常量时间。
  - 配对地址为 `http://IP:端口/#code=<凭据>`；二维码由主机界面按此地址生成。远程 SPA 读取 fragment 后立即 `history.replaceState` 去掉 fragment，凭据不进入请求行、Referer 与日志。
  - 作废条件：配对成功、10 分钟过期、累计失败 10 次、生成新凭据、签发者结束会话（D099 第 7 项）、网络变化、服务停止。
- **会话**：
  - 令牌为 32 字节 CSPRNG 随机值，base64url 编码后作为 Cookie 值；服务端只存 SHA-256(令牌) 作为查找键。会话另有宿主生成的 `session_id`（UUID v4，用于设备列表与断开），`short_id` 为其前 8 位十六进制，只用于显示与审计。
  - Cookie：名称 `dgos_lan`，属性 `HttpOnly; SameSite=Strict; Path=/`，不设 `Domain`、`Max-Age`、`Expires`，无 TLS 所以不设 `Secure`。登出、401 与撤销后的响应用 `Max-Age=0` 清除。
  - 绑定：签发访问凭据的用户（`user_id`）、配对时的对端 IP。
  - 设备标签：配对时从 `User-Agent` 提取平台与浏览器族（如“iPhone · Safari”），不保存原始 `User-Agent`；只出现在主机设备列表，不进审计。
  - 期限：闲置 30 分钟、最长 12 小时，不续期。只有通过准入的 HTTP 请求与 WebSocket 握手刷新闲置时间；WebSocket 帧与 ping 不刷新。到期在每次访问时检查，另有 60 秒一次的清扫。
  - 上限：同时存在的会话最多 8 个。
- **撤销原因**（固定枚举，进审计）：`host_disconnect`、`host_disconnect_all`、`switch_off`、`app_exit`、`service_failed`、`network_changed`、`port_changed`、`issuer_ended`、`ip_changed`、`idle_expired`、`absolute_expired`、`re_paired`、`logout`。撤销的动作见伪代码 B10-60。
- **重新配对**：配对请求带有效 Cookie，且该会话的来源 IP 等于本次对端 IP 时为重新配对：不受 8 个会话上限限制；凭据比对通过后在同一 `state` 锁内移除旧会话再建新会话，会话数不增加，旧会话随后以 `re_paired` 完成撤销；比对失败时旧会话不受影响（D101 第 2 项）。
- **换 IP 配对**：配对请求带有效 Cookie，但该会话的来源 IP 不等于本次对端 IP 时，通过限速检查后先在 `state` 锁内移除该会话，锁外以 `ip_changed` 完成撤销，再按普通配对检查会话上限与凭据；凭据错误时旧会话也已撤销（D105 第 2 项，修订 D101 第 2 项末句）。

### 3. 配对限速、会话上限与审计

- **限速**（滑动 60 秒窗口，只在内存）：配对端点每来源 IP 5 次、全局 20 次。通过准入的每次配对请求都计入窗口（成功与失败都算）；被限速拒绝的请求不计入。超出返回 429 `1010011 lan_rate_limited`，`detail = { scope: 'pair_ip' | 'pair_global', retry_after_seconds }`，并带 `Retry-After` 头；`retry_after_seconds` 为窗口中最早一次请求离开窗口的剩余秒数，向上取整。每 IP 的窗口表最多 256 项，超出时淘汰最久未出现的 IP。
- **会话上限**：已有 8 个有效会话时配对返回 429 `1010011`，`detail = { scope: 'session_limit' }`，不带 `retry_after_seconds`。此检查在比对凭据之前，凭据不被消耗、不计失败。同一设备的重新配对（§2）不做此检查；换 IP 配对先撤销自己的旧会话再做此检查（D105）。
- **单设备聊天会话上限**：一个远程会话在本次配对中最多创建 100 个聊天会话，超出返回 429 `1010011`，`detail = { scope: 'chat_sessions' }`。
- **生成并发**：沿用 FR-006 的每用户单活动生成（`1006010`），桌面与远程共用。
- **审计表** `lan_audit_events`（migration `m20261101_000020_lan_audit_events`，2026-11-01 已建立；列见[数据模型 §4.8](../../../04-技术架构/当前版本/V1-数据模型.md#48-局域网协同fr-010)）：
  - 事件：`pair_succeeded`、`pair_rejected`、`pair_rate_limited`、`code_voided`、`session_revoked`、`request_rejected`。
  - 每行只有：时间（首次、最近）、事件、原因枚举、来源 IP、会话 `short_id`、绑定用户 `user_id`（配对前的拒绝为 NULL）、错误码、合并计数。
  - 不记录：访问凭据（含片段与哈希）、会话令牌与哈希、完整 `session_id`、Cookie、`User-Agent`、设备标签、请求路径与查询串、请求或响应正文、聊天内容、Prompt、会话标题、模型输出。
  - 保留：全表最多 500 条；每次插入在同一事务内删除超出部分中最旧的行。
  - 合并：`pair_rejected`、`pair_rate_limited`、`request_rejected` 在 60 秒内同一（事件、原因、来源 IP）只更新最近时间与计数，不新增行。
  - 读取：只经主机命令 `list_lan_audit_events`，返回 `user_id` 为当前桌面用户或 NULL 的行，按 `rowid` 新到旧分页。没有修改或删除单行的入口。
  - 删除账户：FR-008 的按用户清理增加 `lan` 领域，删除该用户的行；NULL 行保留。
  - 写入失败：只用 `tracing::warn!` 记事件枚举，不改变安全结果（拒绝仍拒绝，成功仍成功），不阻塞请求。

### 4. 远程聊天白名单、WebSocket、幂等与取消

路径与字段见接口契约 §14 与 OpenAPI；下面只写实现规则。

- **白名单**：静态 SPA；配对、会话状态、登出；只读目标列表；聊天会话的新建与列表、消息列表、发送、重新生成、取消本设备的生成、WebSocket 流式接收。白名单外的 `/api/` 路径返回 404，已登记路径的其他方法返回 405，二者都是空包体。
- **执行上下文**：LAN handler 用会话的绑定用户与 `BuiltinCaller::Workbench` 构造 `HostExecutionContext`，调用与桌面聊天命令相同的 `ChatManager` 方法，窗口键为 `lan:<session_id>`（D030、D088）。请求中的用户、会话、模块身份或授权结论一律不接受。Provider 使用记录中的 `caller` 因此也是 `workbench`，与桌面不区分（已知限制，D099 第 14 项）；远程活动窗口由审计中的配对与撤销事件界定。
- **目标列表**：已启用 Provider 的 ID、名称与文本生成模型（ID、名称）；已启用技能的 ID、名称与版本。不含 endpoint、`credential_ref`、配置、用量与连接状态。
- **会话目标**：新建会话时必须给出目标（Provider、模型、技能或明确无技能），之后不能修改；远程没有 `update_chat_session_target`、重命名与删除。
- **远程历史范围**：远程会话持有“本次配对创建的聊天会话 ID”集合，只在内存，随会话撤销消失（D099 第 5 项）。列表只返回集合中的会话；读取、发送、重新生成指向集合外的会话时返回 404 `1006001`（与“不存在”不区分）。D088 写“需要给聊天会话加来源标识（新 migration）”；来源标识只能说明“由远程创建”，无法区分是哪一次配对，内存集合已经满足“本设备本次配对”，所以不加列、不加 migration。主机桌面照常看到这些会话。
- **发送与重新生成**：请求体只有 `content`、`client_request_id`（重新生成只有 `client_request_id`），`deny_unknown_fields`。不接受 `tools`（首批不开放 MCP 工具轮次）与 `accept_destination`。
- **目标指纹变化**：返回 409 `1006012` 且不带 `detail`。远程看不到 endpoint，无法做出有意义的确认；用户须在主机上确认（D099 第 8 项）。
- **幂等**：沿用 FR-006，`client_request_id` 即任务 ID。同键同内容返回原确认 `replayed = true`，不再调用上游、不重新推送事件；同键不同内容返回 409 `1006011`。配对、新建会话与登出没有幂等键：配对的凭据单次有效，响应丢失后重试得到 `1010004`，用户须在主机上重新生成凭据；新建会话重试会多一个空会话；登出总是返回 204。
- **取消**：只能取消本远程会话发起、尚未结束的任务（会话内的任务集合）；集合外、未知、已结束一律返回 `{ cancelled: false }`。取消语义按 FR-006（已收到部分保存为 `interrupted`）。
- **WebSocket**：
  - 一个远程会话同时只有一条连接；新的升级成功后旧连接以 4409 关闭。
  - 握手按普通请求准入（B10-31～B10-38）；失败时以 HTTP 401/403 拒绝升级，不建立连接。
  - 只有服务端到客户端的文本帧：`{ "type": "chat", "event": ChatStreamEvent }` 推送本会话任务的事件（FR-006 的事件形状，去掉 `tool_proposal`）；`{ "type": "session_ended", "reason": <撤销原因> }` 在撤销时发出后关闭。客户端发数据帧时以 1008 关闭。
  - 每连接发送队列 256 帧；满时以 4413 关闭，生成不受影响，客户端重连后读消息列表补齐。
  - 没有连接时到达的事件丢弃，不缓存、不重放；断线重连后以消息列表为准（终态快照在 FR-006 的消息里）。连接断开不取消生成；只有显式取消与会话撤销取消。
  - 服务端每 30 秒发 ping，60 秒无 pong 关闭。关闭码：4401 会话已撤销或过期、4409 被新连接取代、4413 发送队列满、1001 服务停止、1008 协议违规。

### 5. 用户切换、注销与删除时撤销远程会话

- FR-008 结束会话的固定顺序（[接口契约 §9.4](../../../04-技术架构/当前版本/V1-接口契约.md#94-会话结束顺序切换注销改密删除)）第 4 步调用 `RemoteSessionRevoker::revoke_issued_by(user_id)`。本功能把 `NoRemoteSessions` 替换为 `LanSessionRevoker`：作废该用户签发、尚未使用的访问凭据；以 `issuer_ended` 撤销绑定该用户的全部远程会话。改密同样经过这一步。
- 第 1 步之后解析器处于“切换中”。每个远程请求在持有会话读锁时核对解析器：只有 `signed_in` 且当前用户等于绑定用户，或 `no_accounts` 且绑定用户为 `default-user` 时放行；否则以 `issuer_ended` 撤销该会话并返回 401 `1010006`（B10-38）。所以第 1 步到第 4 步之间到达的远程请求也不能启动新生成。
- 尚无账户时签发的会话绑定 `default-user`。之后创建首个账户承接 `default-user`（D087）并处于 `signed_in`，会话继续有效。
- 签发凭据需要可签发的用户：`signed_out`、切换中、删除中时 `issue_lan_access_code` 返回 `null`，设置页提示先登录。

FUNCTION on_app_start():
  enabled = host_settings.get("lan.enabled") ?? true
  IF NOT enabled: state = stopped; RETURN                                  // B10-22
  start()

FUNCTION start():
  ip = pick_private_ipv4()
  IF ip IS NONE: state = failed(1010003); RETURN                           // B10-23
  preferred = host_settings.get("lan.port") ?? 8635                       // D107
  port = NONE
  FOR p IN preferred ..= min(preferred + 19, 65535):                     // socket2，不设 SO_REUSEADDR（D105）
    r = bind_listen(ip, p)                                                // 直接绑定，不先探测
    IF r == Ok(listener): port = p; BREAK
    IF r != Err(EADDRINUSE): state = failed(1010001); RETURN              // 其他错误不递增
  IF port IS NONE: state = failed(1010002); RETURN                         // B10-24
  state = running(ip, port, fallback = port != preferred)                 // B10-25；不写回 lan.port（B10-71）

FUNCTION set_port(p):                                                     // 主机命令 set_lan_port

FUNCTION admit(req) -> Result<SessionGuard | Public>:
  IF NOT private_ipv4(req.peer): audit(request_rejected, peer); RETURN 403 1010007   // B10-31
  IF req.host != "{bound_ip}:{port}": audit(request_rejected, host); RETURN 403 1010007 // B10-32

     AND req.origin != "http://" + req.host:
    audit(request_rejected, origin); RETURN 403 1010007                    // B10-33
  IF route_not_whitelisted(req): RETURN 404 or 405, empty body             // B10-34
  IF req.path NOT STARTS WITH "/api/": RETURN Public (静态 SPA)            // B10-35
  IF req.path == "/api/v1/lan/pair": RETURN Public
  s = sessions.get(sha256(req.cookie("dgos_lan")))
  IF s IS NONE OR s.expired(now): RETURN 401 1010006, clear cookie         // B10-36
  guard = s.lock.read()
  IF req.peer != s.peer_ip: drop guard; revoke(s, "ip_changed"); RETURN 401 1010006   // B10-37
  r = resolver.current_mode()
  IF NOT (r == signed_in(s.user) OR (r == no_accounts AND s.user == "default-user")):
    drop guard; revoke(s, "issuer_ended"); RETURN 401 1010006              // B10-38
  s.last_active = now; RETURN guard                                        // B10-39
  // guard 持续到 handler 返回（含生成登记）

// ---- 配对（state 互斥锁内完成，见“并发控制”）----
FUNCTION pair(req):
  stale = NONE
  LOCK state:
    IF ip_window(req.peer).count >= 5 OR global_window.count >= 20:
      audit(pair_rate_limited); RETURN 429 1010011 {scope, retry_after_seconds}   // B10-40
    record_attempt(req.peer)
    old = sessions.get(sha256(req.cookie("dgos_lan")))
    IF old IS SOME AND old.expired(now): old = NONE
    IF old IS SOME AND old.peer_ip != req.peer:                            // 换 IP 配对（D105）
      sessions.remove(old.id); stale = old; old = NONE
    result = pair_locked(req, old)
  IF stale IS SOME: finish_revoke(stale, "ip_changed")  // 锁外；无论 result 成功与否
  RETURN result

FUNCTION pair_locked(req, old):              // 在 state 锁内
    IF old IS NONE AND active_sessions() >= 8:                             // 重新配对不计上限（D101）
      audit(pair_rejected, session_limit); RETURN 429 1010011 {scope: session_limit} // B10-41
    c = pending_code
    IF c IS NONE OR NOT ct_eq(sha256(decode(req.code)), c.hash):
      IF c IS SOME: c.failures += 1
      IF c IS SOME AND c.failures >= 10: void_code("too_many_failures")
      audit(pair_rejected, invalid_code); RETURN 401 1010004               // B10-42（同 IP 的 old 不受影响）
    IF c.expires_at <= now:
      void_code("expired"); audit(pair_rejected, expired_code); RETURN 401 1010005  // B10-43
    pending_code = NONE
    IF old IS SOME: sessions.remove(old.id)     // 先移除，会话数不增加
    s = new_session(user = c.issuer, peer = req.peer, label = ua_label(req))
    AFTER UNLOCK: IF old IS SOME: finish_revoke(old, "re_paired")   // 锁外：写锁、取消生成、关 WebSocket、审计
    audit(pair_succeeded, s); RETURN 200 SessionStatus + Set-Cookie        // B10-44

## 并发控制

| 场景 | 冲突点 | 控制方式 | 失败策略 |
| --- | --- | --- | --- |
| 两个设备同时用同一凭据配对 | `pending_code` | 限速、上限、比对、消耗、建会话在同一个 `state` 互斥锁内完成 | 只有一个成功，另一个 `1010004` |
| 撤销与在途请求 | 会话 | 每会话 `RwLock`：请求持读锁直到 `ChatManager` 登记完生成；撤销取写锁后 `cancel_window` | 撤销后登记的生成不可能存在 |
| 用户切换与远程请求 | 解析器当前用户 | 准入在读锁内核对解析器（B10-38）；FR-008 第 1 步先置“切换中”，第 4 步撤销 | 返回 `1010006` |
| 远程与桌面同时生成 | 每用户活动生成 | FR-006 的注册表与部分唯一索引 | `1006010` |
| 新 WebSocket 取代旧连接 | 会话的 ws 槽位 | 在会话锁内替换 | 旧连接 4409 |
| 审计并发插入与裁剪 | `lan_audit_events` | 插入与裁剪同一事务；SQLite 串行写 | 写失败按 B10-66 |

死锁预防：加锁顺序固定为 `state` 互斥锁 → 会话锁；持有 `state` 锁时不 `await` 任何 I/O 或 `ChatManager` 调用；`revoke` 先在 `state` 锁内移除会话，释放后再取会话写锁。`revoke_issued_by` 在 FR-008 的账户操作锁内调用，LAN 只读取解析器状态，不取账户锁。

## 事务边界

- 会话、凭据、限速窗口、聊天会话集合与任务集合只在内存，没有事务。
- `lan_audit_events`：每次插入或合并加裁剪为一个事务。审计事务与聊天事务互不包含。
- `host_settings` 的 `lan.enabled`、`lan.port`：单行 upsert。`lan.port` 只由 `set_lan_port` 写入（D107）；启动与回退不写。
- 聊天读写按 FR-006 的事务（D073、D074），LAN 不另开事务。
- 隔离级别：SQLite 默认（串行写），理由：只有单行写与单表裁剪。

## 幂等与重试

- 幂等键：发送与重新生成的 `client_request_id`（UUID，FR-006 即任务 ID）。存储与判定在 FR-006 的任务行与消息索引；重复请求同内容返回首次确认、不同内容 `1006011`。
- 配对：凭据单次有效，不幂等。响应丢失后，客户端拿不到 Cookie，会话在 30 分钟闲置后过期；用户在主机上重新生成凭据。
- 撤销、断开、登出、取消：重复调用无副作用。
- 服务端不自动重试任何操作。远程 SPA 对网络错误的发送重试必须复用同一 `client_request_id`。

## 外部调用与补偿

- 上游 Provider 调用由 FR-006 发起，超时、取消与用量未知的语义沿用 D074、D079、D081；LAN 不增加重试。
- 入站 HTTP：请求头读取 10 秒、请求体读取 10 秒、请求体上限 64 KiB（配对 1 KiB）、handler 总时长 30 秒（发送与重新生成在生成登记后即返回）。同时连接最多 64 个，每 IP 16 个；超出时拒绝新连接。
- WebSocket：ping 30 秒，无 pong 60 秒关闭；发送队列 256 帧。
- 网络接口检查每 10 秒一次。
- 不能把未知结果当成功：发送请求在生成登记后才返回 `SendAck`；网络中断时客户端以同一 `client_request_id` 重试得到原确认。

## 安全与日志

- 敏感字段：访问凭据明文只出现在 `issue_lan_access_code` 的返回值与主机界面；会话令牌只出现在 `Set-Cookie` 与请求 `Cookie` 头。两者及其哈希都不进日志、错误消息、审计、普通 DTO 或 SQLite。`tracing` 不记录请求头、路径查询串与请求体。
- 权限校验位置：准入（B10-31～B10-39）在路由 handler 之前；会话范围（聊天会话集合、任务集合）在 handler 内；聊天业务校验在 FR-006 的 Application Service（D030）。
- 响应头：`Cache-Control: no-store`（`/api/`）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: DENY`。SPA 的 `Content-Security-Policy`：`default-src 'self'; connect-src 'self' ws://<绑定IP:端口>; script-src 'self'; style-src 'self'; img-src 'self' data:; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`。
- 静态资源来自应用打包的远程 SPA 构建产物，不读取用户目录，不提供目录列表。远程 SPA 只包含配对与聊天界面，不包含 Tauri 依赖与模块加载器。

> 2026-11-01 一次性探针，只验证环境事实，不是实现，也不是测试资产；本节不改变任何 AC 的证据状态。探针脚本（Node、Python、Swift 与两个仓库外的 Rust crate）放在 `/tmp` 临时目录，用后已删除。没有读取用户数据库、Provider 凭据或聊天内容；Cookie 是探针自造的随机值，服务端只记录“有无、对应哪个合成会话”，不记录值。证据等级：本机单次运行，同一台机器既当主机又当客户端（客户端经本机私网地址访问自己），不是第二台设备，也不是 CI。

**环境**：macOS 27.0.1（26A434），arm64；Node 22.23.0；Rust 1.99.1（Homebrew），tokio 1.54.1（与 `Cargo.lock` 相同）；Swift 6.4.2 下的 WKWebView（`WKWebsiteDataStore.nonPersistent()`）；托管 Headless Chromium 150（不是用户的 Chrome 配置）；curl 8.7.1。系统应用防火墙关闭（`socketfilterfw` state 0）；没有 sudo 权限。

### 探针结果

| 项 | 问题 | 观察 | 对设计的结论 |
| --- | --- | --- | --- |
| 1 | 私网 IPv4 枚举 | `getifaddrs` 与 Node `os.networkInterfaces()` 一致，IPv4 只有 `lo0 127.0.0.1` 与 `en0 192.168.8.193`。utun0～3（代理 VPN，当时没有 IPv4）、bridge0、awdl0、llw0 只有 IPv6 链路本地地址或没有地址。按 §1 过滤后只剩 en0 | §1 的过滤规则可直接基于 `getifaddrs` 实现 |
| 1 | 默认路由地址 | `route -n get default` 为 `en0`、网关 192.168.8.1。UDP socket `connect` 不发包，`getsockname` 取本端地址：目标为 192.0.2.1、8.8.8.8、10.255.255.1、172.31.255.1 时都返回 192.168.8.193 | 用 UDP connect（目标取文档地址 192.0.2.1）即可得到默认路由的源地址，不需要解析路由表。本机只有一个候选，“默认路由不在私网时取枚举顺序第一个”这一支没有被执行到 |
| 2 | 端口递增 | std `TcpListener::bind` 在 192.168.8.193 上逐个尝试：占住 3000～3004 后选到 3005；占满 3000～3100（101 个）后全部失败，对应 `1010002` | 递增可行；应直接绑定，不先探测再绑定（避免检测与绑定之间的竞态） |
| 2 | **通配地址上的占用识别不到** | std 与 tokio 1.54.1 的 `TcpListener` 在 macOS 上都设置 `SO_REUSEADDR`（`getsockopt` 读出非零）。本机 Docker Desktop 监听 `*:3000`（IPv6 双栈通配），std 与 tokio 绑定 `192.168.8.193:3000` 都成功，之后连向该地址的连接由新监听接收。Python 矩阵：占用方为 `0.0.0.0`（带或不带 `SO_REUSEADDR`）、`::` 双栈、`::` v6only、`127.0.0.1` 时，新方带 `SO_REUSEADDR` 都绑定成功并接走流量，不带时都是 `EADDRINUSE`；占用方为同一具体地址时两种都失败 | 与 §1 原写法“端口被占用则递增”的意图冲突：DG-OS 会在 3000 上遮住用户已有通配服务的局域网流量。已由 D105 第 1 项裁定（见下方“探针发现的冲突与裁定”第 1 项） |
| 2 | TIME_WAIT | 服务端先关闭连接后重建监听：不带 `SO_REUSEADDR` 时重绑同端口失败，带时成功 | 去掉 `SO_REUSEADDR` 后，服务刚停止时 `lan.port` 可能暂时不可用，于是递增到下一个端口 |
| 3 | Host | curl 发送 `evil.example:3050`、`192.168.8.193`（缺端口）、`0xC0A808C1:3050`、空 Host（HTTP/1.0）都被逐字比较拒绝。curl 访问 `http://0xC0A808C1:3050/` 时自己规范化为 `Host: 192.168.8.193:3050`。两种浏览器发出的 Host 都是 `192.168.8.193:3050` | 逐字比较可行，浏览器不会发出其他写法 |
| 3 | Origin | 两种浏览器：同源 `GET` fetch 与顶层导航不带 `Origin`；同源 `POST` 带 `Origin: http://IP:端口`，fetch 设 `referrerPolicy: 'no-referrer'` 时仍是真实来源而不是 `null`；WebSocket 握手总带 `Origin`。跨端口、跨站页面发出的 `POST` 与 WebSocket 带对方来源，被拒绝 | §1 的 Origin 规则与浏览器行为一致 |
| 3 | `Sec-Fetch-*` | 在 `http://私网IP` 上两种浏览器都不发送（非安全上下文）；只有 `127.0.0.1` 的导航带 | 不能用 `Sec-Fetch-Site` 做补充校验 |
| 4 | HttpOnly | 配对后 `document.cookie` 不含 `dgos_lan`（两种浏览器） | 符合设计 |
| 4 | SameSite=Strict，同源 | `dgos_lan`（无 `Domain`、无 `Secure`、`Path=/`）在 `http://IP:端口` 上被接受，之后同源 fetch 与导航都带 | 无 TLS 时可用 |
| 4 | SameSite=Strict，同主机其他端口 | 页面在 `http://192.168.8.193:3051` 时，指向 3050 的 `img`、no-cors `GET`、`POST`、WebSocket 都带 Cookie（同站判断不看端口）。`POST` 与 WebSocket 被 Origin 拒绝；`GET` 没有 `Origin`，通过准入，响应对该页面不可读 | 残余风险：同一主机上其他本地服务的页面可以带 Cookie 发起只读 `GET`，会刷新闲置时间，但读不到内容、改不了状态。不与 D088、D101 冲突，记入实现注意事项 |
| 4 | SameSite=Strict，跨站 | 页面在 `http://127.0.0.1:3052` 时，`img`、`GET`、`POST`、WebSocket 都不带 Cookie；由该页跳转到 3050 的顶层导航也不带，到达后页面内的同源请求带。浏览器的本地网络访问限制没有拦截这些请求 | 跨站伪造不可行；从别的网站点链接进入时首个文档请求没有 Cookie，SPA 应在加载后用同源请求判断会话 |
| 5 | WebSocket 与 Cookie | 两种浏览器的升级请求都带 `dgos_lan` 与同源 `Origin`；服务端删除会话后升级以 401 拒绝 | D088“升级沿用同一 Cookie”成立 |
| 5 | 关闭码 | 客户端 `onclose` 读到服务端发出的 4409（被新连接取代）、4413、4401（之前收到 `session_ended` 帧）；握手被 401 或 403 拒绝时只读到 1006 | 客户端无法从 1006 区分 401、403 与网络错误 |
| 6 | 撤销与登出 | 服务端删除会话后旧 Cookie 仍在浏览器，下一请求得到 401 并由 `Max-Age=0` 清除，之后请求不带 Cookie；登出相同 | 符合设计 |
| 6 | 重新配对（同 IP） | 配对请求（同源 `POST`）带着旧 Cookie；新 `Set-Cookie` 覆盖旧值，之后只发送新令牌；旧会话按 `re_paired` 撤销 | D101 第 2 项的同 IP 分支成立 |
| 6 | 来源 IP 变化 | 本机只有一个私网地址，没有 sudo 无法添加别名；Docker 容器访问主机私网地址超时。所以“同一 Cookie 换来源 IP”没有实测。已证实的环境事实：Cookie 只按主机（绑定地址）匹配，与客户端地址无关；配对成功后新 Cookie 覆盖旧 Cookie | 由这两条事实推出 D101 第 2 项末句的缺口，已由 D105 第 2 项裁定（见下方第 2 项） |

### 探针发现的冲突与裁定

两项冲突已由用户在 2026-11-01 裁定，登记为 [D105](../../../06-决策记录/V1-冻结决策.md#d105-fr-010-阶段-0-裁定监听不设-soreuseaddr换-ip-配对先撤销旧会话)，§1、§2、§3、伪代码 `start` 与 `pair` 和分支追踪已按裁定修订：

1. **端口占用判断与 `SO_REUSEADDR`**：std/tokio 默认带 `SO_REUSEADDR`，具体地址的绑定能叠在通配监听之上并接走该地址的流量（本机 3000 上的 Docker Desktop 即是）。裁定：用 `socket2` 创建监听、不设 `SO_REUSEADDR`；接受 TIME_WAIT 导致的端口跳变。未采纳：绑定前探测通配占用；维持现状只提示。
2. **来源 IP 变化后重新配对留下的旧会话**：浏览器配对成功后用新 Cookie 覆盖旧 Cookie，D101 写的“下次请求按 `ip_changed` 撤销”不会发生，旧会话会占名额 30 分钟。裁定：配对时先按 `ip_changed` 撤销旧会话，再检查上限与凭据。未采纳：凭据正确后才撤销；维持 D101 只改措辞。

### 实现注意事项（不改变冻结决策）

- 接口枚举用 `getifaddrs`；默认路由源地址用 UDP connect 加 `getsockname`。
- 远程 SPA 加载后先调用 `GET /api/v1/lan/session`；WebSocket 以 1006 关闭时同样先查会话状态，再决定重连还是回到配对页。
- 同主机其他端口的页面可以带 Cookie 发 `GET`，SameSite 不能区分同一主机的不同端口；改变状态的请求与 WebSocket 由 Origin 校验拦截。

### 未验证（需要第二台设备、改动网络或 root 权限）

- 第二台真实设备（iOS Safari、Android Chrome）经 Wi-Fi 访问；iOS 相机扫码交给 Safari 时首个导航是否带 Cookie；微信等应用内浏览器的 Cookie 隔离。
- 应用防火墙开启时的首次弹窗与放行（本机防火墙关闭）；macOS 本地网络隐私权限对签名 `.app` 监听与入站的影响。
- 多个私网接口（VPN 分到私网地址、虚拟机网桥、第二块网卡）时的选择；默认路由不在私网的分支；没有私网地址（`1010003`）。
- 绑定地址消失（关 Wi-Fi、切换网络）时监听 socket 的表现与 10 秒检查（D101 第 3 项）；本机没有断网。
- 同一 Cookie 从不同来源 IP 访问（B10-37 `ip_changed`）。
- Windows、Linux；Safari.app 本身（探针用的是 WKWebView 非持久存储，不是 Safari 的 Cookie 存储与 ITP）；Firefox。
