## 2. 功能概述

### 2.1 一句话描述

在本地启动 HTTP 服务，让局域网内的其他设备（手机、平板、其他电脑）可以通过浏览器访问 DGOS，用主机签发的单次访问凭据配对，并由主机管理已连接设备。

### 2.2 详细说明

局域网协同让 DGOS 不仅是桌面应用，也是局域网内的服务。服务随桌面应用自动启动（D007/D039），用户可以在手机上打开浏览器访问 `http://192.168.1.100:3000`，认证后使用主机的能力；远程设备只能使用，不能修改配置（D007/D013）。

**核心价值**：
- ✅ 跨设备访问：手机、平板也能用
- ✅ 无需云端：数据不离开局域网
- ✅ 灵活场景：在沙发上用手机聊天
- ✅ 统一数据：所有设备共享同一份数据

**用户价值**：
- 个人用户：在家里任何设备都能用
- 团队用户：共享局域网内的 DGOS 实例
- 移动场景：不在电脑前也能使用

**V1 局域网 vs 云端**：
- V1 局域网：只能局域网访问，无需注册
- 云端：云端账号从 V3 起提供（D040），公网访问与跨设备同步在 V4

### 2.3 功能边界

**包含**（启动策略与远程范围已由 D039 确定；安全默认值已由 D088 冻结，见 §2.4）：
- ✅ HTTP Server 随应用自动启动；系统设置中的开关可关闭，关闭状态持久化（D039）
- ✅ 自动选择端口（默认 3000，占用时自动递增）
- ✅ 局域网 IP 自动获取和显示
- ✅ 简单认证：随机访问凭据换取会话（D053）；无用户名/密码
- ✅ 已连接设备列表
- ✅ 设备管理（踢出设备）
- HTTP API 白名单：只暴露使用类接口（对话、历史、使用已配置的 Provider/Skills/MCP），不暴露配置修改，不映射全部 Tauri commands；逐项白名单在白名单 OpenAPI 中冻结（D039、D098）
- ✅ 前端应用服务（Vite 构建的 SPA）
- ✅ WebSocket 支持（流式响应）
- ✅ 安全限制（只允许局域网 IP）
- ✅ 二维码分享（扫码连接）

**不包含**（明确说明原因）：
- ❌ HTTPS（自签名证书） → V2 安全增强
- ❌ 公网访问（端口转发） → V4 云端协同
- ❌ 细粒度权限（按设备） → V2 权限增强
- ❌ 设备同步（离线变更合并） → V4 云端协同
- ❌ 多实例集群 → 不在 V1 范围

### 2.4 决策与待决策

启动策略与远程范围已由 [D039](../../../06-决策记录/V1-冻结决策.md#d039-局域网服务随应用自动启动设置开关持久关闭) 确定，认证方式由 D053 确定，安全默认值与首批白名单由 [D088](../../../06-决策记录/V1-冻结决策.md#d088-局域网安全默认值与首批白名单绑定签发者单次凭据换-cookie-会话只绑私网-ipv4首批只开放聊天) 冻结（2026-10-31），审计、限速错误码、白名单路径与实现细则由 [D099](../../../06-决策记录/V1-冻结决策.md#d099-fr-010-规格收口高风险局域网审计表限速错误码-1010011-与白名单路径) 冻结（2026-11-01）。本节与[技术设计](10-局域网协同-技术设计.md)冲突时以冻结决策为准。

#### 已决：启动策略（D039）

以 D007 为准：开关默认开启，开启时应用启动即启动服务；启动失败只提示，不阻塞桌面应用。系统设置中的开关就是 D007 的“可在设置中关闭”：关闭立即停止服务并断开所有设备，状态持久化，之后启动不自动开启，直到用户重新打开。AC01/AC12 的“启动/停止”即该开关的开、关。退出应用时服务随之停止，不常驻后台。

#### 已决：认证方式（D053）

随机访问凭据 + 会话。主机生成随机访问凭据，经地址或二维码交给远程设备，远程设备用它换取有期限、可撤销的会话。远程会话没有独立用户身份，使用主机桌面用户的数据：签发凭据时登录的账户（D088），尚无账户时为 `default-user`（D087）；V1 不引入用户名/密码账号和 JWT 登录。AC05/AC06 中的“token”即访问凭据。D013 的用户名/密码部分由 D053 取代。

#### 已决：远程范围（D039，沿用 D007/D013）

远程设备必须认证，只能使用主机能力：发起对话、查看历史、使用已配置的 Provider/Skills/MCP；不能修改 Provider 等配置。HTTP API 采用白名单，不映射全部 Tauri commands；旧草案中的 `POST /api/providers` 不得开放。逐项白名单见[接口契约 §14](../../../04-技术架构/当前版本/V1-接口契约.md#14-局域网-http-与-websocket-接口fr-010) 与 [OpenAPI](../../../04-技术架构/当前版本/V1-openapi.yaml)（D099 第 4 项）。

#### 已确认：安全约束（2026-10-31 收口）

共用身份模型见 [服务与领域边界 §3.5](../../../04-技术架构/服务与领域边界.md#35-auth统一身份与安全边界fr-008009010)。以下各条来自冻结决策与当前代码：

1. 远程会话是主机签发的、有期限、可撤销的会话对象，不是用户账户，没有独立用户身份（D053）。LAN handler 由会话得到绑定的本地用户（签发访问凭据时登录的桌面用户，D088），构造与桌面命令同一种 `HostExecutionContext`，经 Application Service 调用（D030）；请求中的 `user_id`、模块身份或授权结论一律不接受。旧草案“把 `session.user_id` 注入请求”作废（[旧局域网草案](../../../99-历史归档/V1-FR-010/2026-11-01-旧局域网草案.md)）。
2. 不提供用户名/密码登录、JWT 或用户列表（D053）；旧草案的 `/api/auth/login`、`/api/users` 不开放。
3. 路由是逐项白名单，白名单之外一律拒绝；不映射全部 Tauri commands，不提供“命令名 + 任意 JSON”的通用转发（D039）。
4. 访问凭据只在主机显示，不写日志、不进普通 DTO（D053）；访问凭据与会话令牌都不以明文写入 SQLite（D023 凭据规则）。旧草案的 `lan_config.access_token`、`lan_sessions.session_token` 明文列不采用。
5. 远程会话不继承也不授予模块权限；`network.local` 是模块能力，与本服务无关（[FR-009 §2.4](09-模块权限管理.md#24-四层权限模型与生命周期语义2026-10-31)）。
6. 远程使用 MCP 不绕过 D021、D022、D075 的逐次确认；首批不开放 MCP 工具轮次（D088）。
7. 远程查看历史只限本设备本次配对创建的会话（D088，落实 D072 的隐私要求）。
8. 启动失败不阻塞桌面；关闭开关立即停止服务并断开全部设备；退出应用即停止（D039）。
9. 当前没有任何实现：设置页只显示“局域网协同尚未启用”，不监听端口、不生成凭据（D085，`src/pages/LanSettings.tsx`）。

#### 已决：安全默认值（D088）

| 项 | 规则 |
| --- | --- |
| 远程会话的用户绑定 | 绑定签发访问凭据时登录的桌面用户（FR-008 的 `SessionResolver` 当前用户，尚无账户时为 `default-user`）。该用户注销、切换或被删除时撤销其签发的全部远程会话：FR-008 的 `SessionPort` 结束会话时调用 `RemoteSessionRevoker::revoke_issued_by(user_id)`，该端口在本功能实现前是空操作（`NoRemoteSessions`），本功能须替换为真实撤销 |
| 访问凭据（bootstrap code） | 宿主 CSPRNG 生成 128 位随机值，分组 Base32 显示；单次有效，交换成功即作废；10 分钟过期，服务启动时生成首个，过期后主机打开设置页时生成新的；内存只存哈希，常量时间比较；二维码把凭据放在 URL fragment，不进入请求行和日志 |
| 会话令牌 | 256 位随机不透明值，不是 JWT，不含身份字段，服务端只存哈希；`HttpOnly`、`SameSite=Strict` 的 Cookie（无 TLS 不设 `Secure`），WebSocket 升级沿用同一 Cookie；不放 localStorage 或 sessionStorage；会话绑定来源 IP，变化即作废 |
| 有效期与轮换 | 闲置 30 分钟、最长 12 小时；不静默续期，到期后重新配对。重新生成访问凭据只作废未使用的凭据，不影响已建立的会话 |
| 撤销 | 单设备断开、断开全部、关闭开关、退出应用、绑定用户注销/切换/删除；撤销立即关闭该会话的 WebSocket，在途生成按 FR-006 的取消语义结算 |
| 存储与崩溃恢复 | 会话与凭据只在内存，崩溃或重启后全部失效，远程设备重新配对。只持久化开关与端口（`host_settings`，D087）。服务异常退出时设置页显示原因，开关保持开启，不自动重启 |
| 绑定地址 | 不监听 `0.0.0.0`、回环与 IPv6；只绑定检测到的私网 IPv4 接口地址（10/8、172.16/12、192.168/16），网络变化时重新绑定；对端地址再做私网校验 |
| Host / Origin / CORS | 不返回任何 CORS 头；`Host` 必须等于绑定的 `IP:端口`；改变状态的请求与 WebSocket 升级要求 `Origin` 与 `Host` 同源，缺失或为 `null` 即拒绝 |
| 限速 | 配对端点每来源 IP 每分钟 5 次、全局每分钟 20 次；同一凭据累计失败 10 次即作废；远程会话最多 8 个；生成并发沿用 FR-006 的每用户单活动生成 |
| 重放与 TLS | V1 不做 HTTPS；同网段嗅探 Cookie 是已知残余风险。缓解：单次凭据、短有效期、会话绑定来源 IP、写请求沿用 FR-006 的 `client_request_id` 幂等；设置页提示只在可信网络使用 |
| 默认开启 | 保持 D039。未认证时可达的只有静态 SPA 与配对端点 |

## 3. 核心流程

> 旧草案的流程（随机 UUID token、会话令牌存 localStorage、`Authorization: Bearer`、`/api/auth/verify`、`/api/chat/send`）已作废，原文见[旧局域网草案](../../../99-历史归档/V1-FR-010/2026-11-01-旧局域网草案.md)。分支 ID 见[技术设计](10-局域网协同-技术设计.md#伪代码)。

### 3.1 启动服务

1. 桌面应用启动，读取 `lan.enabled`（默认开启，D039）。关闭时不启动，直到用户在系统设置打开开关。
2. 选择私网 IPv4 接口地址；没有时显示“无网络连接”（`1010003`）。
3. 先试上次成功的端口，再从 3000 递增到 3100；全部被占用时显示“无可用端口”（`1010002`）。
4. 绑定 `IP:端口`，设置页显示访问地址。启动失败只在设置页显示原因，不阻塞桌面应用。

> 设置页入口由 [FR-007](../02-应用模块/07-系统设置.md) 的“局域网协同”标签承载（AC15，D039）；本功能负责服务行为。

### 3.2 配对

1. 主机用户打开局域网标签或点击“重新生成”，宿主生成访问凭据（10 分钟有效），界面显示分组凭据与二维码；二维码地址把凭据放在 URL fragment。
2. 远程设备扫码或输入地址与凭据，SPA 去掉 fragment 后调用配对接口。
3. 凭据正确且未过期：凭据作废，宿主签发会话并以 `HttpOnly` Cookie 返回；远程进入聊天界面，使用签发凭据的桌面用户的数据，不选择用户、不输入密码。
4. 主机设备列表出现该设备。凭据错误、过期或被限速时远程显示对应错误。

### 3.3 远程聊天

1. 远程读取只读目标列表，新建聊天会话并选定 Provider、模型与技能（之后不能修改）。
2. 打开 WebSocket，然后发送消息（带 `client_request_id`）；生成事件经 WebSocket 推送，终态以消息快照为准。
3. WebSocket 断线不取消生成；重连后读取消息列表补齐。
4. 远程可以取消自己发起、尚未结束的生成；只能看到本次配对中创建的会话。

### 3.4 断开设备

1. 主机用户在设备列表点击“断开”并确认。
2. 宿主撤销该会话：取消它的在途生成（已收到部分保存为中断），通过 WebSocket 通知并关闭连接。
3. 远程显示“已被断开连接”，再次使用须重新配对。

### 3.5 停止服务与退出

1. 用户关闭“局域网协同”开关并确认：撤销全部会话、作废未使用的凭据、停止监听，持久化关闭状态（之后启动不再自动开启）。
2. 退出应用：同样撤销与停止，开关状态不变。
3. 服务异常退出：撤销全部会话，设置页显示原因，开关保持开启，不自动重启（D088）。

### 3.6 桌面用户切换、注销与删除

FR-008 结束会话的第 4 步撤销该用户签发的全部远程会话并作废其未使用的凭据；第 1 步之后到达的远程请求已经被拒绝（D088、D099，技术设计 §5）。
