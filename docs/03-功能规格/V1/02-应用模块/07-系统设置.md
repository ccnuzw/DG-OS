## 2. 功能概述

### 2.1 一句话描述

提供统一的系统设置界面，集中管理 Provider、Skills、MCP、模块、主题和用户偏好，让用户可以方便地配置和管理 DGOS。

### 2.2 详细说明

系统设置是 DGOS 的管理中心，所有配置都集中在这里。

**核心价值**：
- ✅ 集中管理：所有配置在一个地方
- ✅ 清晰分类：按功能分 tab（Provider、Skills、MCP、模块、局域网协同、外观、关于）
- ✅ 易于操作：直观的 CRUD 界面
- ✅ 实时生效：配置更改立即生效

**用户价值**：
- 最终用户：方便地管理所有配置
- 开发者：参考实现，学习如何构建管理界面

### 2.3 功能边界

**包含（7 个主要模块；“局域网协同”随 [D039](../../../06-决策记录/V1-冻结决策.md#d039-局域网服务随应用自动启动设置开关持久关闭) 新增，原为 6 个）**：

**1. Provider 管理**：
- ✅ Provider 列表（显示所有已配置的 Provider）
- ✅ 添加 Provider（表单输入）
- ✅ 编辑 Provider（修改配置）
- ✅ 删除 Provider（确认提示）
- ✅ 测试连接（验证配置）
- ✅ 刷新模型列表（手动刷新）
- ✅ 拖拽排序（调整优先级）
- ✅ 启用/禁用开关

**2. Skills 管理（按 D016/D017 调整）**：
- 浏览本地官方 Skills 内容库（分类、搜索及来源状态）
- 查看技能版本、内容摘要与适用信息
- 管理用户启用状态；工作台任务显式选择并固定版本
- 不执行 Skill 内容，不配置 Skill API Key，不提供旧设计中的 HTTP/CLI 安装执行流程
- 第三方来源及其安装/更新流程不属于当前已交付能力，须另按来源安全设计验收

**3. MCP 管理**：
- ✅ MCP 服务器列表
- ✅ 添加 MCP 服务器（Stdio/HTTP）
- ✅ 编辑 MCP 服务器
- ✅ 删除 MCP 服务器
- ✅ 连接状态显示
- ✅ 工具列表查看
- ✅ 连接日志查看

**4. 模块管理**（受 D023–D028 约束：只管理宿主发布器验证过的本地模块包，不加载任意远程 JS）：
- ✅ 已安装模块列表
- ✅ 模块详情（名称、版本、权限）
- ✅ 启用/禁用模块
- ✅ 卸载模块
- ✅ 检查模块更新
- ✅ 更新模块
- ✅ 查看崩溃日志

**5. 外观设置**：
- ✅ 主题切换（亮色/暗色）
- ✅ 字体大小（小/中/大）
- ✅ 紧凑模式（减少间距）
- ✅ 主题预览

**6. 局域网协同**（D039；服务行为、认证与 API 范围以 [V1-FR-010](../03-系统功能/10-局域网协同.md) 为准，本节只定义设置页入口）：
- ✅ 局域网服务开关：打开即启动服务，关闭即停止并断开所有设备；状态持久化，应用启动时按开关自动启动（D039）
- ✅ 显示服务状态、访问地址与启动失败原因
- ✅ 已连接设备列表与断开设备
- 访问凭据的显示、轮换和撤销方式待 FR-010 安全默认值冻结后再定义

**7. 关于**：
- ✅ DGOS 版本信息
- ✅ 系统信息（OS、架构）
- ✅ 许可证信息
- ✅ 检查更新

**不包含**（明确说明原因）：
- ❌ 局域网服务的网络、认证与 API 实现 → V1-FR-010（本功能只提供设置入口）
- ❌ 高级配置（环境变量、调试模式） → V2 开发者工具
- ❌ 插件市场 → V3 应用市场
- ❌ 账号登录 → V3 云端账号（D040）
- ❌ 数据备份/导出 → V2 数据管理
- ❌ 性能监控 → V2 监控功能

## 3. 核心流程

### 3.1 添加 Provider 流程

```
用户打开系统设置
  ↓
点击"Provider"标签
  ↓
显示已配置的 Provider 列表
  ↓
点击"添加 Provider"按钮
  ↓
显示表单：
  - 厂商：[OpenAI] (下拉；首批 OpenAI、Anthropic、自定义)
  - 适配器：厂商有多个端点时再选（如“自定义”：OpenAI 兼容 / Anthropic 兼容）；只有一个端点时不显示
  - 名称：[我的 OpenAI]
  - Base URL：[https://api.openai.com/v1]（随所选端点预填，可修改；“自定义”没有默认值）
  - API Key：[sk-xxx...] (密码输入)
  （厂商表、端点和默认地址由宿主提供，字段定义见 [V1-FR-001 §2.4](../01-底层能力/01-Provider适配框架.md#24-三方兼容协议扩展草案)，本规格不重复）
  ↓
点击"测试连接"
  ↓
调用 Provider API 验证
  ↓
（如果成功）显示"连接成功 ✓"
  ↓
点击"保存"
  ↓
Provider 保存到数据库
  ↓
自动获取模型列表
  ↓
显示在 Provider 列表中
```

### 3.2 安装 Skills 流程

```
用户打开系统设置
  ↓
点击"Skills"标签
  ↓
显示技能库、版本和用户启用状态
  ↓
点击"浏览仓库"
  ↓
显示已随应用发布的官方本地 Skills（分类）
  ↓
搜索或浏览 Skills
  ↓
点击某个 Skill
  ↓
显示详情：名称、描述、来源/版本及适用信息
  ↓
查看或启用本地技能
  ↓
工作台由用户显式选择技能及版本
  ↓
按 D018 固定该版本用于单任务消费
```

### 3.3 主题切换流程

```
用户打开系统设置
  ↓
点击"外观"标签
  ↓
显示主题选项：
  ○ 亮色主题
  ● 暗色主题 (当前选中)
  ↓
点击"亮色主题"
  ↓
立即应用主题
  ↓
显示预览效果
  ↓
保存用户偏好到数据库
  ↓
（可选）显示"主题已更改"提示
```

### 3.4 模块更新流程

```
用户打开系统设置
  ↓
点击"模块"标签
  ↓
系统自动检查更新
  ↓
显示"AI 工作台有更新"标记
  ↓
点击"查看更新"
  ↓
显示更新日志：
  v1.0.1 → v1.0.2
  - 修复流式输出 bug
  - 优化性能
  ↓
点击"更新"
  ↓
下载新版本
  ↓
显示进度条
  ↓
更新完成（热重载，无需重启；发布、校验与失败恢复按 D027 状态机执行）
  ↓
显示"更新成功 ✓"
```

## 4. 数据模型

系统设置主要是对现有数据的管理界面，不新增数据表。

### 4.1 涉及的现有数据表

- `providers` - Provider 配置
- `models` - 模型列表缓存
- `skills` - 已安装的 Skills
- `mcp_servers` - MCP 服务器配置
- `installed_modules` - 已安装模块
- `module_permissions` - 模块权限
- `user_preferences` - 用户偏好（主题等）

### 4.2 读写关系

所有读写操作通过 Tauri Commands 调用对应的宿主能力；调用者身份由宿主派生，不接受 renderer 提交 `user_id`/`userId`（D023）。
- Provider 管理 → 调用 `V1-FR-001` 的接口
- Skills 管理 → 调用 `V1-FR-002` 的接口
- MCP 管理 → 调用 `V1-FR-003` 的接口
- 模块管理 → 调用 `V1-FR-004` 的接口
- 主题管理 → 调用 `V1-FR-005` 的接口

```typescript
  const [showAddModal, setShowAddModal] = useState(false);
  
  // B07-08: 加载 Provider 列表
  useEffect(() => {
    loadProviders();
  }, []);
  
  const loadProviders = async () => {
    const list = await invoke<Provider[]>('list_providers');
    setProviders(list);
  };
  
  // B07-09: 添加 Provider
  const handleAddProvider = async (config: ProviderConfig) => {
    await invoke('create_provider', { config });
    await loadProviders();
    setShowAddModal(false);
  };
  
  // B07-10: 测试连接
  const handleTestConnection = async (config: ProviderConfig) => {
    try {
      const result = await invoke<boolean>('test_provider_connection', { config });
      if (result) {
        toast({ message: '连接成功 ✓', type: 'success' });
      }
    } catch (error) {
      toast({ message: '连接失败', type: 'error' });
    }
  };
  
  // B07-11: 删除 Provider
  const handleDeleteProvider = async (id: string) => {
    if (confirm('确定删除此 Provider？')) {
      await invoke('delete_provider', { id });
      await loadProviders();
    }
  };
  
  return (
    <div className="provider-settings">
      <div className="header">
        <h2>Provider 管理</h2>
        <Button onClick={() => setShowAddModal(true)}>添加 Provider</Button>
      </div>
      
      {/* Provider 列表 */}
      <div className="provider-list">
        {providers.map(provider => (
          <ProviderCard
            key={provider.id}
            provider={provider}
            onDelete={() => handleDeleteProvider(provider.id)}
            onTest={() => handleTestConnection(provider)}
          />
        ))}
      </div>
      
      {/* 添加 Provider 模态框 */}
      <Modal open={showAddModal} onClose={() => setShowAddModal(false)}>
        <ProviderForm
          onSubmit={handleAddProvider}
          onTest={handleTestConnection}
        />
      </Modal>
    </div>
  );
};
```
