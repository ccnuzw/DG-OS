## 2. 功能概述

### 2.1 一句话描述

提供统一的系统设置界面，集中管理 Provider、Skills、MCP、模块、主题和用户偏好，让用户可以方便地配置和管理 DGOS。

### 2.2 详细说明

系统设置是 DGOS 的管理中心，所有配置都集中在这里。

**核心价值**：
- ✅ 集中管理：所有配置在一个地方
- ✅ 清晰分类：按功能分 tab（Provider、Skills、MCP、模块、外观、关于、局域网协同）
- ✅ 易于操作：直观的 CRUD 界面
- ✅ 实时生效：配置更改立即生效

**用户价值**：
- 最终用户：方便地管理所有配置
- 开发者：参考实现，学习如何构建管理界面

### 2.3 功能边界

**包含（7 个主要模块；“局域网协同”随 [D039](../../../06-决策记录/V1-冻结决策.md#d039-局域网服务随应用自动启动设置开关持久关闭) 新增，原为 6 个）**：

**1. Provider 管理**：
- ✅ Provider 列表（显示所有已配置的 Provider）
- ✅ 添加 Provider（表单输入）
- ✅ 编辑 Provider（修改配置）
- ✅ 删除 Provider（确认提示）
- ✅ 测试连接（验证配置）
- ✅ 刷新模型列表（手动刷新）
- ✅ 拖拽排序（调整优先级）
- ✅ 启用/禁用开关

**2. Skills 管理（按 D016/D017 调整）**：
- 浏览本地官方 Skills 内容库（分类、搜索及来源状态）
- 查看技能版本、内容摘要与适用信息
- 管理用户启用状态；工作台任务显式选择并固定版本
- 不执行 Skill 内容，不配置 Skill API Key，不提供旧设计中的 HTTP/CLI 安装执行流程
- 第三方来源及其安装/更新流程不属于当前已交付能力，须另按来源安全设计验收

**3. MCP 管理**：
- ✅ MCP 服务器列表
- ✅ 添加 MCP 服务器（Stdio/HTTP）
- ✅ 编辑 MCP 服务器
- ✅ 删除 MCP 服务器
- ✅ 连接状态显示
- ✅ 工具列表查看
- ✅ 连接日志查看

**4. 模块管理**（受 D023–D028 约束：只管理宿主发布器验证过的本地模块包，不加载任意远程 JS）：
- ✅ 已安装模块列表
- ✅ 模块详情（名称、版本、权限）
- ✅ 启用/禁用模块
- ✅ 卸载模块
- ✅ 检查模块更新
- ✅ 更新模块
- ✅ 查看崩溃日志

**5. 外观设置**（D064、D065、D071）：
- ✅ 主题：亮色、暗色、跟随系统（`light`/`dark`/`auto`，默认亮色）
- ✅ 界面缩放：75%、100%、125%、150%、175% 五档，只改根字号（原"字体大小"和"紧凑模式"并入此项，D064）
- ✅ 预览区：用真实组件展示当前主题与缩放，并可触发一条 Toast（壁纸选择与自定义主题移到 V2，D064）

**6. 局域网协同**（D039；服务行为、认证与 API 范围以 [V1-FR-010](../03-系统功能/10-局域网协同.md) 为准，本节只定义设置页入口）：
- 本阶段（D085）：只有入口与"局域网协同尚未启用"的说明；不显示开关、状态或地址，不调用任何局域网命令
- 随 FR-010 交付：局域网服务开关（打开即启动服务，关闭即停止并断开所有设备；状态持久化，应用启动时按开关自动启动，D039）
- 随 FR-010 交付：显示服务状态、访问地址与启动失败原因；首选端口设置（默认 8635），首选端口被占用而临时回退时提示“首选端口被其他程序占用，当前使用 Q”；运行中修改端口前确认“会断开所有设备”（D107）
- 随 FR-010 交付：已连接设备列表与断开设备
- 访问凭据的显示、轮换和撤销方式待 FR-010 安全默认值冻结后再定义

**7. 关于**：
- ✅ DGOS 版本信息（应用名称、应用版本、Tauri 运行时版本，D085）
- 系统信息（OS、架构）：本阶段不显示，来源待决策（D085"仍开放"）
- 许可证信息：本阶段不显示，仓库尚未声明许可证（D085"仍开放"）
- 检查更新：本阶段不提供，依赖发布通道（发布阶段）

**不包含**（明确说明原因）：
- ❌ 局域网服务的网络、认证与 API 实现 → V1-FR-010（本功能只提供设置入口）
- ❌ 高级配置（环境变量、调试模式） → V2 开发者工具
- ❌ 插件市场 → V3 应用市场
- ❌ 云端账号登录 → V3 云端账号（D040）。本地账户由 V1-FR-008 提供，账户页是独立路由 `/account`（`src/pages/AccountSettings.tsx`），不在本功能的七个入口内
- ❌ 数据备份/导出 → V2 数据管理
- ❌ 性能监控 → V2 监控功能

## 3. 核心流程

### 3.1 添加 Provider 流程

```
用户打开系统设置
  ↓
点击"Provider"标签
  ↓
显示已配置的 Provider 列表
  ↓
点击"添加 Provider"按钮
  ↓
显示表单：
  - 厂商：[OpenAI] (下拉；首批 OpenAI、Anthropic、自定义)
  - 适配器：厂商有多个端点时再选（如“自定义”：OpenAI 兼容 / Anthropic 兼容）；只有一个端点时不显示
  - 名称：[我的 OpenAI]
  - Base URL：[https://api.openai.com/v1]（随所选端点预填，可修改；“自定义”没有默认值）
  - API Key：[sk-xxx...] (密码输入)
  （厂商表、端点和默认地址由宿主提供，字段定义见 [V1-FR-001 §2.4](../01-底层能力/01-Provider适配框架.md#24-三方兼容协议扩展)，本规格不重复）
  ↓
点击"测试连接"
  ↓
调用 Provider API 验证
  ↓
（如果成功）显示"连接成功 ✓"
  ↓
点击"保存"
  ↓
Provider 保存到数据库
  ↓
自动获取模型列表
  ↓
显示在 Provider 列表中
```

### 3.2 安装 Skills 流程

```
用户打开系统设置
  ↓
点击"Skills"标签
  ↓
显示技能库、版本和用户启用状态
  ↓
点击"浏览仓库"
  ↓
显示已随应用发布的官方本地 Skills（分类）
  ↓
搜索或浏览 Skills
  ↓
点击某个 Skill
  ↓
显示详情：名称、描述、来源/版本及适用信息
  ↓
查看或启用本地技能
  ↓
工作台由用户显式选择技能及版本
  ↓
按 D018 固定该版本用于单任务消费
```

### 3.3 主题与界面缩放流程

```
用户打开系统设置（/settings）
  ↓
点击"外观"入口（/settings/appearance）
  ↓
显示"主题"（亮色 / 暗色 / 跟随系统）和"界面缩放"（75%～175%）两组单选，选中项为宿主已确认的值
  ↓
用户选择新的主题或缩放
  ↓
界面立即应用（外观控制器先应用后保存，见 FR-005 §13.1）
  ↓
写入成功：控件保持所选值
写入失败：控制器回退到上一个已确认值并发出错误 Toast，页面重新读取已确认值，控件回到该值
  ↓
预览区的组件随主题与缩放变化；点击预览区的"显示通知"按钮显示一条 Toast
```

### 3.4 模块更新流程

```
用户打开系统设置
  ↓
点击"模块"标签
  ↓
系统自动检查更新
  ↓
显示"AI 工作台有更新"标记
  ↓
点击"查看更新"
  ↓
显示更新日志：
  v1.0.1 → v1.0.2
  - 修复流式输出 bug
  - 优化性能
  ↓
点击"更新"
  ↓
下载新版本
  ↓
显示进度条
  ↓
更新完成（热重载，无需重启；发布、校验与失败恢复按 D027 状态机执行）
  ↓
显示"更新成功 ✓"
```

## 4. 数据模型

系统设置主要是对现有数据的管理界面，不新增数据表。

### 4.1 涉及的现有数据表

- `providers` - Provider 配置
- `models` - 模型列表缓存
- `skills` - 已安装的 Skills
- `mcp_servers` - MCP 服务器配置
- `installed_modules` - 已安装模块
- `module_permissions` - 模块权限
- `system_settings` - 外观偏好（`appearance.theme`、`appearance.density`，D065；由 FR-005 的 `get_appearance_preferences`/`set_appearance_preferences` 读写，本功能不直接访问）

### 4.2 读写关系

所有读写操作通过 Tauri Commands 调用对应的宿主能力；调用者身份由宿主派生，不接受 renderer 提交 `user_id`/`userId`（D023）。
- Provider 管理 → 调用 `V1-FR-001` 的接口
- Skills 管理 → 调用 `V1-FR-002` 的接口
- MCP 管理 → 调用 `V1-FR-003` 的接口
- 模块管理 → 调用 `V1-FR-004` 的接口
- 外观设置 → 只调用 FR-005 外观控制器的 `updateAppearance`（经 `set_appearance_preferences`，D065）；不新增宿主命令、数据表、错误码或通用设置键接口，不提交用户标识（D023）

## 7. 技术设计

### 7.1 Settings 主界面（D085）

```text
SettingsPage                         // src/App.tsx：原始路径不满足 isHostSettingsPath 时显示 Not found（D037）
└─ SettingsShell                     // src/pages/SettingsShell.tsx
   ├─ Tabs（@dgos/ui，activationMode="manual"，aria-label="系统设置"）
   │  └─ 七个 Tabs.Trigger：Provider、Skills、MCP、模块、外观、关于、局域网协同      // B07-01
   │     value = 当前子路径的第一段；不在七个入口内时为 ""（总览，没有选中项）       // B07-15
   │     onValueChange → navigate(ROUTES.settingsX)                                 // 只在 Enter/Space/点击时触发
   ├─ 总览：/settings 与未知子路径；只有说明文字，不调用宿主                         // B07-15
   ├─ Tabs.Content（保活）：Provider / Skills / MCP，首次进入后挂载，切走时隐藏         // B07-02～B07-04、B07-16
   └─ Tabs.Content（按需）：模块（内部再分 modules 与 modules/:moduleId）/ 外观 / 关于 / 局域网协同
                                                                                    // B07-05～B07-07、B07-14
```

- 键盘：`Tabs` 是 Radix 的 tablist，方向键在标签间移动焦点，Home/End 到首尾，Enter/Space 激活；焦点移入内容区由 Tab 键完成。
- 高亮：当前标签由路径决定，直接打开深层路由（如 `/settings/modules/:moduleId`）时对应标签为选中态。
- 错误与重试：外壳不拦截错误。各页面沿用原有的加载、错误、重试逻辑（如 Skills 的"Retry loading skills"、模块页的错误提示）；关于页读取失败时调用 `handleError` 并显示"重试"按钮（B07-17）。
- 顶部导航的 Settings、Modules 链接不变。

设置内的 Provider 入口直接渲染现有 `src/pages/ProviderManagement.tsx`，行为、确认对话框（`Modal`）、错误提示与测试以 [V1-FR-001](../01-底层能力/01-Provider适配框架.md) 和 `tests/provider-management.test.tsx` 为准。原草案中的 `invoke('create_provider')`、`confirm()` 示例不再适用，已删除；B07-08～B07-11 映射到该页面的现有行为。

### 7.3 外观设置界面

```typescript
// D071 的目标形态草图；实现见 src/pages/AppearanceSettings.tsx，差异见本节末说明。只用 @dgos/ui 已导出的接口，不调用 invoke。
import { useState } from 'react';
import {
  Button, Card, Input, RadioGroup, Stack, toast,
  getCurrentDensity, getCurrentTheme, updateAppearance,
} from '@dgos/ui';

const THEME_OPTIONS = [
  { value: 'light', label: '亮色' },
  { value: 'dark', label: '暗色' },
  { value: 'auto', label: '跟随系统' },
] as const;
const DENSITY_OPTIONS = [75, 100, 125, 150, 175].map(d => ({ value: String(d), label: `${d}%` }));

export const AppearanceSettings: React.FC = () => {
  // 控件显示值：选择时先显示所选值，写入结束后重新读取控制器的已确认值。
  const [theme, setTheme] = useState(getCurrentTheme());
  const [density, setDensity] = useState(getCurrentDensity());
  const settle = () => { setTheme(getCurrentTheme()); setDensity(getCurrentDensity()); };

  // B07-12: 切换主题（失败时控制器已回退并发出错误 Toast，页面不重复提示）
  const handleThemeChange = (value: string) => {
    setTheme(value as typeof theme);
    void updateAppearance({ theme: value as typeof theme }).finally(settle);
  };

  // B07-13: 调整界面缩放（D064，原"字体大小"和"紧凑模式"并入此项）
  const handleDensityChange = (value: string) => {
    setDensity(Number(value) as typeof density);
    void updateAppearance({ density: Number(value) as typeof density }).finally(settle);
  };

  return (
    <Stack gap="lg">
      <h2>外观设置</h2>
      <RadioGroup label="主题" options={THEME_OPTIONS} value={theme} onChange={handleThemeChange} />
      <RadioGroup label="界面缩放" options={DENSITY_OPTIONS} value={String(density)} onChange={handleDensityChange} />
      {/* 预览区：真实组件随主题与缩放变化；不含壁纸选择（D064） */}
      <Card>
        <Stack gap="md">
          <Button variant="primary">主要按钮</Button>
          <Button variant="secondary">次要按钮</Button>
          <Input label="输入框示例" placeholder="输入框示例" />
          <Button variant="secondary" onClick={() => toast.info('这是一条示例通知')}>显示通知</Button>
        </Stack>
      </Card>
    </Stack>
  );
};
```

说明：`updateAppearance` 在写入队列空闲时结束；控制器在写入失败时已回退界面并通过 `onWriteError` 发出错误 Toast，所以页面只负责在结束后让控件回到已确认值。实现与草图的差异：标题用 `h1`；布局用 `Card`、`Card.Body` 与数值 `gap` 的 `Stack`；选项来自 `THEMES`、`DENSITIES`；挂载时等待 `initAppearance()` 再读取已确认值；`updateAppearance` 的意外拒绝交给 `usePageError`。组件属性以 `@dgos/ui` 的实际类型为准。

## 8. 错误码设计

系统设置主要是调用其他功能的接口，错误码复用对应功能的错误码。

| 错误码 | 错误信息 | 场景 | 用户操作建议 |
| --- | --- | --- | --- |
| 1007001 | settings_load_failed | 加载设置失败 | 刷新页面 |
| 1007002 | settings_save_failed | 保存设置失败 | 重试 |

其他错误码见：
- Provider 错误：V1-FR-001
- Skills 错误：V1-FR-002
- MCP 错误：V1-FR-003
- 模块错误：V1-FR-004

错误码以当前接口契约及对应底层功能定义为准。本节表格与 [V1 错误码](../../../04-技术架构/当前版本/V1-错误码.md) 不一致：错误码文档把 1007001、1007002 登记为 `config_key_not_found`、`invalid_config_value`（通用设置键接口的错误），本节写的是 `settings_load_failed`、`settings_save_failed`。两者都没有代码使用。本阶段（D085）的外壳、关于页与局域网占位页不需要设置专属错误码，所以不在本次裁定这一冲突，留待需要设置专属错误时再决策。关于页读取失败没有错误码，走 `handleError` 的通用提示。
