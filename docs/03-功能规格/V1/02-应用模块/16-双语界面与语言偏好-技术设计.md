# V1-FR-016：双语界面与语言偏好 - 技术设计

来源：[需求](16-双语界面与语言偏好.md#5-需求说明) · [接口](16-双语界面与语言偏好.md#6-接口契约) · [数据](16-双语界面与语言偏好.md#7-数据与事务) · [验收](16-双语界面与语言偏好.md#8-验收标准)

## 1. 风险与对策

| 风险 | 严重程度 | 对策 | 关联决策 |
| --- | --- | --- | --- |
| 主机偏好在登录前不可用 | 高 | 语言服务独立于账户会话，首帧先初始化，读取失败使用 `zh-CN` | D118 |
| 主题/缩放/语言并发写入互相覆盖 | 高 | 语言使用独立 typed command 和 host_settings key；前端语言队列与外观队列隔离 | D065、D118 |
| 快速切换产生旧写入覆盖新选择 | 高 | 单主机语言写队列、版本序列号和提交后确认；过期结果不得覆盖当前状态 | D118 |
| 局域网远程端与桌面端语言不一致 | 高 | LAN 使用同一 LocaleService 的解析结果，通过无敏感 bootstrap 返回 locale | D118 |
| 动态模块继续硬编码另一种语言 | 中 | `host.i18n` 只读订阅契约、随包模块迁移和 i18n 静态检查 | D067、D118 |
| 英文长文案破坏布局和无障碍 | 中 | 资源 key 检查、缩放矩阵、真实 WebView 与人工无障碍清单 | D069、D118 |

## 2. 组件和数据流

```text
host_settings.ui.language
        │
        ▼
LocaleService（host preference + system locale adapter）
        ├── get_language_preferences / set_language_preferences
        ├── desktop bootstrap → LocaleRuntime → React pages / errors / formatters
        ├── LAN bootstrap → remote LocaleRuntime
        └── host.i18n → trusted dynamic modules
```

LocaleService 只维护一个主机级已确认偏好和一个解析后的 `Locale`。它不持有用户会话、不翻译业务数据、不接受 renderer 提供的用户标识。

## 3. 单元契约

| 函数 | 前置条件 | 返回 / 后置条件 | 副作用 | 幂等 |
| --- | --- | --- | --- | --- |
| `read_language_preferences() -> LanguagePreferences` | 宿主数据库可读 | 返回合法 preference、resolved locale 和 catalog version；缺失时返回默认 `zh-CN` | 只读 `host_settings` | 是 |
| `set_language_preference(preference) -> LanguagePreferences` | preference 在闭合枚举中 | 单行 upsert 成功后返回完整确认状态 | 写 `host_settings.ui.language`，发布 locale 变化 | 相同值重复写入结果相同 |
| `resolve_system_locale(os_locales) -> Locale` | 输入来自受信平台 locale provider | 中文/简体变体返回 `zh-CN`，其余返回 `en-US` | 无 | 是 |
| `translate(key, params) -> string` | key 已在当前资源登记 | 返回当前 locale 文案；缺失 key 在检查阶段失败 | 无 | 是 |
| `formatDateTime(value, locale) -> string` | value 可被 `Intl` 接受 | 按 locale 格式化 | 无 | 是 |
| `get_lan_bootstrap() -> LocaleBootstrap` | LAN 服务已初始化 | 只返回 resolved locale 和 catalog version | 无 | 是 |

## 4. 伪代码

### 4.1 读取和初始化

```text
FUNCTION load_locale() -> LanguagePreferences:
  raw = host_settings.get("ui.language")                         // B16-01
  IF raw is missing: preference = "zh-CN"                         // B16-02
  ELSE IF raw is not one of {"zh-CN", "en-US", "system"}:       // B16-03
    log sanitized invalid preference
    preference = "zh-CN"
  ELSE: preference = raw                                            // B16-04

  IF preference == "system":                                      // B16-05
    locale = resolve_system_locale(platform_locale_provider())
  ELSE: locale = preference                                        // B16-06

  RETURN { preference, locale, catalog_version: CURRENT }          // B16-07
```

### 4.2 保存和发布

```text
FUNCTION save_locale(requested, revision) -> LanguagePreferences:
  IF requested is invalid or request has extra fields:              // B16-08
    RETURN Err(invalid_language_preference)
  IF revision is older than latest accepted revision:               // B16-09
    RETURN latest_confirmed

  BEGIN TRANSACTION
    UPSERT host_settings("ui.language", requested)                 // B16-10
  COMMIT

  confirmed = load_locale()                                        // B16-11
  publish_locale(confirmed.locale, confirmed.preference)            // B16-12
  RETURN confirmed
```

If the transaction or reload fails, do not publish the requested locale; return a stable internal error and retain the last confirmed state. The renderer rolls back its optimistic view.

### 4.3 Remote bootstrap

```text
FUNCTION lan_bootstrap() -> LocaleBootstrap:
  TRY:
    state = locale_service.current()                               // B16-13
    RETURN { locale: state.locale, catalog_version: state.version }
  CATCH:
    RETURN safe_bootstrap_error_without_internal_detail             // B16-14
```

The remote SPA starts with deterministic `zh-CN` copy, requests bootstrap, and switches to the returned `locale` before rendering the main remote view. The bootstrap response never includes the preference value, user ID, database path, or error detail.

## 6. 并发控制

| 场景 | 冲突点 | 控制方式 | 失败策略 |
| --- | --- | --- | --- |
| 用户快速连续切换语言 | 多个 renderer 写入和旧响应回到前端 | LocaleRuntime 单写队列；每个请求带单调 revision，过期响应丢弃 | 回到最近宿主确认值并显示一次错误 |
| 主题/缩放与语言同时变化 | 不同偏好写入不同存储作用域 | 语言命令不调用 AppearanceRepository；各自独立事务和状态机 | 只回滚失败的偏好 |
| 远程页面读取时主机切换语言 | bootstrap 值与主机当前值的时间差 | bootstrap 以读取时的已确认值为准；页面重载获取新值 | 不强制推送，避免新增远程事件协议 |
| 动态模块订阅/卸载同时发生 | listener 泄漏或卸载后更新 | subscribe 返回一次性 unsubscribe；宿主在模块卸载时清理订阅 | 不向已卸载模块发送更新 |

死锁预防：语言设置事务只操作单个 host_settings key，不在事务内执行网络调用、资源加载或模块回调；发布通知发生在提交之后。

## 7. 事务边界

- 范围：单次 `ui.language` upsert。
- 隔离级别：沿用 SeaORM/SQLite 默认事务隔离；单 key 唯一约束保证最后一次已提交值明确。
- 失败回滚：upsert 失败时不发布新 locale，renderer 回退；不写默认值，不触碰其他 host_settings。
- 资源包不是事务数据，不写 SQLite，也不接受运行时远程更新。

## 8. 幂等与重试

- 幂等键：`host_settings.setting_key = ui.language`。
- 同一偏好重复提交：返回同一已确认状态，不重复创建数据。
- 读取失败：一次启动读取使用默认 `zh-CN`，不无限重试。
- 保存失败：前端允许用户再次选择并提交；不自动重放旧请求。
- bootstrap 失败：远程端保留后备语言并允许重新加载；不把内部异常转为成功的主机语言。

## 9. 外部调用与补偿

无业务外部调用。`system` 的平台语言读取属于本机平台适配，不访问网络；LAN bootstrap 是本机 LAN 服务的只读响应，不调用第三方服务。无需补偿任务。

## 10. 安全与日志

- `ui.language` 不属于敏感数据，但远程 bootstrap 仍只返回解析语言和资源版本。
- 不记录用户输入、账户标识、Provider 凭据、远程 Cookie 或原始异常详情。
- 桌面命令使用受信主窗口和宿主派生上下文；局域网端不能调用桌面语言写命令。
- 动态模块只能读取 `host.i18n`，不能获得 host_settings 写入能力。
- 资源 key 和插值参数必须经过静态检查；用户内容作为参数传入时必须按 React 文本或安全格式化路径渲染。

## 11. 发布与回滚

- 前置条件：中英文资源 key 完整；桌面、远程和随包模块的静态检查通过；旧数据库缺失 `ui.language` 的默认行为测试通过。
- 数据回滚：删除 `ui.language` 记录即可回到默认简体中文；不需要 migration 回滚。
- 代码回滚：旧版本忽略未知 host_settings key，不影响既有主题、缩放和局域网设置。
- 监控指标：语言读取失败次数、写入失败次数、bootstrap 失败次数只记录无敏感计数和错误分类，不记录文案输入。
- 低风险分阶段：先实现桌面运行时和设置页，再接入远程 bootstrap，最后启用随包模块语言订阅；任何阶段都不能宣称全功能双语验收已通过。
