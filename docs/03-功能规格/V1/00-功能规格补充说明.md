## 2. 并发场景补充

所有涉及外部调用或状态修改的功能，需要补充并发场景说明。

### 2.1 Provider 适配框架（V1-FR-001）

**并发场景 1：多个用户同时调用同一 Provider**
- **冲突点**：API Key 使用次数、速率限制
- **控制方式**：无锁设计，每个请求独立
- **预期行为**：所有请求正常处理，Provider 端可能触发速率限制
- **失败策略**：429 错误时自动重试（指数退避）

**并发场景 2：多个请求同时写入 provider_usage_logs**
- **冲突点**：数据库写入
- **控制方式**：SQLite 内置锁，ACID 保证
- **预期行为**：所有写入成功，顺序不保证
- **失败策略**：写入失败记录错误日志

**性能目标**：
- 100+ QPS 并发调用不崩溃
- 单个 Provider 调用延迟 < 30s（主要取决于上游 API）

### 2.2 Skills 管理系统（V1-FR-002）

**并发场景 1：多个用户同时调用同一 HTTP Skill**
- **冲突点**：Skills 服务端负载
- **控制方式**：无锁设计，Skills 服务自行处理并发
- **预期行为**：所有请求转发到 Skills 服务
- **失败策略**：Skills 超时或失败时记录错误

**并发场景 2：用户 A 更新 Skill 时，用户 B 调用该 Skill**
- **冲突点**：文件替换、进程重启
- **控制方式**：更新时先禁用 Skill（原子操作）
- **预期行为**：用户 B 调用失败，提示"Skill 正在更新"
- **失败策略**：更新失败时回滚到备份版本

**性能目标**：
- 50+ QPS 并发 Skill 调用不崩溃
- Skills 服务启动时间 < 5s

### 2.3 MCP 管理系统（V1-FR-003）

**并发场景：多个用户同时调用同一 MCP 工具**
- **冲突点**：MCP 服务端负载
- **控制方式**：无锁设计，MCP 服务自行处理
- **预期行为**：所有请求转发到 MCP 服务
- **失败策略**：超时或失败时记录错误

**心跳检测**：
- 每 30s 发送 ping，3 次超时后认为断线
- 断线后自动重连（最多 5 次）

### 2.4 模块系统与热更新（V1-FR-004）

**并发场景：用户 A 热重载模块时，用户 B 调用该模块**
- **冲突点**：模块代码替换
- **控制方式**：引用计数，等待所有调用完成后卸载
- **预期行为**：用户 B 使用旧版本直到调用完成，下次调用使用新版本
- **失败策略**：重载失败时保留旧版本

**性能目标**：
- 模块加载时间 < 1s
- 模块热重载无需重启应用

### 2.5 本地用户管理（V1-FR-008）

**并发场景：用户 A 登录时，用户 B 同时登录**
- **冲突点**：会话创建、Token 生成
- **控制方式**：无锁设计，每个会话独立
- **预期行为**：两个用户同时登录成功
- **失败策略**：生成 Token 失败时重试

### 2.6 局域网协同（V1-FR-010）

**并发场景：多个远程设备同时连接**
- **冲突点**：WebSocket 连接数、内存占用
- **控制方式**：无锁设计，每个连接独立
- **预期行为**：所有设备同时连接成功
- **失败策略**：连接失败时客户端重试

**性能目标**：
- 支持 10+ 并发连接
- WebSocket 心跳每 30s，断线自动重连

## 4. 分支追踪表强化

所有包含伪代码的功能规格，分支追踪表必须包含"风险级别"列：

### 标准格式

```markdown
| 分支编号 | 分支描述 | AC 映射 | E2E 映射 | NFR 映射 | 风险级别 |
|---------|---------|---------|---------|---------|---------|
| B01-01 | 查询 Provider 配置 | AC01, AC12 | V1-E2E-01 | - | 低 |
| B01-04 | 重试循环主逻辑 | AC09, AC10 | - | V1-NFR-001 | 🔴 高 |
| B01-08 | 429 速率限制重试 | AC09 | - | V1-NFR-001 | 🔴 高 |
```

### 风险级别定义

- **🔴 高**：涉及金钱、权限、加密、外部回调、复杂并发、事务边界
- **🟡 中**：涉及网络调用、文件操作、状态转换
- **🟢 低**：纯计算、读取、简单转换

### 高风险分支说明

每个高风险分支必须在表格下方补充说明：

```markdown
**高风险分支说明**：
- 🔴 **B01-04**: 重试循环是可靠性核心，必须充分测试边界（0次、1次、3次重试）
- 🔴 **B01-08, B01-09**: 各种错误的重试逻辑，容易出现死循环或过早放弃
```
