## 2. 功能概述

### 2.1 一句话描述

建立完整的 Design Tokens 体系、主题系统、密度系统、基础组件库和错误通知规范，所有模块强制复用，确保 DGOS 全局视觉和交互的完全一致性。

### 2.2 详细说明

统一设计系统是 DGOS 的**视觉和交互基础设施**，定义了从原子级别（颜色、字号）到分子级别（组件）再到有机体级别（错误处理、通知）的完整规范。

**核心价值**：
- ✅ **原子化设计**：Design Tokens 定义所有视觉基础变量
- ✅ **主题系统**：亮色、暗色、跟随系统；自定义主题属于 V2
- ✅ **密度系统**：5 档界面缩放（75%–175%），适应不同用户偏好
- ✅ **组件库**：13 个基础组件（含 Tabs），统一样式和交互
- ✅ **错误与通知**：统一的错误处理和通知样式
- ✅ **强制复用目标**：设计令牌、组件约束和 `design:check` 静态检查

**用户价值**：
- 视觉一致：全局统一的外观
- 个性化：可调节主题、字号、密度
- 无障碍：按 §15.2 的检查项达到 WCAG 2.1 AA 的相应目标（不声明整体符合，见 D069）

**从老项目学到的教训**：
- ❌ 老项目：内联样式、重复组件、视觉不一致
- ✅ DGOS：Design Tokens、强制复用、全局一致

### 2.3 功能边界

**Design Tokens（设计令牌）**：
- ✅ 色彩系统（主题色、语义色、中性色、透明度，含成对前景令牌，§4.1.5）
- ✅ 字体系统（字体家族、字号、行高、字重）
- ✅ 间距系统（4px 基准、倍数规则）
- ✅ 圆角系统（4px、8px、12px、16px、9999px）
- ✅ 阴影系统（sm、md、lg、xl）
- ✅ 动画系统（过渡时长、缓动函数）

**主题系统**：
- ✅ 亮色模式（Light）
- ✅ 暗色模式（Dark）
- ✅ 跟随系统（Auto，D064）
- ✅ 主题持久化（宿主保存，D065）

**密度系统**（语义是"界面缩放"，只改根字号）：
- ✅ 5 种级别：更紧凑（75%）、标准（100%）、较大（125%）、大（150%）、更大（175%）
- ✅ 字号与间距用 rem，随根字号缩放
- ✅ 最小有效字号（拟 11px，Phase 1 校准）

**基础组件库（13 个）**：
- ✅ Button、Input、Select、Checkbox、Radio、Switch、Modal、Toast、Card、Tooltip、Loading、Divider、Tabs
- ✅ `Input` 的多行形态；极小的布局原语 `Stack`（只有 `gap` 枚举，不计入 13 个）
- ✅ 命令式 API：`toast.*` 与 `Modal.confirm/alert/error`（属于 Toast 与 Modal，不另计组件数）
- ✅ 5 个状态图标：success、error、warning、info、close（内置 SVG，`currentColor`）
- ✅ 实现栈：Shadcn/ui 组件源码纳入仓库自行维护，Radix 提供行为原语，Tailwind 提供样式（D066）

**错误处理与通知体系**：
- ✅ Toast 通知（4 种类型：成功、错误、警告、信息）
- ✅ Modal 对话框（确认、警告、表单）
- ✅ Inline 错误提示（表单验证）
- ✅ `ErrorPage`（404 与通用错误）和路由兜底
- ✅ 错误码到文案的映射（只含登记处"使用中"的码）

**强制复用机制**：
- ✅ `npm run design:check` 加存量清单（D068）
- ✅ 代码审查检查点
- ✅ 动态模块通过继承的 CSS 变量和 `host.ui` 使用统一组件（D067）

**不包含**（明确说明原因）：
- ❌ 自定义主题（壁纸取色） → V2（D064）
- ❌ 断点系统与移动端响应式 → V6；V1 只保证 800px 最小窗口宽度下不重叠、不溢出
- ❌ 复杂业务组件（Table、Chart） → V2 根据需求扩展
- ❌ 动画库（Framer Motion） → 使用 CSS transitions
- ❌ 图标库 → V1 只有 5 个状态图标，其余 V2（D064）
- ❌ 国际化 i18n → V2
- ❌ 网络断开、数据库连接失败等错误页 → 没有宿主事件来源，不在 V1
- ❌ 独立发布的 npm 包与 workspace → V1 用 `src/ui/` 加路径别名 `@dgos/ui`（D066）；图标包也不引入（D064）

## 3. 核心流程

### 3.1 主题切换流程

```
用户打开系统设置 → "外观"
  ↓
选择主题：亮色 / 暗色 / 自动（跟随系统）
  ↓
前端先把根元素 data-theme 设为解析后的值（auto 取系统外观）
  ↓
所有组件通过 CSS 变量立即呈现新主题
  ↓
调用 set_appearance_preferences 保存
  ├─ 成功 → 记为已确认值
  └─ 失败 → 回退到上一个已确认值，显示错误 Toast（AC21）
  ↓
下次启动：读取偏好，首次显示界面前就应用（AC02）
```

### 3.2 密度调整流程

```
用户打开系统设置 → "系统缩放"
  ↓
选择密度：75% / 100% / 125% / 150% / 175%
  ↓
前端先把根元素 data-density 设为所选值，属性选择器改变根字号
  ↓
所有使用 rem 的尺寸同比缩放
  ↓
调用 set_appearance_preferences 保存（失败处理同 3.1）
```

### 3.3 错误通知流程

```
用户操作失败（如 Provider 调用失败）
  ↓
宿主返回数值错误码 1001001
  ↓
前端查映射表（§8.2）
  ├─ 已登记 → 取文案、建议与严重程度
  └─ 未登记 → "操作失败（错误码 N）"
  ↓
按严重程度显示
  ├─ minor / moderate → Toast（3 秒 / 5 秒，悬停或聚焦时暂停）
  └─ severe → Modal，等待用户确认
```

### 3.4 开发者使用组件流程

```
开发者开发新页面
  ↓
导入统一组件：import { Button } from '@dgos/ui'（别名，D066）
  ↓
使用组件：<Button variant="primary">确定</Button>
  ↓
组件自动使用当前主题和密度
  ↓
违反样式约束时 npm run design:check 报告（D068）

动态模块不能 import，从 host.ui 取组件（D067）
```

| 配对 | 亮色 | 暗色 | 门槛 |
| --- | --- | --- | --- |

| `text-secondary` 对 `bg-primary` / `bg-tertiary` | 7.56 / 6.87 | 6.49 / 4.76 | 4.5 |
| `text-tertiary` 对 `bg-primary` / `bg-secondary` | 4.83 / 4.63 | 5.33 / 4.64 | 4.5 |

### 4.7 Tailwind 主题映射（D066，Phase 1 spike 结论）

实现在 `src/ui/styles.css`（入口）、`src/ui/tokens/*.css`（令牌）与 `src/ui/tailwind.css`（映射）。用 Tailwind 4.3.3 的真实编译器验证过（`tests/design-tokens.test.tsx`），并在真实 WKWebView 中读取计算样式（V1 实现状态的 Phase 1 证据）。

**结论**

| 问题 | 结论 |
| --- | --- |
| 14px 根字号 | Tailwind 4 的间距是 `calc(var(--spacing) * N)`，字号取自 `--text-*`。把 `--spacing` 映射到 `--spacing-unit`（`calc(4rem / 14)`）、`--text-*` 映射到 `--font-size-*` 后，编译产物里 `p-2` 是 `calc(var(--spacing-unit) * 2)`，`text-sm` 读 `--font-size-sm`（编译测试）。WKWebView 中实测这些变量：100% 档 `--spacing-2` 为 8px、`text-sm` 对应的 `--font-size-sm` 为 13px，其余四档随根字号同比缩放。`p-2` 这个类本身没有在 WebView 里量过（生产包只含被用到的工具类） |
| 清空默认色板 | 不导入 `tailwindcss/theme.css`（也就没有默认色板、断点、容器尺寸），并在 `colors.css` 写 `--color-*: initial`。`bg-white`、`text-red-500`、`sm:p-2` 都不会生成（测试覆盖）。后果：没有 `sm:` 等断点变体（与 D064 一致），没有 `max-w-lg` 之类的容器尺寸与 `animate-*`，P4/P5 需要时再显式加 |
| 不导入 preflight | `styles.css` 只导入 `tailwindcss/utilities.css`。preflight 会重置全部现有页面的按钮、标题样式，页面迁移属于 Phase 7 |
| 层 | 工具类在 `@layer utilities`。`App.css` 里未分层的 `button`、`input`、`h1`、`p` 选择器曾压过工具类；Phase 7 已删除 `App.css`，该冲突已消失。`index.css` 的通配重置已移入 `@layer base`，否则它会压掉所有 `p-*`/`m-*` |
| 同名别名陷阱 | `@theme inline { --color-primary: var(--color-primary) }` 会输出自引用的无效自定义属性。令牌与 Tailwind 键同名的（颜色、圆角、阴影、缓动、字重、透明度）直接写在 `@theme static`，名字不同的才用 `@theme inline` 映射。测试断言编译产物里没有自引用 |
| 令牌是否输出 | 默认只输出被用到的主题变量；动态模块需要全部令牌，所以同名令牌用 `@theme static`，其余写在 `:root`（始终输出） |
| 暗色覆盖 | 暗色值写在未分层的 `:root[data-theme="dark"]`，优先于 Tailwind 输出的主题变量，工具类读 `var(--color-*)`，因此切换主题不需要重新生成工具类 |
| 不透明度修饰符 | `bg-primary/50` 编译为 `color-mix(in srgb, #2563eb 50%, transparent)` 加 `@supports (color: color-mix(in lab, red, red))` 内的 `color-mix(in oklab, var(--color-primary) 50%, …)`。前一行把**亮色字面值**写进了回退规则，WKWebView 支持 `color-mix`（实测）所以实际走后者，但这条回退在暗色下是错的。组件避免使用 `/N` 修饰符，用 `--opacity-*` 或专门的令牌 |
| 阴影 | 阴影颜色以 `rgb(0 0 0 / var(--shadow-alpha-*))` 写入工具类，强度随主题变量变化 |
| 过渡 | `--duration-*` 不是 Tailwind 的主题命名空间（`duration-fast` 不会生成）；只把 `--default-transition-duration` 映射为 `--duration-fast`，`--default-transition-timing-function` 映射为 `--ease-in-out` |
| 工具类的扫描范围 | `@import "tailwindcss/utilities.css" source(none)` 关闭自动扫描，只 `@source` 了 `index.html` 与 `src/`，不扫描文档（文档里有 `bg-[#fff]` 这类反例字符串）与 `bundled-modules/`（D067） |
| tailwind-merge | `cn()` 对令牌命名的颜色、间距、圆角、字号都能正确判断冲突（`text-sm` 与 `text-foreground` 共存，`text-muted-foreground` 被 `text-destructive-foreground` 覆盖），不需要扩展它的配置（测试覆盖） |

**Shadcn 语义色键到 FR-005 令牌**（只作为工具类名存在，运行时没有裸的 `--primary`、`--background` 变量；从 Shadcn 复制来的组件如果直接写 `var(--primary)` 会失效，迁入时必须改成工具类或 FR-005 令牌）：

| Shadcn 键 | FR-005 令牌 | 备注 |
| --- | --- | --- |
| `background` / `foreground` | `bg-primary` / `text-primary` | 页面底与正文 |
| `card` / `card-foreground` | `bg-secondary` / `text-primary` | 已复核（Phase 4）：卡片内常见的 `text-primary`、`text-secondary` 对 `bg-secondary` 已是 §4.1.5 声明的对，`tests/ui-controls.test.tsx` 另计算了组件实际使用的 18 对；一次性计算（未入库）：`error-text`、`success-text` 对 `bg-secondary` 亮 6.19/5.25、暗 7.56/7.47 |
| `popover` / `popover-foreground` | `bg-primary` / `text-primary` | 已复核（Phase 5）：Modal、Tooltip、Select 弹层都用这一对，`text-primary`/`text-secondary`/`*-text` 对 `bg-primary` 亮暗两主题均 ≥ 4.5:1（`tests/ui-overlays.test.tsx`）；Toast 的 `*-text` 对 `*-bg` 是 §4.1.5 声明的对 |
| `primary` / `primary-foreground` | `primary` / `on-primary` | `primary` 与 FR-005 同名，无需别名 |
| `secondary` / `secondary-foreground` | `bg-tertiary` / `text-primary` | |

| `destructive` / `destructive-foreground` | `error` / `on-error` | `on-error` 是 Phase 1 新增（§4.1.5） |
| `input` | `border-control` | 控件边界 |
| `ring` | `focus-ring` | 焦点环 |

**Phase 2 的决定**：Shadcn 模板里的任意值写法一律在迁入时改写。`w-[--radix-select-trigger-width]` 在 Tailwind 4.3.3 下编译为 `width: --radix-select-trigger-width`（缺少 `var()`，是无效 CSS，一次性编译验证，未入测试），正确写法是括号形式 `w-(--radix-select-trigger-width)`，编译为 `width: var(--radix-select-trigger-width)`。因此 R2 禁止方括号形式，括号形式与 `--radix-*` 变量（R3 的运行时前缀）允许。`data-[state=open]:`、`aria-[sort=asc]:` 是变体而不是任意值，允许；其他任意变体（`min-[400px]:`、`supports-[…]:`）与任意选择器（`[&>svg]:`、`[--x:1px]`）禁止，迁入时改写为令牌类或组件 props。

### 4.8 层叠（z-index）

全局层叠只有三个令牌，写在 `src/ui/tokens/scale.css` 的 `@theme static`，对应工具类 `z-modal`、`z-popover`、`z-toast`。只有经 portal 挂到 `<body>` 的浮层使用它们，它们也是唯一大于 49 的 z-index。

| 令牌 | 值 | 使用者 | 为什么在这一层 |
| --- | --- | --- | --- |
| `--z-index-modal` | 50 | Modal 的遮罩与对话框 | 盖住页面 |
| `--z-index-popover` | 60 | Select 弹层、Tooltip | 对话框里的 Select、Tooltip 要显示在对话框之上 |
| `--z-index-toast` | 70 | Toast 区域 | 任何时候都在最上层，包括对话框打开时 |

**0～49 留给页面内部**。页面或画布要给自己的内容分层（连线、节点、选框、协作者光标、小地图）时，在自己的根元素上建立层叠上下文（`isolate`），内部只用 `z-0`～`z-49`。这样页面内部的任何层级都不会盖过对话框；节点里打开的 Select、Tooltip 经 portal 渲染，仍在全局 `z-popover`。这一约定是为 V2 画布预留的，V1 没有使用者。

**旧页面的例外（已在 Phase 7 清除）**：`ProviderManagement.css` 与 `SkillsManagement.css` 的旧弹窗遮罩曾写 `z-index: 1000`，`McpManagement.css` 写过 `20`，`ProviderManagement.css` 另有一处 `50`。这些样式表已删除或不再含 `z-index`，弹窗迁到 `Modal`（`z-modal`）。`design:check` 不检查 z-index 数值，`src/` 中页面代码无 `z-index` 由检索确认，不是由工具保证。

**证据范围**：jsdom 不绘制，测试只能证明组件引用了哪个层叠令牌，以及令牌之间的大小关系（`tests/ui-overlays.test.tsx`、`tests/ui-feedback.test.tsx`）。实际谁盖在谁上面，要在真实 WebView 中验证（Phase 8）。

## 5. 主题系统

### 5.1 主题类型

#### 5.1.1 亮色模式（Light）

**默认主题**，适合白天使用。

**特点**：
- 白色背景（`#FFFFFF`）
- 深色文本（`#111827`）
- 高对比度
- 明亮清爽

#### 5.1.2 暗色模式（Dark）

**护眼主题**，适合夜间使用。

**特点**：
- 深色背景（`#1F1F1F`）
- 浅色文本（`#F9FAFB`）
- 降低蓝光
- 省电（OLED 屏幕）

#### 5.1.3 跟随系统（Auto）

偏好值 `auto` 表示界面外观跟随操作系统。保存的值始终是 `auto`，实际应用的是解析后的 `light` 或 `dark`。

- 只有偏好为 `auto` 时，系统外观变化才会改变界面；选择 `light` 或 `dark` 后系统变化不影响界面（AC25）。
- 监听 `prefers-color-scheme` 的订阅在卸载时必须释放（B05-26）。
- 默认主题是 `light`。`auto` 不是 D008 或 PRD 的内容，是 D064 保留的选项，依据是现有 `index.css` 已经按 `prefers-color-scheme` 渲染。

#### 5.1.4 自定义主题（V2，V1 不做）

壁纸取色和自定义主题属于 V2（D064）。V1 不实现也不留空壳，不在 V1 的 AC 范围内；已登记功能演进矩阵的"V2 设计系统扩展"。

### 5.2 主题切换实现

#### 5.2.1 CSS 变量切换

主题只通过根元素的 `data-theme` 属性和 CSS 属性选择器实现，不写内联样式（D068 R1）：

```css
/* 亮色模式（默认） */
:root {
  color-scheme: light;
  --color-bg-primary: #FFFFFF;
  --color-text-primary: #111827;
  /* …其余 token 见 §4 */
}

/* 暗色模式 */
:root[data-theme="dark"] {
  color-scheme: dark;
  --color-bg-primary: #1F1F1F;
  --color-text-primary: #F9FAFB;
  /* …其余 token 见 §4 */
}
```

这些字面颜色只允许出现在 `src/ui/tokens/**`（D068 R2）。`App.css` 的 `@media (prefers-color-scheme)` 覆盖已随 Phase 7 删除（`index.css` 本来没有）；`src/ui/appearance/controller.ts` 里的 `prefers-color-scheme` 是 `auto` 模式的系统外观监听，不是样式覆盖。

#### 5.2.2 组件响应主题

组件只引用 token，不写字面颜色。主色按钮的前景色使用成对令牌 `--color-on-primary`（D069），不再拿 `--color-bg-primary` 当按钮文字色（原稿写法在亮色模式对比度只有 3.68:1，§4.1.5）。

#### 5.2.3 主题持久化

偏好由宿主保存（D065）：取值 `light`、`dark`、`auto`，默认 `light`。读取、写入、失败回退的行为见 §10、§12、§13.1 与 AC02、AC21。原稿的 `loadTheme()` 示例（`theme || 'light'`）对非法值不做校验，已由 `sanitize` 取代。

### 5.3 主题预览

主题预览是系统设置"外观"页（V1-FR-007）里用真实组件（Button、Input、Card 等）摆出的一块样例区，随主题和密度实时变化。原稿的壁纸选择布局图来自另一个系统的截图，DGOS 没有壁纸功能，已删除。页面布局属于 V1-FR-007，本规格只提供组件。

## 6. 密度系统

### 6.1 密度级别

| 级别 | 缩放比例 | 根字号 | 用途 |
|------|---------|--------|------|
| **更紧凑** | 75% | 10.5px | 最大化内容密度 |
| **标准** | 100% | 14px | 推荐设置 |
| **较大文字** | 125% | 17.5px | 轻度视力障碍 |
| **大文字** | 150% | 21px | 中度视力障碍 |
| **更大文字** | 175% | 24.5px | 重度视力障碍 |

**UI 设计**（参考你提供的截图）：

```
系统缩放
调整菜单、窗口、桌面图标和应用内容的大小，
适配不同尺寸与分辨率的屏幕。

┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
│ 更多   │  │ 标准   │  │ 较大   │  │ 大文字 │  │ 更大   │
│ 空间   │  │        │  │ 文字   │  │        │  │ 文字   │
│ [  ]   │  │ [✓]    │  │ [  ]   │  │ [  ]   │  │ [  ]   │
│ 75%    │  │ 100%   │  │ 125%   │  │ 150%   │  │ 175%   │
└────────┘  └────────┘  └────────┘  └────────┘  └────────┘
```

**最小有效字号**：75% 档的根字号是 10.5px，`--font-size-xs`（12px 基准）会降到 9px，见 §6.2.3。

### 6.2 实现方式

#### 6.2.1 根字号缩放（属性选择器）

密度只通过根元素的 `data-density` 属性和 CSS 属性选择器实现，不写内联样式（D068 R1）。原稿的 `style.fontSize = …` 写法与 §9 的禁令冲突，已删除。

```css
html { font-size: 14px; }                          /* 100% */
html[data-density="75"]  { font-size: 10.5px; }
html[data-density="125"] { font-size: 17.5px; }
html[data-density="150"] { font-size: 21px; }
html[data-density="175"] { font-size: 24.5px; }
```

#### 6.2.2 使用 rem 单位

字号、间距、圆角、组件尺寸用 `rem`，自动跟随根字号：

```tsx
// 类名只是示意，实际名称见 §7.2.1；字号、间距、圆角都来自 token，随根字号缩放
<button className="text-base px-4 py-2 rounded-sm">确定</button>
```

#### 6.2.3 最小有效字号

75% 档下 `--font-size-xs` 是 9px。token 层的最小有效字号为 11px（D064，Phase 1 已实现并在真实 WKWebView 校准）：八个字号 token 都是 `max(calc(Nrem / 14), var(--font-size-min))`，`--font-size-min: 11px`；不通过抬高基准字号解决。

实测（WKWebView，`webview_smoke_appearance`，字号 px）：

| 档位 | xs | sm | base | lg | xl | 2xl | 3xl | 4xl |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 75%（根 10.5px） | 11 | 11 | 11 | 12 | 13.5 | 15 | 18 | 22.5 |
| 100%（根 14px） | 12 | 13 | 14 | 16 | 18 | 20 | 24 | 30 |
| 175%（根 24.5px） | 21 | 22.75 | 24.5 | 28 | 31.5 | 35 | 42 | 52.5 |

75% 档下 `xs`、`sm`、`base` 压平为同一个 11px：下限对所有 token 一视同仁是最简单的做法，代价是该档位下辅助文字与正文没有字号差。若评审认为不可接受，备选是按比例保留层级（例如 `xs` 11、`sm` 11.5、`base` 12），但这会让 75% 档的正文大于 `14 × 0.75`，与"界面缩放"的语义不一致，所以暂不采用，需要用户裁定时再开决策。

下限只保护使用 token 的文字。Phase 7 之前的旧页面 CSS 直接写 `rem`/`px`，已随迁移删除；Phase 8 在 macOS WKWebView 对 8 条路由量过，75% 档有文字的元素最小字号为 11px，没有低于下限。

#### 6.2.4 布局约束

窗口最小尺寸是 800×600（`tauri.conf.json`）。175% 档的根字号是 24.5px，800px 宽只有约 32.7rem。固定宽度的组件必须同时受视口限制，例如 Modal 宽度取 `min(上限 rem, 100vw 减两侧间距)`。jsdom 不做布局，溢出和重叠只能在真实 WebView 验证（AC03、§11.2）。

#### 6.2.5 根字号基准：保持 14px（D064）

用户确认保持 14px。旧页面的 CSS 曾大量使用 `rem`（`ProviderManagement.css` 约 222 处）并按浏览器默认的 16px 渲染，整体比设计小约 12.5%，这一后果已被接受；Phase 7 已删除这些样式表，页面改用 token 与工具类。Tailwind 的间距与字号按 `rem`、以 16px 根字号为准（Phase 1 spike 在 `tailwindcss` 4.3.3 的编译产物中确认：间距是 `calc(var(--spacing) * N)`，没有覆盖时 `p-2` 为 0.5rem），根字号是 14px 时已在主题里覆盖：`--spacing` 映射到 `calc(4rem / 14)`，`--text-*` 映射到 `--font-size-*`（§4.7）。真实 WKWebView 实测 100% 档：根 14px、`--spacing-unit` 4px、`--spacing-2` 8px、`--radius-md` 8px、字号 12/13/14/16/18/20/24/30；125%/150%/175%/75% 档的根字号与间距按 1.25/1.5/1.75/0.75 同比缩放。注意实测读取的是工具类所引用的变量，生产包里只有被用到的工具类（Phase 1 时只有 `bg-background`、`text-foreground`），所以 `p-2` 这个类本身没有在 WebView 里量过，由编译测试证明它等于 `calc(var(--spacing-unit) * 2)`；Phase 7 之后页面用到的工具类大量增加，仍未在 WebView 量过。§4.2.2、§4.3、§6.1 的 rem 列按 14px 书写。

### 6.3 密度持久化

密度由宿主保存，见 §10 与 D065。界面读取失败时使用 100%，写入失败时回退到上一个已确认值（AC21）。原稿此处用 `parseInt(density) || 100` 和直接写 `style.fontSize` 的代码已删除。

**类型**：
- `success`：成功（绿色）
- `error`：错误（红色）
- `warning`：警告（黄色）
- `info`：信息（蓝色）

**示例**：

**样式规范**：
```css
.toast {
  min-width: 300px;
  padding: var(--spacing-3) var(--spacing-4);
  border-radius: var(--radius-md);
  box-shadow: var(--shadow-lg);
```

**注意**：上面的 `color: var(--color-success)` 在亮色模式对 `--color-success-bg` 只有 2.24:1（§4.1.5）。实现使用成对的 `--color-success-text` 等文本令牌，不直接拿语义色做文字。

**动画**：
- 出现：从右侧滑入（`translateX(100%)` → `translateX(0)`）

### 7.2 组件开发规范

#### 7.2.1 强制使用 Design Tokens

❌ **禁止**（Tailwind 任意值、字面颜色、内联样式）：
```tsx
<button className="bg-[#3B82F6] p-[13px]" style={{ color: '#fff' }}>确定</button>
```

✅ **正确**（类名来自映射到 token 的主题）：
```tsx
<button className="bg-primary text-primary-foreground px-4 py-2">确定</button>
```

类名只是示意，实际名称由 Phase 1 的主题映射 spike 确定。主题只在 `@theme` 中映射 FR-005 的 token，清空 Tailwind 默认色板，禁止任意值写法；组件不接受 `style` 属性，不用内联样式（D068 R1）。原稿的 `styled-components` 示例和此前草案的 `dg-` 类名前缀都不再使用。

#### 7.2.2 响应主题和密度

颜色、字号、间距、圆角全部来自 token，尺寸用 rem（§6.2）。组件不监听主题或密度的变化，只读取 CSS 变量。根字号保持 14px 时 Tailwind 的默认 rem 换算要覆盖（§6.2.5）。

#### 7.2.3 无障碍性（A11y）

D069 取代原稿的"每个组件都写 aria-label"：可见文字与 `aria-label` 不一致违反 WCAG 2.5.3。

- 可访问名称：来自可见文字或关联的 `<label>`；`aria-label` 只用于纯图标控件。
- 状态用原生属性或 ARIA 表达：`disabled`、`aria-busy`、`aria-invalid`、`aria-checked`、`aria-expanded`。
- 键盘：原生 `button`、`input` 已处理 Enter 与空格，不重复写键盘处理；Modal、Tooltip、Select、Tabs 的焦点与键盘行为来自对应的 Radix 原语，仍由 AC 逐项验证，不因使用原语而默认成立。
- 焦点指示：使用 `focus-visible` 变体与 `--color-focus-ring`（对比度 ≥ 3:1）；不得使用 `outline-none` 而不配对 `focus-visible` 样式（AC24）。

```tsx
// 有可见文字：不需要 aria-label
<Button variant="danger" loading={isDeleting}>删除</Button>
// 纯图标：必须有 aria-label；图标是内置 SVG，不引入图标包
<Button variant="ghost" aria-label="关闭"><CloseIcon /></Button>
```

#### 7.2.4 Phase 4 的接口取舍

下列是 Phase 4 实现时定下的细节，规格正文没有写明，按这里为准。组件位于 `src/ui/components/`，从 `@dgos/ui` 导出。

| 项目 | 取舍 |
| --- | --- |
| 可访问名称的类型 | `Input`、`Select`、`Checkbox`、`RadioGroup`、`Switch` 的 props 是三选一的互斥联合：可见 `label`，或 `aria-label`，或 `aria-labelledby`；缺名称、同时给两项都是类型错误。`Loading` 要求 `label` 与 `aria-label` 二选一，不能同时出现，避免名称与可见文字不一致（D069）。`Button` 的 `iconOnly` 形态在类型上要求 `aria-label`。运行时再处理一次，因为模块代码是没有类型的 JS（D067）：有可见 `label`（`undefined`、`null`、布尔值、空串不算可见；`0` 算）时，丢弃 `aria-label` 与 `aria-labelledby`，名称只来自可见文字，否则 `aria-label` 会覆盖它（WCAG 2.5.3）；没有可见 `label` 而两者同时给出时，`aria-labelledby` 优先，与 accname 的取值顺序一致。实现在 `src/ui/lib/props.ts` 的 `hasVisibleLabel` 与 `accessibleName`，Input（含多行）、Select、Checkbox、RadioGroup、Switch、Loading 共用。类型约束由 `tsc` 检查，`tests/` 不在 `tsc` 范围内，所以测试里的 `@ts-expect-error` 只在手工运行带测试文件的 `tsc` 时生效，不属于 `npm run build` 的证据 |
| `style` | 类型上去掉（`Omit<…, 'style'>`），运行时再丢弃一次（`omitStyle`），因为模块代码是没有类型的 JS（D067）。`className` 保留，类名受 `design:check` 约束。Radix 在 `radiogroup`、`tablist` 容器上自己写 `outline: none` 的内联样式，不属于调用方传入，也不在扫描范围（§9.1） |
| `Button` | 默认 `type="button"`，避免表单内误提交。`loading` 不设 `disabled`：按钮保持可聚焦，点击被吞掉且对 `type="submit"` 调用 `preventDefault`。`iconOnly` 加载中不显示图标，只显示加载图形 |
| `Input` | `type` 只接受 `text`、`password`、`email`、`number`（§7.1.2）。`error` 优先于 `success` 决定边框色。调用方自己的 `aria-describedby` 与错误文本的 id 合并 |
| `Select`、`Checkbox`、`RadioGroup`、`Switch` | 只有受控形态（`value`/`checked` 加 `onChange`）。`Checkbox` 的 `onChange` 收到布尔值，`indeterminate` 点击后变为 `true`。`Select` 只有一个 `disabled`，没有选项级禁用；`RadioGroup` 有选项级 `disabled`。`Select` 的 `value` 为空串或不在 `options` 中时显示 `placeholder`，选项被动态移除后同样回到占位，不自动选中其他项，也不调用 `onChange`；选项恢复后重新显示该项。原因：Radix 对没有对应 `Item` 的非空值显示为空白，所以组件把不在 `options` 中的值按空串交给 Radix |
| `Tabs` | 只有受控形态，没有 `defaultValue`。非激活面板由 Radix 卸载，不是隐藏 |
| `Stack` | `gap` 取 `0`、`1`、`2`、`3`、`4`、`5`、`6`、`8`、`10`、`12`（正好是 `--spacing-N` 已有的步长），必填。枚举外的值（含 `'constructor'` 这类继承属性名）不产生任何 gap 类，不会退化成任意值 |
| 焦点环 | `src/ui/lib/focus.ts` 的 `FOCUS_RING`（外描边）与 `FOCUS_RING_INSET`（列表项内描边）。类名是完整字面量，Tailwind 才会生成 CSS。`outline-hidden` 允许（Tailwind 在强制颜色模式下保留轮廓） |
| 旋转图形 | `--animate-spin` 在 `src/ui/tailwind.css` 声明（默认主题未导入，没有 `animate-*`，§4.7）；`motion-reduce` 下不转 |
| 内部图形 | 勾、减号、箭头三个内部 SVG（`currentColor`）不导出。D064 的 5 个状态图标（success、error、warning、info、close）在 Phase 5 以 `StatusIcon` 导出，同为 `currentColor`，带 `aria-hidden`，含义由文字与 `role` 承担，不靠图形 |

## 8. 错误处理与通知体系

### 8.1 通知类型

#### 8.1.1 Toast 通知（轻提示）

**用途**：短暂的、非阻塞的反馈

**使用场景**：
- ✅ 操作成功：保存成功、删除成功
- ✅ 操作失败：网络错误、参数错误
- ✅ 系统提示：正在同步、已断开连接

**设计规范**：
- 位置：右上角（距离顶部 80px，距离右侧 20px）
- 宽度：最小 300px，最大 400px
- 高度：自动（根据内容）

### 8.2 错误码映射

**原则**：所有错误都显示用户友好的消息；映射表只含登记处（[V1 错误码](../../../04-技术架构/当前版本/V1-错误码.md)）状态为"使用中"的码。

宿主命令返回 `{ success, data, error }`，`error.code` 是数值（现有 `ModuleApiError.code` 即 `number`），所以映射表按数值键。

```typescript
// errors.ts
type Severity = 'minor' | 'moderate' | 'severe';

interface ErrorMessage {
  message: string;
  description?: string;
  severity: Severity;
  // 只有目标路由存在于应用路由表时才显示按钮
  action?: { label: string; route: string };
}

export const ERROR_MESSAGES: Readonly<Record<number, ErrorMessage>> = {
  1001001: {
    message: 'Provider 不存在',
    description: '请检查 Provider ID 是否正确',
    severity: 'moderate',
    action: { label: '查看 Provider 列表', route: '/providers' },
  },
  1001002: {
    message: 'API Key 无效',
    description: 'Provider 返回认证错误',
    severity: 'moderate',
  },
  // 其余只补登记处"使用中"的码
};
```

规则：
- 未登记的码使用通用文案"操作失败（错误码 N）"，严重程度按 `moderate`；不显示宿主原文，不显示堆栈（AC18）。
- 原稿示例的路由 `/settings/providers`、`/settings/providers/:id/edit` 在当前路由表中不存在（现有路由是 `/providers`），映射表不得引用不存在的路由。
- 原稿的 `1008001`（用户名已存在）属于 V1-FR-008，该功能未实现，登记处也未标"使用中"前不进入映射表。

### 8.3 统一错误处理流程

```
操作失败
  ↓
捕获错误，取数值错误码
  ↓
查找映射
  ├─ 已登记 → 取 severity
  └─ 未登记 → 通用文案，按 moderate 处理
  ↓
判断严重程度
  ├─ minor    → Toast（3 秒）
  ├─ moderate → Toast + 操作建议（5 秒）
  └─ severe   → Modal 对话框（需要用户确认）
  ↓
记录日志：只含错误码与发生位置，不含请求内容、凭据、宿主原文或堆栈
```

V1 不把错误上报到外部监控系统。

## 10. 数据模型

### 10.1 外观偏好（D065）

**用途**：保存主题和密度两项偏好。

| 键（逻辑） | 值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `appearance.theme` | `"light"`、`"dark"`、`"auto"`（JSON 字符串） | `"light"` | 主题 |
| `appearance.density` | `75`、`100`、`125`、`150`、`175`（JSON 数字） | `100` | 界面缩放 |

- **物理存储**：[V1 数据模型](../../../04-技术架构/当前版本/V1-数据模型.md) §4.7 的 `system_settings(user_id, setting_key, setting_value)`，由 migration `m20261029_000014_system_settings` 创建（Phase 3）。数据模型原稿把 `user_id` 定义为 INTEGER 外键，而代码使用字符串 `default-user`（D023）且没有 `users` 表，所以实际列为 `user_id TEXT NOT NULL`，唯一键 `(user_id, setting_key)`，不使用 NULL 表示全局，不预置默认行（默认值由宿主在读取时给出）。理由与兼容性见数据模型 §4.7。
- **用户范围**：宿主派生的 `default-user`，renderer 不传用户。FR-008 落地后偏好随用户隔离；局域网远程设备只能使用，不修改配置（D007/D013）。
- **不使用 `app_config`**：该表名在 V1-FR-008 §4.1 另有用途（`last_login_user_id`）。原稿的 `font_size` 键作废，字号并入密度。
- **编码**：值一律 JSON。原稿预设数据写 `'"light"'`（带引号），写入命令却写裸字符串 `dark`，两者不一致；类型化命令由宿主统一编码。

### 10.2 读写关系

**读操作**：启动时 `get_appearance_preferences` 一次读取两项；任一项缺失或非法，该项使用默认值（B05-22）。

**写操作**：`set_appearance_preferences` 在同一事务内写入传入的项，不传的项不变；宿主只接受上表的封闭取值。

## 11. 验收标准

### 11.1 AC 逐项测试设计表

#### AC01 主题切换生效

Given 当前亮色模式，组件已渲染

When 切换到暗色

Then 根元素 `data-theme` 变为 `dark`；暗色与亮色定义同一组 token 名；真实 WebView 中 `body` 的计算背景色等于暗色的 `--color-bg-primary`

#### AC02 主题持久化

Given 用户把主题切到暗色，宿主已确认保存

When 应用重启

Then 首次显示界面前已读取偏好，界面为暗色模式

#### AC03 密度调整生效

Given 标准密度（100%）

When 切换到 125%

Then 根元素 `data-density` 为 `125`，根字号为标准的 1.25 倍，以 rem 定义的字号、间距、组件尺寸同比放大

#### AC04 密度持久化

Given 切换到 125%，宿主已确认保存

When 重启应用

Then 首次显示界面前已读取偏好，仍为 125%

#### AC05 Button 组件渲染

Given 无

When 渲染各 `variant`（primary、secondary、danger、ghost、link）与 `size`（sm、md、lg），并设置 `disabled` 或 `loading`

Then 对应类名与尺寸 token 生效；`disabled` 使用原生 `disabled` 且不触发 `onClick`；`loading` 时 `aria-busy="true"` 且不触发 `onClick`；有可见文字时不强制 `aria-label`，纯图标形态的 `aria-label` 在类型上必填

#### AC06 Input 组件渲染

Given 无

When 渲染 Input（text、password、email、number），传入 `label` 与 `error`

Then `label` 与输入关联；有 `error` 时 `aria-invalid="true"`，错误文本显示在输入框下方并通过 `aria-describedby` 关联；`disabled` 时不可编辑

#### AC07 Modal 组件渲染

Given 无

When 打开 Modal

Then 显示遮罩和内容；容器为 `role="dialog"`，标题通过 `aria-labelledby` 关联，背景内容对辅助技术隐藏（`aria-modal` 或给兄弟节点设 `aria-hidden`，由所用原语决定，Phase 1 spike 确认）；关闭后从 DOM 移除

#### AC08 Toast 通知显示

Given 无

When 分别调用 `toast.success`、`toast.error`、`toast.warning`、`toast.info`

Then 显示对应类型的 Toast（类名与图标）；`success`、`info`、`warning` 为 `role="status"`，`error` 为 `role="alert"`

#### AC09 Toast 自动消失

Given Toast 显示

When 等待 3 秒（`error` 为 5 秒）

Then Toast 开始淡出并在 250ms 后从 DOM 移除；鼠标悬停或键盘聚焦期间不消失

#### AC10 错误码映射正确

Given 宿主返回错误码 1001001

When 调用统一错误处理

Then 显示"Provider 不存在"及其建议；文案来自映射表，不显示宿主返回的原文

#### AC11 禁止内联样式

Given 源码中含内联样式写法（JSX `style` 属性、对象字面量 `style` 键、`.style` 赋值、`setAttribute('style', …)`）

#### AC12 禁止硬编码颜色

#### AC13 表单控件

Given 无

When 渲染 Select、Checkbox、Radio（成组）、Switch，并用键盘操作

Then 受控值与 `onChange` 一致；`disabled` 不可操作；标签与控件关联；Switch 为 `role="switch"` 且 `aria-checked` 随状态变化；Radio 组内方向键移动选择；空格切换 Checkbox 与 Switch

#### AC14 展示组件

Given 无

When 渲染 Card（含 Header、Body）、Loading、Divider

Then Card 按插槽渲染；Loading 为 `role="status"`，无可见文字时有 `aria-label`；Divider 为 `role="separator"`，垂直时 `aria-orientation="vertical"`

#### AC15 Tooltip

Given 一个可聚焦的触发元素

When 鼠标悬停或键盘聚焦，然后按 Esc 或失去焦点

Then 提示显示并通过 `aria-describedby` 关联触发元素；Esc 或失焦后隐藏；内容按纯文本渲染

#### AC16 Modal 无障碍与层叠

Given Modal 已打开

When 按 Tab 与 Shift+Tab 循环、按 Esc、再打开第二个 Modal、在异步确认执行期间连续点击确认

Then 焦点被限制在 Modal 内；关闭后焦点还原到触发元素；Esc 只关闭最上层；遮罩随层数加深；确认回调只触发一次

#### AC17 Toast 队列与文本安全

Given 无

When 连续调用 `toast` 10 次，消息中含 HTML 标签或超过 100 字

Then 同时显示 3 个，其余排队，前面的移除后依次显示；HTML 标签按文本显示；长文本自动换行，最大宽度 400px（实现为 rem）

#### AC18 未登记错误码兜底与分流

Given 宿主返回未在映射表登记的错误码，或登记为 `severe` 的错误码

Given 访问一个不存在的路由

When 路由匹配失败

Then 显示 `ErrorPage`（404 文案与"返回首页"操作），不是空白页；渲染异常的兜底使用同一组件的 `error` 形态

#### AC20 token 对比度

Given 亮色与暗色的 token 定义和声明的配对表

#### AC21 偏好读写失败

Given 宿主读取偏好失败、超时或返回非法值，或写入失败

#### AC22 样式变量与存量清单

#### AC23 动态模块使用统一组件

Given 一个经 `createModule(host)` 加载的模块

When 模块使用 `host.ui` 的组件，并切换主题与密度

#### AC24 焦点环

Given 每个可交互的统一组件

When 键盘聚焦

Then 组件带有基于 `--color-focus-ring` 的 `focus-visible` 样式；源码中不存在没有配对 `focus-visible` 样式的 `outline-none`；真实 WebView 中聚焦后计算样式出现可见的焦点指示

#### AC25 跟随系统

Given 偏好为 `auto`

When 操作系统外观在亮色与暗色之间变化；或用户改选 `light` 后系统外观再变化

Then `auto` 下界面跟随系统；选择 `light` 或 `dark` 后系统变化不影响界面；应用卸载时系统外观监听被释放

#### AC26 Tabs

Given 一组受控 `value` 的 `Tabs`

When 点击标签，或在标签上按方向键

Then 容器为 `role="tablist"`，标签为 `role="tab"` 且 `aria-selected` 随选中变化，内容为 `role="tabpanel"` 并与标签关联；方向键移动焦点与选中；非选中面板不可见

#### AC27 多行 Input 与 Stack

Given 无

When 渲染 `Input` 的多行形态（带 `label`、`error`、`disabled`），以及 `Stack` 的各 `gap` 取值

## 12. 接口设计

### 12.1 Tauri Commands（D065，已冻结；Phase 3 已实现并注册）

不提供原稿的通用 `get_app_config`/`set_app_config(key, value)`：renderer 能借它写任意键，与 AGENTS.md 的"身份由宿主派生"和命令参数白名单做法不一致。改为两个类型化命令。

#### 读取外观偏好

```text
get_appearance_preferences(window) -> { success, data: AppearancePreferences, error }
```

#### 更新外观偏好

```text
set_appearance_preferences(window, patch: AppearancePatch) -> { success, data: AppearancePreferences, error }
```

- `AppearancePreferences`：`theme` 取 `light`、`dark`、`auto`；`density` 取 `75`、`100`、`125`、`150`、`175`。
- `AppearancePatch`：`theme` 与 `density` 都可选，至少一项；`null` 视为未传。取值非法时返回错误且不写入：`theme` 非法返回 1005001，`density` 非法（不在封闭取值内，或不是 JSON 整数）返回 1005006，补丁不是对象、为空或含 `theme`、`density` 以外的键返回 1005002；两项同时非法时 `theme` 的错误优先。补丁以原始 JSON 接收并由宿主校验，所以每种拒绝都走命令信封，而不是在 Tauri 参数解码阶段失败。
- 参数里没有用户标识；用户由宿主派生（D023），V1 为 `default-user`。命令只校验受信主窗口，不要求 Settings 路由，因为偏好不是授权，也不属于 D037 的模块生命周期命令。
- 返回更新后的完整偏好，前端据此记为已确认值。
- 加入 `scripts/check-host-contracts.mjs` 的精确参数白名单：`get_appearance_preferences` 只有 `app`、`window`，`set_appearance_preferences` 只有 `app`、`window`、`patch`（`app` 是 Tauri 句柄，不是业务参数）。
- 不新增 HTTP 接口，OpenAPI 不变。

**前端调用示例**：
```typescript
const prefs = await invoke('get_appearance_preferences');
await invoke('set_appearance_preferences', { patch: { theme: 'dark' } });
```

### 13.1 外观偏好控制器

```typescript
// B05-01: 类型定义
type Theme = 'light' | 'dark' | 'auto';
type ResolvedTheme = 'light' | 'dark';
// B05-07: 密度类型定义
type Density = 75 | 100 | 125 | 150 | 175;
interface Appearance { theme: Theme; density: Density }
const DEFAULTS: Appearance = { theme: 'light', density: 100 };

// B05-02 B05-08: 状态。confirmed 是宿主已保存的值，applied 是界面当前值
let confirmed: Appearance = DEFAULTS;
let applied: Appearance = DEFAULTS;
let systemTheme: ResolvedTheme = 'light';
let inFlight = false;                           // 同一时刻只有一个写入在途
let pendingPatch: Partial<Appearance> | null = null;
let disposeSystemListener: (() => void) | null = null;

// B05-03 B05-09: 初始化主题与密度
async function initAppearance(): Promise<void> {
  // B05-25: 首帧门控。根元素带 data-appearance-pending，样式表在该属性存在时隐藏内容。
  // 宿主 1 秒内不应答就按默认值显示，不阻塞启动
  const stored = await withTimeout(readPreferences(), 1000).catch(() => null);
  confirmed = sanitize(stored);
  applied = confirmed;
  systemTheme = readSystemTheme();
  disposeSystemListener = subscribeSystemTheme(onSystemChange);   // B05-26
  render(applied);
  root.removeAttribute('data-appearance-pending');
}

// B05-22: 缺失或非法的项回退默认值，不抛错，不回显非法值
function sanitize(raw: unknown): Appearance {
  return {
    theme: isTheme(raw?.theme) ? raw.theme : DEFAULTS.theme,
    density: isDensity(raw?.density) ? raw.density : DEFAULTS.density,
  };
}

// B05-04: 解析主题（auto 取系统外观）
function resolveTheme(theme: Theme): ResolvedTheme {
  return theme === 'auto' ? systemTheme : theme;
}

// 应用只写属性，样式由 CSS 的属性选择器完成，不写内联样式（D068 R1）
function render(a: Appearance): void {
  root.setAttribute('data-theme', resolveTheme(a.theme));    // B05-05
  root.setAttribute('data-density', String(a.density));      // B05-10
}

// B05-06 B05-11: 切换主题、更新密度。先应用，再保存
async function updateAppearance(patch: Partial<Appearance>): Promise<void> {
  applied = { ...applied, ...patch };
  render(applied);
  pendingPatch = { ...pendingPatch, ...patch };              // B05-23: 在途期间的新修改合并为一个补丁
  if (inFlight) return;
  inFlight = true;
  while (pendingPatch !== null) {
    const next = pendingPatch;
    pendingPatch = null;
    try {
      confirmed = sanitize(await writePreferences(next));    // 宿主返回更新后的完整偏好
    } catch {
      pendingPatch = null;                                   // B05-24: 失败则丢弃待写补丁，回退到已确认值
      applied = confirmed;
      render(applied);
      toast.error('保存外观设置失败');
      break;
    }
  }
  inFlight = false;
}

// B05-26: 系统外观变化只在偏好为 auto 时生效；卸载时释放监听
function onSystemChange(next: ResolvedTheme): void {
  systemTheme = next;
  if (applied.theme === 'auto') render(applied);
}
function disposeAppearance(): void { disposeSystemListener?.(); }

// B05-12: 获取当前密度
export function getCurrentDensity(): Density { return applied.density; }
```

### 13.2 通知、错误与 Modal

Toast 是 React 组件，不再用 `innerHTML` 拼 DOM。原稿的实现把 `message` 直接拼进 HTML，消息里含标签时会被解析。

```typescript
// B05-13: Toast 类型
type ToastType = 'success' | 'error' | 'warning' | 'info';
interface ToastOptions {
  description?: string;
  duration?: number;
  action?: { label: string; onClick: () => void };
}

// B05-14: 队列放在组件外的 store，组件用 useSyncExternalStore 读取
const queue: ToastItem[] = [];
let visible: ToastItem[] = [];
const MAX_VISIBLE = 3;

// B05-15: 显示 Toast
function showToast(type: ToastType, message: string, options?: ToastOptions): void {
  queue.push({ id: nextId(), type, message, options });
  processQueue();
}

// B05-16: 处理队列
function processQueue(): void {
  while (visible.length < MAX_VISIBLE && queue.length > 0) visible.push(queue.shift()!);
  notify();
}

// B05-17: 渲染。message 是文本节点；error 用 role="alert"，其余用 role="status"
// B05-33: 悬停或聚焦时暂停计时，离开后用剩余时间继续（D069）
// 默认时长：error 5000ms，其余 3000ms；options.duration 优先

// B05-18: 移除。淡出动画结束后调用
function removeToast(id: string): void {
  visible = visible.filter((t) => t.id !== id);
  processQueue();
}

// B05-19: 容器。ToastViewport 在应用根挂载一次
// B05-20: 辅助。5 个内置 SVG 图标（success、error、warning、info、close），使用 currentColor

// B05-21: 导出 API
export const toast = {
  success: (m: string, o?: ToastOptions) => showToast('success', m, o),
  error: (m: string, o?: ToastOptions) => showToast('error', m, o),
  warning: (m: string, o?: ToastOptions) => showToast('warning', m, o),
  info: (m: string, o?: ToastOptions) => showToast('info', m, o),
};

// B05-27: 统一错误处理。error.code 是数值
function handleError(error: { code: number }): void {
  const info = ERROR_MESSAGES[error.code];
  if (!info) {                                                   // B05-28: 未登记的码
    toast.error(`操作失败（错误码 ${error.code}）`);
    logError(error.code);                                        // 只记错误码与位置
    return;
  }
  if (info.severity === 'severe') {                              // B05-29: 严重错误走 Modal
    Modal.error({ title: info.message, content: info.description });
    logError(error.code);
    return;
  }
  toast.error(info.message, {
    description: info.description,
    duration: info.severity === 'moderate' ? 5000 : 3000,
    action: info.action && routeExists(info.action.route) ? toToastAction(info.action) : undefined,
  });
  logError(error.code);
}
```

| --- | --- |
| Toast 用自有 store | `toastStore` 管理队列与「显示哪几个」，`ToastViewport` 管理计时、暂停与淡出。选择理由：§13.2 的伪代码本来就是 store 加 `MAX_VISIBLE`，需要的「最多 3 个、其余排队」是自己的逻辑；Radix Toast 原语没有被评估过，这里不对它下结论。没有挂载 `ToastViewport` 时 `toast.*` 只入队 |
| Toast 计时 | 可见后才开始计时（排队中不计时）；悬停或焦点在卡片内（含其按钮之间移动）暂停，离开后用剩余时间继续；到时先淡出 250 ms 再移除。jsdom 没有 `animationend`，所以移除按 250 ms 定时，不由动画驱动。`duration` 非正数、`NaN` 回退默认值 |
| Toast 文本 | `message`、`description` 一律转为字符串后作为文本节点渲染；非字符串被转换而不是当作元素 |
| Modal 原语 | `Dialog` 加自有层。点击遮罩**不关闭**（避免误点取消删除或丢失表单；2026-10-30 用户确认所有 Modal 同此规则）；Esc、×、取消照常关闭并调用 `onCancel`。确认回调进行中，Esc、×、取消被忽略，确认按钮显示加载 |
| 确认回调拒绝 | 回调返回的 Promise 被拒绝时，对话框保持打开，显示固定文案「操作未完成，请重试。」（`role="alert"`），不渲染拒绝原因，可再次点击确认。规格没有规定该情形 |
| 对话框的「一轮」 | 每次 `open` 变化（关闭、重新打开）和卸载都结束当前一轮。新一轮开始时清除上一轮的失败提示、加载状态和忙碌标记；上一轮尚未完成的确认回调之后无论成功还是拒绝，都不会关闭新一轮的对话框、不会在其中显示失败提示、也不会清除其忙碌标记（该回调本身不会被取消，副作用照常发生）。规格没有规定该情形 |
| 焦点还原 | 没有 `Dialog.Trigger` 时 Radix 不会还原焦点，所以在打开前记下 `document.activeElement`，关闭后手动还原 |
| 层叠 | 每个对话框各带一层遮罩，遮罩叠加即「随层数加深」；后打开的在 DOM 中更靠后，同 `z-index` 下盖在上面。层级用 §4.8 的令牌：Modal `z-modal`（50），Select 弹层与 Tooltip `z-popover`（60），Toast `z-toast`（70） |
| Toast 与 Modal 同时出现 | `ToastViewport` 经 portal 挂到 `<body>`，卡片显式写 `aria-live`（`error` 为 `assertive`，其余 `polite`）。原因：Modal 打开时 Radix 用 `aria-hidden` 的 `hideOthers` 把对话框以外的内容对辅助技术隐藏，只放过 `[aria-live]` 元素；原先区域挂在应用根节点里，被一并隐藏，确认回调里调用的 `toast.success` 不会被朗读。portal 解决“对话框打开后出现的 Toast”，`aria-live` 解决“对话框打开前已在显示的 Toast”，两者缺一都会让对应用例失败（反向验证过） |
| `ModalHost` 逐个挂载 | 同一次提交里挂载两个对话框时，Radix 会让各自把对方隐藏，最上层对话框对辅助技术不可见（用 jsdom 复现过）。`ModalHost` 因此每次提交只挂载一个，按打开顺序依次挂载 |
| 错误码映射 | `ERROR_MESSAGES` 只含登记处标「使用中」且由宿主以数字码返回的码：1000000、1001001～1001008、1001012、1001015、1001016。Skills 码（1002xxx）是字符串码，MCP 命令返回 `Result<_, String>`，数字码到不了前端，都不收；模块码（1004xxx）经 `CommandResponse` 到前端，登记处 §3.4 已于 2026-10-30 补上状态列，其“使用中”的码符合收录条件，但每个码的文案与严重程度未定，本阶段未收；预留与作废的码走兜底。严重程度是展示层的决定，规格只给出 1001001 为 `moderate`，其余为本阶段取值并已于 2026-10-30 由用户确认保持现状，其中只有 1001015 为 `severe`（Modal 路径需要一个真实的码），1001007、1001012 为 `minor`，其余 `moderate` |
| 错误处理入参 | `handleError(error, { where, navigate, routeExists })`。按钮只在 `navigate` 与 `routeExists` 都提供且路由存在时出现，路由表由调用方持有。Phase 7：路由表在 `src/appRoutes.ts`（`ROUTES`、`routeExists`），页面经 `src/pageError.ts` 的 `usePageError(where)` 取得绑定了 `where`、`navigate`（无 Router 时不提供，因此无按钮）与 `routeExists` 的函数，应用外壳的外观控制器 `onWriteError` 也接到 `handleError`（`where: 'appearance'`）。日志只写 `{ code, where }` |
| 错误页 | `ErrorPage` 不依赖路由库，按钮由调用方传入处理函数；`ErrorBoundary` 的日志是固定的 `{ code: null, where: 'render' }`，不含异常内容。`main.tsx` 挂载 `ErrorBoundary`、`ToastViewport`、`ModalHost`，`App.tsx` 增加 `path="*"` 的 404 路由；其余应用外壳、业务页面不动 |

**Phase 6 的实现取舍**（实现：`src/modules/moduleHostUi.ts`；注入点：`src/modules/moduleRuntimeHost.ts` 的 `readContract`）：

| 项目 | 取舍 |
| --- | --- |
| 共享与冻结 | `moduleHostUi` 是模块级单例，所有模块拿到同一个对象，不含按模块的状态。`ui`、每个包装后的组件、`Card`/`Tabs` 的子组件、`Modal`、`toast` 都已冻结，一个模块改不了另一个模块拿到的东西 |
| 组件包装 | 每个组件经 `guard`：以 `createElement(Component, omitStyle(props))` 渲染，不是直接调用组件函数，所以组件的 Hook 与 ref 照常工作。`Tooltip` 走同一个 `guard`；`guard` 只过滤它自己的属性，不去改写模块传给它的子元素。模块自己创建的原生元素带 `style` 不在运行时检查范围内，靠 `design:check` 与审查（D068） |

| 不是沙箱 | 同 D042，模块与宿主共享 realm 与文档；`host.ui` 防的是误用，V1 的安全边界仍是 D041 的准入 |
| 错误展示 | 模块错误码 1004xxx 没有加入 `ERROR_MESSAGES`（文案与严重程度未定，§13.2）。`provider-console` 把失败显示为模块内的 `role="alert"` 段落并带数字码，不调用 `toast`，也不经 `handleError` |

依据与限度：
- 前三项来自 Tailwind 4 官方文档声明的核心功能依赖（<https://tailwindcss.com/docs/compatibility>，2026-10-29 读取）。Edge 基于 Chromium，取 111 是推断。
- 前端产物含 `@layer`、`@property`、`color-mix()`、`max()`，没有 polyfill；低于上表的浏览器不承诺样式可用。
- `:focus-visible` 从 Chrome 86、Firefox 85、Safari 15.4 起支持（MDN browser-compat-data，2026-10-29 读取），都低于上表，所以焦点环不再受这一项限制。
- 这些最低版本本身没有在对应浏览器上运行验证。仓库内实测的只有 macOS WKWebView（User-Agent 不含 Safari 版本号，因此没有记录其版本）：上述 CSS 特性在其中均可用（`CSS.supports` 与 `@layer` 语句规则探测）。局域网浏览器的实际验证属于 V1-FR-010。
