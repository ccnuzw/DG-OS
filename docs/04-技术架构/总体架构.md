# DGOS 总体架构

## 1. 架构定位

DGOS 是本地优先的 AI 应用开发框架。它提供统一的 Provider 适配、Skills/MCP 管理和模块系统基础能力；桌面端与局域网 Web 端共用同一套前端应用包、设计系统和版本化 API。本地数据存储在 SQLite，云端服务为可选增强。

跨版本保持以下边界稳定：应用模块通过统一接口调用底层能力；模块之间不直接访问彼此私有状态；跨模块通信通过系统 API 完成。

## 2. 核心原则

- **本地优先**：SQLite 单文件数据库，本地管理功能离线可用（调用云端模型仍需网络），云端为可选增强
- **强制模块化**：单文件不超过 1000 行，按领域拆分 crate，计划由 CI 自动检查（CI 尚未配置）
- **标准协议**：使用现有 Skills/MCP 标准，不重新发明轮子
- **热更新**：应用模块独立构建、动态加载，无需重启主程序
- **统一设计**：所有模块强制使用统一 Design System，禁止自定义样式

## 4. 数据流

### 4.1 Provider 调用流

```
应用模块（AI工作台）
    ↓ 选择模型
应用框架（权限检查）
    ↓ 授权通过
Provider 适配框架
    ↓ 路由到具体适配器
OpenAI Adapter
    ↓ HTTP 请求
OpenAI API
    ↓ 返回结果
流式响应 → 应用模块
```

### 4.2 Skills 调用流

D016 起，Skill 是 `SKILL.md` 内容包，作为任务上下文使用，不执行：

```
应用模块（AI 工作台）
    ↓ 用户显式选择已启用的 Skill（可选）
技能中心
    ↓ 校验用户状态，锁定版本与内容哈希
准备上下文（正文作为低于宿主策略的用户级指导）
    ↓
Provider 调用（工具动作另经 MCP 逐次确认）
    ↓
记录版本引用与安全摘要
```

早期的 Skill Caller（HTTP/CLI 外部执行）模型已被 D016/D017 关闭，旧 Legacy 包只读。

### 4.3 模块加载流（FR-004 规划）

当前已实现模块包发布、完整性校验、启动恢复和 runtime supervisor（`dgos-modules::ModuleRuntimeSupervisor`）。D041～D046 起，执行型加载器 `PageModuleLoader` 把经准入的入口源码交给主窗口页面，由页面用 Blob URL 动态 `import()`、渲染并回执，runtime 收到有效回执才 `ready`；`LocalArtifactLoader` 只做宿主侧入口/摘要检查，不执行 JavaScript，也不进入生产装配。当前没有 Module Federation 插件，执行发生在与宿主共享的 JS realm 中，不是沙箱，唯一的安全边界是编译进宿主的固定准入清单（生产为空，所以生产中尚无可执行模块）。D034 起 `dgos-application::ModuleOperationManager` 是 transport 的唯一入口：生命周期在脱离调用方的后台 operation 中串行执行，启动恢复成功前拒绝 start/update，更新只读取宿主拥有的本地来源目录，不接受 renderer 提供的路径或 URL。下图是目标流程，V1 只加载宿主发布器验证过的本地包（D025/D028），其中“Module Federation 动态加载”一步目前由页面加载器代替：

D046 的 `attach_module_host`/`report_module_host` 只是页面生命周期的 transport 扩展，门禁为 `main` 窗口加可信来源，与 Settings 路由和 caller/capability 策略解耦；回执不是身份、权限或沙箱。D047 冻结了准入闭环的边界：清单只能来自发布构建对随包目录的重算摘要，信任根是宿主二进制，撤销即在下一个构建中移除 pin；签名清单、轮换、运行中撤销和产物比对门禁尚未实现。D048 增加了一条运行时绑定的 `providers.call` 路径（Rust 内部，经 supervisor 签发的句柄与逐次授权），当前只有 Rust 集成测试证据，模块 JS 没有触发路径。

```
应用启动
    ↓
读取已安装模块列表（SQLite）
    ↓ 按 DB 指针恢复/校验版本与完整性
Module Federation 动态加载
    ↓ 并行加载多个模块
权限检查与授予
    ↓
模块注册到系统
    ↓
模块可用
```

## 5. 核心组件

### 5.1 Provider 适配框架

```rust
// 统一接口
trait ProviderAdapter {
    async fn list_models(&self) -> Result<Vec<Model>>;
    async fn call_model(&self, request: Request) -> Result<Response>;
    async fn stream_model(&self, request: Request) -> Stream<Chunk>;
}

// 模型分类
enum Capability {
    TextGeneration,
    ImageGeneration,
    VideoGeneration,
    AudioGeneration,
}

// 具体适配器
OpenAIAdapter implements ProviderAdapter
ClaudeAdapter implements ProviderAdapter
CustomAdapter implements ProviderAdapter
```

**职责**：
- 适配各厂商 API
- 统一接口封装
- 模型列表管理
- 模型分类标签
- 调用路由

### 5.2 Skills 管理系统

// Skills 管理器（早期草图）
struct SkillsManager {

    registry_client: RegistryClient,

impl SkillsManager {
    async fn fetch_registry(&self) -> Vec<SkillInfo>;
    async fn install(&mut self, config: SkillConfig);
    async fn call(&self, id: &str, params: Value) -> Result<Value>;

// Skills 调用器（已关闭）

    Http(HttpCaller),
    Cli(CliCaller),

**职责**（D016）：
- 随应用发布官方内容包，离线可浏览

### 5.3 MCP 管理系统

```rust
// MCP 管理器
struct MCPManager {
    servers: HashMap<String, MCPClient>,

impl MCPManager {
    async fn connect(&mut self, config: MCPConfig);
    async fn list_tools(&self, server_id: &str) -> Vec<Tool>;
    async fn call_tool(&self, server_id: &str, tool: &str, params: Value);

// MCP 客户端
struct MCPClient {
    transport: Transport, // stdio / Streamable HTTP（含 legacy SSE 兼容），D021

```

**职责**：
- 连接 MCP 服务器
- 工具列表管理
- 调用桥接
- 连接状态监控

**不做**：
- ❌ 依赖第三方 MCP 客户端库（`dgos-mcp` 自行实现 JSON-RPC 传输，协议版本按 MCP 规范协商）
- ❌ MCP 服务器端

## 6. 技术栈

### 6.1 核心技术

| 层级 | 技术 | 当前情况 | 作用 |
|------|------|------|------|
| 桌面容器 | Tauri 2 | 已采用（2.12） | 跨平台桌面应用 |
| 后端语言 | Rust | 已采用（需 1.90+） | 核心逻辑 |
| Web 框架 | Axum | 规划（FR-010） | 局域网 HTTP API |
| 数据库 | SQLite | 已采用 | 本地存储 |
| ORM | SeaORM | 已采用（1.1） | 数据库操作 |
| 前端框架 | React | 已采用（19） | UI 渲染 |
| 前端语言 | TypeScript | 已采用（6） | 类型安全 |
| 构建工具 | Vite | 已采用（8） | 开发服务器 + 打包 |
| 模块加载 | Module Federation | 规划（FR-004） | 热更新 |
| 状态管理 | Zustand | 已采用（4） | 全局状态 |
| UI 组件 | 基于 Shadcn/ui 的统一组件库 | 规划（FR-005） | 基础组件 |

详见[技术栈选型](技术栈选型.md)。

### 6.2 明确不采用

| 技术 | 理由 |
|------|------|
| 内嵌 QuickJS/Node.js 运行时 | 技能内容不执行（D016）；MCP 服务器按协议作为独立进程或远程服务运行 |
| PostgreSQL | 本地优先，SQLite 足够 |
| Redis | 单机不需要缓存 |
| MinIO/S3 | 文件系统足够 |

## 8. 拆分条件

V1 在单一 Tauri 应用内保持逻辑边界和契约隔离。只有出现以下信号时才拆分物理服务：

- 安全边界不同，需要独立沙箱或网络出口
- 资源曲线影响主应用稳定性
- 某领域需要独立水平扩展或版本发布
- 跨进程调用已有稳定 API、幂等、超时和重试语义
- 监控数据证明合并部署已成为瓶颈

未满足这些条件时，不为"看起来像微服务"而拆分；先在同一应用内保持单一契约和可测试边界。
