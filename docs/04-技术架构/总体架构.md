# DGOS 总体架构

## 1. 架构定位

DGOS 是本地优先的 AI 应用开发框架。它提供统一的 Provider 适配、Skills/MCP 管理和模块系统基础能力；桌面端与局域网 Web 端共用同一套前端应用包、设计系统和版本化 API。本地数据存储在 SQLite，云端服务为可选增强。

跨版本保持以下边界稳定：应用模块通过统一接口调用底层能力；模块之间不直接访问彼此私有状态；跨模块通信通过系统 API 完成。

## 2. 核心原则

- **本地优先**：SQLite 单文件数据库，完全离线可用，云端为可选增强
- **强制模块化**：单文件不超过 1000 行，按领域拆分 crate，CI 自动检查
- **标准协议**：使用现有 Skills/MCP 标准，不重新发明轮子
- **热更新**：应用模块独立构建、动态加载，无需重启主程序
- **统一设计**：所有模块强制使用统一 Design System，禁止自定义样式

## 4. 数据流

### 4.1 Provider 调用流

```
应用模块（AI工作台）
    ↓ 选择模型
应用框架（权限检查）
    ↓ 授权通过
Provider 适配框架
    ↓ 路由到具体适配器
OpenAI Adapter
    ↓ HTTP 请求
OpenAI API
    ↓ 返回结果
流式响应 → 应用模块
```

### 4.2 Skills 调用流

```
应用模块（画布 LLM 节点）
    ↓ 用户选择 Skill（可选）
Skills 管理器
    ↓ 查找已安装 Skill
Skill Caller（HTTP/CLI）
    ↓ 调用外部 Skill
Skill 自己运行
    ↓ 返回结果
应用模块展示结果
```

### 4.3 模块加载流

当前已实现模块包发布、完整性校验、启动恢复和 D033 第一阶段 runtime supervisor（`dgos-modules::ModuleRuntimeSupervisor`）：只通过 `ModuleLoader` 端口处理 Publisher 验证过的本地 artifact，内置的 `LocalArtifactLoader` 只做宿主侧入口/摘要检查，不执行 JavaScript，也没有 Federation 或 WebView 加载。D034 起 `dgos-application::ModuleOperationManager` 是 transport 的唯一入口：生命周期在脱离调用方的后台 operation 中串行执行，启动恢复成功前拒绝 start/update，更新只读取宿主拥有的本地来源目录，不接受 renderer 提供的路径或 URL。下图是目标流程，V1 只加载宿主发布器验证过的本地包（D025/D028）：

```
应用启动
    ↓
读取已安装模块列表（SQLite）
    ↓
Module Federation 动态加载
    ↓ 并行加载多个模块
权限检查与授予
    ↓
模块注册到系统
    ↓
模块可用
```

## 5. 核心组件

### 5.1 Provider 适配框架

```rust
// 统一接口
trait ProviderAdapter {
    async fn list_models(&self) -> Result<Vec<Model>>;
    async fn call_model(&self, request: Request) -> Result<Response>;
    async fn stream_model(&self, request: Request) -> Stream<Chunk>;
}

// 模型分类
enum Capability {
    TextGeneration,
    ImageGeneration,
    VideoGeneration,
    AudioGeneration,
}

// 具体适配器
OpenAIAdapter implements ProviderAdapter
ClaudeAdapter implements ProviderAdapter
CustomAdapter implements ProviderAdapter
```

**职责**：
- 适配各厂商 API
- 统一接口封装
- 模型列表管理
- 模型分类标签
- 调用路由

### 5.2 Skills 管理系统

```rust
// Skills 管理器
struct SkillsManager {
    installed: Vec<Skill>,
    registry_client: RegistryClient,
}

impl SkillsManager {
    async fn fetch_registry(&self) -> Vec<SkillInfo>;
    async fn install(&mut self, config: SkillConfig);
    async fn call(&self, id: &str, params: Value) -> Result<Value>;
}

// Skills 调用器
enum SkillCaller {
    Http(HttpCaller),
    Cli(CliCaller),
}
```

**职责**：
- 连接远程仓库
- 安装/卸载 Skills
- 配置管理
- 调用接口封装
- 使用记录

**不做**：
- ❌ 执行 Skills 代码
- ❌ 实现 Skills 协议
- ❌ Skills 沙箱隔离

### 5.3 MCP 管理系统

```rust
// MCP 管理器
struct MCPManager {
    servers: HashMap<String, MCPClient>,
}

impl MCPManager {
    async fn connect(&mut self, config: MCPConfig);
    async fn list_tools(&self, server_id: &str) -> Vec<Tool>;
    async fn call_tool(&self, server_id: &str, tool: &str, params: Value);
}

// MCP 客户端
struct MCPClient {
    transport: Transport, // HTTP/Stdio/WebSocket
}
```

**职责**：
- 连接 MCP 服务器
- 工具列表管理
- 调用桥接
- 连接状态监控

**不做**：
- ❌ 实现 MCP 协议（使用现有库）
- ❌ MCP 服务器端

### 5.4 模块系统

- 独立构建

## 6. 技术栈

### 6.1 核心技术

| 层级 | 技术 | 版本 | 作用 |
|------|------|------|------|
| 桌面容器 | Tauri 2 | 2.0+ | 跨平台桌面应用 |
| 后端语言 | Rust | 1.75+ | 核心逻辑 |
| Web 框架 | Axum | 0.7+ | HTTP API |
| 数据库 | SQLite | 3.45+ | 本地存储 |
| ORM | SeaORM | 0.12+ | 数据库操作 |
| 前端框架 | React 19 | 19.1+ | UI 渲染 |
| 前端语言 | TypeScript | 5.0+ | 类型安全 |
| 构建工具 | Vite | 8.0+ | 开发服务器 + 打包 |
| 模块加载 | Module Federation | - | 热更新 |
| 状态管理 | Zustand | 4.0+ | 全局状态 |
| UI 组件 | Shadcn/ui | - | 基础组件 |

### 6.2 明确不采用

| 技术 | 理由 |
|------|------|
| QuickJS/Node.js | Skills/MCP 自己运行 |
| PostgreSQL | 本地优先，SQLite 足够 |
| Redis | 单机不需要缓存 |
| MinIO/S3 | 文件系统足够 |

## 8. 拆分条件

V1 在单一 Tauri 应用内保持逻辑边界和契约隔离。只有出现以下信号时才拆分物理服务：

- 安全边界不同，需要独立沙箱或网络出口
- 资源曲线影响主应用稳定性
- 某领域需要独立水平扩展或版本发布
- 跨进程调用已有稳定 API、幂等、超时和重试语义
- 监控数据证明合并部署已成为瓶颈

未满足这些条件时，不为"看起来像微服务"而拆分；先在同一应用内保持单一契约和可测试边界。
