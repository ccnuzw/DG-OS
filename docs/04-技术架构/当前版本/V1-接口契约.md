# V1 接口契约

## 1. 文档目标

定义 DGOS V1.0 前后端通信的完整接口契约，包括 Tauri IPC 接口、HTTP API（局域网模式）和事件系统。

**权威性**：本文档是接口设计的唯一权威来源。前后端必须严格遵守契约。

**更新规则**：接口变更必须先更新本文档，再修改代码。破坏性变更需要记录 Migration 路径。

---

## 2. 通信架构

### 2.1 桌面模式（Tauri IPC）

**D023 身份基线（2026-10-28）**：所有已注册桌面命令要求可信本地主窗口，用户由 Rust 宿主派生为既有 `default-user`。Provider、Skills、Workbench 命令不再接收 `userId`；MCP 同样使用统一宿主入口。此为前后端同步升级的破坏性 IPC 调整：旧前端需同时替换，不提供任意用户兼容入口。不创建用户、不改变既有数据归属，也不代表 FR-008 登录或局域网认证已完成。

配置管理路由绑定内置 Settings 来源，任务编排绑定 Workbench 来源。来源由 Rust 命令选择，renderer 不能提交模块身份；同 realm 的 JS 仍是可信宿主代码，不能以此宣称第三方隔离。完整边界见 [前置收口设计](V1-FR004前置收口设计.md)。

```
React Frontend  ←→  Tauri IPC  ←→  Rust Backend
     (TS)                              (Rust)
```

**特点**：
- 类型安全（通过代码生成）
- 进程内通信（低延迟）
- 支持流式响应（通过事件）

### 2.2 局域网模式（HTTP API）

```
Browser  ←→  HTTP/WebSocket  ←→  Rust Backend
  (TS)         (JSON/SSE)          (Rust)
```

**特点**：
- RESTful API（JSON 格式）
- Server-Sent Events（SSE）用于流式响应
- 简单认证（Bearer Token）

**引用决策**：[D007](../../06-决策记录/V1-冻结决策.md#d007-局域网-http-服务始终开启) - 局域网 HTTP 服务始终开启

## 3. 错误处理

### 3.1 统一错误格式

所有错误遵循统一格式（参考 [V1-错误码](V1-错误码.md)）：

```typescript
interface ApiError {
  code: string;        // 错误码（如 "ERR_PROVIDER_001"）
  message: string;     // 用户可读的错误消息
  details?: unknown;   // 详细信息（可选）
}
```

### 3.2 HTTP 状态码映射

| HTTP 状态码 | 含义 | 示例错误码 |
|------------|------|-----------|
| 200 | 成功 | - |
| 400 | 客户端错误 | ERR_VALIDATION_001 |
| 401 | 未认证 | ERR_AUTH_001 |
| 403 | 无权限 | ERR_PERMISSION_001 |
| 404 | 资源不存在 | ERR_NOT_FOUND_001 |
| 500 | 服务器错误 | ERR_INTERNAL_001 |

### 3.3 Tauri IPC 错误处理

```typescript
try {
  const result = await invoke<Provider>('create_provider', { request });
  // 成功
} catch (error) {
  const apiError = error as ApiError;
  console.error(apiError.code, apiError.message);
}
```

## 4. Provider 管理接口

### 4.0 当前桌面实施契约（D023）

本节是当前桌面 IPC 的字段级依据；§4.1 起保留早期 HTTP/API 规划，不能把其 INTEGER ID、软删除、`is_enabled` 或加密声明当成当前实现证据。HTTP 字段仍以 OpenAPI 为规划来源，当前没有注册这些 HTTP 路由。

```typescript
interface ProviderConfig {
  name: string; provider_type: string; base_url: string;
  api_key: string; enabled: boolean; config?: Record<string, unknown>;
}
interface DesktopProvider {
  id: string; user_id: string; name: string; provider_type: string;
  base_url: string; enabled: boolean; sort_order: number;
  config?: Record<string, unknown>; created_at: string; updated_at: string;
  credential_ref?: string;
  credential_status: 'stored' | 'migration_required' | 'missing';
  config_revision: number; // 宿主递增的配置/已发布模型缓存代次；不是 renderer 身份
  // 不返回 api_key；stored 表示引用已保存，不保证 OS vault 当前已解锁。
}
interface CommandResponse<T> {
  success: boolean; data: T | null;
  error: {code: number; message: string} | null;
}
interface ChatResponse {
  content: string; usage: TokenUsage;
  audit_warning?: boolean; // Provider completed; usage audit persistence needs review
}
```

| Command / IPC 参数 | `CommandResponse` 的 data |
| --- | --- |
| `list_providers({})` | `DesktopProvider[]`，含禁用配置，按 sort_order 排序 |
| `create_provider({config})` | `DesktopProvider` |
| `create_provider_with_models({config, models})` | `DesktopProvider`；模型 DTO 见 `src/stores/providerStore.ts` |
| `update_provider({id, config})` | `DesktopProvider` |
| `toggle_provider({id, enabled})` | `DesktopProvider` |
| `delete_provider({id})` | `null`；当前实现为数据库删除，不是软删除 |
| `test_provider_connection({config})` | `boolean`，测试未保存配置 |
| `test_provider_by_id({providerId})` | `boolean`，只使用当前用户的保存配置 |
| `list_models_for_config({config})` | `Model[]`，预览不写入缓存 |
| `list_models({providerId})` | `Model[]`，当前用户资源的缓存 |
| `refresh_models({providerId})` | `Model[]` |
| `call_provider({providerId, modelId, request})` | `ChatResponse`；当前普通调用非 streaming IPC；`audit_warning` 不触发自动重试 |
| `update_provider_order({providerIds})` | `null`；同一用户的排序在事务中提交 |
| `list_usage_logs({limit?})` | `UsageLog[]`，默认/最大 100 条，按用户过滤 |
| `migrate_provider_credential({providerId})` | `DesktopProvider`；重试该 Provider 的 legacy 凭据迁移，不接收 secret 或引用 |

普通、流式和 tools 的 Rust Provider 服务均校验用户资源归属。流式服务不等于桌面 streaming command 已注册。

凭据契约（D023）：新建必须提供 key；更新时空 key 仅保留相同完整 endpoint 与 provider_type 的现有绑定，更换其一必须显式提供新 key。secret 只写入 OS vault，不返回 Provider DTO。迁移先写入并读回核验 vault，再原子提交引用和清空活动明文字段；失败保留原行供重试，消费不回退到 SQLite 明文。清理意图保存在无 secret 的持久队列中，启动及后续修改重试未完成清理，不把清理失败误报为已提交配置失败。`credential_status` 是存储状态，不是连接测试结果。旧前端须同步升级；其他 Provider 历史 schema 仍属规划，不可套用到桌面。

生命周期契约（D023）：`create_provider_with_models` 的 Provider、首次缓存和新凭据引用在一个数据库事务提交；vault 写入失败/数据库提交失败不产生半成品 Provider。`refresh_models` 每次开始领取持久刷新代次，网络期间不持有配置锁，只有配置未变化且仍是最新发起者才能事务替换缓存；旧结果返回 `1001012`，不覆盖新缓存。endpoint/type/凭据轮换同时清空缓存，界面须刷新模型后重新选择。配置修改与成功发布模型缓存递增 `config_revision`；Workbench 固定初始 revision，后续模型轮次和尚未执行的工具操作发现变化时停止并保留任务记录，不自动切换 Provider、不自动重放。已派发外部请求继续使用原快照，取消不能保证撤销外部副作用。

#### 拟增：三方兼容协议扩展的命令（D062、D063，均未注册）

字段级定义在 [FR-001 §6.3](../../03-功能规格/V1/01-底层能力/01-Provider适配框架.md#63-三方兼容协议扩展的命令与字段草案)，本节只登记命令清单，不复制字段。下列命令**当前没有注册到 Tauri**，不能当作已实现接口使用；新增命令落地时需同步 `scripts/check-host-contracts.mjs`，且入参不含 `user_id`、`module_id`、`caller`。

| Command | `CommandResponse` 的 data | 说明 |
| --- | --- | --- |
| `list_provider_vendors({})` | `ProviderVendor[]` | 只读，宿主内置厂商表的公开字段（厂商、端点、适配器、默认 base_url）；前端不自带厂商列表 |
| `add_manual_model({providerId, modelId, kind?})` | `Model` | 幂等；递增 `config_revision` |
| `remove_manual_model({providerId, modelId})` | `null` | 只删除 `source=manual` 的行 |
| `call_provider_stream({providerId, modelId, request, onEvent})` | `{stream_id}` | 事件只推送到调用方传入的 Tauri Channel |
| `cancel_provider_stream({streamId})` | `boolean` | 只取消本窗口发起的流 |

对现有命令的拟议变更：`test_provider_connection` 增加可选 `probeModel`；`create_provider_with_models` 的 `models` 只采用 `model_id` 与 `model_name`，其余由宿主重新计算；`Model` DTO 增加 `kind_source`、`source`、`capabilities`，`model_type` 承载 `kind`（旧值 `chat` 读取时视为 `text-generation`）；`ProviderConfig.config` 增加 `vendor_id`、`auth_style`、`allow_insecure_http`。模块 `providers.call`（D051）的 `request` 与 `ChatRequest` 同源，自动获得新的可选字段，命令入参白名单不变。

### 5.2 流式调用

**Tauri Command**: `call_provider_stream`

**请求**：
```typescript
// 同 CallProviderRequest
```

**响应**：
```typescript
// 不直接返回，通过事件推送
interface StreamChunk {
  request_id: string;        // 请求唯一标识
  chunk_type: 'content' | 'usage' | 'done' | 'error';
  content?: string;          // 内容片段
  usage?: {
    prompt_tokens: number;
    completion_tokens: number;
    total_tokens: number;
  };
  error?: ApiError;
}
```

**事件**：
```typescript
// 前端监听事件
listen<StreamChunk>('provider_stream', (event) => {
  const chunk = event.payload;
  
  switch (chunk.chunk_type) {
    case 'content':
      // 追加内容片段
      appendContent(chunk.content!);
      break;
    case 'usage':
      // 显示用量统计
      showUsage(chunk.usage!);
      break;
    case 'done':
      // 流结束
      finishStream();
      break;
    case 'error':
      // 处理错误
      handleError(chunk.error!);
      break;
  }
});

// 调用
await invoke('call_provider_stream', { request });
```

**HTTP API（SSE）**：
```
POST /api/v1/providers/:id/call/stream
Authorization: Bearer <token>
Content-Type: application/json

Body: CallProviderRequest (without provider_id)

Response: text/event-stream

event: content
data: {"content": "Hello"}

event: content
data: {"content": " world"}

event: usage
data: {"prompt_tokens": 10, "completion_tokens": 5, "total_tokens": 15}

event: done
data: {}
```

## 7. MCP 管理接口

> D021 已冻结 V1 的 MCP 边界。以下是桌面 Tauri IPC 的实施契约；局域网 HTTP 暴露需等认证、凭据和权限门禁完成后单独开放，不把桌面命令自动等同为公网 API。

### 7.1 公共类型

```typescript
type McpTransport = 'stdio' | 'http';
type McpStatus = 'configured' | 'connecting' | 'ready' | 'degraded' | 'error' | 'disconnecting';

interface McpServer {
  id: string;                 // UUID
  user_id: string;
  name: string;
  transport: McpTransport;
  enabled: boolean;
  auto_connect: boolean;     // 默认 false
  status: McpStatus;
  reconnect_attempts: number; // 仅运行时；0–3，重启/手动操作后重置
  reconnect_exhausted: boolean; // 仅运行时；全局恢复失败通知依据
  last_error_class?: string;
  credential_ref?: string;   // 仅引用，不返回 secret
  created_at: number;        // Unix 秒
  updated_at: number;        // Unix 秒
}

interface McpTool {
  server_id: string;
  tool_name: string;
  title?: string;
  description?: string;
  input_schema: unknown;
  output_schema?: unknown;
  schema_hash: string;
  discovered_at: number;     // Unix 秒
}
```

stdio 配置使用 `executable: string`、`args: string[]`、可选 `cwd`；HTTP 配置使用 `url`、可选 `credential_ref` 和默认 `false` 的 `allow_insecure_http`，不接收任意 header 或内联 secret。命令参数不得是 shell 字符串，响应不得包含 secret、完整命令环境或凭据内容。

HTTPS 与明确的 localhost/回环地址可使用默认配置；非回环明文 HTTP 必须单独勾选风险确认，并将 `allow_insecure_http: true` 保存在本 Server 配置。旧配置缺字段按 false 处理。编辑 URL 会清除前端风险确认与凭据绑定，重新保存须重新确认；此许可不绕过凭据作用域、同源跳转/SSE endpoint 限制或工具逐次确认。该标记不表示明文传输安全。

### 7.2 Server 配置与生命周期

MCP 命令由宿主从可信本地主窗口派生 V1 单用户身份 `default-user`，不使用 renderer 的 user_id；尚不代表完整 FR-008/009 多用户鉴权。Tauri 参数使用 camelCase（如 serverId），请求 DTO 字段保持 snake_case。使用记录默认最近 50 条，上限 100 条。

`call_mcp_tool` 不接受模型直接传入的权限声明；Server 必须启用，当前用户必须拥有 `mcp.call`，工具必须存在且参数通过 JSON Schema 校验。写操作、网络外发和未知副作用工具没有有效确认凭证时拒绝发送网络请求。

工具输入/输出 schema 必须是对象类型且能在不获取外部引用的前提下编译；`schema_hash` 覆盖规范化输入和可选输出 schema，输出契约变更同样使固定任务引用失效。成功结果须有合法 content 数组；声明 outputSchema 时须包含通过校验的 structuredContent。非法结果作为脱敏协议错误返回，Workbench 终止而不继续模型；普通合法 `isError: true` 可继续交由模型解释，不自动重试工具。

取消入口不占用 Server 的调用操作锁或生命周期写锁，以免被在途请求阻塞。取消绑定当前用户、Server 和 call_id；别的用户/Server 不可取消。排队中的取消不会发送 tools/call；已经发送时停止等待结果，并尽力发送 `notifications/cancelled`，不终止其他正常调用、不自动重试，也不宣称已经撤销外部副作用。晚到响应不能匹配其他调用。相同 call_id 的同时调用拒绝，但 ID 不是跨进程幂等键；重复操作仍需新的显式确认。

使用审计在外部操作前保存 pending，超时/取消分别记录 timeout/cancelled；权限、schema、确认等拒绝只为当前用户拥有的 Server 记录 denied，禁止给其他用户的 Server 伪造日志。应用重启时 pending 转为 interrupted，表示外部最终结果未知，不能自动重放。取消/超时/中断均须先核对外部状态，再由用户决定是否重新操作。

### 7.4 错误映射

MCP 命令使用 [V1 错误码](V1-错误码.md) 的 `1003xxx` 范围。Tauri IPC 与未来 HTTP API 共享错误类别，但 HTTP 暴露前必须补齐会话鉴权和用户隔离门禁。

## 8. 模块系统接口

> FR-004 整体未完成。§8.1/§8.2 仍是 D024 冻结后的未来契约形状，不代表已有对应 Tauri 命令。§8.3 记录 D034 已实现的生命周期命令；它们不含远程入口加载、WebView 加载或安全隔离实现。

模块调用边界（D025/D026/D029）：模块身份由宿主发布器根据已校验 manifest、当前版本和 artifact SHA-256 构造；renderer 不提交 `user_id`、caller 或授权 token（D034 的生命周期命令只接受 `module_id` 选择器，见 §8.3，它不是授权依据）。模块能力请求只携带业务字段，宿主在实际 dispatch 前绑定用户、模块版本、完整性和 request ID，并逐次检查当前包摘要、manifest 声明能力与 `module_permissions`；manifest 是能力上限，授权只能授予其交集。撤销立即拒绝新请求；已派发的 Provider/MCP 外部请求继续使用原快照，不伪报为已撤销或已回滚，终态按既有取消/未知结果语义记录。当前 `ModulePermissionRepository` 是 PRE04-09 持久化授权切片，不参与任何真实模块能力调用，也不证明模块身份可信；Host Capability API 已接入 Provider 宿主服务，但尚未向 renderer 或真实模块运行时开放。

发布器状态机（D027）：`staged → validated → switched → committed`；失败进入 `recovery_pending`，启动恢复依据 DB 当前指针和文件摘要选择旧版本或禁用模块。数据库事务不替代文件暂存、fsync、原子目录切换、回滚和孤儿文件清理。V1 只允许内置/宿主已发布包，不接受任意远程 `entry_url`。

### 8.3 生命周期命令（D034，已实现）

响应沿用 `CommandResponse<T>`（`success/data/error{code,message}`）。所有命令仅限 `main` 窗口、可信来源且当前路径为 `/settings` 或其子路径的页面（D037）；其他路径、其他窗口一律 `1004004`。用户身份由宿主派生，请求中没有 `user_id`、runtime handle、版本、摘要、路径或 URL；Tauri 会丢弃请求中未声明的额外字段，它们不影响结果。

| Tauri Command | 请求 | 响应 `data` | 说明 |
| --- | --- | --- | --- |
| `start_module` | `{ module_id }` | `{ operation_id }` | 受理后在后台启动已发布且校验通过的模块；启动恢复成功前以 `1004019` 拒绝 |
| `stop_module` | `{ module_id }` | `{ operation_id }` | 停止当前 runtime 并重试该模块全部待释放实例；宿主不可用时仍受理 |
| `update_module` | `{ module_id }` | `{ operation_id }` | 只读取宿主拥有的 `module-sources/<module_id>` 目录，不接受路径或 URL |
| `get_module_operation` | `{ operation_id }` | `ModuleOperationView` | 内存中保留未结束操作与最近 64 条已结束操作，其余及应用重启后的任何 ID 均为 `1004018`（D036） |
| `get_module_runtime_status` | `{ module_id }` | `ModuleRuntimeStatusView` | 含 `state`（`not_loaded/starting/ready/draining/stopped/failed`）、`pending_releases`、`active_operation_id`、`executes_module_code`（`false` 表示 ready 只经过宿主侧校验，未执行任何模块代码，D043） |

`ModuleOperationView`：`operation_id`、`module_id`、`kind`（`start/stop/update`）、`state`（`queued/running/succeeded/failed`）、`outcome`（`started/stopped/updated/updated_pending_release/unchanged`）、`failure{kind,code,retryable}`、`submitted_at`、`finished_at`（Unix 秒）。`ModuleRuntimeStatusView` 的 `runtime_id` 只是展示用标签，没有命令接受它。

### 8.4 页面桥接命令（D046，已实现）

页面生命周期的 transport 扩展，不是通用模块 IPC：模块代码不能经它们调用宿主能力。只服务页面自身的生命周期，不执行生命周期操作、不返回模块数据，请求中没有也不接受 `module_id`、用户、版本、摘要、路径、URL、权限或 manifest。门禁为 `main` 窗口加可信来源（`host::module_host_window`），不要求 Settings 路由，也不经过 caller/capability 策略（页面在应用启动时附着，模块实例跨 SPA 路由保持）；5 个生命周期命令的 Settings 路由门禁不变。响应同样是 `CommandResponse<T>`。

| Tauri Command | 请求 | 响应 `data` | 说明 |
| --- | --- | --- | --- |
| `attach_module_host` | `{ onInstruction: Channel }` | `{ attachmentId }` | 页面附着并登记指令通道；同一窗口的新附着取代旧附着，旧附着上的待处理 ticket 以 `PageLost` 失败、已加载实例被上报丢失 |
| `report_module_host` | `{ attachmentId, ticket, receipt }` | `{ disposition }` | 提交一条指令的结果；`disposition` 为 `applied/duplicate/stale/abandoned/unknown`，只有 `applied` 改变状态 |

通道上的指令：`{kind:'load', ticket, runtimeId, moduleId, version, source, hookTimeoutMs}`、`{kind:'unload', ticket, runtimeId, hookTimeoutMs}`。回执：`{kind:'loaded'}`、`{kind:'loadFailed', stage}`（`import/contract/render/hook/timeout/cancelled`）、`{kind:'unloaded', hookFailed}`，不含消息、堆栈、模块 id 或路径。`attachmentId` 与 `ticket` 由宿主签发、单次有效，宿主据 ticket 映射到 runtime；页面不能指定 runtime。

这两条命令不是授权：与宿主共享 JS realm 的脚本可以调用它们并伪造回执，回执只决定宿主是否把 runtime 标为 ready；真正限制什么能运行的是 D041 的固定准入清单。设计依据见 [D041](../../06-决策记录/V1-冻结决策.md#d041-v1-可执行模块包的准入来源宿主固定清单摘要不等于可信)～[D046](../../06-决策记录/V1-冻结决策.md#d046-模块宿主桥接命令对-d034-命令边界的最小扩展) 与 [FR-004 §7.7](../../03-功能规格/V1/01-底层能力/04-模块系统与热更新.md#77-真实模块加载纵切片d041d046)。

**运行时能力调用（D048，D051）**：`ModuleCapabilityDispatchService::call_provider_bound(call, providers, provider_id, model_id, request)` 对应 `providers.call`，由命令 `module_call_provider`（§8.5）使用；`call_provider(handle, …)` 仍保留给持有 supervisor 句柄的宿主 Rust 代码。用户、版本、integrity 取自句柄，`request_id` 逐次生成，调用方不提供任何身份。授权每次调用前重新检查；准入与授权失败为 `1004004`，Provider 失败保持自身错误码；不去重、不重试、不重放。

### 8.5 模块到宿主能力调用通道（D050、D051、D054，ADR-0001，已实现，仅限首方模块）

模块 JS 通过冻结的 `host.providers.call(providerId, modelId, request)` 触发。它不是通用模块 IPC：每种能力一条类型化命令，没有“能力名 + 任意 JSON”的入口。

| Tauri Command | 请求 | 响应 `data` | 说明 |
| --- | --- | --- | --- |
| `module_call_provider` | `{ attachmentId, route, callId, providerId, modelId, request }` | `ChatResponse` | 门禁：`main` 窗口与可信来源（`host::module_host_window`），不要求 Settings 路由。`route` 是宿主在 runtime `ready` 后经指令通道推送给页面的路由键；`callId` 由页面每次调用生成（1～64 位字母数字、`-`、`_`），宿主按路由丢弃重复值（D054） |
| `report_module_crash` | `{ attachmentId, route, callId, source, errorName, stack }` | `{ recorded }` | 页面上报挂载后被 Error Boundary 捕获的渲染错误（D055）。runtime 由路由解析，不接受 `module_id`；宿主清洗 `errorName` 与 `stack`，不保存消息文本 |

通道指令新增 `{kind:'route', runtimeId, route}`（无 ticket、无回执）；`load` 指令新增可选 `replaces`（被替换实例的 `runtimeId`，D055）。

| 项 | 规则 |
| --- | --- |
| 禁止 | 携带 `module_id` 的普通命令；通用转发入口；远程 URL；`runtime_id`、用户、版本、摘要、路径、权限、能力令牌类入参。`contracts:check` 以逐命令的入参白名单强制 |
| 宿主绑定 | supervisor 签发的 runtime；该句柄中的 `(module_id, version, integrity)`；页面附着与代次；宿主在准入时生成的 `request_id`；均不由调用方提供 |
| 准入顺序 | `ModuleCallRouter::admit_once`（路由存在、附着一致且仍是当前、代次未变、`call_id` 未见过、runtime `ready`、在途未超限）→ 逐次授权（D048）→ 执行能力 |
| 在途上限 | 每个 runtime 8 个在途调用（当前仅一种能力）；超限返回可重试的 `1001005`，不计入 `admitted` |
| 期限 | `providers.call` 总期限 120 秒，由宿主执行；到期返回 `1001006`，请求按 `Interrupted` 结算，外部结果未知，不重放 |
| 失败映射 | 通道准入、重复 `call_id` 与授权失败统一 `1004004`，原因不返回给模块；能力自身失败保持其错误码 |
| 撤权/停止/重载 | 撤权在下一次调用前生效，不取消在途调用；runtime 停止、被取代或页面重载使路由失效；重启需重新签发。页面重载时在途调用在宿主侧运行到终态，结果无人接收 |
| 未实现 | 取消命令；`mcp.call`、`skills.execute` 等其他能力；跨路由或跨重启的 `call_id` 去重 |
| 安全定性 | 同 realm 不是沙箱：同页脚本可读取并重放路由键，也可绕过通道直接 `invoke`；通道提供归因与按模块授权，不提供隔离；D041/D052 的固定准入仍是唯一执行边界；V1 仅适用于清单内首方模块 |

### 8.6 模块管理命令（D055，已实现）

沿用 §8.3 的门禁（`main` 窗口、可信来源、`/settings` 路径）与 `CommandResponse<T>`。入参只含 `module_id`、`operation_id` 与（授予/撤销时）一个 D006 权限字符串；宿主重新读取 manifest 并拒绝未声明的权限。

| --- | --- | --- | --- |

| `disable_module` | `{ module_id }` | `{ operation_id }` | 先停止 runtime，再禁用 |

## 10. 对话管理接口

### 10.0 桌面单任务与受控工具消费（D018/D022）

这是当前单任务切片的实际 Commands，不代表后续完整对话 API 已交付。所有命令要求可信本地主窗口，宿主使用 default-user；D023 已移除 userId 参数。无对应局域网 HTTP 路由。

```typescript
interface WorkbenchTaskInput {
  provider_id: string; model_id: string; prompt: string;
  skill_id: string | null; allow_without_skill: boolean;
  client_task_id?: string; // UUID correlation only; host still binds user/task ownership
}
interface WorkbenchToolSelection { server_id: string; tool_name: string; schema_hash: string }
type WorkbenchToolAction = { type: 'run_model' }
  | { type: 'approve' | 'deny'; proposal_id: string };
interface WorkbenchToolProposal {
  id: string; server_id: string; server_name: string; tool_name: string;
  schema_hash: string; arguments: unknown; expires_at: number; // Unix seconds
}
```

| Command / IPC 参数 | 返回与行为 |
| --- | --- |
| `run_workbench_task({ input: WorkbenchTaskInput })` | D018 文本链路，返回 `{record, content?, audit_warning?}`；不发送工具；页面离开可用 host-bound correlation ID 取消 |
| `list_workbench_tasks({})` | 至多 50 条 `{task, skills, tools}` 安全审计；tools 仅 Server/工具/schema 引用，不含正文 |
| `start_workbench_tool_task({ input: {task: WorkbenchTaskInput, tools: WorkbenchToolSelection[]} })` | 1–8 个显式工具；创建事务固定引用，返回 ready 与真实任务 ID；不调用 Provider 或工具 |
| `advance_workbench_tool_task({ taskId, action: WorkbenchToolAction })` | ready 才可 run_model；awaiting_confirmation 才可按单次宿主提案 ID approve/deny；原子取走上下文，重复/过期 action 拒绝 |
| `cancel_workbench_tool_task({ taskId })` | 取消内存会话、终结失败；已终结的当前用户工具任务返回原终态，不重写、不重放；不保证撤销外部副作用 |
| `cancel_workbench_task({ taskId })` | 取消当前用户的文本 Provider 请求；终态为 `interrupted/task_cancelled`，不自动重放；不存在或已终结任务返回 `false` |

工具任务返回 `{record, phase, proposal: WorkbenchToolProposal|null, content: string|null}`。phase 为 ready/awaiting_confirmation/finished；Provider/MCP 执行期间该 invoke 挂起但可通过独立取消命令停止。只有 awaiting_confirmation 携带提案；只有成功终结携带最终正文。确认不接收 arguments/confirmation_token 等替换字段，DTO 拒绝未知字段。命令以 `Result<T,String>` 返回稳定错误摘要；已建任务失败时返回 fixed error_code 的 failed 记录，不包装为 Provider 成功。

每次批准后宿主以固定 schema 调用 Manager 的受控入口，在 dispatch 锁内重新校验；真实任务 ID 进入 MCP 使用记录 task_ref。工具输出使用 Provider tool 角色关联原模型 call ID，并重新检查 24 KiB/模型窗口预算。工具失败不自动重试；正文与确认信息只在内存中，重启不恢复。完整时序和证据见[工作台技能消费设计](V1-工作台技能消费设计.md#5-mcp-显式消费扩展d022)。

### 12.2 后端推送事件

```rust
#[tauri::command]
async fn call_provider_stream(
    app_handle: tauri::AppHandle,
    request: CallProviderRequest,
) -> Result<(), String> {
    // 流式调用 Provider
    let mut stream = provider.call_stream(&request).await?;
    
    while let Some(chunk) = stream.next().await {
        // 推送事件到前端
        app_handle.emit_all("provider_stream", StreamChunk {
            request_id: request.id,
            chunk_type: "content",
            content: Some(chunk),
            ..Default::default()
        })?;
    }
    
    // 发送结束事件
    app_handle.emit_all("provider_stream", StreamChunk {
        request_id: request.id,
        chunk_type: "done",
        ..Default::default()
    })?;
    
    Ok(())
}
```
