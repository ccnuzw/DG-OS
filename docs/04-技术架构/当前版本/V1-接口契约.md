# V1 接口契约

## 1. 文档目标

定义 DGOS V1.0 前后端通信的完整接口契约，包括 Tauri IPC 接口、HTTP API（局域网模式）和事件系统。

**权威性**：桌面 Tauri IPC 的命令清单、参数和语义以本文档为准；HTTP 字段级定义以 [OpenAPI](V1-openapi.yaml) 为准（见 [文档权威性](../../README.md)），本文档负责公共语义。前后端必须严格遵守契约。

**更新规则**：接口变更必须先更新本文档，再修改代码。破坏性变更需要记录 Migration 路径。

## 2. 通信架构

### 2.1 桌面模式（Tauri IPC）

**D023 身份基线（2026-10-28）**：所有已注册桌面命令要求可信本地主窗口，用户由 Rust 宿主派生为既有 `default-user`。Provider、Skills、Workbench 命令不再接收 `userId`；MCP 同样使用统一宿主入口。此为前后端同步升级的破坏性 IPC 调整：旧前端需同时替换，不提供任意用户兼容入口。这是 D023 当时的基线；FR-008 已于 2026-11-01 实现（见下一段），局域网认证（FR-010）仍未实现。

**FR-008 会话解析（2026-11-01，已实现）**：用户不再固定为 `default-user`，由宿主内存中的 `SessionResolver`（`src-tauri/src/session.rs`）给出。`no_accounts`（尚无账户，含升级后的旧库）时仍为 `default-user`、没有门禁；有账户时必须登录，`signed_out` 与切换中、删除中时 `host::context`、`host::module_session`、`host::module_confirmation_session` 返回 `1008007`，先于 caller/capability 检查。所有已注册命令的签名不变，仍不携带用户身份。账户命令见 §9。

配置管理路由绑定内置 Settings 来源，任务编排绑定 Workbench 来源。来源由 Rust 命令选择，renderer 不能提交模块身份；同 realm 的 JS 仍是可信宿主代码，不能以此宣称第三方隔离。完整边界见 [前置收口设计](V1-FR004前置收口设计.md)。

```
React Frontend  ←→  Tauri IPC  ←→  Rust Backend
     (TS)                              (Rust)
```

**特点**：
- 类型安全（通过代码生成）
- 进程内通信（低延迟）
- 支持流式响应（通过事件）

### 2.2 局域网模式（HTTP API）

```
Browser  ←→  HTTP/WebSocket  ←→  Rust Backend
  (TS)         (JSON/SSE)          (Rust)
```

**特点**（FR-010 局域网契约，已实现；见 §14）：
- JSON 接口，流式响应用 WebSocket（D013；本文 §15.2 的“WebSocket V2”已不适用）
- 认证：主机生成的单次访问凭据换取 `HttpOnly` Cookie 会话（[D053](../../06-决策记录/V1-冻结决策.md#d053-局域网远程认证采用随机访问凭据加会话不使用用户名密码)、D088）；不使用 JWT、用户名/密码、`Authorization: Bearer` 或浏览器存储；远程会话没有独立用户身份
- 只开放 §14.4 的逐项白名单，不映射 Tauri commands（[D039](../../06-决策记录/V1-冻结决策.md#d039-局域网服务随应用自动启动设置开关持久关闭)、D099）。本文其他各节的 `HTTP API` 示例块（含 `Authorization: Bearer`）都是早期草图，已作废，不构成白名单

**引用决策**：[D007](../../06-决策记录/V1-冻结决策.md#d007-局域网-http-服务始终开启)（自动启动）、D039、D053、D088、[D099](../../06-决策记录/V1-冻结决策.md#d099-fr-010-规格收口高风险局域网审计表限速错误码-1010011-与白名单路径)。统一身份边界见 [服务与领域边界 §3.5](../服务与领域边界.md#35-auth统一身份与安全边界fr-008009010)

## 3. 错误处理

### 3.1 统一错误格式

所有错误遵循统一格式（参考 [V1-错误码](V1-错误码.md)）：

```typescript
interface ApiError {
  code: string;        // 错误码（如 "ERR_PROVIDER_001"）
  message: string;     // 用户可读的错误消息
  details?: unknown;   // 详细信息（可选）
}
```

> `ERR_*` 字符串码是早期草案写法，已作废。现行错误码是 7 位数字，登记见 [V1-错误码](V1-错误码.md)（D038）：Provider、模块、聊天、账户、外观命令经 `CommandResponse.error.code` 返回数字码；Skills、MCP 和 §10.0 的单任务命令返回 `Result<T, String>`，invoke 以错误字符串 reject。局域网 HTTP 错误包体见 §14.3。

### 3.2 HTTP 状态码映射

| HTTP 状态码 | 含义 | 示例错误码 |
|------------|------|-----------|
| 200 | 成功 | - |
| 400 | 客户端错误 | ERR_VALIDATION_001 |
| 401 | 未认证 | ERR_AUTH_001 |
| 403 | 无权限 | ERR_PERMISSION_001 |
| 404 | 资源不存在 | ERR_NOT_FOUND_001 |
| 500 | 服务器错误 | ERR_INTERNAL_001 |

> 上表的 `ERR_*` 示例同样作废，HTTP 状态码与数字错误码的对应以 [V1-错误码 §5](V1-错误码.md) 为准。

### 3.3 Tauri IPC 错误处理

```typescript
const response = await invoke<CommandResponse<DesktopProvider>>('create_provider', {
  config, probeModel,
});
if (!response.success) {
  console.error(response.error.code, response.error.message); // code 为数字，见 V1-错误码
}
```

## 4. Provider 管理接口

### 4.0 当前桌面实施契约（D023）

本节是当前桌面 IPC 的字段级依据；§4.1 起保留早期 HTTP/API 规划，不能把其 INTEGER ID、软删除、`is_enabled` 或加密声明当成当前实现证据。HTTP 字段仍以 OpenAPI 为规划来源，当前没有注册这些 HTTP 路由。

```typescript
interface ProviderConfig {
  name: string; provider_type: string; base_url: string;
  api_key: string; enabled: boolean; config?: Record<string, unknown>;
}
interface DesktopProvider {
  id: string; user_id: string; name: string; provider_type: string;
  base_url: string; enabled: boolean; sort_order: number;
  config?: Record<string, unknown>; created_at: string; updated_at: string;
  credential_ref?: string;
  credential_status: 'stored' | 'migration_required' | 'missing';
  config_revision: number; // 宿主递增的配置/已发布模型缓存代次；不是 renderer 身份
  // 不返回 api_key；stored 表示引用已保存，不保证 OS vault 当前已解锁。
}
interface CommandResponse<T> {
  success: boolean; data: T | null;
  error: {code: number; message: string} | null;
}
interface ChatResponse {
  content: string; usage: TokenUsage;
  audit_warning?: boolean; // Provider completed; usage audit persistence needs review
}
```

| Command / IPC 参数 | `CommandResponse` 的 data |
| --- | --- |
| `list_providers({})` | `DesktopProvider[]`，含禁用配置，按 sort_order 排序 |
| `create_provider({config, probeModel?})` | `DesktopProvider` |
| `create_provider_with_models({config, models, probeModel?})` | `DesktopProvider`；模型 DTO 见 `src/stores/providerStore.ts`；`models` 只采用 `model_id`、`model_name` |
| `update_provider({id, config})` | `DesktopProvider` |
| `toggle_provider({id, enabled})` | `DesktopProvider` |
| `delete_provider({id})` | `null`；当前实现为数据库删除，不是软删除 |
| `test_provider_connection({config, probeModel?})` | `boolean`，测试未保存配置；成功恒为 `true`，失败返回具体错误码，不返回 `false`（见下“连接测试契约”）；`probeModel` 仅在服务没有模型列表接口时使用，探测请求会消耗少量 token |
| `test_provider_by_id({providerId, probeModel?})` | `boolean`，只使用当前用户的保存配置；失败语义同上；`probeModel` 仅在服务没有模型列表接口时使用 |
| `list_models_for_config({config})` | `Model[]`，预览不写入缓存 |
| `list_models({providerId})` | `Model[]`，当前用户资源的缓存 |
| `refresh_models({providerId})` | `Model[]` |
| `call_provider({providerId, modelId, request})` | `ChatResponse`；非流式 IPC（流式见 `call_provider_stream`）；`audit_warning` 不触发自动重试 |
| `update_provider_order({providerIds})` | `null`；同一用户的排序在事务中提交 |
| `list_usage_logs({limit?})` | `UsageLog[]`，默认/最大 100 条，按用户过滤。`usage_reported?: boolean \| null`（D081）：`false` 表示 token 数未知（调用可能已计费），`null` 为旧记录 |
| `migrate_provider_credential({providerId})` | `DesktopProvider`；重试该 Provider 的 legacy 凭据迁移，不接收 secret 或引用 |

普通、流式和 tools 的 Rust Provider 服务均校验用户资源归属。桌面流式命令 `call_provider_stream` 与 `cancel_provider_stream` 已注册（见下“三方兼容协议扩展的命令”）；工作台任务仍走自己的非流式 tools 路径。

凭据契约（D023）：新建必须提供 key；更新时空 key 仅保留相同完整 endpoint 与 provider_type 的现有绑定，更换其一必须显式提供新 key。secret 只写入 OS vault，不返回 Provider DTO。迁移先写入并读回核验 vault，再原子提交引用和清空活动明文字段；失败保留原行供重试，消费不回退到 SQLite 明文。清理意图保存在无 secret 的持久队列中，启动及后续修改重试未完成清理，不把清理失败误报为已提交配置失败。`credential_status` 是存储状态，不是连接测试结果。旧前端须同步升级；其他 Provider 历史 schema 仍属规划，不可套用到桌面。

生命周期契约（D023）：`create_provider_with_models` 的 Provider、首次缓存和新凭据引用在一个数据库事务提交；vault 写入失败/数据库提交失败不产生半成品 Provider。`refresh_models` 每次开始领取持久刷新代次，网络期间不持有配置锁，只有配置未变化且仍是最新发起者才能事务替换缓存；旧结果返回 `1001012`，不覆盖新缓存。endpoint/type/凭据轮换同时清空缓存，界面须刷新模型后重新选择。配置修改与成功发布模型缓存递增 `config_revision`；Workbench 固定初始 revision，后续模型轮次和尚未执行的工具操作发现变化时停止并保留任务记录，不自动切换 Provider、不自动重放。已派发外部请求继续使用原快照，取消不能保证撤销外部副作用。

连接测试契约（V1-FR-001 §2.4.5）：`test_provider_connection` 与 `test_provider_by_id` 失败时返回具体错误码，不返回 `Ok(false)`，也不统一为 `provider_unavailable`（1001003）。例如 401 返回 `invalid_api_key`（1001002），403 返回 `provider_permission_denied`（1001019），200 但响应不是预期 JSON 或收到 3xx 返回 `provider_response_invalid`（1001025），网络错误与超时返回对应的网络错误或 `timeout`（1001006）。上游模型列表返回 404 或 405 且没有探测模型时，返回 `request_not_supported`（1001020）；给出探测模型时，宿主向该模型发一次最小请求（`max_tokens=16`），任何 2xx 都算成功。

宿主库的 `create_provider` 与 `create_provider_with_models` 接受可选的 `probe_model`，语义与上面相同：模型列表返回 404 或 405 且未给 `probe_model` 时，创建失败并返回 `request_not_supported`，不会静默保存；给出 `probe_model` 时，探测成功才保存 Provider。Tauri 命令 `create_provider`、`create_provider_with_models`、`test_provider_connection`、`test_provider_by_id` 现在都接收可选 `probeModel`（2026-10-30）并传给管理器，界面因此可以在没有模型列表接口的服务上完成连接测试与创建。`request_not_supported` 同时也表示高级选项取值非法，界面只在尚未填写探测模型时把它解释为“没有模型列表接口”。

#### 三方兼容协议扩展的命令（D062、D063，已注册，2026-10-30）

字段级定义在 [FR-001 §6.3](../../03-功能规格/V1/01-底层能力/01-Provider适配框架.md#63-三方兼容协议扩展的命令与字段草案)，本节只登记命令清单，不复制字段。命令实现在 `src-tauri/src/commands/provider_commands.rs`，已列入 `src-tauri/src/lib.rs` 的 handler；入参不含 `user_id`、`module_id`、`caller`，`scripts/check-host-contracts.mjs` 对每个命令的参数列表做精确核对（`npm run contracts:check`）。验证证据等级只在 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)记录，本节不重复。

| Command | `CommandResponse` 的 data | 说明 |
| --- | --- | --- |
| `list_provider_vendors({})` | `ProviderVendor[]` | 只读，宿主内置厂商表的公开字段（厂商、端点、适配器、默认 base_url）；前端不自带厂商列表。能力：`ProvidersRead` |
| `add_manual_model({providerId, modelId, kind?})` | `Model` | 幂等：同 ID 已存在时原样返回，不递增 `config_revision`；真正插入时在同一事务内递增 `config_revision`。`modelId` 非法或 `kind` 不是规范拼写返回 `request_not_supported` |
| `remove_manual_model({providerId, modelId})` | `null` | 只删除 `source=manual` 的行；行不存在或为远程模型时也返回成功且不递增 `config_revision` |
| `call_provider_stream({providerId, modelId, request, onEvent})` | `{stream_id}` | `onEvent` 是调用方传入的 Tauri `Channel<ProviderStreamEvent>`，事件只推送到它，宿主不发全局事件（D042）。一个流以恰好一个 `done` 或 `error` 事件结束，其后不再有事件。授权与启动失败作为命令错误返回，此时没有 `stream_id`。使用记录带 `caller` 与 `request_id`，和 `call_provider` 一致。仅内置调用方可用，模块上下文返回 `permission_denied`（`providers.call` 是非流式能力，D051） |
| `cancel_provider_stream({streamId})` | `boolean` | 只取消本窗口（窗口标签）发起的流并返回 `true`；未知、已结束、已取消或属于其他窗口的 `streamId` 返回 `false`。窗口销毁或页面重新加载时，宿主取消该窗口的全部流 |

`call_provider_stream` 的事件为 `{kind: 'delta' | 'reasoning_delta', text}`、`{kind: 'done', finish_reason, usage}`、`{kind: 'error', code, message}`；定义在 `crates/dgos-types/src/provider.rs` 的 `ProviderStreamEvent`。流在读取上游期间被取消，调用方收到一次 `error`（`stream_interrupted`，1001007），使用记录为 `success=false`、`error_code=1001007`；流在没有结束原因时结束，同样报告一次 `stream_interrupted`。接收端消失（`Channel.send` 失败）时宿主停止读取上游，使用记录同样按中断写入。应用层入口是 `ProviderCallService::execute_stream`（`crates/dgos-application/src/lib.rs`），注册表与转发逻辑在 `src-tauri/src/provider_streams.rs`。

现有命令的变化（均已实现）：`test_provider_connection({config, probeModel?})`、`test_provider_by_id({providerId, probeModel?})`、`create_provider({config, probeModel?})`、`create_provider_with_models({config, models, probeModel?})` 增加可选 `probeModel`，原样传给管理器；`create_provider_with_models` 的 `models` 只采用 `model_id` 与 `model_name`，其余由宿主重新计算；`Model` DTO 增加 `kind_source`、`source`、`capabilities`，`model_type` 承载 `kind`（旧值 `chat` 读取时视为 `text-generation`）；`ProviderConfig.config` 增加 `vendor_id`、`auth_style`、`allow_insecure_http`（以及可选的 `workspace_id`，仅官方 Anthropic 画像发送）。模块 `providers.call`（D051）的 `request` 与 `ChatRequest` 同源，自动获得新的可选字段，命令入参白名单不变。

### 4.1 创建 Provider

**Tauri Command**: `create_provider`

**请求**：
```typescript
interface CreateProviderRequest {
  name: string;              // Provider 名称
  provider_type: string;     // 类型（当前代码只支持 "openai_compatible"；D062 起另有 "anthropic"，未实现）
  base_url: string;          // API 基础 URL
  api_key: string;           // API Key（明文，后端负责加密）
}
```

**响应**：
```typescript
interface Provider {
  id: number;
  user_id: number;
  name: string;
  provider_type: string;
  base_url: string;
  is_enabled: boolean;
  sort_order: number;
  created_at: string;        // ISO 8601
  updated_at: string;
}
```

**错误场景**：
- `ERR_VALIDATION_001`: 必填字段缺失
- `ERR_PROVIDER_001`: Provider 名称已存在
- `ERR_PROVIDER_002`: base_url 格式无效
- `ERR_PROVIDER_003`: API Key 加密失败

**HTTP API**：
```
POST /api/v1/providers
Content-Type: application/json
Authorization: Bearer <token>

Body: CreateProviderRequest
Response: Provider
```

### 4.5 获取 Provider 模型列表

**Tauri Command**: `get_provider_models`

**请求**：
```typescript
interface GetProviderModelsRequest {
  provider_id: number;
  force_refresh?: boolean;   // 是否强制刷新缓存
}
```

**响应**：
```typescript
interface ProviderModel {
  id: number;
  provider_id: number;
  model_id: string;          // 模型标识符（如 "gpt-4"）
  model_name: string;        // 模型名称
  model_type: string;        // 类型（text-generation 等）
  context_window: number;
  max_output_tokens: number;
  supports_streaming: boolean;
  supports_vision: boolean;
  cached_at: string;
}

interface GetProviderModelsResponse {
  models: ProviderModel[];
  cached_at: string;         // 缓存时间
}
```

**行为**：
1. 首次调用：从 Provider API 获取模型列表并缓存
2. 后续调用：返回缓存数据
3. force_refresh=true：重新获取并更新缓存

**错误场景**：
- `ERR_PROVIDER_004`: Provider API 调用失败
- `ERR_PROVIDER_005`: 模型列表解析失败

**HTTP API**：
```
GET /api/v1/providers/:id/models?force_refresh=false
Authorization: Bearer <token>

Response: GetProviderModelsResponse
```

## 5. Provider 调用接口

### 5.1 同步调用（非流式）

**Tauri Command**: `call_provider`

**请求**：
```typescript
interface CallProviderRequest {
  provider_id: number;
  model_id: string;
  messages: ChatMessage[];
  temperature?: number;      // 默认 0.7
  max_tokens?: number;
  top_p?: number;
}

interface ChatMessage {
  role: 'system' | 'user' | 'assistant';
  content: string;
}
```

**响应**：
```typescript
interface CallProviderResponse {
  content: string;           // 生成的内容
  model: string;             // 实际使用的模型

    prompt_tokens: number;
```

### 5.2 流式调用

**Tauri Command**: `call_provider_stream({providerId, modelId, request, onEvent})`


**响应**：命令返回 `{ stream_id }`；内容、用量和终态通过 `onEvent` 逐条到达：
```typescript
type ProviderStreamEvent =
  | { kind: 'delta'; text: string }
  | { kind: 'reasoning_delta'; text: string }
  | { kind: 'done'; finish_reason: string; usage: TokenUsage } // 上游未给用量时为 0（聊天持久化时另按 NULL 处理，见 §10.1 与 D074）

```

```typescript
import { Channel, invoke } from '@tauri-apps/api/core';

const onEvent = new Channel<ProviderStreamEvent>();
onEvent.onmessage = (event) => {
  switch (event.kind) {
    case 'delta':
      appendContent(event.text); // 追加内容片段
      break;
    case 'reasoning_delta':
      appendReasoning(event.text); // 只显示
      break;
    case 'done':
      finishStream(event.usage); // 流结束，其后不再有事件
      break;
    case 'error':
      handleError(event.code, event.message); // 流结束，其后不再有事件

};

const { stream_id } = await invoke('call_provider_stream', {
  providerId, modelId, request, onEvent,
});
// 取消：await invoke('cancel_provider_stream', { streamId: stream_id });
```

聊天（多轮会话）的流式不经过本命令：它使用 §10.1 的 `send_chat_message`，事件类型为 `ChatStreamEvent`，同样只走调用方的 Channel。

## 7. MCP 管理接口

> D021 已冻结 V1 的 MCP 边界。以下是桌面 Tauri IPC 的实施契约；局域网 HTTP 暴露需等认证、凭据和权限门禁完成后单独开放，不把桌面命令自动等同为公网 API。

### 7.1 公共类型

```typescript
type McpTransport = 'stdio' | 'http';
type McpStatus = 'configured' | 'connecting' | 'ready' | 'degraded' | 'error' | 'disconnecting';

interface McpServer {
  id: string;                 // UUID
  user_id: string;
  name: string;
  transport: McpTransport;
  enabled: boolean;
  auto_connect: boolean;     // 默认 false
  status: McpStatus;
  reconnect_attempts: number; // 仅运行时；0–3，重启/手动操作后重置
  reconnect_exhausted: boolean; // 仅运行时；全局恢复失败通知依据
  last_error_class?: string;
  credential_ref?: string;   // 仅引用，不返回 secret
  created_at: number;        // Unix 秒
  updated_at: number;        // Unix 秒
}

interface McpTool {
  server_id: string;
  tool_name: string;
  title?: string;
  description?: string;
  input_schema: unknown;
  output_schema?: unknown;
  schema_hash: string;
  discovered_at: number;     // Unix 秒
}
```

stdio 配置使用 `executable: string`、`args: string[]`、可选 `cwd`；HTTP 配置使用 `url`、可选 `credential_ref` 和默认 `false` 的 `allow_insecure_http`，不接收任意 header 或内联 secret。命令参数不得是 shell 字符串，响应不得包含 secret、完整命令环境或凭据内容。

HTTPS 与明确的 localhost/回环地址可使用默认配置；非回环明文 HTTP 必须单独勾选风险确认，并将 `allow_insecure_http: true` 保存在本 Server 配置。旧配置缺字段按 false 处理。编辑 URL 会清除前端风险确认与凭据绑定，重新保存须重新确认；此许可不绕过凭据作用域、同源跳转/SSE endpoint 限制或工具逐次确认。该标记不表示明文传输安全。

MCP 命令由宿主从可信本地主窗口派生用户身份（§2.1：无账户时为 `default-user`，有账户时为已登录账户），不使用 renderer 的 user_id。Tauri 参数使用 camelCase（如 serverId），请求 DTO 字段保持 snake_case。使用记录默认最近 50 条，上限 100 条。

工具输入/输出 schema 必须是对象类型且能在不获取外部引用的前提下编译；`schema_hash` 覆盖规范化输入和可选输出 schema，输出契约变更同样使固定任务引用失效。成功结果须有合法 content 数组；声明 outputSchema 时须包含通过校验的 structuredContent。非法结果作为脱敏协议错误返回，Workbench 终止而不继续模型；普通合法 `isError: true` 可继续交由模型解释，不自动重试工具。

取消入口不占用 Server 的调用操作锁或生命周期写锁，以免被在途请求阻塞。取消绑定当前用户、Server 和 call_id；别的用户/Server 不可取消。排队中的取消不会发送 tools/call；已经发送时停止等待结果，并尽力发送 `notifications/cancelled`，不终止其他正常调用、不自动重试，也不宣称已经撤销外部副作用。晚到响应不能匹配其他调用。相同 call_id 的同时调用拒绝，但 ID 不是跨进程幂等键；重复操作仍需新的显式确认。

使用审计在外部操作前保存 pending，超时/取消分别记录 timeout/cancelled；权限、schema、确认等拒绝只为当前用户拥有的 Server 记录 denied，禁止给其他用户的 Server 伪造日志。应用重启时 pending 转为 interrupted，表示外部最终结果未知，不能自动重放。取消/超时/中断均须先核对外部状态，再由用户决定是否重新操作。

### 7.4 错误映射

MCP 命令使用 [V1 错误码](V1-错误码.md) 的 `1003xxx` 范围。Tauri IPC 与未来 HTTP API 共享错误类别，但 HTTP 暴露前必须补齐会话鉴权和用户隔离门禁。

模块调用边界（D025/D026/D029）：模块身份由宿主发布器根据已校验 manifest、当前版本和 artifact SHA-256 构造；renderer 不提交 `user_id`、caller 或授权 token（D034 的生命周期命令只接受 `module_id` 选择器，见 §8.3，它不是授权依据）。模块能力请求只携带业务字段，宿主在实际 dispatch 前绑定用户、模块版本、完整性和 request ID，并逐次检查当前包摘要、manifest 声明能力与 `module_permissions`；manifest 是能力上限，授权只能授予其交集。撤销立即拒绝新请求；已派发的 Provider/MCP 外部请求继续使用原快照，不伪报为已撤销或已回滚，终态按既有取消/未知结果语义记录。`ModulePermissionRepository` 持久化授权，由 `ModuleCapabilityDispatchService` 在每次能力调用前检查（§8.5）；授权不证明模块身份可信，D041/D052 的固定准入仍是唯一执行边界。

### 8.4 页面桥接命令（D046，已实现）

页面生命周期的 transport 扩展，不是通用模块 IPC：模块代码不能经它们调用宿主能力。只服务页面自身的生命周期，不执行生命周期操作、不返回模块数据，请求中没有也不接受 `module_id`、用户、版本、摘要、路径、URL、权限或 manifest。门禁为 `main` 窗口加可信来源（`host::module_host_window`），不要求 Settings 路由，也不经过 caller/capability 策略（页面在应用启动时附着，模块实例跨 SPA 路由保持）；5 个生命周期命令的 Settings 路由门禁不变。响应同样是 `CommandResponse<T>`。

### 8.7 工作区目录与独立视图（D128、D129）

`read_workspace_app_catalog()` 无参数，返回 `CommandResponse<{catalogRevision: string, entries: WorkspaceAppEntry[]}>`。只允许可信main窗口、宿主派生的有效会话；不要求Settings路径，不开放远程入口。条目只包含 `moduleId, displayName, iconResourceId: string|null, layout: document|full-bleed, viewCapability: single|multiple, enabled, permissionState: granted|pending|denied, runtimeState, crashed`。无安全图标时为空，使用宿主图标；不返回路径、源码、manifest、凭据或租约。目录来自当前账户已安装模块，包含未加载/禁用项；安装、更新、启停、撤权、崩溃后失效重读。目录读取不授予执行能力，§8.3/8.6管理门禁不变。

模块manifest可声明 `views: {layout: document|full-bleed, capability: single|multiple}`，纳入摘要和准入pin。未声明为single稳定根；multiple必须实现 `openView({viewId, documentId}) -> {Component, beforeClose?, save?, dispose?}`。每runtime仅一次createModule/onLoad/onUnload，每view独立container/root，共享能力租约；相同document聚焦已有view。beforeClose返回 `{dirty, canSave?, blocked?}`，可保存时提供保存/放弃/取消；save只有返回true且原runtime/view仍有效才允许关闭。multiple关闭dispose局部视图，不stop/onUnload；single关闭只detach，重开恢复稳定根。热更新重建原view/document身份；停用、撤权、崩溃清除可执行内容。viewId和布局提示不构成宿主调用授权。

任务标签关闭采用D130：切换/Settings覆盖不取消；显式关闭确认后请求停止并等待任务终态或Agent进程退出。ack不等于终态，失败/未知不移除任务归属。账户结束按D131及§9.4先失效旧授权、并行有界清理；不将账户退出的best-effort策略用于普通标签关闭。

> **已实现并注册（2026-11-01）。** 依据 [D023](../../06-决策记录/V1-冻结决策.md#d023-fr-004-前置收口采用宿主身份与能力边界)、[D087](../../06-决策记录/V1-冻结决策.md#d087-本地账户首个账户承接-default-userargon2id-与退避会话只在内存删除账户可恢复地清理)、[D088](../../06-决策记录/V1-冻结决策.md#d088-局域网安全默认值与首批白名单绑定签发者单次凭据换-cookie-会话只绑私网-ipv4首批只开放聊天)、[D090](../../06-决策记录/V1-冻结决策.md#d090-fr-008-账户命令契约与实现取舍独立账户入口未登录-1008007退避-1008011可恢复删除与-mcp-凭据-outbox)。命令在 `src-tauri/src/commands/accounts.rs`，用例在 `crates/dgos-application/src/accounts.rs`；实现方式与偏差见 [FR-008 技术设计](../../03-功能规格/V1/03-系统功能/08-本地用户管理-技术设计.md)，验证证据见 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)。原 §9.1～§9.3 的 `login`/`create_user`/`switch_user` 草案（`User.id: number`、`switch_user(user_id)`、JWT `token`、HTTP 路由）作废，不实现。

### 9.1 约定

- **命令文件**：`src-tauri/src/commands/accounts.rs`，已加入 `scripts/check-host-contracts.mjs` 的 `files` 与精确参数白名单（§9.5）。
- **返回**：`CommandResponse<T>`（`{ success, data, error: { code, message, detail? } }`），错误码见 [错误码 §3.8](V1-错误码.md#38-本地用户管理08)，消息为固定文本，不回显入参。
- **身份**：任何参数都不含 `user_id`、会话令牌或账户 ID。账户只按 `username`（与密码一起验证的选择器）出现；DTO 不暴露内部 `user_id`。会话令牌只在宿主内存，renderer 拿不到（D087）。
- **输入**：每个命令只有一个 `input` 参数（类型化结构，`deny_unknown_fields`），未知字段整条拒绝。口令字段在 Rust 侧以清零类型持有（与 `SecretValue` 同一做法），`Debug` 不输出内容，不进日志、错误或审计。
- **门禁**：账户命令走新入口 `host::account_window(&window)`：只校验 `main` 窗口与可信来源（与 `module_host_window` 一样共用 `trusted_main_window`），**不要求已登录**，因为登录页本身要调用它们。是否允许执行由账户状态决定（下表“允许的模式”），不经 caller/capability 策略。
- **其他命令在未登录时**：存在账户而尚未登录（`signed_out`）或正在删除账户时，`host::context` 与 `host::module_session` 返回 `1008007 session_invalid`，先于 caller/capability 检查；`no_accounts` 模式下仍以 `default-user` 放行（D087）。模块桥接命令（`module_host_window`）不受影响，但宿主在未登录时不自动启动模块（§9.4）。
- **局域网**：本节命令都不开放 HTTP 路由，不在 D088 的白名单内（[FR-010 §2.4](../../03-功能规格/V1/03-系统功能/10-局域网协同.md#已确认禁止远程调用的能力)）。

### 9.2 类型

```typescript
type AccountMode = 'no_accounts' | 'signed_out' | 'signed_in';

interface AccountSummary {
  username: string;                 // 展示与选择用；不含内部 user_id
  last_sign_in_at: number | null;   // Unix 秒
}

interface AccountState {
  mode: AccountMode;
  current: AccountSummary | null;    // 仅 signed_in
  accounts: AccountSummary[];        // 登录页的账户列表，按 last_sign_in_at 新到旧；no_accounts 时为空
  preselected: string | null;        // “记住上次登录”：上次成功登录的 username（AC11），只预选不登录
}

interface CreateAccountInput { username: string; password: string }
interface SignInInput       { username: string; password: string }
interface ChangePasswordInput { current_password: string; new_password: string }
interface DeleteAccountInput  { password: string }

interface DeleteAccountResult {
  state: AccountState;               // 删除完成后的状态
  credential_cleanup_pending: boolean; // true：部分 vault 项删除失败，已进入持久 outbox 重试（D023），不报告为已删除
}
```

规则：`username` 不做首尾裁剪，含首尾空白、控制字符或长度不在 1～32 个 Unicode 标量值内即 `1008003`；唯一性按 Unicode 简单小写比较（`Admin` 与 `admin` 冲突）。口令长度为 8～128 个 Unicode 标量值，不裁剪、不设组成规则，不符即 `1008002`。确认口令（两次输入一致）是前端校验，不进入命令。

### 9.3 命令

| Tauri Command | 参数 | 允许的模式 | 返回 `data` | 行为 |

### 9.4 会话结束顺序（切换、注销、改密、删除）

账户操作在宿主内串行（一把账户操作锁）。结束当前会话的固定顺序（D086、D087、D088）：

1. 密码验证成功后解析器进入“切换中”：此后的 `host::context`/`host::module_session` 返回 `1008007`，旧Agent会话租约不可恢复（D131）。认证失败不触发renderer或宿主取消。
2. 先撤销旧模块调用路由、Provider流及待确认MCP审批，再并行停止模块、Agent，取消聊天生成与单任务并断开MCP。各领域按既有上限等待；慢模块不能延迟其他领域收到停止请求。停止失败/未知不恢复旧授权或宣称已停止，旧对象仍绑定原owner，不转移给新账户；同账户重登不复活旧租约，不自动重放外部效果。
3. 等待各清理分支结算；失败维持既有best-effort账户结束，残留由旧owner的既有清理/启动恢复收敛。普通标签关闭仍按D130等待实际终态。
4. 撤销该用户签发的局域网远程会话（D088）。
5. 切换解析器到新状态（`signed_in` 新用户 / `signed_out` / `no_accounts`）。
6. 命令返回后由页面整页重新加载；重新附着时宿主只在 `signed_in` 或 `no_accounts` 下自动启动已启用模块。

不发送全局事件（D042/D073）。登录成功前不执行第 2～5 步，所以登录失败不会注销当前用户。

### 9.5 静态契约检查（已加入 `scripts/check-host-contracts.mjs`）

- `accounts.rs` 加入 `files`；精确参数（`accountParams`）：`get_account_state`、`sign_out` 只有 `app`、`window`；其余四个只有 `app`、`window`、`input`，且 `input` 为类型化 `*Input`。
- 每个命令体先调用 `host::account_window(&window)`，再取账户服务，且不调用 `host::context`/`host::module_session`；`account_window` 不得引用 `context`、`BuiltinCaller`、`Capability`、`allows`、Settings 路由判断或会话解析器。
- 其余文件仍禁止 `user_id`/`module_id`/`caller` 参数；`host::context` 必须经 `resolved_session(window)?` 取用户，函数体内不得出现 `LOCAL_USER`、`DEFAULT_USER_ID`、`local_default`；`LOCAL_USER` 只在 `cfg(any(test, feature = "webview-smoke"))` 下存在；宿主与 `dgos-application` 的生产代码（`#[cfg(test)]` 之前）不得调用 `HostSession::local_default()`。

### 9.6 D087 之外的设计取舍（已由 D090 冻结，2026-11-01）

| 取舍 | 内容 | 理由 |
| --- | --- | --- |
| 账户命令的门禁 | 新入口 `host::account_window`，只看窗口与来源，按账户模式决定可执行性 | 登录页在未登录时就要调用；同 realm 下路由与 caller 都不是安全边界（D042），口令校验才是 |
| 未登录时其他命令的错误 | `1008007 session_invalid`，在 caller/capability 之前返回 | 沿用已登记含义，不新增编号 |
| 退避错误 | 新登记 `1008011 sign_in_throttled`（HTTP 429），`detail.retry_after_seconds` | 1008005 无法告诉用户何时可再试；1001005 属于 Provider 域 |
| 用户名大小写 | 唯一性按 Unicode 简单小写比较 | 避免登录页出现只差大小写的两个账户 |
| 登录页不能新建账户 | `signed_out` 时 `create_account` 返回 `1008007` | 否则任何人都能在锁屏状态下建号进入；新建只在首次引导或已登录时 |
| 用户名不存在时不计退避 | 只返回 1008005，不写失败计数 | 账户列表本就展示在登录页，按不存在的用户名猜测没有收益 |

### 10.0 桌面单任务与受控工具消费（D018/D022）

这是当前单任务切片的实际 Commands，不代表后续完整对话 API 已交付。所有命令要求可信本地主窗口，用户由宿主会话解析（无账户时为 `default-user`，见 §2.1）；D023 已移除 userId 参数。无对应局域网 HTTP 路由。

```typescript
interface GenerationParameters {
  temperature?: number | null; reasoning?: {effort?: string; budget_tokens?: number} | null;
  max_tokens?: number | null; instruction?: string;

interface WorkbenchTaskInput {
```

| Command / IPC 参数 | 返回与行为 |
| --- | --- |
| `run_workbench_task({ input: WorkbenchTaskInput })` | D018 文本链路，返回 `{record, content?, audit_warning?}`；不发送工具；页面离开可用 host-bound correlation ID 取消 |

工具任务返回 `{record, phase, proposal: WorkbenchToolProposal|null, content: string|null}`。phase 为 ready/awaiting_confirmation/finished；Provider/MCP 执行期间该 invoke 挂起但可通过独立取消命令停止。只有 awaiting_confirmation 携带提案；只有成功终结携带最终正文。确认不接收 arguments/confirmation_token 等替换字段，DTO 拒绝未知字段。命令以 `Result<T,String>` 返回稳定错误摘要；已建任务失败时返回 fixed error_code 的 failed 记录，不包装为 Provider 成功。

### 10.1 聊天命令（D072～D077，FR-006 阶段 1～5）

聊天命令与 §10.0 的单任务命令并存；单任务命令在 V1 内不改（[D078](../../06-决策记录/V1-冻结决策.md#d078-单任务页面在-v1-保留为兼容面)）。`list_workbench_tasks` 只返回 `kind = 'single'` 的任务行，聊天生成的任务行不出现在其中。约定：

- 每个命令入口为 `host::context(&window, BuiltinCaller::Workbench, Capability::TasksRun)`：主窗口与可信来源，模块上下文一律拒绝。身份由宿主派生，输入不含 `user_id`/`userId`，所有输入结构 `deny_unknown_fields`，出现未知字段（含 `user_id`）整条拒绝。
- 返回 `CommandResponse<T>`：`{ success, data, error: { code, message, detail? } }`，`code` 为 [错误码 §3.6](V1-错误码.md) 的数字码或 Provider 的 1001xxx（原样透传，不包装）。只有 `destination_changed` 带 `detail`。
- 输入结构字段为 snake_case（与 §10.0 一致）。命令的顶层参数沿用 Tauri 2 默认命名：Rust 的 `on_event`、`task_id` 在 JavaScript 侧为 `onEvent`、`taskId`（与现有 `cancel_workbench_task({ taskId })` 一致）；`onEvent` 是 Tauri `Channel`，是命令参数而不是输入结构字段。
- 无对应局域网 HTTP 路由（D072：V1 聊天命令只对桌面主窗口开放）。远程聊天走 §14 的独立白名单路由，复用同一 `ChatManager`，范围限本设备本次配对创建的会话（D088、D099）。
- 他人与不存在的资源返回同一个答案：会话为 `session_not_found`（1006001）；`regenerate_chat_message` 的消息不存在、属于他人或不是最后一条助手回复，统一返回 `message_not_regenerable`（1006014），三者不区分；工具轮次为 `tool_turn_invalid`（1006017）；`cancel_chat_generation` 返回 `false`。`message_not_found`（1006002）已登记，但当前没有命令发出它（2026-10-30 阶段 6 回归核对，`chat.rs` 的 `regenerate` 与 `ChatRepository::begin_generation`）。

```typescript
type ChatMessageStatus = 'generating' | 'completed' | 'interrupted' | 'failed';

interface ChatSession {
  id: string; title: string; title_source: 'auto' | 'user';
  provider_id: string | null; model_id: string | null;
  skills: Array<{skill_id: string; version_id: string; content_hash: string}>;
  generation: GenerationParameters;
  no_skill_confirmed: boolean; // 旧客户端兼容元数据；false 不阻止空技能发送或重新生成
  created_at: number; updated_at: number; // Unix seconds
```

**流式事件**（`ChatStreamEvent`，`kind` 区分，只走调用方传入的 `Channel`，不发全局事件）：

```typescript
type ChatStreamEvent =
  | { kind: 'started'; task_id: string; assistant_message_id: string }
  | { kind: 'delta'; assistant_message_id: string; text: string }
  | { kind: 'reasoning_delta'; assistant_message_id: string; text: string } // 只显示，不入库、不入日志、不入后续上下文
  | { kind: 'tool_proposal'; assistant_message_id: string; proposal: ChatToolProposal }
  | { kind: 'done'; message: ChatMessage }                                   // status = completed
  | { kind: 'error'; assistant_message_id: string; message: ChatMessage | null;
      error_code: string; provider_code: number | null;
      result_unknown: boolean; regeneration_discarded: boolean };
interface ChatToolProposal {
  id: string; server_id: string; server_name: string; tool_name: string;
  schema_hash: string; arguments: unknown; expires_at: number;
}
```

- `done` 与 `error` 之一恰好出现一次，之后不再有事件；携带落库后的助手消息快照，渲染进程以快照为准，不依赖累积的 `delta`。
- 取消、网络错误、空闲超时、宿主上限、窗口销毁都以 `error` 结束；有已收到内容时快照为 `interrupted`，否则为 `failed`。重新生成失败或被取消时 `regeneration_discarded = true`，`message` 为保留的旧回复。
- 事件可能先于 `invoke` 的返回到达，渲染端按 `assistant_message_id` 缓存。
- 窗口销毁或页面重载时宿主取消该窗口的全部生成，已收到部分按 `interrupted` 保存；强杀进程时本次未提交的生成内容可能丢失，重启后按中断恢复，不自动重放。
- 带工具的轮次不流式：只有 `started`、`tool_proposal`（可多次，每次需 `advance_chat_tool_turn`）和终态事件。

**错误映射**：`session_not_found` 1006001、`message_not_found` 1006002、`session_creation_failed` 1006005、`session_deletion_failed` 1006006、`invalid_message_content` 1006007（空或超过 16384 UTF-8 字节、标题无效）、`context_too_long` 1006008、`no_provider_configured` 1006009、`generation_in_progress` 1006010、`request_id_conflict` 1006011、`destination_changed` 1006012（`detail = { fingerprint, host }`）、`skill_unavailable` 1006013、`message_not_regenerable` 1006014、`provider_not_selected` 1006015、`invalid_search_query` 1006016、`tool_turn_invalid` 1006017；Provider 错误透传 1001xxx（如 1001012 配置已变更、1001007 流中断）。

**幂等**：`client_request_id` 即任务 ID。同一键重复且内容一致返回原确认（`replayed = true`，不再调用上游，也不重新附着事件通道，界面重新拉取消息）；内容不一致返回 1006011。宿主不自动重试已派发的生成。

**不是**：不提供 `get_session_config`/`update_session_config`（D073 推迟到 V2）、`conversation_id: number` 形态的旧接口，以及基于全局事件的流式推送。

| `check_cli_update` | `window`, `tool`, `path?` | `{status, current_version, latest_version, method, ticket}` | 手动检测或点击更新图标时确认原安装方式与真实新版，不安装；按原路径/版本条件持久化去票据提示，旧检查不得覆盖新检测；Node返回unsupported |
| `update_cli` | `window`, `ticket` | `{status, probe}` | 消费当前账户租约绑定的120秒一次性票据，原方式升级并实测；成功持久化新标签，安装后存储失败返回unknown而非安全失败 |

- `tool` 为 `codex`、`claude`、`gemini`、`node`；`path` 为空时在 PATH 与宿主固定目录中查找。
- `detections`为按工具键控的宿主记录 `{status, path, version, update}`；`update`为null或 `{status, current_version, latest_version, method}`，不含票据。与路径共用 `cli.paths.v1` JSON快照、账户作用域和JS安全整数revision；旧仅路径格式默认空记录，无migration、读取不重写。每工具CAS合并，其他工具竞态时只重放本工具的存储合并，不重跑外部探测/升级。新版本提示只代表上次手动检测；点击图标重新核验并取得新票据后才确认，不在进入页时刷新。
- 设置页四路径框始终只读；Codex/Claude/Gemini手动检测搜索PATH及宿主固定目录，Node使用已保存的选择路径优先。Node目录选择只产生草稿，显式保存才提交；手动检测结果自动持久化。无新版不展示更新图标或最新版提示。逐项检测/检查进度不禁用整页或阻止导航，离页停止接收旧UI响应，宿主已发起的只读检查仍受账户租约与期限约束。
- 限制：5 秒、stdout 4 KiB；版本行须匹配工具格式（`codex-cli X.Y.Z`、`X.Y.Z (Claude Code)`、`X.Y.Z`、`vX.Y.Z`），任意数字不通过。
- `status`：`available`、`not_installed`、`not_executable`、`start_failed`、`execution_failed`、`output_limit`、`protocol_unsupported`、`timeout`。
- `available` 只表示版本输出通过，不是协议握手成功；运行仍由 Codex App Server 或 Claude SDK 的握手决定。
- `managed` 恒为 `false`，DG-OS不接管安装生命周期；D139只调用已确认的原安装方式执行用户授权升级。
- 只有 Codex 与 Claude 的已保存路径用于会话启动（`commands/agents.rs`）；Gemini 与 Node 仅检测。
- 账户切换使探测响应失效；宿主只接受 `main` 窗口与可信来源。
- 错误使用固定消息，不回显路径。
- D139升级：检查状态为 `available`、`up_to_date`、`unsupported`、`check_failed`、`not_installed`；只有可升级的 `available` 返回非空票据。执行状态为 `updated`、`failed`、`unknown`、`stale`、`busy`；`updated` 必须附实际成功的版本探测，其他状态不宣称安装成功。
- 升级必须由界面显示当前/目标版本、原安装方式及操作系统用户共享安装影响并确认；宿主只执行固定官方包/来源与参数，不经shell、不提权、不自动重试。未知来源不发票据。更新期间取得既有进程级独占维护租约：已有活动返回busy，新活动不能并发进入；不自动关闭会话。
- 票据绑定当前账户、租约、启动路径、原安装身份与目标版本；新可升级检查替换本工具旧票据，消费后不可重放。过期、账户变化、原安装或目标变化返回stale；已派发后超时、取消、失败或版本未核实返回unknown，不能当作未发生变更。票据仅在内存，不落账户快照。
- 支持方式：官方npm全局包 `@openai/codex`、`@anthropic-ai/claude-code`、`@google/gemini-cli`；Homebrew官方tap的Codex cask/formula、Claude Code cask及Gemini CLI formula；Claude原生稳定启动器按既有 `autoUpdatesChannel` 查询官方latest/stable端点并执行 `claude update`。目录身份、包归属、稳定启动器与管理器均须匹配；不切换来源、不改channel。大文件SHA身份校验在线程池执行，不占异步执行器线程；整次新版检查总期限25秒（含版本/来源识别/联网），升级进程上限180秒；读取受限，安装输出持续排空且只保留有界内容，账户失效时结束受控进程组。
- 方式依据：[Claude官方更新说明](https://code.claude.com/docs/en/setup#update-claude-code)、[Claude官方引导程序](https://claude.ai/install.sh)、[Codex CLI](https://developers.openai.com/codex/cli)、[Gemini CLI安装与版本](https://geminicli.com/docs/get-started/installation/)。外部发行方及当前机器包管理器状态是外部依赖；本地fixture通过不代表真实工作站升级已验收。

### 11.7 存储统计与清理（D133 第5项，V2-FR-009 阶段6）

五类清理统计只读取真实来源，统计按当前宿主绑定账户计算，不返回路径或他人数据。`get_storage_overview()` 返回 `{categories:[{category,status,count,bytes}]}`，`category` 为 `old_chats`、`session_assets`、`temp_files`、`cache`、`activity_records`，`status` 为 `ok`、`empty` 或 `not_applicable`。读取失败时界面显示“—”，不显示 0。
`bytes` 为可空整数：旧对话统计消息UTF-8字节、附件统计资产字节；临时目录和活动记录存在对象但未测量物理占用时为 `null`，界面显示“—”；空集合为0。不适用的共享缓存为 `null`，不把未知大小伪报为0。

- 旧对话：`chat_sessions` 中超过截止天数（默认 30）未更新、无 `generating` 消息、无 `running` 工作台任务的会话。删除按会话在事务内复验版本（`updated_at`）。
- 会话附件：当前账户无消息引用的 `chat_assets`；未过期草稿租约（`asset_leases`，由附件宿主维护）内的附件保留。
- 临时文件：`skill_install_operations` 中 `failed`/`abandoned` 且 `staging_relpath` 形如 `staging/<id>` 的目录。路径先按组件校验，拒绝绝对路径、`..`、符号链接，canonical 后必须仍在技能根下。`committed` 不计。
- 缓存：共享的 `skill_registry_cache` 不属于单账户范围，本版标记为 `not_applicable`，不执行清理。
- 活动记录：`provider_usage_logs`、`mcp_usage_logs`、`skill_usage_logs`、`mcp_connection_logs` 中超过截止天数（默认 90）的非安全用量记录。权限/安全审计、LAN 审计与凭据不在范围内。

`preview_storage_cleanup({input:{category,cutoffDays?}})` 返回 `{preview_id,category,cutoff,expires_at,count,bytes}`。预览绑定账户、截止时间与候选版本，15 分钟过期。`execute_storage_cleanup({input:{previewId}})` 只执行该预览的候选；预览属于其他账户或已消费时返回拒绝；执行后返回逐类 `{status:'done'|'partial'|'failed',deleted,failed}` 与重读后的统计。逐项失败如实计入 `failed`，不伪装成功。

共享库 VACUUM 独立于六类清理：`preview_vacuum()` 返回 `{preview_id,expires_at}`；`execute_vacuum({input:{previewId,confirmed:true}})` 返回 `{bytes_before,bytes_after}`。执行前以非阻塞方式取得进程内独占维护租约，任一已登记活动持有准入许可或已有维护时返回忙碌，不排队、不先采样后执行。VACUUM 不承诺物理擦除已删除数据。

维护准入共享同一 `MaintenanceGate`：宿主账户/Provider/模型/Skills/MCP/模块/偏好命令覆盖完整 await；聊天/重生成、单任务/工具任务、Provider流与终态用量审计、模块异步生命周期持有跨命令许可。Agent从启动至子进程回收保持许可，停止失败不提前释放；空闲MCP连接、模块runtime和LAN监听不独占许可，后台MCP监测逐轮准入，LAN审计逐条等候维护结束后落库。维护期间新业务准入拒绝，取消/停止失败保留原对象与明确归属。共享库维护不可用于物理擦除承诺。

聊天工具轮次从发送到持久终态持续持有维护许可，包含等待用户审批的停驻期；终态落库后释放，不因审批计时器仍持有事件对象而延迟。取消、审批过期和失败仍按同一终态路径结算。

所有存储命令要求受信任 `main` 窗口与 `Settings` 调用方的 `StorageManage` 能力，不接受 `account_id` 参数。失败固定为 `1000000`，消息不含 SQL 或路径。

## 12. 事件系统

### 12.1 事件通道约定

桌面端不使用全局事件推送 Provider 或聊天的流式内容。流式命令由 renderer 创建 Tauri `Channel` 并作为命令参数传入，宿主只向该 Channel 推送，窗口销毁或页面重载时宿主取消该窗口的流（见 §4.0 `call_provider_stream`、`cancel_provider_stream` 与 §10.1）。

```typescript
import { Channel, invoke } from '@tauri-apps/api/core';

const onEvent = new Channel<ProviderStreamEvent>();
onEvent.onmessage = (event) => {
  console.log('Received event:', event);
};
await invoke('call_provider_stream', { providerId, modelId, request, onEvent });
```

Channel 随调用方生命周期结束，不需要像 `listen` 那样手动取消监听。

### 12.2 后端推送事件

宿主侧通过命令参数里的 `Channel<T>` 推送，不调用 `AppHandle::emit`。示意（真实实现见 `src-tauri/src/provider_streams.rs`）：

```rust
#[tauri::command]
async fn call_provider_stream(
    window: tauri::Window,
    provider_id: String,
    model_id: String,
    request: ChatRequest,
    on_event: tauri::ipc::Channel<ProviderStreamEvent>,
) -> CommandResponse<StreamStarted> {
    // 授权与启动失败作为命令错误返回，此时没有 stream_id；
    // 之后的内容、结束和错误都经 on_event.send(..) 发给调用方，
    // 一个流以恰好一个 done 或 error 事件结束。
}
```

聊天的 `ChatStreamEvent` 沿用同一机制，定义见 §10.1。

## 14. 局域网 HTTP 与 WebSocket 接口（FR-010）

> **契约（D099，2026-11-01）；2026-11-01 已实现**：`crates/dgos-lan` 提供 HTTP 与 WebSocket 路由，八条局域网主机命令已在 `src-tauri/src/commands/lan.rs` 注册。状态与证据见 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)。取代旧 §14（“随机密码 → `/api/v1/auth/login` → JWT”、`Authorization: Bearer`、Token 载荷含 `user_id`/`username`、24 小时过期），旧内容作废，见 Git 历史与 [旧 OpenAPI 归档](../../99-历史归档/V1-FR-010/2026-11-01-旧OpenAPI草图.yaml)。字段级定义以 [OpenAPI](V1-openapi.yaml) 为准；实现规则与分支见 [FR-010 技术设计](../../03-功能规格/V1/03-系统功能/10-局域网协同-技术设计.md)。

### 14.1 约定

- **地址**：`http://<绑定的私网 IPv4>:<端口>`。只绑定一个私网 IPv4 接口地址（10/8、172.16/12、192.168/16），不监听 `0.0.0.0`、回环与 IPv6（D088）。API 前缀只有 `/api/v1/lan`。
- **身份**：只来自 Cookie `dgos_lan`（`HttpOnly; SameSite=Strict; Path=/`，无 `Secure`、`Domain`、`Max-Age`）。不读取 `Authorization` 头；SPA 不把会话放进 localStorage 或 sessionStorage。远程会话没有独立用户身份，绑定签发访问凭据的桌面用户（D088）；请求中的 `user_id`、会话或授权字段一律不接受。
- **CORS**：不返回任何 `Access-Control-*` 头，不处理 `OPTIONS` 预检。
- **请求体**：`application/json`，UTF-8，`deny_unknown_fields`；上限 64 KiB，配对 1 KiB。
- **时间**：Unix 秒整数。字段为 snake_case。

### 14.2 准入顺序

每个请求按下列顺序检查，前一步失败即返回：

| 步 | 检查 | 失败 |
| --- | --- | --- |
| 1 | TCP 对端是私网 IPv4 | 403 `1010007` |
| 2 | `Host` 逐字等于 `绑定IP:端口` | 403 `1010007` |
| 3 | `POST`、`DELETE` 与 WebSocket 升级必须带 `Origin` 且等于 `http://` + `Host`；`GET` 带 `Origin` 时同样必须相等 | 403 `1010007` |
| 4 | 路径与方法在 §14.4 白名单内 | 404 或 405，空包体 |
| 5 | 静态 SPA 与配对端点到此放行 | - |
| 6 | Cookie 对应的会话存在、未撤销、未过期 | 401 `1010006`，清除 Cookie |
| 7 | 对端 IP 等于配对时的 IP | 撤销（`ip_changed`），401 `1010006` |
| 8 | 宿主会话解析器的当前用户等于绑定用户（`no_accounts` 时绑定用户为 `default-user`） | 撤销（`issuer_ended`），401 `1010006` |

通过后刷新会话闲置时间。被拒绝的请求按技术设计写审计（`request_rejected`，60 秒内合并）。

### 14.5 配对与会话

```typescript
interface LanPairInput { code: string }  // 26 个 Crockford Base32 字符；'-' 与空白被忽略，大小写不敏感
interface LanSessionStatus {
  short_id: string;        // 会话 ID 前 8 位十六进制，只用于显示
  device_label: string;    // 由 User-Agent 提取的平台与浏览器族
  created_at: number;
  expires_at: number;      // created_at + 12 小时
  idle_expires_at: number; // 最近一次准入 + 30 分钟
}
```

- 访问凭据由主机命令 `issue_lan_access_code` 生成（§14.8），128 位、单次有效、10 分钟过期，累计失败 10 次作废；配对地址为 `http://IP:端口/#code=<凭据>`，SPA 读取后立即去掉 fragment。
- 配对限速：每来源 IP 每分钟 5 次、全局每分钟 20 次；已有 8 个会话时拒绝且不消耗凭据（同一设备的重新配对除外，见下条）。均返回 429 `1010011`（§14.3）。
- 配对成功：凭据作废；签发 256 位不透明令牌，经 `Set-Cookie` 返回，响应体不含令牌。带有效 Cookie 且来源 IP 与该会话相同的设备再次配对时为重新配对：不受会话上限限制，旧会话以 `re_paired` 撤销，会话数不增加；凭据错误时旧会话保留（D101）。带有效 Cookie 但来源 IP 不同时，先以 `ip_changed` 撤销该旧会话，再按普通配对检查上限与凭据；凭据错误时旧会话也已撤销（D105）。
- 期限：闲置 30 分钟、最长 12 小时，不续期；到期后重新配对。
- 撤销：主机断开单个或全部、关闭开关、退出应用、服务异常、网络变化（只在绑定地址从本机接口消失时，D101）、主机修改端口（`port_changed`，D107）、绑定用户结束会话（FR-008 §9.4 第 4 步，同时作废其未使用的凭据）、IP 变化、到期、重新配对、登出。
- 配对没有幂等键：响应丢失后重试得到 `1010004`，须在主机上重新生成凭据。

### 14.6 远程聊天

```typescript

}
interface LanSendInput { content: string; client_request_id: string } // 无 tools、accept_destination
interface LanRegenerateInput { client_request_id: string }
// ChatSession、ChatMessage、ChatMessagePage、SendAck 与 §10.1 相同
```

- 范围：远程会话只看到、只能操作本次配对中自己创建的聊天会话（内存集合，D099 第 5 项）；集合外的会话返回 404 `1006001`，与“不存在”不区分。每个远程会话最多创建 100 个聊天会话（429 `1010011`，`scope = chat_sessions`）。
- 会话目标在新建时固定，必须提供 Provider 与模型，技能可省略或为 null；兼容字段 `no_skill` 省略/false/true 均允许空技能，所选技能仍按 §10.1 固定并重验。远程不能修改、重命名或删除会话。
- `limit` 与分页规则同 §10.1 的 `list_chat_messages`；会话列表不分页，按 `updated_at` 倒序。
- 幂等：同 §10.1，`client_request_id` 即任务 ID；重放返回 `replayed = true` 且不再推送事件。
- 取消：只取消本远程会话发起、尚未结束的任务；其他一律 `{ cancelled: false }`，重复调用无副作用。
- 发送与重新生成在生成登记后返回 202；生成事件只经 §14.7 推送。

### 14.7 WebSocket

```typescript
type LanStreamFrame =
  | { type: 'chat'; event: Exclude<ChatStreamEvent, { kind: 'tool_proposal' }> } // §10.1 的事件
  | { type: 'session_ended'; reason: LanRevokeReason };
type LanRevokeReason = 'host_disconnect' | 'host_disconnect_all' | 'switch_off' | 'app_exit'
  | 'service_failed' | 'network_changed' | 'port_changed' | 'issuer_ended' | 'ip_changed'
  | 'idle_expired' | 'absolute_expired' | 're_paired' | 'logout';
```

- 握手按 §14.2 准入（必须带同源 `Origin` 与有效 Cookie），失败以 HTTP 状态拒绝升级。
- 每个远程会话同时只有一条连接；只推送本会话任务的事件。只有服务端到客户端的文本帧，客户端发数据帧即关闭。
- 没有连接时到达的事件丢弃，不缓存、不重放；断线不取消生成，重连后以消息列表为准。
- 服务端每 30 秒 ping，60 秒无 pong 关闭；发送队列 256 帧。
- 关闭码：`4401` 会话已撤销或过期（先发 `session_ended`）、`4409` 被同一会话的新连接取代、`4413` 发送队列满、`1001` 服务停止、`1008` 协议违规。

## 17. 迁移阶段6桌面增量（D133）

以下契约是桌面增量；账户、调用者和窗口由宿主派生，均返回 `CommandResponse<T>`。不新增 LAN 通用转发。批准范围见 [D133](../../06-决策记录/V2-冻结决策.md#d133-迁移阶段6真实能力与账户资源边界)。存储及独立维护见 §11.7。

### 17.1 多Skills及生成参数

会话目标和单任务输入使用有序 `skill_ids: string[]` 与 `generation: { temperature?: number; reasoning?: { effort?: string; budget_tokens?: number }; max_tokens?: number; instruction: string }`。每项锁定版本及内容哈希，重复拒绝；自然语言冲突不做猜测或确定性覆盖。短/中/长分别1024/4096/8192输出tokens，已知模型上限和Provider画像在宿主校验，不支持的参数拒绝。自定义指导保持用户权限并计入24 KiB上下文预算。空Skill提交仍需明确 `allow_without_skill`。保存目标不提交任务，运行输入使用已确认快照；敏感指导文本不写参数审计。

### 17.5 D136 AI 公共服务与模块 IPC

共享 DTO 的 Rust 唯一来源为 `dgos-types::ai`，TypeScript 对应 `src/types/ai.ts`。`AiRunInput` 包含 Provider/model/revision、prompt、固定 Skill refs、选定 MCP tools 与 generation；不接受 caller identity、credentials、lease 或 approval。事件含 `run_id`、`request_id`、递增 `seq` 与 `started/delta/reasoning_delta/phase/terminal`；run summary 不含 prompt、output、tool details。历史读取由可信 host context 限定 owner/module；撤销执行权限不撤销历史读取权。

公共错误为 `AiFailure {domain,code,reason,result_unknown}`；Provider/Skill/MCP 的数值码保持原领域。宿主本地输入、上下文预算、选择变化、工具次数、执行期限、工具提议、空回复及其他执行失败使用[错误码 §2.3](V1-错误码.md#23-通用错误00) 1000010～1000017，不能冒充上游错误。明确拒绝与已派发后结果不确定分开表达；审计写失败通过 audit_warning 表达，禁止自动重放。终态写库前原子封存取消竞争且继续占用 runtime 在途请求；此后取消返回 false，持久化 CAS、Promise 和 Channel 不因写库期间迟到取消产生不同业务终态。

Tauri 命令均返回 `CommandResponse<T>`，调用者身份、账户与 attachment lease 由宿主派生：

| 命令 | IPC 入参（除宿主派生上下文外） | 返回 |
| --- | --- | --- |
| `module_list_ai_providers` / `module_list_ai_skills` / `module_list_ai_tools` | `attachment_id, route, call_id` | 最小 Provider、固定 Skill pin、已连接 MCP 工具目录 |
| `module_run_ai` | `attachment_id, route, call_id, input, on_event: Channel<AiEvent>` | `AiTerminal`；宿主 task 驱动至审计与模块调用结算 |
| `module_list_ai_runs` | `attachment_id, route, call_id, input: AiRunListInput` | owner/module 限定的 `AiRunPage` |
| `module_get_ai_run` / `module_cancel_ai_run` | `attachment_id, route, call_id, run_id` | `AiRunSummary?` / `boolean`；取消仅命中当前 runtime 自有且未进入 settling 的运行 |
| `resolve_module_mcp_confirmation` | host-issued `confirmation_id, approved` | `()`；session 由宿主解析，模块不能自批 |

模块 `host.ai` 提供对应 typed provider/skill/tool 目录、`run(input,onEvent,{signal?})`、`listRuns(input?,{signal?})`、`getRun(runId,{signal?})` 与 `cancel(runId,{signal?})`。AbortSignal 经 `cancel_module_call` 取消目录/读取或当前 run；运行由宿主持有至结算，renderer channel 断开不能丢弃收尾。SPA 切换不失效 attachment；全页 reload、窗口销毁、attachment supersede 与账户 lease 更替会取消旧调用。事件和异步返回必须匹配原 route、attachment、view epoch、run/request ID 与递增 sequence。模块外显 result 属模块自身，不进入 D136 审计，也不因 status=succeeded 就表示可从宿主恢复正文。

provider-console@1.1.0 消费上述目录、精确 revision/pins/schema、事件、取消与本模块历史；新增 Skills/MCP 权限不得自动授予，工具批准仅走宿主对话框。当前执行/provision/update pin 只选择 1.1.0；原 1.0.0 原文保留为受控升级失败恢复的完整性材料，不获执行准入。显式 update 仅传 module_id，宿主从完整校验的随包 release 选择来源；已停止或停用模块可更新且保留 enabled 与原 grants，失败恢复旧磁盘 release，不尝试执行失去准入的旧包。静态契约及注册不代表真实闭环通过，验证证据见 V1 实现状态。`run_builtin` 尚未作为生产 Chat/Workbench adapter 消费；现有 Chat/Workbench 仍直接使用共享 executor。

### 17.6 D136 原生 Skills/MCP 管理 IPC

本节固定原生配置管理的宿主接线契约，实施与验证状态只记入版本实现状态。依据 [D136 原生扩展技术设计](D136-原生扩展统一管理技术设计.md)，DG-OS AI 继续使用 §6/§7 的账户服务；Codex/Claude 使用各自原生文件，不能写入宿主 MCP 数据库或启动宿主连接。

所有新增命令使用 `app, window, input`，返回 `Result<T, String>`，错误仅为固定 `native_extension_*` 类别或现有会话/项目错误，不回显原文、路径、程序输出或凭据。入口复用 Settings 的 `SkillsRead/SkillsManage` 或 `McpRead/McpManage`，账户、lease、根和项目目录身份由宿主派生；请求禁止 `user_id`、根路径、lease、JSON pointer。TypeScript 输入由 Rust 宿主 DTO 对应维护，不将内核 `TrustedRoots` 暴露为 IPC。

范围输入为 `{target: 'Codex'|'Claude', scope: 'OsUser'|'ProjectShared'|'ProjectLocal', project_id: string|null}`。项目范围必须传当前账户可访问且未归档的项目 ID，并重验目录身份；OsUser 不带项目。Skill 资源不支持 ProjectLocal；Codex MCP 不支持 ProjectLocal。配置根从受信启动环境解析，未确认覆盖布局时拒绝操作。OS 用户根由同一 OS 用户共享，界面须明确说明跨 DG-OS 账户可见。

| 命令 | `input` | 返回与约束 |
| --- | --- | --- |
| `discover_native_skills` | 范围 + `query` | 有界资源实例目录、missing/incomplete；不执行脚本、不联网 |
| `get_native_skill` | 范围 + `slug` | 资源摘要与实例 id/revision、来源、owner、依赖声明；不返回正文或脚本 |
| `preview_native_skill` | 范围 + `action: install|update|remove`、`slug`、`expected`、`source` | 内核资源预览；update/remove 必须匹配发现得到的实例。install/update 的 source 为显式 ZIP 字节或现有受控 GitHub 来源输入，宿主获取并校验包，计算 hash，不信任 renderer 自报摘要 |
| `preview_native_skill_visibility` | 范围 + `instance`、`visible` | 宿主从已发现实例派生原生 selector；不接受 renderer 绝对 Skill 路径。Claude 按名称影响多个实例时预览列出影响，不能伪称单路径开关 |
| `discover_native_mcp` | 范围 | 安全实例目录；认证存在、已认证、已连接、已批准、活动会话独立表示；未知为 null |

三种文件操作均按 journal 领域要求 Manage 权限，并在执行前重新校验当前账户、授权项目、根及目标身份。`inspect_native_operation` 可能核实并持久化 journal 回执，不重新发布目标文件；它不同于仅查内存的 `inspect_native_session_request`。同一账户重新授权后可以核实已发生的文件副作用；提交和取消旧代预览仍拒绝。

每个预览在宿主绑定当前账户代次、授权领域、项目和根身份。同步撤权必须与内核 publication gate 排序：账户切换、退出先使所有旧 HostContext 失效，再允许下一代请求。不能只在后台监听 token 后异步撤权。提交前重新核对权限与项目；跨账户或旧代次操作拒绝，不能用同名账户重登恢复提交。已发生文件副作用保留，并通过当前账户重新授权的只读核实入口恢复原回执；不重放写操作。

所有文件工作在阻塞任务中执行，命令持有 maintenance admission 至完成；读取不创建目录，预览/提交才允许事务内核创建私有 staging。恢复材料路径不进入普通 DTO；journal 与实例索引不得保存秘密原文。页面自动刷新仅调用发现；保存成功仍为 pending_activation，不能推断 CLI 已加载或 MCP 已连接。认证、显式版本探测与活动 CLI 刷新属于独立原生会话操作，不由这些命令隐式触发。

#### 17.6.1 自有活动原生会话控制

以下四个命令同样使用 `app, window, input`，已接入 `commands` 导出和 `generate_handler!`。owner、账户代次和取消 lease 由 SessionResolver 派生；`generation` 是活动进程代次 UUID，不是账户代次。读取不会创建/恢复会话，不观测外部终端进程。每次核对 owner、项目未归档、目录身份、活动 lease 和 Provider 精确绑定/撤销；命令结束再核对账户代次。

| 命令 | 精确 `input` | 返回 |
| --- | --- | --- |
| `list_native_sessions` | `{project_id:string, domain:'skills'|'mcp'}` | `NativeSessionHandle[]`，仅当前账户指定项目的自有活动进程，最多256个；领域决定 Settings 的 SkillsRead/McpRead 准入 |
| `observe_native_session` | `{session_id:string, generation:string, domain:'skills'|'mcp'}` | `NativeSessionObservation`，对应领域 Read 权限；只查询既有私有控制通道 |
| `native_session_action` | `{session_id:string, generation:string, request_id:UUID, action:NativeSessionAction}` | `NativeSessionReceipt`，action 领域决定 SkillsManage/McpManage；必须由显式用户操作发起 |
| `inspect_native_session_request` | `{session_id:string, generation:string, request_id:UUID, domain:'skills'|'mcp'}` | `NativeSessionReceipt\|null`，对应领域 Read 权限；只读该代缓存回执，不取控制锁、不派发原生动作。请求不存在或领域不符返回 null，不能据此解除 unknown 或重试 |

`NativeSessionHandle = {session_id,generation,project_id,engine,capabilities}`；`engine='codex'|'claude'`。`NativeSessionObservation = {session_id,generation,engine,observed_at,domain,capabilities,skills,mcp_servers,incomplete}`，`observed_at` 为 Unix 毫秒。`skills=[{name,enabled:boolean|null,classification:'skill'|'builtin_command'|'unknown',builtin:boolean|null,path:string|null,scope:'user'|'repo'|'system'|'admin'|null,plugin_id:string|null}]`；`mcp_servers=[{name,status,auth_status:string|null,source:string|null,scope:string|null,tools:string[],schema_observed:false}]`。每个目录最多256项、每台服务器最多64个工具；名称仅接受1～128字节 ASCII 标识符 `[A-Za-z0-9_.:@-]`，不接受路径、URL或原生自由文本，过滤或截断置 incomplete。不返回描述、配置、错误正文、工具 schema/结果、HTTP origin、OAuth对象或凭据；`schema_observed:false` 不宣称已校验工具 schema。未知连接状态为 `unknown`；Codex 的 `authenticationRequired` 与 Claude 的 `needs-auth` 保留原生语义，不等同已授权。

Skill来源字段只作当前会话的只读协议证据：Codex保留`skills/list`的原始path（最多2048字节，不改写为本机路径）、scope与pluginId（最多256字节）；控制字符、异常类型、缺少必需元数据标 incomplete。Claude SDK0.3.317 `supportedCommands`仅提供可选builtin标记，无可靠source/path/pluginId；只有builtin=true分类内置命令，false或缺省均unknown，不根据名称猜Skill、旧commands或MCP prompt，不把整个目录称作已安装Skills。此DTO不含文件root/instance授权，不能据其路径打开/编辑原生文件；管理操作仍重新校验现有实例权限。完整Claude visibility来源影响仍不在此观测合同内。

工具目录接受 Codex 的对象或数组形状；非法条目、未知状态、重复服务器、connected 缺少可读工具目录和原生工具读取错误标记 incomplete。非 connected 不返回旧工具名；工具 schema 仍未观测。界面按账户、项目根身份、目标、领域、session 和 generation 隔离观察，展示带时间的读取快照；已知会话关闭、unknown 或切换时移除旧投影，读取失败清除快照。不会将清单、认证方式或文件发布回执解释为工具可用、认证成功或获准调用。

`capabilities={observe_skills,observe_mcp,reload_skills,reload_plugins,reconnect_mcp,toggle_mcp,native_login,native_logout,native_auth_guidance}`，前八项为 boolean。`native_auth_guidance=null|{verified_version,reason,login_argv:string[],logout_argv:string[]}`；reason 固定 `missing_session_interaction_cancel_contract`，argv 为 `['codex'|'claude','mcp','login'|'logout','<NAME>']` 模板，仅供用户在正确项目和同一原生配置环境中自行执行，不交给 shell 插值。模板依据本机 Codex 0.167.0 和 Claude Code 2.1.319 的 `mcp --help` / Codex `mcp login/logout --help`；不运行实际认证。未知版本能力全 false、guidance=null。

`NativeSessionAction` 是拒绝未知字段的 kind 联合：`{kind:'reload_skills'}`、`{kind:'reload_plugins',hold_on_cache_impact:boolean}`、`{kind:'reconnect_mcp',server_name:string}`、`{kind:'toggle_mcp',server_name:string,enabled:boolean}`、`{kind:'native_login'|'native_logout',server_name:string}`。最后两种始终返回 `native_extension_Unsupported`：SDK 私有实现虽有认证方法、Codex虽有OAuth协议，但缺少本适配器已核实的瞬态交互/取消闭环，不启动认证、不收集callback URL。Claude MCP写操作必须在当前原生status中唯一命中 source=user/project/local；managed/plugin/sdk/dynamic/缺失来源均只读。

支持矩阵固定到实际响应版本：Codex `codex-cli 0.167.0` 使用 `skills/list({cwds:[workspace],forceReload:false|true})`、`mcpServerStatus/list({threadId,detail:'toolsAndAuthOnly',limit:64,cursor})`；仅支持 reload_skills 写操作，MCP无可靠热应用控制，配置变更须新会话。MCP最多4页，重复/过长cursor标记 incomplete。Claude Code `2.1.319` + SDK `0.3.317` 使用 `supportedCommands()`、`mcpServerStatus()`、`reloadSkills()`、`reloadPlugins({holdOnCacheImpact})`、`reconnectMcpServer(name)`、`toggleMcpServer(name,enabled)`。held不自动force；插件error_count非零或hold请求未返回held布尔值为unknown。ack仅证明控制请求完成，连接状态必须独立观测。

`NativeSessionReceipt={session_id,generation,request_id,state:'applied'|'held'|'unknown'}`。每代最多256个请求；同UUID/相同参数返回原回执，不重复派发，参数改变为 `request_conflict`。IO前预留unknown，取消、超时、丢失响应/格式异常不重放；该代其后的新写控制和send均返回 `result_unknown`，仍可只读观测或显式关闭/新会话，不允许换UUID绕过。内存回执不跨进程代次恢复；重启后不会自动重建旧进程或执行旧控制。stale generation 返回 `native_extension_StaleGeneration`，不支持返回 `native_extension_Unsupported`，并发控制/send/显式close 返回 `session_busy`，超限为 `native_extension_Limit` / `request_capacity`；其余保留现有项目/账户/Provider固定错误。每会话短准入后保留独立control锁，IO不持全局manager admission，撤权/强制shutdown不被45秒原生请求阻塞；迟到结果不能回填旧代次。

界面在派发前保留原 request_id 和领域，跨管理页重挂载保持；丢失回执仅显式调用 `inspect_native_session_request` 核实。null、错误或 unknown 保留原身份与阻塞；applied/held 才解除该请求阻塞。账户切换清除界面记录；宿主旧账户、旧进程代次及失效项目入口仍拒绝。核实不启动原生进程、不改变文件、不自动重新派发。

回归源码入口：`cargo test -p dgos-agents native_session` 与 `cargo test -p dgos-agents claude_session::tests::native_held_receipt_is_preserved_and_managed_mcp_is_read_only`。源码覆盖投影脱敏/限额、分页循环、owner/项目/Provider撤销、代次变化、同UUID去重/参数冲突、unknown不重放、cancel/迟到结果、send/close竞争和held保留；本批未运行，真实CLI/bridge闭环证据不能由这些fixture替代。


### 17.7 D136 CLI 清理重核实

`recheck_development_cli_cleanup` 无 renderer 参数，返回 `Result<(), String>`。入口使用 Workbench/TasksRun、当前账户 lease 和维护准入；宿主读取可信 machine/boot 身份，只将同机器不同启动的既有待清理记录收敛为本地已停止，不改变外部 unknown、不恢复旧会话、不发进程信号或重放请求。缺可信启动标识返回 `boot_identity_unavailable`；响应不含跨账户清理数量。工作台提供显式入口，检查完成后仍由下一次新建/恢复的正常准入判断目录是否可用。
