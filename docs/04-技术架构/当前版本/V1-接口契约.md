# V1 接口契约

## 1. 文档目标

本文档定义 DGOS V1 的所有接口，包括 Tauri Commands（桌面端）和 HTTP API（局域网）。

**权威性**：
- ✅ 接口的唯一权威来源
- ✅ 前后端开发的契约
- ✅ API 文档自动生成的基础

**更新原则**：
- 新增接口：先更新此文档，再编码
- 修改接口：记录版本和兼容性
- 废弃接口：标记 `@deprecated`，至少保留一个版本

---

### 2.2 权限检查分层

根据 spec-docs-pro 的建议：

**Tauri Command 层**：
```rust
#[tauri::command]
async fn list_providers(
    state: State<'_, AppState>,
    session_token: String, // 从前端传入
) -> Result<Vec<Provider>> {
    // 1. 验证 session
    let user_id = state.auth.verify_session(&session_token).await?;
    
    // 2. 调用业务逻辑（再次检查权限）
    state.provider_service.list_providers(&user_id).await
}
```

**HTTP API 层**：
```rust
async fn list_providers(
    Extension(db): Extension<DatabasePool>,
    Extension(user_id): Extension<String>, // 从中间件注入
) -> Result<Json<Vec<Provider>>> {
    // 1. user_id 已由中间件验证
    
    // 2. 调用业务逻辑（再次检查权限）
    let providers = provider_service.list_providers(&user_id).await?;
    Ok(Json(providers))
}
```

**业务逻辑层**：
```rust
impl ProviderService {
    pub async fn list_providers(&self, user_id: &str) -> Result<Vec<Provider>> {
        // 最终防线：确保数据隔离
        self.db.find_by_user(user_id).await
    }
}
```

## 7. 接口版本与兼容性

### 7.1 版本策略

**V1 阶段**：
- 所有接口 URL：`/api/v1/*`
- 不引入 Breaking Changes
- 废弃接口标记 `@deprecated`，至少保留一个版本

**V2 阶段**（未来）：
- 新增 `/api/v2/*`
- V1 接口继续支持

### 7.2 废弃流程

1. **标记废弃**：在文档中标记 `@deprecated`
2. **添加警告**：接口返回 `X-Deprecated: true` Header
3. **通知用户**：前端显示废弃提示
4. **迁移期**：至少保留一个版本
5. **删除**：在下一个大版本中删除

## 9. 安全要求

### 9.1 认证

**Tauri Commands**：
- 所有需要用户上下文的接口都需要 `session_token`
- 中间件验证 token，注入 `user_id`

**HTTP API**：
- 所有接口（除 `/api/v1/auth/verify`）都需要 `Authorization: Bearer {session_token}` Header
- 中间件验证 token，注入 `user_id`

### 9.2 权限检查

参见"2.2 权限检查分层"。

### 9.3 数据隔离

所有业务逻辑层查询都必须加上 `WHERE user_id = ?`，确保用户只能访问自己的数据。
