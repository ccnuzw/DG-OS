## 3. 使用方、范围与原生格式

### 3.1 统一目标模型

内部设计对象（不是已注册 IPC）：

```text
Target = DgosAi | Codex | Claude
Scope = DgosAccount | OsUser | ProjectShared(project_id) | ProjectLocal(project_id)
Instance = { opaque_id, target, scope, native_key, source_ref,
             root_identity, owner_kind, version_or_hash, writable_capabilities }
Owner = Dgos | LooseNative | Plugin(owner_ref) | PackageManager(owner_ref)
        | ManagedPolicy | CloudSynced | Bundled | Unknown
```

资源操作的前端传 target、scope、project_id、opaque_id；名称规则操作只传原生名称、状态与设置层。不得传 user_id、OS 账户、任意配置绝对路径、原生 JSON 指针或插件缓存路径作为权威。宿主从 Settings 能力、当前 lease、项目归属和已验证目录派生实际位置。ProjectLocal 用于 Claude 原生 MCP 项目私有配置及 Skill 名称规则本地设置，不用于 Skill 资源 CRUD，也不等于 DG-OS 账户私有；切换 DG-OS 账户不会更换 CLI 的 OS 用户配置。

对同一物理文件使用同一锁，即便它同时包含 Claude user/local 配置或被两个 DG-OS 账户操作。目录身份包括真实路径、平台文件 ID 和宿主确认代次；同一路径被换根后不沿用授权。无法确定真实 native_key/所有者时保持 Unknown 和只读。

Codex 文档允许链接 Skill 目录；Claude 也允许 loose skill 链接。因此扫描不能把“CLI 支持”误写成“DG-OS 可安全改目标”。链接实例展示链接与解析目标，默认只读；不跟随任意外链递归，不通过 unlink/remove 变相删除目标。用户选定实际来源根且完成独立安全预览后，可复制普通文件形成新实例，不自动接管链接资源。

Codex OS 用户 `.agents/skills` 可能被其他工具同时使用；“安装到 Codex”必须展示此共享范围，不能说只影响 Codex。管理员、内置和其他历史发现根保留来源；未核对的兼容根不作为写入默认值。

#### 3.2.1 D142 Claude 名称规则

[D142](../../06-决策记录/V7-冻结决策.md#d142-claude-skill-可见性按名称规则管理) 取代原先“证明所有同名来源后才能写 visibility”的前提。规则绑定原生名称及设置层，覆盖当前和未来同名 Skill；不承诺单文件开关、来源的精确实例启停或完整影响枚举。名称按原名匹配，不能把别名推断为目标 Skill 名。按 [Claude 官方状态定义](https://code.claude.com/docs/en/skills.md#override-skill-visibility-from-settings)：

| 状态 | Claude 上下文中的列示 | 用户显式调用 |
| --- | --- | --- |
| `on` | 名称及描述 | 允许 |
| `name-only` | 仅名称 | 允许 |
| `user-invocable-only` | 隐藏 | 允许 |
| `off` | 隐藏 | 隐藏/拒绝 |
| `inherit` | 删除所选层的对应条目，交由原生剩余设置及默认行为决定 | 不代表强制开启 |

读写位置是受信 Claude 配置根 `settings.json`（OsUser，OS 用户共享，包括其他项目）、授权项目 `.claude/settings.json`（ProjectShared）或 `.claude/settings.local.json`（ProjectLocal）；项目范围展示授权目录及原生适用范围，不能把 local 说成 DG-OS 账户私有。只读规则目录仅反映所选设置层，不合并有效配置；规则可在未发现同名资源时建立、编辑及移除。插件明确不受 skillOverrides 影响，仍由插件所有者管理；managed 策略和其他更高优先级层未求值，可能覆盖本层，不推算当前有效状态。

正式输入、只读 `discover_native_skill_rules` 与预览证据以 [接口契约 §17.6](V1-接口契约.md#176-d136-原生-skillsmcp-管理-ipc) 为唯一字段来源。Claude 预览声明当前观察覆盖边界，但后端不采集资源/会话观察；空 `affected` 配合未采集标记，不表示当前已观察到零实例。资源发现及同页 NativeSessionPanel 的显式活动会话观察独立展示当前已知快照，不为预览启动会话，不作为规则提交门禁，也不能当作未来或全部来源的清单。确认须明确当前及未来名称范围、插件排除、更高层未求值和保存可能触发原生 ConfigChange Hook。

名称规则复用配置事务：按目标原文摘要、文件/父目录身份、账户 lease 和项目授权 CAS，保留无关/未知字段；不把资源清单、manifest 或观察快照纳入 CAS，同名实例新增不改变已确认意图。journal 必须保留 `evidence_version:1` 的名称/状态/设置层证据；旧 Claude 布尔/实例 visibility journal 缺证据时拒绝发布，不自动迁移或重放。发布前从通过 CAS 的原文重新生成规则 patch 和证据，核对 journal 证据及 staging 完整字节一致，拒绝被改写的证据或 payload。资源写操作继续按原实例及全树 CAS，不由名称规则授予文件权限。

配置提交与会话生效独立；仅在显式刷新后重读规则及可用会话观察，不自动 reload、启动、重建或重发。ConfigChange Hook 是原生保存可能触发的行为，不构成 DG-OS 自动执行 Hook 的授权；保存与刷新回执均不能单独证明实际加载。

## 4. 发现、安装、更新与依赖契约

### 4.1 无执行发现

发现只读取登记的根、已知 manifest 和原生配置；不运行 CLI mcp list/get、plugin list/doctor、Git、npx、uvx、Python、Shell、headersHelper、Skill 的动态正文或安装指令。网络来源检查更新为独立显式动作，不在页面打开或轮询时联网。

2. DG-OS AI 继续既有只接受内容包的安全规则。原生目标采用独立 NativeSkillPackage 校验：保持 SKILL.md、未知 frontmatter 和引用资源；可包含原生脚本但只作为未执行文件，预览列明 scripts、动态命令片段及插件/Hook 组件。

### 4.3 依赖检测

纯扫描报告 CLI/解释器/stdio 程序是否能按目标环境定位、候选路径、可执行标记、声明版本范围和 required_tools；不执行用户指定二进制。PATH 来自真实 CLI 启动环境的受控快照，不根据前端任意环境值推导。

“检测版本”先展示将运行的实际程序、固定 argv、cwd 和可能执行代码的事实，再显式启动；批准绑定二进制目标身份及摘要，启动前复核。CLI 入口可为包管理器 symlink，解析链及最终二进制身份纳入预览，不能把允许 CLI 链接推广为允许配置写入跟随链接。CLI 版本探测复用现有 5 秒、输出 4 KiB 上限，最多并行 2 个，不自动重试、不安装。工具依赖检测可另定义已验证的限制，但本批不新增第二套探测实现。未知 helper、包内版本脚本、动态 Shell 表达式不自动探测；只提供配置指引。packages、工具 API 权限或外部服务缺失不能由 Python/Node 版本存在判满足。

结果分为 found_unprobed / version_checked / missing / incompatible / timed_out / unreadable / unknown；附时间和可执行身份。换目录、引擎版本或 PATH 改变使结果 stale。检测已安装不代表 Skill 能完成任务，也不代表 MCP 已连接。

## 6. 配置保留、并发与事务恢复

### 6.1 保留未知内容

TOML 使用保留 trivia 的编辑树（实现优先评估 toml_edit），只修改精确 mcp_servers 表/skills.config 条目；服务器名作为字面 key，不拼接 dotted path。JSON 使用可保留原文的 AST/范围编辑，保留不相关字节、顺序与换行；重复键或歧义格式拒绝写入。禁止先反序列化为仅含已知字段的 DTO 再 stringify 整个文件。

对目标资源也采用字段 patch，未展示或不可读取的 env/header/扩展字段保持原字节。新增已知字段不能覆盖同名未知对象；删实例仅移除精确节点。UI 使用“保留原值/替换引用/移除”三态，不把脱敏占位符写回。输出重新解析并比较：除批准字段和必要分隔符外其他内容不变；不自动整理格式、迁移旧键或提升权限。

### 6.2 路径与文件安全

根来自宿主目录授权。逐级以 capability 目录句柄打开，不跟随 symlink/reparse point；检查根身份、普通文件、owner、权限及硬链接数，写入拒绝 nlink > 1。缺少父目录时只允许在已验证根下逐级创建明确目录，既有路径身份改变则拒绝。配置/安装目标及 staging 同文件系统；原文件权限保持，用户配置新建 0600、私有 staging 0700；项目共享配置不提高旧权限。不能在不支持安全原子操作的文件系统静默退化为 truncate/write。

读取原生 Skill symlink 仅记录链接与受限元数据，越出授权根不读正文。写入前后复核句柄身份与父目录；发现链接替换、目录被换、文件增长超限或输出校验失败立即进入冲突/恢复分支。配置路径安全规则不用于阻止合法包管理器 CLI 入口，但入口最终目标改变会使探测/操作预览过期。

### 6.3 并发控制

| 场景 | 控制方式 | 失败策略 |
| --- | --- | --- |
| 本宿主多个目标/账户改同一文件 | 物理文件/父目录稳定身份锁，按 canonical root + 相对路径排序；10 分钟预览不持有锁 | 仅提交短临界区排队；前一写使旧预览失效 |
| 两个 DG-OS 进程 | 配置事务使用跨进程锁/独占 journal 所有权；租约撤销和发布互斥 | 锁不可取得返回 busy，不抢旧进程锁 |
| 编辑器或 CLI 外部改文件 | 比对全原文 hash、inode/file ID、父目录及预览 revision，提交紧前重读；发布保留被替换 inode | 观测到变更返回冲突；不三方自动合并、不 force |
| 目标原先不存在 | 原子 no-replace rename 发布 staging | 外部抢先创建时不覆盖 |
| 同名 Skill 或插件拥有目录 | 比较准确实例及全树 manifest；目录发布采用同卷原子交换/无覆盖操作 | owner 不匹配只读，外部改动拒绝 |

必须承认：普通文件系统没有对不合作写者的“按内容 hash 原子 CAS”。仅 `hash → rename` 不能消除最后一次检查后的 TOCTOU；flock 也不能约束编辑器或 CLI。因此存在目标时，发布必须采用保留旧 inode/目录的原子交换（macOS 例如 renameatx_np RENAME_SWAP；其他平台使用已验证等价能力），并对交换所得旧版本复核。原先不存在使用 no-replace。不能声称该流程冻结外部修改或具有数据库级串行化。

若交换所得旧版本与预览不符：不标 committed，保留旧/新两份、journal 和目标身份；只有能再次证明目标仍是本操作发布版本时才作受保护还原，无法证明则进入 recovery_required/unknown，禁止盲目 swap-back 和删除任何一份。外部写者持旧 FD 继续写的内容必须随被保留 inode 留存；恢复不能只看先前 hash。极短窗口可能出现待核实配置，不能向用户宣称“竞争下从未短暂可见”；原生会话可能热读这一事实属于 P7 并发验证风险。若目标平台不能保证至少完整保留被替换版本与无覆盖新建，该适配器禁止写入并说明原因，不以普通覆盖作为 fallback。

### 6.4 事务边界与操作日志

原生配置文件是原生配置权威，SQLite 不做其镜像写源。DG-OS 本地 journal 仅保存 operation UUID、宿主账户绑定、目标引用、根身份、动作、非敏感摘要、状态、预期/实际文件身份和恢复位置引用；不存完整原生配置/包正文/环境值。P3 优先以 app 私有目录的持久小文件 journal 实现，避免为原生配置再建数据库镜像；如最终需数据库索引，只能追加 migration 并由协调者指定编号。

配置 journal 的项目范围额外固定预览时的原生项目键、授权项目根路径及目录身份 `(dev, ino)`，并将项目根加入 operation anchors。Claude `ProjectLocal` 虽写入共享 `claude_user_file`，也必须绑定其 `projects[native_key]`；物理文件相同、账户相同或 lease 相同都不能替代项目授权。commit、inspect、cancel 与 recovery_material 统一在加载 journal 时核对当前 HostContext 的授权项目相同且根身份未变；发布前再次复核。更换项目或缺失项目授权返回 AccessDenied，同路径换根返回 RootChanged，均不得改写配置或 journal。缺少项目绑定的旧项目范围 journal 保留恢复材料但拒绝继续操作，不从当前项目或共享文件反推绑定；OsUser journal 不绑定当前选中项目。

资源 journal 的 `ProjectShared` 操作同样持久绑定授权项目根路径和目录身份。`resource_load` 在提交、查询、取消与恢复材料定位前统一核对当前项目；缺少项目授权、换项目或缺少绑定的旧项目资源 journal 拒绝继续操作。OsUser 操作不绑定当前项目。已安装树的全部文件及目录也须通过保留路径检查；带嵌套 Hook/托管标记的实例保持只读投影，owner 不可判定时为 Unknown，禁止更新和移除。移除提交须重新检查实际 before 树，旧版本的匹配快照不能绕过保留路径保护。

状态：previewed → prepared → publishing → committed；另有 cancelled、conflict、failed、unknown、recovery_required。每步写 journal 用原子替换并 fsync；配置临时文件/Skill staging 全量写完、重算 manifest、fsync 后才入 publishing。交换后 fsync 父目录、读取实际目标并持久 committed，之后才返回成功。journal 写失败不继续下一步发布。

配置备份可能已有原生 secret。不得把它复制到普通应用数据库、日志、诊断压缩包或 renderer；保留 inode/备份位于同一受保护目标父目录或等权限恢复区，0600/ACL 不扩权，journal 只引用、不收集内容。备份属于配置事务恢复材料，不作为新凭据源。宿主无法证明外部进程已关闭旧 FD，因此即使提交成功，也保留交换出的旧 inode；不自动清理，不按时间删除唯一版本。恢复材料只能通过宿主显式恢复流程定位，删除前展示影响并由用户处理，不能把无法观测的“无外部句柄”写成成功或清理条件。

Skill 更新和禁用若需要两个目标（目录和配置）必须列明顺序、分别预写 journal；不伪称多文件原子。优先先提交资源，再由独立操作启用；安装回执可为 installed + pending_activation。移除先保留资源恢复副本、再变更精确引用，各步失败可由 journal 定位。不得清理其他 owner 缓存或在配置失败后删除外部新改目录。

## 8. 幂等与重试

预览与确认以宿主生成的 operation_id 绑定账户 lease、目标实例、动作、before 指纹、来源 after 指纹及适配器版本；同 ID 不同意图返回冲突。预览 TTL 10 分钟，重复确认已 committed 返回原回执；publishing/unknown 只核实原目标，不创建新 operation 代替结果。账户切换后旧预览不可提交；原已发生的共享磁盘变更仍保留。

外部认证、插件管理、连接、工具调用和版本探测不自动重试。CLI login 的退出码不能单独证明当前会话已经采用新 token，写配置的退出码也不能替代原目标重读。独立状态读取失败不倒退已知的 committed 事实；失败后的再次尝试先显示原结果和新动作影响。刷新技能属于可能改变会话资源的独立动作，不放入后台“重试读取”。

## 9. MCP 认证、检测、会话生效与补偿

### 9.1 认证与凭据

Codex 使用 native OAuth login/logout，或配置 bearer_token_env_var / env_http_headers / env_vars 等原生引用；Claude 使用 native OAuth login/logout 或原生 `${VAR}` 引用（headers/env/args 支持范围按版本验证）。引用只在 CLI 环境解析，管理页仅显示变量名及存在性，不能展开秘密。URL userinfo、含秘密 query、header/env/argv 中的直接 token 不允许由新编辑表单创建；导入既有项时敏感节点不回显且原字节保持。

Codex 帮助/文档可让 OAuth client_secret 写入 TOML，并可经 argv 传入；DG-OS 不采用此方式创建新 secret。若原生没有不经 argv/普通配置的安全入口，就引导用户在原生界面完成该认证，不伪造保密适配。Claude 的 client-secret 提示/环境方式只在验证安全渠道后接入；不把 MCP_CLIENT_SECRET 或 OAuth code/state/callback URL 写进普通日志或操作 journal。

OAuth 流程由原生 CLI 持有 state、回调监听及 token；宿主只启动明确实例的原生认证并转交受控用户交互。认证 URL 仅在当次必要的登录界面短暂显示，禁止进入通用事件/诊断；远程页面不能取得宿主授权结果。超时 180 秒，可取消；只终止本宿主本次拥有的认证进程组，不杀 CLI 共享 daemon。终止未知时保留 auth_unknown，下一次先查询可安全观察的原生状态。没有权限绕过审批或执行 helper 的隐含授权。

原生 remove 的 token 清理可能由 CLI 实现，与本地配置 patch 不等价：UI 分开“移除该配置”和“原生退出认证”。先退出认证如被选择，必须展示会影响的有效原生实例和共享认证；失败保留凭据清理待核实，不声称服务端已撤销 token。不能从更改低优先级实例意外注销高优先级同名服务。原生认证存储只由其所有者处理，不手写 OAuth 文件。

Claude 2.1.319认证独立于对话控制请求：专属PTY运行受信可执行文件的`mcp login NAME --no-browser`或`mcp logout NAME`，继承同一cwd及启动配置环境，禁止普通终端、运行记录、诊断和journal捕获输出。原生输出仅在有界内存提取授权URL及粘贴提示；原始错误不透传。当前CLI手工完整回调路径对预注册clientId可完成交换；动态注册若原生报错则命令失败，不改用SDK私有方法兜底。只对既有会话唯一有效且source=user/project/local的实例开放；名称不是scope选择器，所有同名低优先级配置不产生独立认证入口。

认证单独使用操作UUID、owner、session_id、进程generation及账户/Provider/session/宿主lease，180秒从准入起算。相同UUID同意图只读原操作，参数改变冲突；共享OS配置可能跨会话复用凭据，故宿主全局最多一个未停止认证（含cleanup_pending），准入时会话须idle/error；等待认证期间原对话仍可正常使用。`starting → waiting_callback → succeeded|failed`；取消/过期先清除瞬态交互，`stopping → stopped`仅在自有进程会话清理并wait后发布，reason分别cancelled/expired/revoked。`credential_outcome`单列`confirmed|unknown`：取消、超时、非零退出和清理不确定均unknown，停止不保证远端未交换；不能确认清理为auth_unknown，保留未回收leader、监督任务和maintenance permit，只有监督者可重试清理，不重放认证。原对话不close、不interrupt、不发送提示，不自动浏览器/重连/重试。退出认证成功只证明CLI命令成功，远端撤销与现有内存连接另行观察。

瞬态交互只经Settings/McpManage的认证读取/回调命令返回；每次复核owner及当前generation/lease。URL仅允许HTTPS或loopback HTTP且无userinfo，callback完整URL交给同一PTY，不进入argv。回调必须匹配原生授权URL中的redirect_uri与state且仅提交一次；重复、迟到、已取消或旧代拒绝。账户撤权和显式关闭撤销交互并等待专属子进程；UI隐藏不取消。重启不恢复URL、callback或认证进程。

PTY在启动和回调提交时设raw/no-echo，master非阻塞；callback上限16384字节，匹配后先消耗交互，spawn_blocking内256字节分片写入，2秒期限并持续检查lease，不持async状态锁等待写入。专属reader并发排空输出避免大URL回压死锁；URL/state/callback原文最多65536字节暂存，超限停止认证，不写诊断。回调写入部分完成亦不重试。取消清理使用未回收leader固定session身份，TERM→KILL、成员确认后wait；无法确认保留auth_unknown，不凭旧PID后续发信号。


### 9.2 检测与连接所有权

“检查配置”只做本地解析；“检测连接”属于显式进程/网络操作，最多 30 秒、输出 256 KiB、不重试；只做初始化和工具发现，不调用工具。CLI 启动可能加载原生 Hook/helper/MCP，预览必须写明。Claude `mcp list/get` 的帮助已明确会健康检查已批准服务，因此禁止用于自动列表扫描；若作为用户检测动作使用，结果标 probe process，退出后关闭其自有子进程。

优先查询现有 DG-OS 自有 CLI 会话，不为管理页后台启动第二个 MCP Client。Codex 只使用版本证实的 App Server 状态方法与分页，当前源码已有 mcpServerStatus/list 调用但新原生视图仍须重新验证；不得沿用旧网关 ready 判据。Claude 使用现有 Query 的 mcpServerStatus，只投影 name/status/source/scope/serverInfo 和工具安全摘要，绝不直接透传可能含 config/error 敏感内容的 SDK 对象。

原生支持重连/开关时向指定会话发控制请求；新配置服务器是否进入存活进程须按协议实证，reconnect 老名字不等于重载配置成功。没有对应控制 API 时提示新建会话或原生界面操作。DG-OS 不额外启动/持有原生 Server，不把原生 connect/disconnect 映射到宿主 McpManager。

### 9.3 状态模型

状态是并列事实，不能塞进一个绿色状态点：

| 维度 | 示例 | 证据主体与有效期 |
| --- | --- | --- |
| 资源配置 | installed/configured/disabled/shadowed/unreadable | 本地文件/库和 revision；文件变化后 stale |
| 依赖/检测 | not_checked/passed/failed/auth_required/unknown | probe ID、二进制/配置指纹与时间；仅该探测 |
| 会话注册 | registered/not_reported/unobservable | 原生技能/工具清单；不能等同 Skill 正文执行 |
| 会话连接 | connected/pending/failed/needs-auth/disabled/unknown | session_id、进程代次、原生来源和观察时间；断流/进程换代后 stale 或 unknown |
| 生效条件 | pending_refresh/pending_new_session/native_dynamic/unverified | 对应 CLI 操作/字段能力记录；保存不改会话事实 |
| 执行记录 | native_started/completed/failed/cancelled/unknown | 原生 run/tool 事件；不写成 DG-OS 执行/逐次宿主审批 |

Skill 是否实际加载正文并使用资源，仅有清单不足以证明；验收须原生 Skill/文件读取结果佐证。原生状态无 schema hash 时保持 schema_unobserved；不能从名字推断 schema 没变化或套用 DG-OS 固定工具批准。状态列表未完整分页时 incomplete，不能把没看到的服务判定未连接。外部终端会话不可观测，明确显示不可观测而非全部离线。

普通保存不重启/重建会话，不自动 reloadSkills/reloadPlugins/reconnect。用户显式刷新须说明可能加载脚本/Hook/插件或建立连接；Claude reloadPlugins 可用 holdOnCacheImpact，held 返回保持未应用，进一步应用由用户显式操作，不能自动加 force。标签隐藏不触发刷新或停止。

### 9.4 外部调用与补偿

原生 Server/插件/认证外部副作用不在数据库事务内。网络失败/取消/断线保持原生已观察到的结果；工具结果未知不重放，取消不承诺撤回服务端效果。配置回滚是新预览和新操作，必须检查当前原文与所有者；不自动覆盖后来用户更改。已经发给 CLI 的凭据、上下文或工具请求不能通过删除配置回收。

## 10. 账户结束、退出与恢复

沿 D130/D131，UI 切换、管理页面覆盖、标签收起不停止运行。显式关闭 CLI 先确认，再等待实际退出；失败/超时/未知保留可核实入口。账户结束先撤销 lease，阻止新预览提交、认证控制、会话状态结果回填和旧批准；对共享 OS 用户配置不能承诺账户隔离或删除。

文件提交和账户撤销使用同一 admission/publication gate：撤销前已越过不可中断发布点的写入必须到达可恢复持久边界，不能让新账户继承可提交的旧预览。普通本地文件临界段目标 2 秒；超时记录待恢复，不通过取消异步任务放弃已启动的写线程。所有新探测/认证的停止复用进程所有权，最多并行 2 个；应用清理总预算沿既有 5 秒，不叠加每项 180 秒认证超时。CLI 控制 close 沿原生实现（Claude 请求 close 最多 2 秒，transport 后续清理仍受总预算约束）。

应用退出只停止自己拥有的认证/探测进程、CLI 及普通后代，不杀外部 CLI、包管理器用户会话、共享 Server/daemon 或凭旧 PID 操作。不能确认已脱离进程组的后代结束时记录 cleanup_pending，不谎报全部清理。

重启只读 journal/目标并恢复本地写入事实；不自动 login、启动 Server、刷新插件、发送模型/工具请求或重放批准。恢复现有 CLI 之前重验 owner、目录身份、CLI/SDK 能力、Provider 和原生配置来源；旧 D135 混合会话由 P2 阻止恢复并显式交接。文件 hash 只描述观察时刻，不宣称冻结以后原生热读的文件。

ACL 无附加条目的正常路径采用协调者本机观测：临时普通目录及 0600 文件的 `acl_get_fd_np(fd, ACL_TYPE_EXTENDED)` 返回 `NULL` 且立即 errno 为 `ENOENT`。Apple [Libc ACL 读取实现](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_file.c)通过 `filesec_get_property(FILESEC_ACL)` 获取该属性；FD 路径仅放行 `NULL + ENOENT`，其他错误拒绝。非空返回指针一律释放并拒绝，包括显式空 ACL；不再将 `acl_get_entry` 的 `EINVAL` 当作无 ACL 证明。测试源码同时覆盖无 ACL 普通目录/0600 写入，以及继承 everyone ACL 的目录和 chmod 0600 后的文件拒绝；本 TAB 未重跑协调者已报告的系统 API 复现，集中验证由协调者执行。

### 16.1 来源、资源与工作区

- 仓库来源存于应用私有、账户隔离的来源库；只保存受支持 HTTPS GitHub 标识、ref、受限元数据、索引时间和不可变提交。显式刷新下载并有界扫描多 Skill；保存/移除来源不安装/卸载资源，失败保留旧结果并标记过期。不预置演示来源。
- ZIP/目录通过宿主文件选择器获得短期、账户代次绑定句柄；renderer 不传任意路径或伪造内容哈希。导入固定安全包快照，继承既有全树/路径/类型/配额检查。来源正文是不可信内容，不执行其中指令、脚本或 Hook。

- `Selection.task_id` 可选；宿主先校验 project，再于同一项目准入下从 task 解析实际 workspace、核对归属和目录身份。缓存和 journal 绑定完整选择及真实根；无 task 才管理项目根，OsUser 不携带项目/task。切换不将旧请求映射到当前选择。

### 16.2 Registry 与 MCP 临时测试

- 官方 Registry 使用已核对的版本化 API，显式搜索、opaque cursor 分页，限量并固定同一筛选；请求失败保留旧缓存与时间。来源名称、描述、版本和部署是目录声明，不是安全背书。部署向导只生成配置草稿；npm/uvx/docker 的代码下载/执行风险在实际测试前另行预览。
- probe 计划绑定账户/代次、目标平台、范围/目录身份、配置摘要、实际程序身份、argv、cwd、网络地址和凭据引用；环境秘密仅宿主持有，普通 DTO/日志不包含秘密。既有原生 OAuth 仍由独立原生认证处理，不能借用 DGOS vault/token。
- 最多一个正在执行的独立探针；总期限15秒、结束清理预算2秒。只执行 initialize、initialized 和 tools/list（有界分页），不暴露 tools/call。工具定义标记临时观测及配置摘要，不写原生活动会话或宿主连接池。配置改变后显示结果过期。
