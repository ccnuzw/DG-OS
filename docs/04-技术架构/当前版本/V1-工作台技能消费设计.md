# V1 工作台技能消费设计

日期：2026-10-27。依据：D018、V1-FR-002 AC20–24/AC35、V1-FR-006。前置内容契约见 [Skills 内容包规范](V1-Skills内容包与发布规范.md)。实现状态仅在 [版本状态](../../02-产品与版本/当前版本/V1-实现状态.md) 维护。

## 1. 交付切片

新增桌面单任务工作台，复用已配置的 OpenAI-compatible Provider。用户选择已缓存模型、一个已添加/启用且适用 `ai-workbench` 的技能，输入任务后发送。也可显式勾选“无技能运行”。本轮不取代完整聊天工作台规格，不支持多轮、流式、取消、MCP 或多技能。

上述为 D018 原始文本切片；D022 的显式 MCP 扩展见第 5 节，不改变未选工具时的行为。

## 2. 服务流程与边界

1. B02-21：可信宿主当前仍为桌面 `default-user`；用户参数不能用于远程认证。校验 Provider 归属和启用状态，模型必须在本地缓存且是文本聊天模型，不接受前端提交消息角色或任意正文。
2. B02-22：按用户加载所选技能版本，校验启用、兼容性、工具缺口、快照路径与完整性；最多一个技能，避免无实现的冲突消解。未选择且未明确确认无技能运行即拒绝。
3. B02-22：非空用户输入最大 16 KiB，技能正文最大 16 KiB，完整请求文本最大 24 KiB；拒绝而非截断。固定最大输出 1024 tokens；模型已知窗口时以 UTF-8 字节数加 1024 消息开销保守计入输入，预留输出，超过窗口拒绝。未知窗口只有字节硬限制，最终由 Provider 判定，不宣称精确 tokenizer 或自动分块。
4. B02-23：宿主 system 只声明指导优先级、无工具及数据边界；技能作为独立 user 消息，实际用户任务作为末条 user 消息。技能不能取得更高优先级或工具权限。此边界依靠服务不提供工具实现，不承诺提示词可消除所有模型注入。
5. B02-22/B02-26：在短数据库事务中重验用户所选版本/启用状态，写入 running 任务及不可变版本引用后提交。随后调用 Provider，不在网络请求期间持有事务。关闭/更新技能不改变已捕获的任务上下文。
6. B02-26：成功/失败以 running 为条件终结一次；错误仅记录固定类别，绝不存储原始 URL、响应或凭据。120 秒超时记为本地失败，外站结果/计费可能未知。进程重启将 running 标记 interrupted，不自动重放。

Provider 适配层已有网络重试可能多次发送；本设计不保证外部 exactly-once。重复点击由界面禁用及同步防重保护拦截；再次手动提交会创建新任务，不能当成幂等重试。

## 3. 数据与接口

增量 migration `m005_create_workbench_tasks`：

| 表 | 字段和约束 |
| --- | --- |
| `workbench_tasks` | String PK `id`；非空 `user_id, app_id, provider_id, model_id, status`；i64 `created_at`；可空 i64 `finished_at`、String `error_code`、i64 `total_tokens` |
| `workbench_task_skills` | 复合 PK `(task_id, version_id)`；FK task_id→tasks.id、version_id→skill_versions.id；非空 String `skill_id, content_hash` |

引用行不随用户开关删除；当前不提供技能版本删除/回收接口。任务状态为 running→succeeded/failed/interrupted，终态不可重写。完整输入输出只在当前调用/页面内存，离开或刷新不恢复；审计列表最多 50 条并按用户过滤。API key 沿用 Provider 现有存储，本次不声称实现系统钥匙串。

桌面 Commands：`run_workbench_task(input, user_id)` 返回任务状态、版本引用与可选输出；`list_workbench_tasks(user_id)` 仅返回安全审计字段。前置校验失败不发送、不写成功记录；Provider 失败返回带任务 ID 的 failed 结果；落库失败返回错误，不假装审计成功。无任何公网 HTTP 路由。

## 5. MCP 显式消费扩展（D022）

保持原 B02/AC 的含义，消费桥接追溯 FR-003 AC06/AC13 与 FR-006 AC11、B06-09。仅桌面本地 main 窗口可进入，宿主固定 default-user，不接受 renderer 伪造用户身份。

1. 创建阶段校验 Provider/缓存模型、Skill 和显式选择的至多 8 个工具；只允许已连接且启用的 Server，校验前端提供的输入/可选输出 schema 联合 hash，输出契约单独变更也使引用失效。为每个工具生成 `dgos_tool_N` 别名，Provider 只看到选中工具的描述及输入 schema，不接触 MCP URL、凭据或连接。
2. 在原任务创建事务中写入 `workbench_task_tools(task_id, server_id, tool_name, schema_hash)`；复合主键防重复，task_id 外键引用任务，Server 删除不删除历史引用。任务状态保持原 CHECK；内存阶段为 ready → model → awaiting_confirmation → tool → model，最终 succeeded/failed。单用户仅允许一个活动工具任务。
3. `start_workbench_tool_task` 返回 ready 及真实任务 ID；`advance_workbench_tool_task` 的 action 为 `run_model`、`approve(proposal_id)` 或 `deny(proposal_id)`。内存原子取走上下文后再做外部 I/O，重复 action 拒绝，网络期间不持有数据库事务。用户确认只传提案 ID，不接收替换参数或授权令牌。
4. Provider 使用结构化 tools/tool_calls，禁用并行调用，仍拒绝返回的多调用批次。每轮校验 alias、唯一调用 ID、JSON 对象参数和固定 schema，最多 8 次调用。单次提案等待最多 120 秒，超时不能再批准；整个任务 15 分钟后销毁内存并终结。Provider 不支持 tools 时显示失败，不降级为正文解析。
5. 批准后用宿主保存的参数、真实 task_ref、随机 call_id、固定 30 秒超时申请单次 MCP 确认；Manager 在 dispatch 的快照锁内重验固定 schema hash、权限、启用和连接。取消会通知 Manager，不能承诺撤销外部副作用。MCP 返回未知结果、超时、取消或 audit_warning 时终止而不继续模型，更不自动重试工具。
6. MCP 普通成功/isError 结果作为 tool 角色数据回传，包含 content/structuredContent/isError；system 明确工具输出不可信。每次 Provider 调用重新计算 messages+工具描述的 UTF-8 字节，遵守 24 KiB 与已知模型窗口、1024 输出预留。超限终止而非截断。
7. 任务列表只返回安全审计与不可变工具引用；正文、提案、参数、结果只在当前宿主内存与页面中，终结、过期或重启销毁。取消/拒绝/过期保存固定错误类别；重启 running→interrupted；不恢复调用。
