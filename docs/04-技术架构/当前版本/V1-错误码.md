# V1 错误码

## 1. 文档目标

本文档汇总 DGOS V1 的所有错误码，确保全局唯一、语义清晰、易于维护。

**权威性**：
- ✅ 错误码编号与含义的登记处；与代码已发出的映射冲突时以代码为准并修订本文（D038）
- ✅ 前端国际化的依据
- ✅ 日志分析和监控的基础

**更新原则**：
- 新增错误码：先分配编号，再编码
- 错误码一旦分配，永不修改、永不复用
- 废弃错误码：在“状态”列标为作废，保留在文档中

---

## 2. 错误码规范

### 2.1 编码规则

**格式**：7 位数字 `FFMMEEE`

- `FF`（2 位）：固定功能域前缀 `10`
- `MM`（2 位）：功能编号（00 为通用错误，01-10 对应功能映射表）
- `EEE`（3 位）：错误序号（001-999）

**示例**：
- `1001001`：前缀 `10`、功能域 `01`（Provider）的错误序号 `001`
- `1008005`：前缀 `10`、功能域 `08`（本地用户管理）的错误序号 `005`

**例外**（D038）：`1000000` internal_error 是唯一使用序号 `000` 的通用码；`1002999` 是 Skills 未单独映射错误的回退码。

**权威性**（D038）：代码已发出或已持久化的编号以代码映射为准；本文与之冲突的旧含义作废，编号不以旧含义复用。下表“状态”列中，“预留”表示代码尚未发出，“作废”表示登记含义已由其他编号覆盖，均不得改作他用。

### 2.3 通用错误（00）

### 7.1 错误处理

> 示例按 D038 的编号书写，属于规划写法。当前只有 Provider command 返回 `CommandResponse { success, data, error: { code, message } }`（`code` 为数字），前端只显示 `message`，没有错误码映射表；MCP/Skills command 返回错误字符串。

// 错误码映射
const ERROR_MESSAGES: Record<string, string> = {
  '1001001': 'Provider 不存在',
  '1001002': 'API Key 无效',
  '1001004': '模型不存在',
  // ...
};

// 错误处理
try {
  const result = await invoke('call_provider', { ... });
} catch (error) {
  const errorCode = error.code;
  const message = ERROR_MESSAGES[errorCode] || '未知错误';
  
  // 显示错误提示
  toast.error(message);
  
  // 根据错误码处理
  if (errorCode === '1001002') {
    // 跳转到 Provider 配置页面

  }
}

### 9.2 错误码统计（规划示例）

以下查询依赖尚未实现的 `error_logs` 表，并使用 PostgreSQL 时间语法；当前 SQLite 数据库不支持 `NOW() - INTERVAL` 这种写法。不能视为可直接运行的当前监控查询。

```sql
-- 统计错误码分布
SELECT 
    error_code,
    COUNT(*) as count,
    MIN(created_at) as first_seen,
    MAX(created_at) as last_seen
FROM error_logs
WHERE created_at > NOW() - INTERVAL '7 days'
GROUP BY error_code
ORDER BY count DESC
LIMIT 10;
```
