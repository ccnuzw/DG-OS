# FR-004 前置收口设计

## 1. 目标与边界

依据 D023 和 D030，将 FR-001～003 的既有能力收敛为可信宿主服务及跨入口 Application Service，减少后续接入模块时的返工。本轮不实现 federation、模块安装/热更新、模块市场或任意远程 JavaScript 执行。

实现状态只在 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md) 维护；本文件维护要求、实现依据与验证资产，不用既有绿色测试替代新增要求的证据。

## 3. 身份与能力

桌面 IPC 不接受 `user_id` 作为身份。宿主校验窗口与 origin 后派生本地会话，并把配置管理归入 Settings、任务编排归入 Workbench。域服务可服务于将来的多用户，但调用者必须来自宿主；所有按 ID 资源操作也必须校验所属用户。

能力分为 Provider 读/管理/调用、Skills 读/管理/内容准备、MCP 读/管理/提案执行/确认、任务编排。授予这些内置能力不会授予 Skill 文本任何工具权限。模块能力必须经 `HostCapabilityService` 的具体方法逐次 dispatch；不提供通用命令名/JSON 转发入口。Provider 调用已接入该服务作为首个具体 capability adapter，Skills 与 MCP 后续接入时仍需保留 Manager 的用户归属、固定版本、逐次确认和未知结果语义。

同源 remote 能访问宿主 JS 与 IPC 的事实不能靠闭包、前端拦截器、隐藏 token 或 Error Boundary 改变。此阶段只绑定内置宿主来源；独立模块的可信身份和可撤销授权需要在 FR-004/009 中通过执行边界设计落实。

## 4. 凭据与恢复

Provider 复用 OS 安全存储原则，不把 secret 搬到通用配置 JSON。引用与用户、Provider、endpoint 绑定。更换 endpoint 需要显式新凭据或明确重新绑定，不能静默把旧 secret 发往新 origin。更新采用新引用，提交失败不破坏旧引用；OS vault 不可用时 fail-closed。

既有明文迁移不得破坏用户配置。正常启动不因单条迁移失败抹除原值；失败状态与重试必须可见。日志仅记录类别和引用，不保存 key、提示、完整工具参数或返回正文。

Provider 引用保存前由宿主生成 Provider ID 和随机引用，vault account 绑定用户、Provider、完整 endpoint 与引用。数据库以无 secret 的 cleanup outbox 先登记清理意图；成功提交活动引用时原子移除该意图，旧引用轮换/删除时原子加入队列。启动恢复只清理不再被活动 Provider 引用的条目。Provider DTO 删除 legacy secret 字段，仅显示 stored/migration_required/missing；迁移失败可从管理页逐项重试。所有持久化新写入禁止 legacy key，普通消费不使用 legacy secret 作网络认证；命令行示例和测试显式注入隔离的临时内存 vault，不作生产回退。

## 5. 后续契约收敛要求

FR-004 的 `installed_modules` 与模型文档 `modules` 不一致，权限名与 D006 也不一致；依据 D024，`modules`/`module_permissions` 和 D006 权限值是唯一新实现依据，旧草图仅作追溯。不得把旧表草图直接应用为 migration。模块更新至少区分 package artifact、版本、完整性、当前版本指针与更新事件，数据库事务不能代替文件发布恢复。

V1 内置 UI/React 共享接口需基于实际 React 19 与 Vite 版本；插件兼容性、完整 UI 包和两个 federation fixture 属于未来 FR-004 预研，不是本轮实现内容。当前前置完成并不自动证明 Module Federation 可用或任意第三方代码安全。

## 7. 面向后续版本的复用边界

- **Workbench 流式**：复用 Host Service 生成的 execution context/request ID、Provider config revision、取消 token、审计 warning 和 unknown-result 语义。流式 command/event 只能作为传输适配，不绕过调用前授权和资源归属；部分输出是否持久化由 FR-006 单独冻结。
- **多用户（FR-008/009）**：将当前宿主固定 `default-user` 替换为可信会话解析器，调用 DTO 继续不包含用户身份。权限主键保持 `(user_id, module_id, permission)`；切换用户时不复用前一会话创建的 HostExecutionContext。
- **LAN（FR-010）**：只有在认证中间件构造相同 HostExecutionContext 后才可复用 Host Application Services；HTTP handler 不能把 Bearer token 解码结果直接交由 renderer/module 自报。局域网权限和用户会话需单独决策，不因 Tauri 单机授权而自动开放。
- **可执行范围**：本轮 package publisher 目前实现本地目录包摘要（不含 manifest 本身，manifest schema 独立解析），并用 DB current pointer 作启动恢复的权威值；未实现签名信任根、跨平台 crash consistency 验收，因此以上是基础边界，不是 V1 FR-004/006/008/009/010 的验收完成。模块运行时第一阶段（supervisor、本地受信任加载 smoke、在途请求终态与热更新回滚）后续已按 D033 在 FR-004 §7.5 实现，不属于本前置工作包。

PRE04-06 的 Provider 规则：首次 Provider/缓存/凭据引用在同一 DB 事务提交；缓存替换亦在事务内发布。新增 `config_revision` 与 `model_refresh_revision`，区分配置快照和最新发起的刷新；过期结果不发布。endpoint/type/凭据轮换原子清空旧缓存；Workbench 绑定初始配置 revision，后续轮次不切换到新配置。已派发请求仍属原快照，不能宣称取消撤销了外部结果。同步 Provider 响应与使用量可在审计写入失败时返回，并以 `audit_warning` 明示，不自动重放；MCP 外部结果的未知/审计警告仍终止任务。取消/退出/离页清理仍需各自验证，不能由缓存事务验证代替。
