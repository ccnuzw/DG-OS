# V1 数据模型

## 1. 文档目标

定义 DGOS V1.0 的完整数据库模型，包括表结构、索引、约束和数据关系。

**权威性**：本文档是数据库设计的唯一权威来源。Migration 文件必须与本文档保持一致。

**更新规则**：表结构变更必须先更新本文档，再生成 Migration。

---

## 2. 数据库选型

根据冻结决策 [D002](../../06-决策记录/V1-冻结决策.md#d002-使用-sqlite-而非-postgresql)：

- **数据库**：SQLite 3.x
- **ORM**：SeaORM
- **文件位置**：`~/.dgos/data.db`（单机模式）
- **备份策略**：用户手动复制文件

---

## 3. 核心设计原则

### 3.1 本地优先
- 所有数据存储在本地 SQLite
- 无需网络连接即可运行
- 云端同步为可选增强（V4+）

### 3.2 多用户隔离
- 所有业务表包含 `user_id` 外键
- 应用层强制查询过滤：`WHERE user_id = current_user`
- 敏感数据（API Key）加密存储

### 3.3 软删除
- 重要数据（Provider、Skills、对话记录）使用 `deleted_at` 软删除
- 保留审计追踪
- 定期清理可选

### 4.1 用户管理

#### users（本地用户）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 用户 ID |
| username | VARCHAR(50) | UNIQUE NOT NULL | 用户名 |
| password_hash | VARCHAR(255) | NOT NULL | 密码哈希（bcrypt） |
| display_name | VARCHAR(100) | | 显示名称 |
| avatar_url | TEXT | | 头像 URL（可选） |

| updated_at | TIMESTAMP | NOT NULL | 更新时间 |
| last_login_at | TIMESTAMP | | 最后登录时间 |

### 4.2 Provider 管理

#### 当前桌面实施基线（D023）

当前 SQLite `providers` 使用 UUID/TEXT 的 `id`、TEXT `user_id`（现阶段为既有 `default-user`）、`enabled`、`config` 与数据库物理删除；不是下面历史规划中的 INTEGER ID、`is_enabled` 或软删除。既有迁移不重写；新增 `m20261028_000004_provider_credentials`：

| 表/列 | 类型与约束 | 用途 |
| --- | --- | --- |
| `providers.credential_ref` | 可空 VARCHAR(128) | OS 凭据库引用，作用域绑定用户、Provider、完整 endpoint 与随机引用 |
| `providers.api_key` | 既有非空 TEXT/VARCHAR 字段 | 只兼容读取历史数据用于显式迁移；所有新建/轮换写入空串，迁移成功才清空 |
| `provider_credential_cleanup.credential_ref` | TEXT PRIMARY KEY | 待清理意图；不含 secret，不与 Provider 级联删除 |
| `provider_credential_cleanup.user_id/provider_id/endpoint` | TEXT NOT NULL | 重建 vault account 的非 secret 作用域 |

新引用写入 vault 前登记 cleanup 意图；保存 Provider/清空 legacy key 与撤销新引用清理意图在同一事务内提交。轮换及删除在相同事务中登记旧引用清理。启动或后续配置修改重试清理，已提交配置不因清理尚未完成而回报失败。迁移 schema 为 forward-only：不能通过 down 删除引用后自动恢复密钥，恢复须使用明确备份策略。SQL UPDATE 不保证旧 WAL、空闲页和备份中的物理擦除，不删除用户备份。

DTO 不包含 secret。`credential_status` 为派生字段：有引用为 `stored`，无引用但有 legacy key 为 `migration_required`，两者皆无为 `missing`；`stored` 不保证 OS vault 当前已解锁。实现状态与验证见 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)。

#### 拟增：三方兼容协议扩展（D063，尚无 migration）

下表是 [FR-001 §4.3](../../03-功能规格/V1/01-底层能力/01-Provider适配框架.md#43-多协议扩展的数据变化草案) 的登记，不是已执行的 migration；落地时按 forward-only 追加新 migration，不修改已执行的 `m20261027_000002_create_models`。当前物理表名是 `models`（本节下方 `provider_models` 为早期规划）。

| 表/列 | 类型与约束 | 用途 |
| --- | --- | --- |
| `models.source` | VARCHAR，`remote` 或 `manual`，默认 `remote` | 刷新模型列表只替换 `remote` 行，保留手动添加的模型 |
| `models.kind` | 可空 VARCHAR | 模型分类：`text-generation`、`embedding`、`rerank`、`image-generation`、`video-generation`、`speech-synthesis`、`speech-transcription`、`moderation`；NULL 的旧行读取时按 `model_id` 规则即时计算，不回写 |
| `models.kind_source` | 可空 VARCHAR，`protocol`、`rule`、`default` 或 `manual` | 分类来源 |
| `models.max_output_tokens` | 可空 INTEGER | 上游文档化的最大输出长度（现有表没有这一列，DTO 字段一直为空） |
| `models.capabilities` | JSON，形状由数组扩展为对象 `{streaming, vision, tools, reasoning, structured_output}`，每项 `supported`、`unsupported` 或 `unknown` | 能力提示，只供展示；读取时兼容旧数组 |
| `providers.config` | JSON，增加 `vendor_id`、`auth_style`、`allow_insecure_http` 三个键 | 不需要 migration；缺省值与旧数据的推断规则见 FR-001 §2.4.2 |

`provider_usage_logs` 不变。推理文本和思考块不落库、不进使用记录与日志。上游不返回用量时记 0，没有“用量未知”标记列（已知限制）。

#### providers（Provider 配置）

> 以下保留早期加密/用户模型规划，仅作历史追溯，不是当前桌面 migration 或已完成证明；当前字段依据为上方 D023 实施基线。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | Provider ID |
| user_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 所属用户 |
| name | VARCHAR(100) | NOT NULL | Provider 名称 |
| provider_type | VARCHAR(50) | NOT NULL | 类型（openai_compatible） |
| base_url | TEXT | NOT NULL | API 基础 URL |
| api_key_encrypted | BLOB | NOT NULL | 加密的 API Key |
| api_key_iv | BLOB | NOT NULL | 加密 IV |
| is_enabled | BOOLEAN | DEFAULT TRUE | 是否启用 |
| sort_order | INTEGER | DEFAULT 0 | 排序优先级 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |
| deleted_at | TIMESTAMP | | 软删除时间 |

**索引**：
```sql
CREATE INDEX idx_providers_user_id ON providers(user_id);
CREATE INDEX idx_providers_user_enabled ON providers(user_id, is_enabled) 
    WHERE deleted_at IS NULL;
```

**设计要点**：
- API Key 加密存储（AES-256-GCM）
- 使用操作系统密钥链派生加密密钥
- sort_order 用于 Provider 排序（对应决策 D012）
- 软删除保留历史配置

**安全考虑**：
- api_key_encrypted：存储加密后的 API Key
- api_key_iv：存储加密 IV（Initialization Vector）
- 加密密钥从操作系统密钥链获取，不存储在数据库

### 4.3 Skills 管理

> D016–D019 修订提示（2026-10-27）：本节区分新增内容模型与旧 HTTP/CLI 基线。[DGOS 技能中心](../../03-功能规格/V1/01-底层能力/02-Skills管理系统.md)现已新增内容来源、不可变版本、用户启用与工作台任务引用表；旧列不被重解释，也不作为当前物理模型描述。

#### 新增内容模型（V1 additive baseline）

- `skill_catalog`：稳定技能身份、官方/精选/第三方身份、DGOS 分类、作者/许可、兼容应用、来源和验证状态。
- `skill_versions`：不可变版本、内容哈希、只读/下载路径、内置标记、校验状态和最小文件清单。
- `skill_user_states`：按用户/技能复合主键维护所选版本与启用状态，外键关联不可变版本。
- 旧 `skills`、`skill_registry_cache` 和 `skill_usage_logs` 保留为 Legacy 兼容；不自动把 `manifest.json` 转换为 `SKILL.md`。
- 物理建表见 `m004_create_skill_content_tables`；用户启用已有独立表，应用会话绑定和任务引用仍待后续 migration，不能从共享版本记录推断用户授权。

新增表字段与约束（时间均为 Unix 秒；JSON 保留结构化值，非可执行配置）：

| 表 | 字段 | 类型与约束 |
| --- | --- | --- |
| `skill_catalog` | `skill_id` | String 主键，非自增 |
| `skill_catalog` | `identity, name, latest_version, category, source_kind, verification_status` | String，非空 |
| `skill_catalog` | `description, author, license_spdx, source_ref` | String，可空 |
| `skill_catalog` | `tags, compatible_apps, metadata` | JSON，非空 |
| `skill_catalog` | `synced_at` | i64，非空 |
| `skill_versions` | `id` | String 主键，`skill_id@version` |
| `skill_versions` | `skill_id, version` | String，非空；联合唯一索引 `idx_skill_versions_identity` |
| `skill_versions` | `content_hash, install_path, verification_status` | String，非空 |
| `skill_versions` | `is_bundled` | Boolean，非空，默认 false |
| `skill_versions` | `file_manifest, metadata` | JSON，非空 |
| `skill_versions` | `installed_at` | i64，非空 |
| `skill_user_states` | `user_id, skill_id` | String，非空，复合主键；当前无 users 外键，不能视作会话鉴权 |
| `skill_user_states` | `version_id` | String，非空，外键 `skill_versions.id` |
| `skill_user_states` | `enabled` | Boolean，非空 |
| `skill_user_states` | `created_at` | i64，非空 |

`skill_versions.skill_id` 暂无指向目录的数据库外键；批量登记事务保证当前目录与版本同时可用，版本独立保留以服务历史引用。`skill_user_states.skill_id` 与所选版本所属技能的一致性由 Manager 控制，不接受任意 version_id 的桌面写入接口。完整流程见 [内容包与发布规范](V1-Skills内容包与发布规范.md)。

#### Workbench 任务引用（V1 技能消费切片）

物理建表见 `m005_create_workbench_tasks`；任务不保存完整输入、正文或模型输出。任务的版本绑定仍以 `workbench_task_skills` 为权威；`skill_usage_logs` 仅作为兼容的脱敏使用审计汇聚表，不替代任务引用。

| 表 | 字段 | 类型与约束 |
| --- | --- | --- |
| `workbench_tasks` | `id` | String 主键 |
| `workbench_tasks` | `user_id, app_id, provider_id, model_id, status` | String，非空；`status` 仅 `running/succeeded/failed/interrupted` |
| `workbench_tasks` | `created_at` | i64，非空 |
| `workbench_tasks` | `finished_at, error_code, total_tokens` | 可空；错误仅固定类别，不保存原始 Provider 信息 |
| `workbench_task_skills` | `task_id, version_id` | String，复合主键；分别外键任务和 `skill_versions.id` |
| `workbench_task_skills` | `skill_id, content_hash` | String，非空；记录任务实际绑定的技能版本与完整性摘要 |
| `workbench_task_tools` | `task_id, server_id, tool_name` | String，非空，复合主键；task_id 外键引用任务；Server 删除不删除历史引用 |
| `workbench_task_tools` | `schema_hash` | String，非空；固定本任务显式选择的工具输入和可选输出 schema 摘要 |

任务状态只允许 `running → succeeded/failed/interrupted`；终态更新使用条件更新，进程启动时将遗留 `running` 标记为 `interrupted`，不自动重放。任务引用不会因用户后来禁用技能而删除。完整边界和事务时序见 [工作台技能消费设计](V1-工作台技能消费设计.md)。

`m20261028_000008_skill_usage_provenance` 为旧 `skill_usage_logs` 增加可空的 `caller`、`request_id`、`task_ref`；内容 Skill 准备只写版本/hash 和错误类别等安全摘要，不写正文、提示词或 Provider 凭据。旧历史行保持可读，缺失来源字段不被推断为模块身份。

工具引用由 D022 的增量 migration `m010_create_workbench_task_tools` 新增，与任务/技能引用同一事务写入，不修改原有 status CHECK。等待确认、模型请求、工具执行仅为内存阶段；取消/拒绝/过期终结为 failed。表中不保存参数、返回值、工具调用 ID、提案 ID 或确认令牌；Server 不建立外键，以保留配置删除后的历史身份引用。

### 4.4 MCP 管理

#### mcp_servers（MCP 服务器配置）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | TEXT | PRIMARY KEY | 稳定 UUID；不使用外部 Server 名称作为主键 |
| user_id | TEXT | NOT NULL | 宿主身份，当前桌面为 `default-user` |
| name | VARCHAR(100) | NOT NULL | 用户可见名称；同一用户内唯一 |
| transport | VARCHAR(20) | NOT NULL | `stdio` 或 `http` |
| config_json | TEXT | NOT NULL | 非敏感连接配置；stdio 使用 executable/args/cwd，http 使用 URL 与 allow_insecure_http（默认 false） |
| credential_ref | TEXT | | 宿主凭据服务引用，不保存明文 secret |
| enabled | BOOLEAN | DEFAULT FALSE | 是否允许连接和工具调用 |
| auto_connect | BOOLEAN | DEFAULT FALSE | 启动时是否尝试连接；默认关闭 |
| status | VARCHAR(20) | NOT NULL | `configured`/`connecting`/`ready`/`degraded`/`error` 等运行摘要 |
| last_error_class | VARCHAR(80) | | 最近一次脱敏错误类别 |
| created_at | BIGINT | NOT NULL | 创建时间，Unix 秒 |
| updated_at | BIGINT | NOT NULL | 更新时间，Unix 秒 |
| deleted_at | BIGINT | | 软删除时间，Unix 秒 |

**索引**：
```sql
CREATE INDEX idx_mcp_servers_user_id ON mcp_servers(user_id);
CREATE UNIQUE INDEX idx_mcp_servers_user_name
    ON mcp_servers(user_id, name) WHERE deleted_at IS NULL;
CREATE INDEX idx_mcp_servers_user_enabled
    ON mcp_servers(user_id, enabled) WHERE deleted_at IS NULL;
```

**设计要点**：
- 支持 stdio 和 HTTP 两种传输；HTTP 优先 Streamable HTTP，legacy SSE 由适配器内部兼容
- 不持久化进程句柄、HTTP stream 或取消 token；应用重启后从 `configured` 恢复
- 保存配置默认不连接；用户可按 Server 开启 `auto_connect`
- `config_json` 不得保存 API Key、OAuth token 或完整认证 Header
- 非回环明文 HTTP 需要显式 `allow_insecure_http: true`；旧配置缺字段按 false 解释。凭据引用仍独立存列，不进入配置正文。
- `reconnect_attempts` / `reconnect_exhausted` 是 DTO 的运行时字段，不新增数据库列，不在重启后恢复自动重试状态。

#### modules（模块配置，FR-004 前置 broker 表；不包含安装/加载运行时）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|

| manifest | JSON | NOT NULL | 已校验 manifest 摘要，不承载任意执行权限 |
| integrity | CHAR(64) | NOT NULL | 当前 package 的完整性值（D057）：`v2:` + 64 位小写十六进制（67 字符）；不带前缀的 64 位十六进制是遗留 v1 值，只作为一次性迁移的输入，不能执行。`CHAR(64)` 是历史声明类型，SQLite 不校验长度且无 CHECK 约束，因此不需要 migration；换用会强制长度的数据库前必须先追加兼容迁移 |

| updated_at | TIMESTAMP | NOT NULL | 更新时间 |

**索引**：
```sql
CREATE UNIQUE INDEX idx_modules_name ON modules(module_name);
CREATE INDEX idx_modules_enabled ON modules(is_enabled);
```

**设计要点**：
- module_name 是唯一标识（如 `@dgos/ai-workspace`）
- package artifact、manifest、版本、完整性摘要、当前版本指针和更新事件必须分离；数据库事务不能代替文件发布恢复
- is_official 标记官方模块（不可卸载）

发布器的文件对象不直接等同于 `modules` 行：artifact 存放在应用数据目录的版本目录中，当前指针由发布器原子切换；版本/artifact/更新事件不能把历史版本 JSON 或文件路径堆入本表。当前代码的 `dgos-modules::ModulePublisher` 已提供暂存、manifest/完整性校验、版本目录切换、数据库当前指针提交和启动恢复；尚未加载或执行模块代码。

当前新增的 `m20261028_000010_module_release_history` 与追加的 `m20261028_000012_module_release_operation` 已提供最小 `module_versions`（版本/摘要/入口相对路径）和 `module_update_events`（operation、阶段、结果、错误类别）持久化对象；它们记录发布证据，不等同于运行时热更新完成。`module_update_events.module_id` 暂不设外键，允许首次安装在模块身份事务回滚后仍记录失败尝试；因此它是审计事件，不保证关联的模块行始终存在。

`m20261028_000011_module_release_locks` 增加单行 `module_release_locks` lease 表。发布器在 stage 后、切换文件指针和数据库提交前取得 `modules` 全局 lease，并在成功或失败恢复后释放；过期 lease 可由下一次操作清理。它补充同实例 mutex，避免多个进程/独立 publisher 同时切换同一模块目录；仍不替代跨平台断电一致性测试。

### 4.7 系统配置

#### system_settings（系统设置）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 设置 ID |
| user_id | TEXT | NOT NULL | 宿主派生的用户 ID（V1 为 `default-user`；原稿 INTEGER 外键已由 Phase 3 取代，见下） |
| setting_key | TEXT | NOT NULL | 设置键 |

| updated_at | INTEGER | NOT NULL | 更新时间（Unix 秒） |

**索引**：
```sql

    ON system_settings(user_id, setting_key);
```

**设计要点**：
- 所有行都属于某个用户（`user_id NOT NULL`）；本表当前只有外观偏好的两个键
- setting_value 存储 JSON 格式

**外观偏好（D065，FR-005 Phase 3，migration `m20261029_000014_system_settings`）**：外观偏好使用 `appearance.theme`（JSON 字符串 `"light"`、`"dark"`、`"auto"`，默认 `"light"`）与 `appearance.density`（JSON 数字 `75`、`100`、`125`、`150`、`175`，默认 `100`）两个键，由 `get_appearance_preferences`/`set_appearance_preferences` 读写，`user_id` 恒为宿主派生的 `default-user`。

**schema 决策（Phase 3，以 migration 为准）**：
- `user_id` 为 `TEXT NOT NULL`，不是早期规划的 INTEGER 外键：仓库没有 `users` 表，所有用户范围的表（`providers`、`skills`、`module_crash_logs` 等）都用字符串 `default-user`（D023），外键无从建立。FR-008 落地后如需改为外键，须追加兼容 migration，不修改本 migration。
- 不使用 `user_id = NULL` 表示全局设置：SQLite 的唯一索引把 NULL 视为互不相等，全局键可重复插入。本 migration 不提供全局设置；需要全局设置的功能（如 HTTP 端口）须另行决策其 `user_id` 取值，不得复用 NULL。
- 唯一键为 `(user_id, setting_key)`（`idx_system_settings_unique`），写入用 `INSERT … ON CONFLICT(user_id, setting_key) DO UPDATE`，同一用户同一键只有一行。
- 默认值不写入 migration，也不预置行：读取时缺失、不是合法 JSON 或不在封闭取值内的值，按字段回退到默认值，不报错、不回显。
- `id` 为 `INTEGER PRIMARY KEY AUTOINCREMENT`，`updated_at` 为 INTEGER（Unix 秒），与 `module_crash_logs` 一致；`setting_key` 为 `TEXT`，不设长度。
- 兼容性：只新增一张表，不修改既有表和行；旧数据库升级后 `system_settings` 为空，偏好读为默认值。forward-only，`down` 返回错误。
- 同时写入 `theme` 与 `density` 时在同一事务内完成，任一键写入失败则两者都不落库。
- 上面“常见设置”里的 `"theme": "dark"` 是示意，实际键名以本段为准。

**常见设置**：
```json
{
  "theme": "dark",
  "language": "zh-CN",
  "http_port": 3000,
  "http_enabled": true
}
```

## 7. 安全考虑

### 7.1 敏感数据加密

> 当前桌面 Provider 与 MCP 均采用宿主 OS 凭据库引用（Provider 迁移规则见 §4.2）。下方 AES 字段与伪代码是早期规划，不是当前 SQLite 的加密实施或历史数据已物理擦除的证明。

**加密字段**：
- providers.api_key_encrypted
- MCP 的 `credential_ref` 只保存宿主凭据引用；`mcp_servers.config_json` 禁止写入明文认证信息

**加密方案**：
```rust
// 使用操作系统密钥链派生加密密钥
let master_key = keyring::get_encryption_key("dgos")?;
let cipher = Aes256Gcm::new(&master_key);

// 加密
let iv = generate_random_iv();
let encrypted = cipher.encrypt(&iv, api_key.as_bytes())?;

// 存储
provider.api_key_encrypted = encrypted;
provider.api_key_iv = iv;
```

### 7.2 SQL 注入防护

**强制规则**：
- 所有查询使用 SeaORM 参数化查询
- 禁止字符串拼接 SQL
- 禁止动态表名/列名

### 7.3 多用户隔离

**强制规则**：
- 所有查询必须包含 `WHERE user_id = ?`
- 使用 SeaORM 的 global scope 自动添加过滤
- 管理员接口单独实现（不走常规 CRUD）
