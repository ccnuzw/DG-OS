# V1 数据模型

## 1. 文档目标

定义 DGOS V1.0 的完整数据库模型，包括表结构、索引、约束和数据关系。

**权威性**：数据库物理事实（表、列、索引、约束）以 `crates/dgos-db/src/migrations/` 的 migration 文件为准（见 [文档权威性](../../README.md)）；本文档解释约束、状态与演进，与 migration 冲突时先修订本文档。

**更新规则**：表结构变更必须先更新本文档，再生成 Migration。

---

## 2. 数据库选型

根据冻结决策 [D002](../../06-决策记录/V1-冻结决策.md#d002-使用-sqlite-而非-postgresql)：

- **数据库**：SQLite 3.x
- **ORM**：SeaORM
- **文件位置**：Tauri 应用数据目录（`app_data_dir()`）下的单个 `dgos.db`（`src-tauri/src/lib.rs`）
- **备份策略**：用户手动复制文件

---

## 3. 核心设计原则

### 3.1 本地优先
- 所有数据存储在本地 SQLite
- 无需网络连接即可运行
- 云端同步为可选增强（V4+）

### 3.2 多用户隔离
- 业务表按宿主派生的TEXT `user_id`隔离；D023既有表多数无`users`外键，由应用层按领域清理。ASST-FOUNDATION新增内容表明确使用`users(id) ON DELETE CASCADE`，不是全库无外键承诺（见§4.9及migration037）。
- 应用层强制查询过滤：`WHERE user_id = current_user`
- API Key 与 MCP token 不以密文存库，只保存 OS 凭据库引用（见 §4.2 D023 基线、§4.4）

### 3.3 软删除
- 当前只有 `mcp_servers` 使用 `deleted_at` 软删除；Provider 为数据库物理删除（D023，见 §4.2），旧 `skills` 表没有 `deleted_at` 列；聊天会话与消息采用硬删除（D072，见 §4.6）
- 保留审计追踪
- 定期清理可选

## 4. 表结构设计

### 4.1 用户管理

#### users（本地用户）

> 已由 migration `m20261101_000019_local_accounts` 建立（2026-11-01，FR-008 实现；物理结构以 migration 为准）。设计见 [FR-008 技术设计“物理模型”](../../03-功能规格/V1/03-系统功能/08-本地用户管理-技术设计.md#物理模型新增-migration)（D087、D090）：`id` 为 TEXT（首个账户为 `default-user`）；`username_key` 为 Unicode 简单小写后的唯一键；`password_hash` 为 Argon2id PHC 串；`failed_attempts`、`locked_until` 用于退避；`deleting_since` 为持久删除标记。现有表的 `user_id` 都没有外键，删除账户由应用层逐领域清理（见下文“按用户清理”）。不建会话表：桌面会话只在宿主内存。旧规划的 `display_name`、`avatar_url`、`is_active` 不采用。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | TEXT | PRIMARY KEY | 用户 ID（首个账户为 `default-user`，其余为 UUID 文本，D087） |
| username | TEXT | NOT NULL | 用户名（1～32 个 Unicode 标量值） |
| username_key | TEXT | UNIQUE NOT NULL | 简单小写后的用户名，用于唯一性与查找 |
| password_hash | TEXT | NOT NULL | Argon2id PHC 串（D087） |
| failed_attempts | INTEGER | NOT NULL DEFAULT 0 | 连续失败次数 |
| locked_until | BIGINT | | 退避截止（Unix 秒） |
| last_sign_in_at | BIGINT | | 最后登录时间 |
| deleting_since | BIGINT | | 非空即删除进行中 |
| created_at | BIGINT | NOT NULL | 创建时间 |
| updated_at | BIGINT | NOT NULL | 更新时间 |

**设计要点**：
- 密码使用 Argon2id（D087；原写 bcrypt cost=12）
- 不加指向 `users` 的外键；`username` 不改（V1 没有改名入口）
- 账户不能禁用，只能删除（D087）

#### host_settings（宿主级设置，D087、D118）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| setting_key | TEXT | PRIMARY KEY | 如 `last_sign_in_user`；FR-010 的 `lan.enabled`、`lan.port` 也放在这里（`lan.port` 为用户设定的首选端口，只由主机命令 `set_lan_port` 写入；缺省 8635，D107） |
| setting_value | TEXT | NOT NULL | 值 |
| updated_at | BIGINT | NOT NULL | Unix 秒 |

不属于任何用户。删除账户只清除 `last_sign_in_user` 指向该用户的行。

#### mcp_credential_cleanup（MCP 凭据清理 outbox，D090）

与 `provider_credential_cleanup` 同形：`credential_ref` 主键，`user_id`、`server_id`、`endpoint`（HTTP 配置的 `url`）非空。`credential_ref` 停止被行引用之前写入（服务器删除、改端点、换 token 与 `mcp_servers` 更新在同一事务；删除账户在写删除标记的事务里），vault 删除成功后才删除该行。删除失败的项保留，启动与之后的清理重试。`mcp_servers` 中仍未软删除的行引用的 `credential_ref` 不会被删除。

#### 按用户清理（删除账户，D087、D090）

`crates/dgos-db/src/repositories/user_data_repository.rs` 的 `UserDataDomain` 是唯一清单：库中每个含 `user_id` 列的表都登记在一个领域下，或作为 vault 重试 outbox 保留（`provider_credential_cleanup`、`mcp_credential_cleanup`）。`user_scope_tests::every_user_scoped_table_has_exactly_one_purge_entry` 在新 migration 增加未登记的 `user_id` 表时失败。顺序与范围：

| 领域 | 含 `user_id` 的表 | 经父 ID 删除的子表 |
|------|------|------|
| chat | `chat_messages`、`chat_sessions`（`ChatRepository::purge_user`；仍有 `generating` 消息时拒绝） | - |
| workbench | `ai_content_resources`、`ai_content_runs`、`ai_run_bindings`、`workbench_tasks`（公共内容包含module/chat scope，均由宿主绑定） | `ai_content_tool_receipts`、`workbench_task_skills`、`workbench_task_tools` |
| mcp | `mcp_usage_logs`、`mcp_connection_logs`、`mcp_servers`（含已软删除） | `mcp_server_tools` |
| providers | `provider_usage_logs`、`usage_logs`（遗留）、`providers` | `models` |
| skills | `skill_user_states`、`skill_usage_logs`、`skills`（遗留） | - |
| modules | `module_permissions`、`module_permission_audits`、`module_storage`、`module_crash_logs` | - |
| settings | `system_settings` | - |
| lan（FR-010） | `lan_audit_events`（只删该用户的行；`user_id` 为 NULL 的行保留） | - |

全局、不删除：`modules`、`module_versions`、`module_update_events`、`module_release_locks`、`skill_catalog`、`skill_versions`、`skill_registry_cache`、`host_settings`（除指向该用户的 `last_sign_in_user`）。每个领域一个事务、可重复执行。

`host_settings` 的语言键为 `ui.language`，值为 `zh-CN`、`en-US` 或 `system`。该键属于主机，不随用户删除、登录或切换清理；缺失时由语言服务使用 `zh-CN`，不新增默认行（D118）。

**引用决策**：[V1-FR-008](../../03-功能规格/V1/03-系统功能/08-本地用户管理.md)

### 4.2 Provider 管理

#### 当前桌面实施基线（D023）

当前 SQLite `providers` 使用 UUID/TEXT 的 `id`、TEXT `user_id`（现阶段为既有 `default-user`）、`enabled`、`config` 与数据库物理删除；不是下面历史规划中的 INTEGER ID、`is_enabled` 或软删除。既有迁移不重写；新增 `m20261028_000004_provider_credentials`：

| 表/列 | 类型与约束 | 用途 |
| --- | --- | --- |
| `providers.credential_ref` | 可空 VARCHAR(128) | OS 凭据库引用，作用域绑定用户、Provider、完整 endpoint 与随机引用 |
| `providers.api_key` | 既有非空 TEXT/VARCHAR 字段 | 只兼容读取历史数据用于显式迁移；所有新建/轮换写入空串，迁移成功才清空 |
| `provider_credential_cleanup.credential_ref` | TEXT PRIMARY KEY | 待清理意图；不含 secret，不与 Provider 级联删除 |
| `provider_credential_cleanup.user_id/provider_id/endpoint` | TEXT NOT NULL | 重建 vault account 的非 secret 作用域 |

新引用写入 vault 前登记 cleanup 意图；保存 Provider/清空 legacy key 与撤销新引用清理意图在同一事务内提交。轮换及删除在相同事务中登记旧引用清理。启动或后续配置修改重试清理，已提交配置不因清理尚未完成而回报失败。迁移 schema 为 forward-only：不能通过 down 删除引用后自动恢复密钥，恢复须使用明确备份策略。SQL UPDATE 不保证旧 WAL、空闲页和备份中的物理擦除，不删除用户备份。

Provider 删除先按宿主用户核对归属，在同一事务中清除该用户、该 Provider 的 `provider_usage_logs` 与遗留 `usage_logs`，再物理删除 `providers`（`models` 由外键级联删除），避免两张使用记录表的非级联外键阻止删除。其他 Provider 或其他账户的数据不受影响；`chat_sessions`、`workbench_tasks` 中没有 Provider 外键的历史引用保持可读，凭据清理 outbox 保留到 vault 删除成功。

DTO 不包含 secret。`credential_status` 为派生字段：有引用为 `stored`，无引用但有 legacy key 为 `migration_required`，两者皆无为 `missing`；`stored` 不保证 OS vault 当前已解锁。实现状态与验证见 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)。

#### 三方兼容协议扩展（D063）：`models` 新列与 `providers.config` 新键均已落地

下表是 [FR-001 §4.3](../../03-功能规格/V1/01-底层能力/01-Provider适配框架.md#43-多协议扩展的数据变化草案) 的登记。`models` 的四个新列由 migration `m20261030_000015_model_kind_and_source`（forward-only，只追加四列，不修改已执行的 `m20261027_000002_create_models`）落地；`capabilities` 形状变化无需 migration；`providers.config` 的新键只是 JSON 键，不需要 migration。当前物理表名是 `models`（本节下方 `provider_models` 为早期规划）。

| 表/列 | 类型与约束 | 用途 |
| --- | --- | --- |
| `models.source` | TEXT NOT NULL DEFAULT `remote`，`remote` 或 `manual` | 刷新模型列表只替换 `remote` 行，保留手动添加的模型 |
| `models.kind` | 可空 TEXT | 模型分类：`text-generation`、`embedding`、`rerank`、`image-generation`、`video-generation`、`speech-synthesis`、`speech-transcription`、`moderation`；NULL 的旧行读取时按 `model_id` 规则即时计算，不回写 |
| `models.kind_source` | 可空 TEXT，`protocol`、`rule`、`default` 或 `manual` | 分类来源 |
| `models.max_output_tokens` | 可空 INTEGER | 上游文档化的最大输出长度（`anthropic` 取自 `/v1/models` 的 `max_tokens`；`openai_compatible` 没有文档化字段，总是 NULL）。`anthropic` 调用未给 `max_tokens` 时用它补全 |
| `models.capabilities` | JSON，形状由数组扩展为对象 `{streaming, vision, tools, reasoning, structured_output}`，每项 `supported`、`unsupported` 或 `unknown` | 能力提示，只供展示；读取时兼容旧数组（数组里的 `streaming`、`vision` 视为 `supported`，其余 `unknown`）；已落地 |
| `providers.config.allow_insecure_http` | JSON 布尔，缺省 `false` | 已落地：保存与每次调用时校验，非布尔值被 `request_not_supported` 拒绝 |
| `providers.config.vendor_id` | JSON 字符串，缺省时按 `provider_type` 与 base_url 推断（官方主机归对应厂商，否则 `custom`） | 已落地：保存与每次调用时校验，厂商不存在或该厂商没有 `provider_type` 对应的端点返回 `unsupported_provider_type`；旧数据不迁移 |
| `providers.config.auth_style` | JSON 字符串 `bearer`、`x-api-key` 或 `both`，缺省取画像默认值 | 已落地：取值非法返回 `request_not_supported`；只改鉴权头，不改目标主机 |
| `providers.config.workspace_id` | JSON 字符串，可选，最长 128 个可见 ASCII 字符（`null` 或空串视为未设置） | 后端已落地，界面没有入口（§2.4.6 第 8 项）：只在官方 Anthropic 画像下作为 `anthropic-workspace-id` 头发送，其他画像保存但不发送；不是敏感值，存在 `providers.config` JSON 中而不是凭据库；取值非法（非字符串、含空白或超长）返回 `request_not_supported`。它是 `config` 里的普通键，前端编辑 Provider 时必须原样保留（`ProviderForm` 保留 `config` 里它不认识的键），否则会丢失。没有真实调用核对过官方 Anthropic 服务是否接受该头 |

本扩展不修改 `provider_usage_logs`。推理文本和思考块不落库、不进使用记录与日志。上游不返回用量时 token 列记 0；`usage_reported`（`m20261031_000017_usage_reported`，D081）区分“未回报”与真实 0，见下文 `provider_usage_logs`。

#### providers（Provider 配置）

> 以下保留早期加密/用户模型规划，仅作历史追溯，不是当前桌面 migration 或已完成证明；当前字段依据为上方 D023 实施基线。

**索引**：
```sql
CREATE INDEX idx_providers_user_id ON providers(user_id);
CREATE INDEX idx_providers_user_enabled ON providers(user_id, is_enabled)

```

**设计要点**：
- API Key 加密存储（AES-256-GCM）
- 使用操作系统密钥链派生加密密钥
- sort_order 用于 Provider 排序（对应决策 D012）
- 软删除保留历史配置

**安全考虑**：
- api_key_encrypted：存储加密后的 API Key
- api_key_iv：存储加密 IV（Initialization Vector）
- 加密密钥从操作系统密钥链获取，不存储在数据库

### 4.3 Skills 管理

> D016–D019 修订提示（2026-10-27）：本节区分新增内容模型与旧 HTTP/CLI 基线。[DGOS 技能中心](../../03-功能规格/V1/01-底层能力/02-Skills管理系统.md)现已新增内容来源、不可变版本、用户启用与工作台任务引用表；旧列不被重解释，也不作为当前物理模型描述。

#### 新增内容模型（V1 additive baseline）

- `skill_catalog`：稳定技能身份、官方/精选/第三方身份、DGOS 分类、作者/许可、兼容应用、来源和验证状态。
- `skill_versions`：不可变版本、内容哈希、只读/下载路径、内置标记、校验状态和最小文件清单。
- `skill_user_states`：按用户/技能复合主键维护所选版本与启用状态，外键关联不可变版本。
- 旧 `skills`、`skill_registry_cache` 和 `skill_usage_logs` 保留为 Legacy 兼容；不自动把 `manifest.json` 转换为 `SKILL.md`。
- 物理建表见 `m004_create_skill_content_tables`；用户启用已有独立表，应用会话绑定和任务引用仍待后续 migration，不能从共享版本记录推断用户授权。

新增表字段与约束（时间均为 Unix 秒；JSON 保留结构化值，非可执行配置）：

| 表 | 字段 | 类型与约束 |
| --- | --- | --- |
| `skill_catalog` | `skill_id` | String 主键，非自增 |
| `skill_catalog` | `identity, name, latest_version, category, source_kind, verification_status` | String，非空 |
| `skill_catalog` | `description, author, license_spdx, source_ref` | String，可空 |
| `skill_catalog` | `tags, compatible_apps, metadata` | JSON，非空 |
| `skill_catalog` | `synced_at` | i64，非空 |
| `skill_versions` | `id` | String 主键，`skill_id@version` |
| `skill_versions` | `skill_id, version` | String，非空；联合唯一索引 `idx_skill_versions_identity` |
| `skill_versions` | `content_hash, install_path, verification_status` | String，非空 |

**索引**：
```sql

CREATE INDEX idx_modules_enabled ON modules(is_enabled);
```

**设计要点**：
- module_name 是唯一标识（如 `@dgos/ai-workspace`）
- package artifact、manifest、版本、完整性摘要、当前版本指针和更新事件必须分离；数据库事务不能代替文件发布恢复
- is_official 标记官方模块（不可卸载）

发布器的文件对象不直接等同于 `modules` 行：artifact 存放在应用数据目录的版本目录中，当前指针由发布器原子切换；版本/artifact/更新事件不能把历史版本 JSON 或文件路径堆入本表。当前代码的 `dgos-modules::ModulePublisher` 已提供暂存、manifest/完整性校验、版本目录切换、数据库当前指针提交和启动恢复；尚未加载或执行模块代码。

当前新增的 `m20261028_000010_module_release_history` 与追加的 `m20261028_000012_module_release_operation` 已提供最小 `module_versions`（版本/摘要/入口相对路径）和 `module_update_events`（operation、阶段、结果、错误类别）持久化对象；它们记录发布证据，不等同于运行时热更新完成。`module_update_events.module_id` 暂不设外键，允许首次安装在模块身份事务回滚后仍记录失败尝试；因此它是审计事件，不保证关联的模块行始终存在。

`m20261028_000011_module_release_locks` 增加单行 `module_release_locks` lease 表。发布器在 stage 后、切换文件指针和数据库提交前取得 `modules` 全局 lease，并在成功或失败恢复后释放；过期 lease 可由下一次操作清理。它补充同实例 mutex，避免多个进程/独立 publisher 同时切换同一模块目录；仍不替代跨平台断电一致性测试。

| --- | --- |

**D133桌面偏好**：`desktop.snapshot.v1`为`{revision,values}`完整JSON，values包括最多3项`pinnedModuleIds`及顺序、`showEntries`、`showRecent`、`sidebarCollapsed`；按账户CAS写入，不在读取成功前回写默认值。只保存设备内该账户偏好，不恢复任务、租约、标签或临时专注。读取/保存失败和revision冲突均须重新读取后再写。

**CLI 偏好（D133 第4项，`setting_key = 'cli.paths.v1'`）**：`CliSnapshot` 为 `{revision, paths:{codex,claude,gemini,node}}` 完整 JSON，路径为 `null` 或绝对路径（最长 4096 字节，不含 NUL）。按 `user_id` 写入，整单 `UPDATE ... WHERE json_extract(setting_value,'$.revision') = ?` CAS；`expectedRevision = 0` 时使用 `INSERT ... ON CONFLICT DO NOTHING`。缺失行读为默认空值，不写库；损坏值返回固定错误。revision 上限 2^53-1。

**schema 决策（Phase 3，以 migration 为准）**：
- `user_id` 为 `TEXT NOT NULL`，不是早期规划的 INTEGER 外键：所有用户范围的表（`providers`、`skills`、`module_crash_logs` 等）都用字符串 user_id 且不建外键（D023）。`users` 表由 `m20261101_000019_local_accounts` 建立（§4.1），但既有表没有加指向它的外键；本 migration 未修改。
- 不使用 `user_id = NULL` 表示全局设置：SQLite 的唯一索引把 NULL 视为互不相等，全局键可重复插入。本 migration 不提供全局设置；需要全局设置的功能（如 HTTP 端口）须另行决策其 `user_id` 取值，不得复用 NULL。
- 唯一键为 `(user_id, setting_key)`（`idx_system_settings_unique`），写入用 `INSERT … ON CONFLICT(user_id, setting_key) DO UPDATE`，同一用户同一键只有一行。
- 默认值不预置于migration；外观完整快照的缺记录初始化、只读修复、损坏与未来版本规则按§11.3接口契约，不能以默认值静默覆盖损坏原行。桌面和CLI偏好沿各自缺失行只读默认约定。
- `id` 为 `INTEGER PRIMARY KEY AUTOINCREMENT`，`updated_at` 为 INTEGER（Unix 秒），与 `module_crash_logs` 一致；`setting_key` 为 `TEXT`，不设长度。
- 兼容性：只新增一张表，不修改既有表和行；旧数据库升级后 `system_settings` 为空，偏好读为默认值。forward-only，`down` 返回错误。
- 外观完整快照在单事务内CAS并原子替换，不再同时写theme/density旧两键；任一校验/事务失败均不部分保存。
- 上面“常见设置”里的`theme`仅为历史示意；现行固定键与快照形状以本节各偏好契约为准。

**常见设置**：

- **保留**：全表最多 500 条。每次插入与裁剪（删除超出部分中最旧的行）在同一事务。`pair_rejected`、`pair_rate_limited`、`request_rejected` 在 60 秒内同一（事件、原因、来源 IP）只更新 `last_at` 与 `count`。

- **读取**：只经主机命令 `list_lan_audit_events`（[接口契约 §14.8](V1-接口契约.md#148-主机命令tauri已注册)），返回 `user_id` 为当前桌面用户或 NULL 的行，按 `rowid` 新到旧分页。没有修改或删除单行的入口。
- **删除账户**：`UserDataDomain::Lan` 删除该用户的行（§4.1“按用户清理”）。`user_scope_tests::every_user_scoped_table_has_exactly_one_purge_entry` 要求这一登记。
- **写入失败**：不改变安全结果，只记 `tracing::warn!`。

**引用功能**：[V1-FR-010](../../03-功能规格/V1/03-系统功能/10-局域网协同.md)

### 4.9 ASST-FOUNDATION 临时内容与持久副作用回执

物理来源：`m20261110_000037_ai_foundation`（forward-only，down明确拒绝）。语义依据[AI助手运行基础技术设计](AI助手运行基础技术设计.md)，DTO见[接口契约§17.5](V1-接口契约.md#175-d136-ai-公共服务与模块-ipc)。新增表独立于`ai_run_bindings`及`workbench_tasks`，没有要求module任务行的外键；聊天导入公共资料无需伪造module任务。聊天原消息、D140运行/步骤/摘要继续归原聊天表，模块内容不借读`chat_assets`。

#### ai_content_resources

| 列/约束 | 物理定义与语义 |
| --- | --- |
| `id` | TEXT PRIMARY KEY NOT NULL，宿主随机资源ID；内容不可变 |
| `user_id` | TEXT NOT NULL，REFERENCES `users(id)` ON DELETE CASCADE |
| `scope` | TEXT NOT NULL，宿主生成`module:<id>`或`chat:<session>`，不接受前端scope或账户 |
| `name`, `mime` | TEXT NOT NULL；仅展示名和允许MIME，不是路径/可信身份 |
| `bytes` | BLOB NOT NULL，CHECK length≤8388608；文本1 MiB、图片8 MiB及UTF-8/签名限制由共享验证和仓储执行 |
| `sha256` | TEXT NOT NULL，CHECK length=64；宿主计算哈希，不授予读取权限 |
| `created_at`, `expires_at` | BIGINT NOT NULL，Unix秒；导入固定24小时租期，读取不续租 |
| `ai_content_resources_owner` | INDEX `(user_id,scope,expires_at)` |

每账户/scope有效资料合计≤24 MiB，短事务清理到期资源并原子检查配额。读取始终带owner/scope/未过期条件，即使清理尚未运行也不可读取过期字节；删除后下一次读取失效，已外发内容不能宣称撤回。最多16个固定引用及选定范围由运行层验证，不由数据库hash替代授权。

#### ai_content_runs

| 列/约束 | 物理定义与语义 |
| --- | --- |
| `run_id` | TEXT PRIMARY KEY NOT NULL，开始身份不可重置，不因正文清理被复用 |
| `user_id`, `scope` | TEXT NOT NULL；user FK级联，scope宿主绑定；每次操作核实仍存活且非删除中账户，chat scope还核实原会话归属 |
| `source_run_id` | 可空TEXT；同scope来源由仓储验证，不是数据库自引用外键，不提供跨来源读取权 |
| `retain` | INTEGER NOT NULL，CHECK IN(0,1)；CHECK `retain=1 OR content IS NULL` |
| `status` | TEXT NOT NULL DEFAULT running，CHECK running/succeeded/failed/cancelled/interrupted；仅running CAS转一次终态 |
| `content` | 可空TEXT，CHECK UTF-8字节≤65536；retain=false连部分检查点也不保存正文 |
| `content_expired` | INTEGER NOT NULL DEFAULT 0；到期/32份正文淘汰后置1，后续检查点不能复活正文 |
| `output_valid`, `audit_warning` | INTEGER NOT NULL DEFAULT 0；输出校验与审计可靠性分开，不代表业务保存成功 |
| `context_receipts`, `skill_receipts` | TEXT NOT NULL DEFAULT '[]'；上下文最多128项，各JSON快照≤16 KiB；仅实际提供范围/固定技能消费证据 |
| `acknowledged_at` | 可空BIGINT；首次领取确认时间，重复确认不变，不清正文、不外发 |
| `created_at`, `updated_at`, `expires_at` | BIGINT NOT NULL；新运行起固定24小时，checkpoint/领取/确认不续租 |
| `ai_content_runs_owner` | INDEX `(user_id,scope,created_at)` |

每账户/scope最多32份非空正文，按创建时间及rowid保留最新；清正文不删除运行行和回执。数据库status没有expired枚举，DTO根据`expires_at/content_expired`派生`expired/content=null`，无正文不等于从未执行，审计仍通过原summary读取。仅明确用户清理/账户删除/所属聊天会话删除删除运行内容行；普通审计不存prompt、output、reasoning、原工具参数/结果或凭据。`AiRunContent.tool_receipts/skill_receipts`来自该内容域，不把原始MCP输出灌入审计。

#### ai_content_tool_receipts

| 列/约束 | 物理定义与语义 |
| --- | --- |
| `run_id` | TEXT NOT NULL，REFERENCES `ai_content_runs(run_id)` ON DELETE CASCADE |
| `call_id` | TEXT NOT NULL；只作本次工具步骤关联，不能作为副作用去重依据 |
| `fingerprint` | TEXT NOT NULL，CHECK length=64；规范化server/tool/args的SHA-256，不保存原始参数 |
| `outcome` | 可空TEXT，CHECK succeeded/failed/cancelled/unknown；派发前写NULL，首次实际观察后结算，终态不可把unknown改成success |
| `unknown`, `inherited` | INTEGER NOT NULL DEFAULT 0；保留不确定性及继承标记 |
| 主键/索引 | PRIMARY KEY `(run_id,fingerprint)`；部分UNIQUE `ai_content_tool_call(run_id,call_id) WHERE inherited=0`；每run≤128项由仓储执行 |

新运行开始与继承来源指纹在一个短事务提交；同scope有未过期保留终态、无audit warning且无NULL/unknown工具步骤才允许继续。相同参数换call ID仍不能重新派发；继承回执不占新工具call ID唯一槽，新效果可使用复用的Provider call ID。网络不在数据库事务内；先落派发回执再外发、观察后结算，终态成功禁止未决/unknown或审计失败。模块任务审计与内容终态在同一事务提交，内容写失败回滚两侧，不能回报成功。

模块继续还沿来源及祖先运行关联核实元数据，最多32层、累计128条来源回执，超限拒绝；祖先正文过期不删除来源事实，关联的资源删除/过期仍阻断继续。历史来源核实不混入本轮实际交付片段回执。该遍历上限是运行服务准入，不新增migration列或把来源hash当授权；详见ASST-FOUNDATION技术设计。

启动恢复仅把running转interrupted、其未结算工具标unknown并清过期正文/资源，绝不自动重放。`ai_content_chat_deleted`触发器在`chat_sessions`删除后只删除相同user及`chat:<旧session>`资料/运行，再级联其工具回执；账户删除通过Workbench清单清理全scope，并有users FK兜底。模块撤权/卸载不让旧运行复活，正文领取仍受当前授权；同module JS realm不是文档安全沙箱。

直接目标资产为`crates/dgos-db/src/ai_content_tests.rs`（opt-out、配额、expiry/32份淘汰、CAS、确认、跨scope、指纹、unknown、文件库重开、会话/账户删除、审计+内容事务回滚）；命令`cargo test -p dgos-db ai_content_tests`。本批未运行，不能写为本地通过。

### 4.10 D143 CLI Agent 账户工作现场与目录授权

物理定义以追加 migration `m20261110_000039_development_desktop` 及 D144 `m20261110_000040_workspace_agent_activation` 为准，不改已执行 migration。

| 表 | 主键与字段 | 约束与生命周期 |
| --- | --- | --- |
| `development_desktop_state` | `owner TEXT PRIMARY KEY`、`revision INTEGER`、`value TEXT` | owner非空、revision>0、value为JSON对象且UTF-8≤8388608字节；仓储按owner/revision CAS，并在提交前重验账户租约 |
| `development_workspace_trust` | 复合主键`(owner,project_id,path,directory_identity)`；`agent/agent_revoked/terminal/service INTEGER`、`revision INTEGER` | 四个布尔字段CHECK IN(0,1)，默认0，禁止agent与agent_revoked同时为1；revision>0；`(project_id,owner)`外键级联到`development_projects(id,owner)` |

项目路径或目录身份更新触发删除原项目授权；删除`development_workspaces`时删除该真实目录的对应授权。账户删除清单与孤儿统计覆盖两表，工作现场表不依赖用户外键自动清理。无记录的读DTO使用revision=0，不代表已插入空行。

D144 的 agent_revoked 区分“尚未授予”和“明确拒绝”：未建行及新版仅设置 terminal/service 的行保留 agent_revoked=0，可由活动工作区进入动作补建 Agent 授权；显式撤销写 agent=0/agent_revoked=1，并沿 revision CAS 持久化，自动激活只返回拒绝、不修改。显式重新启用写 agent=1/agent_revoked=0，其他范围修改不影响此标记。旧库 agent=0 行无法从原字段判定是否发生过撤销，migration 保守标记为 agent_revoked=1，避免反授予；这类旧行需直接重新启用一次。旧 agent=1 行保持授权，未建行仍可自动补建。所有自动激活和显式修改共用修订 CAS 与提交前账户租约复核，普通读不会插入空行或增加修订。

桌面JSON是账户私有内容域，不进入普通审计。仅保存配置引用、草稿/有界附件和呈现现场；仓储拒绝凭据、批准、运行/授权字段，恢复不把JSON变成执行权限。配置引用失效保留原值，不补造旧会话配置。未知操作只保留核实身份，不重放批准、消息、终端输入或服务启动；错误码及退出保存协议见[接口契约§17.11](V1-接口契约.md#1711-d143-cli-agent-工作现场目录授权与退出)。

`module_authorization_epochs(user_id,module_id,epoch)` uses a composite primary key and deliberately has no module foreign key, so uninstall/reinstall cannot reset a prior grant epoch. Epoch overflow is rejected by the integer CHECK.

`ai_run_bindings` has `task_id` as its primary key and cascading foreign keys to `workbench_tasks(id)` and `(id,user_id)`. It stores trusted owner/module/version/integrity/runtime/request identity, the fixed epoch and selected pin snapshots, terminal status/error category, unknown/audit flags, and dispatch metadata; it does not store prompt, generated content, or MCP arguments/results. Insert requires an owner-matched running single task whose `app_id` is the module id. Binding identity fields are immutable. Task deletion removes restrictive legacy skill/tool references before cascade. Existing Workbench recovery from running to interrupted synchronizes the binding. The repository scopes list/get/admission/finalization by owner and module; purge or prior finalization cannot be resurrected by a late writer.

## 7. 安全考虑

### 7.1 敏感数据加密

> 当前桌面 Provider 与 MCP 均采用宿主 OS 凭据库引用（Provider 迁移规则见 §4.2）。下方 AES 字段与伪代码是早期规划，不是当前 SQLite 的加密实施或历史数据已物理擦除的证明。

**加密字段**：
- providers.api_key_encrypted
- MCP 的 `credential_ref` 只保存宿主凭据引用；`mcp_servers.config_json` 禁止写入明文认证信息

**加密方案**：
```rust
// 使用操作系统密钥链派生加密密钥
let master_key = keyring::get_encryption_key("dgos")?;
let cipher = Aes256Gcm::new(&master_key);

// 加密
let iv = generate_random_iv();
let encrypted = cipher.encrypt(&iv, api_key.as_bytes())?;

// 存储
provider.api_key_encrypted = encrypted;
provider.api_key_iv = iv;
```

### 7.2 SQL 注入防护

**强制规则**：
- 所有查询使用 SeaORM 参数化查询
- 禁止字符串拼接 SQL
- 禁止动态表名/列名

### 7.3 多用户隔离

**强制规则**：
- 所有查询必须包含 `WHERE user_id = ?`
- 使用 SeaORM 的 global scope 自动添加过滤
- 管理员接口单独实现（不走常规 CRUD）
