# V1 数据模型

## 1. 文档目标

定义 DGOS V1.0 的完整数据库模型，包括表结构、索引、约束和数据关系。

**权威性**：本文档是数据库设计的唯一权威来源。Migration 文件必须与本文档保持一致。

**更新规则**：表结构变更必须先更新本文档，再生成 Migration。

---

## 2. 数据库选型

根据冻结决策 [D002](../../06-决策记录/V1-冻结决策.md#d002)：

- **数据库**：SQLite 3.x
- **ORM**：SeaORM
- **文件位置**：`~/.dgos/data.db`（单机模式）
- **备份策略**：用户手动复制文件

---

## 3. 核心设计原则

### 3.1 本地优先
- 所有数据存储在本地 SQLite
- 无需网络连接即可运行
- 云端同步为可选增强（V4+）

### 3.2 多用户隔离
- 所有业务表包含 `user_id` 外键
- 应用层强制查询过滤：`WHERE user_id = current_user`
- 敏感数据（API Key）加密存储

### 3.3 软删除
- 重要数据（Provider、Skills、对话记录）使用 `deleted_at` 软删除
- 保留审计追踪
- 定期清理可选

## 4. 表结构设计

### 4.1 用户管理

#### users（本地用户）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 用户 ID |
| username | VARCHAR(50) | UNIQUE NOT NULL | 用户名 |
| password_hash | VARCHAR(255) | NOT NULL | 密码哈希（bcrypt） |
| display_name | VARCHAR(100) | | 显示名称 |
| avatar_url | TEXT | | 头像 URL（可选） |
| is_active | BOOLEAN | DEFAULT TRUE | 是否启用 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |
| last_login_at | TIMESTAMP | | 最后登录时间 |

**索引**：
```sql
CREATE UNIQUE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_is_active ON users(is_active);
```

**设计要点**：
- 密码使用 bcrypt（cost=12）
- username 不可变（影响数据隔离）
- is_active 用于禁用用户（不删除数据）

**引用决策**：[V1-FR-008](../../03-功能规格/V1/03-系统功能/01-本地用户管理.md)

### 4.2 Provider 管理

#### providers（Provider 配置）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | Provider ID |
| user_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 所属用户 |
| name | VARCHAR(100) | NOT NULL | Provider 名称 |
| provider_type | VARCHAR(50) | NOT NULL | 类型（openai_compatible） |
| base_url | TEXT | NOT NULL | API 基础 URL |
| api_key_encrypted | BLOB | NOT NULL | 加密的 API Key |
| api_key_iv | BLOB | NOT NULL | 加密 IV |
| is_enabled | BOOLEAN | DEFAULT TRUE | 是否启用 |
| sort_order | INTEGER | DEFAULT 0 | 排序优先级 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |
| deleted_at | TIMESTAMP | | 软删除时间 |

**索引**：
```sql
CREATE INDEX idx_providers_user_id ON providers(user_id);
CREATE INDEX idx_providers_user_enabled ON providers(user_id, is_enabled) 
    WHERE deleted_at IS NULL;
```

**设计要点**：
- API Key 加密存储（AES-256-GCM）
- 使用操作系统密钥链派生加密密钥
- sort_order 用于 Provider 排序（对应决策 D012）
- 软删除保留历史配置

**安全考虑**：
- api_key_encrypted：存储加密后的 API Key
- api_key_iv：存储加密 IV（Initialization Vector）
- 加密密钥从操作系统密钥链获取，不存储在数据库

**引用决策**：
- [D001](../../06-决策记录/V1-冻结决策.md#d001) - 使用 Rust + Tauri
- [D012](../../06-决策记录/V1-冻结决策.md#d012) - Provider 排序机制
- [V1-FR-001](../../03-功能规格/V1/01-底层能力/01-Provider适配框架.md)

#### provider_models（Provider 模型缓存）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 模型 ID |
| provider_id | INTEGER | FOREIGN KEY(providers.id) NOT NULL | 所属 Provider |
| model_id | VARCHAR(255) | NOT NULL | 模型标识符 |
| model_name | VARCHAR(255) | NOT NULL | 模型名称 |
| model_type | VARCHAR(50) | NOT NULL | 模型类型（text-generation 等） |
| context_window | INTEGER | | 上下文窗口大小 |
| max_output_tokens | INTEGER | | 最大输出 Token 数 |
| supports_streaming | BOOLEAN | DEFAULT TRUE | 是否支持流式 |
| supports_vision | BOOLEAN | DEFAULT FALSE | 是否支持视觉 |
| cached_at | TIMESTAMP | NOT NULL | 缓存时间 |

**索引**：
```sql
CREATE INDEX idx_provider_models_provider ON provider_models(provider_id);
CREATE UNIQUE INDEX idx_provider_models_unique 
    ON provider_models(provider_id, model_id);
```

**设计要点**：
- 永久缓存，手动刷新（对应决策 D014）
- model_type 对应内置分类标签
- 支持能力标记（streaming、vision）

**引用决策**：[D014](../../06-决策记录/V1-冻结决策.md#d014) - 模型分类标签内置维护

#### provider_usage_logs（Provider 使用记录）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 记录 ID |
| user_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 使用用户 |
| provider_id | INTEGER | FOREIGN KEY(providers.id) NOT NULL | 使用的 Provider |
| model_id | VARCHAR(255) | NOT NULL | 使用的模型 |
| request_type | VARCHAR(50) | NOT NULL | 请求类型（chat/completion） |
| prompt_tokens | INTEGER | | 输入 Token 数 |
| completion_tokens | INTEGER | | 输出 Token 数 |
| total_tokens | INTEGER | | 总 Token 数 |
| response_time_ms | INTEGER | | 响应时间（毫秒） |
| is_success | BOOLEAN | NOT NULL | 是否成功 |
| error_message | TEXT | | 错误信息 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |

**索引**：
```sql
CREATE INDEX idx_provider_usage_user_time 
    ON provider_usage_logs(user_id, created_at DESC);
CREATE INDEX idx_provider_usage_provider 
    ON provider_usage_logs(provider_id, created_at DESC);
```

**设计要点**：
- 记录每次 Provider 调用
- 支持用量统计和计费（V4）
- 不存储完整请求/响应（隐私保护）

## 7. 安全考虑

### 7.1 敏感数据加密

**加密字段**：
- providers.api_key_encrypted
- skills.config_json（如果包含 API Key）
- mcp_servers.config_json（如果包含认证信息）

**加密方案**：
```rust
// 使用操作系统密钥链派生加密密钥
let master_key = keyring::get_encryption_key("dgos")?;
let cipher = Aes256Gcm::new(&master_key);

// 加密
let iv = generate_random_iv();
let encrypted = cipher.encrypt(&iv, api_key.as_bytes())?;

// 存储
provider.api_key_encrypted = encrypted;
provider.api_key_iv = iv;
```

### 7.2 SQL 注入防护

**强制规则**：
- 所有查询使用 SeaORM 参数化查询
- 禁止字符串拼接 SQL
- 禁止动态表名/列名

### 7.3 多用户隔离

**强制规则**：
- 所有查询必须包含 `WHERE user_id = ?`
- 使用 SeaORM 的 global scope 自动添加过滤
- 管理员接口单独实现（不走常规 CRUD）

## 8. 性能优化

### 8.1 索引策略

**原则**：
- 外键列必须建索引
- 常用查询条件建复合索引
- 软删除查询使用 WHERE deleted_at IS NULL

### 8.2 查询优化

**批量操作**：
```sql
-- 批量插入使用事务
BEGIN TRANSACTION;
INSERT INTO provider_usage_logs ...;
INSERT INTO provider_usage_logs ...;
COMMIT;
```

**分页查询**：
```sql
SELECT * FROM conversations
WHERE user_id = ? AND deleted_at IS NULL
ORDER BY updated_at DESC
LIMIT 20 OFFSET ?;
```
