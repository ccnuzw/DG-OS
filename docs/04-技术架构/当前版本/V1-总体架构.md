# V1 总体架构

本文档描述 DGOS V1.0 的总体架构设计，包括系统分层、模块组织、数据流和技术选型。

---

## 1. 架构概览

DGOS V1.0 采用**模块化单体架构**（Modular Monolith）+ **微前端架构**（Module Federation）：

```
┌─────────────────────────────────────────────────────────────────┐
│                          用户界面                                │
│                     (Tauri Desktop App)                         │
└─────────────────────────────────────────────────────────────────┘
                              ↓

│                        前端层 (React SPA)                        │
├─────────────────────────────────────────────────────────────────┤
│  ┌───────────────┬───────────────┬──────────────────────────┐  │
│  │  AI 工作台    │   系统设置    │   第三方模块（动态加载）  │  │
│  └───────────────┴───────────────┴──────────────────────────┘  │

│  │  │Workbench │ Settings │  Canvas  │   第三方模块...   │  │  │
```

## 2. 分层设计

### 2.1 前端层（React + Vite + Module Federation）

**职责**：
- 用户交互界面
- 业务逻辑展示
- 模块动态加载

**核心模块**：
- **AI 工作台**：对话界面、流式响应、历史记录
- **系统设置**：Provider/Skills/MCP/模块管理
- **统一设计系统**：`@dgos/ui` 组件库

**技术特点**：
- Module Federation 实现微前端
- 模块运行时动态加载
- 共享 React、Zustand 等依赖

### 2.2 Tauri IPC 层

**职责**：
- 前后端通信桥梁
- 类型安全的 RPC
- 事件系统

**通信模式**：
```rust
// 前端调用后端
const result = await invoke('call_provider', { 
    providerId, modelId, request 
});

// 后端推送事件
#[tauri::command]
async fn stream_response(...) {
    app_handle.emit("chat_chunk", chunk)?;
}
```

### 2.3 应用服务层（Rust）

**职责**：
- 处理前端请求
- 协调多个领域服务
- 业务流程编排

**示例**：
```rust
// Workbench 服务
pub struct WorkbenchService {
    providers: Arc<ProvidersManager>,
    skills: Arc<SkillsManager>,
}

impl WorkbenchService {
    pub async fn send_message(&self, request: ChatRequest) -> Result<Response> {
        // 1. 调用 Provider
        let response = self.providers.call(request).await?;
        
        // 2. 可选 Skills 增强
        if let Some(skill_id) = request.skill_id {
            let enhanced = self.skills.enhance(response).await?;
            return Ok(enhanced);
        }
        
        Ok(response)
    }
}
```

### 2.4 领域服务层（Rust）

**职责**：
- 实现核心业务逻辑
- 领域模型封装
- 对外提供统一接口

**核心服务**：
- **ProvidersManager**：Provider 适配和调用
- **SkillsManager**：Skills 管理和调用
- **MCPClient**：MCP 连接和工具调用
- **ModuleLoader**：模块加载和权限管理
- **AuthService**：认证和权限检查

### 2.5 基础设施层（Rust）

**职责**：
- 提供技术基础设施
- 不涉及业务逻辑

**核心组件**：
- **Storage**：SQLite 数据访问
- **Network**：HTTP 服务器（局域网）
- **Logger**：日志记录
- **Config**：配置管理

### 2.6 数据层（SQLite）

**职责**：
- 持久化存储
- 数据隔离
- 事务支持

**核心表**：
- `users`：用户账号
- `providers`：Provider 配置
- `models`：模型列表
- `skills`：已安装 Skills
- `mcp_servers`：MCP 服务器
- `installed_modules`：已安装模块
- `conversations`：对话历史

## 3. 核心流程

### 3.1 用户发起对话

```
用户输入 "你好"
   ↓
前端：Workbench 组件
   ↓
Tauri IPC：invoke('send_message', { text: '你好' })
   ↓
后端：WorkbenchService.send_message()
   ↓
ProvidersManager.call(provider_id, request)
   ↓
OpenAI API（外部）
   ↓
流式返回：SSE chunks
   ↓
后端：app_handle.emit("chat_chunk", chunk)
   ↓
前端：监听事件，实时渲染
   ↓
用户看到流式响应
```

### 3.2 动态加载模块

```
用户点击"加载模块"
   ↓
前端：Settings 组件
   ↓
Tauri IPC：invoke('load_module', { manifest })
   ↓
后端：ModuleLoader.load_module()
   ↓
验证 manifest.json
   ↓
检查权限要求
   ↓
前端：显示权限授权对话框
   ↓
用户授权
   ↓
后端：注册模块，返回加载地址
   ↓
前端：动态 import 模块代码
   ↓
Module Federation 加载
   ↓
模块渲染到界面
```

### 3.3 Skills 调用（可选增强）

```
用户发起对话，选择 Skill
   ↓
WorkbenchService.send_message()
   ↓
1. ProvidersManager.call() → LLM 响应
   ↓
2. SkillsManager.call_skill(skill_id, response)
   ↓
HTTP 请求到 Skill 服务
   ↓
Skill 处理（如格式化、增强）
   ↓
返回增强后的结果
   ↓
合并展示给用户
```

## 4. 数据流

### 4.1 用户数据隔离

```
用户 A 登录
   ↓
JWT Token（包含 user_id）
   ↓
所有请求携带 Token
   ↓
后端验证 Token，提取 user_id
   ↓
所有数据库查询自动过滤：WHERE user_id = ?
   ↓
用户 A 只能看到自己的数据
```

### 4.2 模块权限检查

```
模块调用 Provider
   ↓
ModuleLoader.check_permission(module_id, "providers.call")
   ↓
查询 module_permissions 表
   ↓
有权限 → 允许调用
无权限 → 返回 403 错误
```

## 5. 技术特性

### 5.1 模块热更新

**实现**：Module Federation + Vite

```javascript
// 模块定义
export default {
  name: 'my-module',
  filename: 'remoteEntry.js',
  exposes: {
    './App': './src/App',
  },
  shared: ['react', 'react-dom'],
};

// 动态加载
const module = await import('http://localhost:3001/remoteEntry.js');
```

### 5.2 流式响应

**实现**：SSE (Server-Sent Events) + Tauri Events

```rust
// 后端
pub async fn stream_provider(&self, request: Request) -> Result<()> {
    let mut stream = self.provider.stream(request).await?;
    
    while let Some(chunk) = stream.next().await {
        self.app_handle.emit("chat_chunk", chunk)?;
    }
    
    Ok(())
}
```

```typescript
// 前端
listen('chat_chunk', (event) => {
    const chunk = event.payload;
    appendToMessage(chunk);
});
```

### 5.3 数据库迁移

**实现**：SeaORM Migrations

```rust
// migrations/m20240101_000001_create_providers.rs
pub struct Migration;

impl MigrationTrait for Migration {

    }
```

## 6. 非功能特性

### 6.1 性能

| 指标 | 目标 | 实现方式 |
|------|------|---------|
| 启动时间 | < 2s | Rust 编译优化 + 懒加载 |
| 模块加载 | < 1s | Module Federation + 代码分割 |
| API 响应 | P95 < 200ms | 异步 I/O + 本地 SQLite |
| UI 帧率 | > 60fps | React 18 Concurrent Mode |
| 内存占用 | < 200MB | Rust 无 GC + 按需加载 |

### 6.2 安全

| 层次 | 措施 |
|------|------|
| **后端** | Rust 内存安全 + 参数化查询 |
| **认证** | JWT + bcrypt 密码哈希 |
| **权限** | 模块级粗粒度权限检查 |
| **数据** | API Key 加密存储（AES-256） |
| **前端** | Tauri CSP + XSS 防护 |

### 6.3 可维护性

| 措施 | 说明 |
|------|------|
| **强制模块化** | Rust 编译期保证，单文件 < 1000 行 |
| **类型安全** | Rust + TypeScript 端到端类型安全 |
| **文档驱动** | spec-docs-pro 规格驱动开发 |
| **自动化测试** | 单元测试 + 集成测试 + E2E |
| **CI/CD** | GitHub Actions 自动检查 |

## 7. 部署架构

### 7.1 本地部署（V1.0）

```
用户机器
├── DGOS.app (macOS)
│   ├── Rust 后端（嵌入）
│   ├── React 前端（嵌入）
│   └── SQLite 数据库
└── ~/.dgos/
    ├── users/
    │   └── {user_id}/
    │       └── data.db
    ├── modules/
    │   └── {module_id}/
    └── skills/
        └── {skill_id}/
```

### 7.2 局域网协同（V1.0）

```
主机（192.168.1.100）
├── DGOS.app
└── HTTP 服务 :3000

远程设备
└── 浏览器 → http://192.168.1.100:3000
    ├── 认证（用户名/密码）
    ├── 只读模式
    └── 使用主机的 Provider/Skills/MCP
```

### 7.3 云端同步（V2.0）

```
用户机器
├── DGOS.app
└── 可选同步到云端

云端服务器
├── PostgreSQL
└── S3 存储
```

## 9. 架构决策

所有架构决策记录在 [V1 冻结决策](../../06-决策记录/V1-冻结决策.md)：

- **D001**：Rust + Tauri 而非 Python + Electron
- **D002**：SQLite 而非 PostgreSQL
- **D003**：不嵌入 JavaScript 运行时
- **D004**：Module Federation 实现模块热更新
- **D005**：使用现有标准协议（LangChain、MCP）
- **D006**：粗粒度模块级权限
- **D007**：局域网服务始终开启
- **D008**：统一设计系统强制复用
- **D009**：无限画布分多版本实现
