# V1 总体架构

本文档混合描述目标架构与当前实现边界；文中部分服务和流程仍是规划，并非已实现事实。当前有 Tauri commands 与 `Channel` 作为桌面宿主入口，用户由宿主会话解析（FR-008 本地账户已实现，尚无账户时为 `default-user`），已有首方模块 runtime，尚无 HTTP/LAN 服务。实现状态见 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)，FR-004 前置边界见 [前置收口设计](V1-FR004前置收口设计.md)。

## 1. 架构概览

图中的 Axum/HTTP 为规划组件：当前没有 HTTP/LAN server 或 router、JWT。桌面本地账户（FR-008）已实现，没有独立的 AuthService，账户用例在 `dgos-application` 的 `accounts` 模块，会话解析在 `src-tauri/src/session.rs`。模块 runtime 已实现并限于宿主固定清单内的首方模块，页面以原生动态 `import()` 加载（D042），不使用 Module Federation（D098 将其移出 V1 范围，是后续可选的加载适配，不承诺版本）。D025/D028 仍禁止 V1 任意远程 JavaScript。其余目标流程不应视为当前实现状态。

目标架构为**模块化单体**；当前实现 Tauri 桌面宿主与首方模块 runtime（宿主 WebView 内原生动态 `import()`，不使用 Module Federation）：

## 2. 分层设计

### 2.1 前端层（React + Vite；原生动态 `import()` 加载首方模块）

**职责**：
- 用户交互界面
- 业务逻辑展示
- 模块动态加载（已实现，首方模块；D025/D028 限制为可信代码）

**核心模块**：
- **AI 工作台**：单任务 Workbench task 与多轮聊天（含流式 UI）均已有命令，见接口契约 §10.0、§10.1；实现进度只在实现状态维护
- **系统设置**：Provider/Skills/MCP/模块管理
- **统一设计系统**：`@dgos/ui`（FR-005/D008/D066；路径别名指向 `src/ui/`，不是 npm 包）

**技术特点**：
- 模块运行时动态加载已实现（宿主 WebView 原生 `import()`，D042）；Module Federation 不在 V1 范围（D098）
- 共享 React、Zustand 等依赖

### 2.2 Tauri IPC 层

**职责**：
- 前后端通信桥梁
- 类型安全的 RPC
- 事件系统

**通信模式**：
```rust
// 前端通过已注册 Tauri command 调用宿主能力
const result = await invoke('call_provider', { providerId, modelId, request });

// Provider 与聊天的流式内容经调用方传入的 Tauri Channel 推送，不发全局事件；聊天流程见 §3.1 与接口契约 §10.1
```

### 2.3 应用服务层（Rust）

**职责**：
- 处理前端请求
- 协调多个领域服务
- 业务流程编排

**规划示例（非当前 API）**：
```rust
// Workbench 服务
pub struct WorkbenchService {
    providers: Arc<ProvidersManager>,
    skills: Arc<SkillsManager>,
}

impl WorkbenchService {
    pub async fn send_message(&self, request: ChatRequest) -> Result<Response> {
        // 1. 调用 Provider
        let response = self.providers.call(request).await?;
        
        // 2. 可选 Skills 增强
        if let Some(skill_id) = request.skill_id {
            let enhanced = self.skills.enhance(response).await?;
            return Ok(enhanced);
        }
        
        Ok(response)
    }
}
```

### 2.4 领域服务层（Rust）

**职责**：
- 实现核心业务逻辑
- 领域模型封装
- 对外提供统一接口

**核心服务**：
- **ProvidersManager**：Provider 适配和调用
- **SkillsManager**：Skills 管理和调用
- **MCPClient**：MCP 连接和工具调用
- **ModuleLoader**：`ModuleRuntimeSupervisor` 与 `PageModuleLoader` 负责运行时生命周期与页面加载，`ModuleOperationManager` 编排操作，`ModuleCallRouter` 与 `ModuleCapabilityDispatchService` 负责模块到宿主的类型化能力调用（已实现，首方模块）
- **账户与会话**：`dgos-application` 的 `accounts` 模块与 `SessionResolver`（FR-008 已实现）；没有独立 `AuthService`，不使用 JWT

### 2.5 基础设施层（Rust）

**职责**：
- 提供技术基础设施
- 不涉及业务逻辑

**核心组件**：
- **Storage**：SQLite 数据访问
- **Network**：HTTP 服务器（FR-010 规划；当前未实现）
- **Logger**：日志记录
- **Config**：配置管理

### 2.6 数据层（SQLite）

**职责**：
- 持久化存储
- 数据隔离
- 事务支持

**核心表（现有表举例；非完整列表）**：
- `providers`：Provider 配置
- `models`：模型列表
- `skills`：已安装 Skills
- `mcp_servers`：MCP 服务器
- `modules`、`module_permissions`、`module_crash_logs`：模块授权与崩溃数据（D024、D055）

## 3. 核心流程

### 3.1 用户发起对话

下图是 FR-006 聊天的目标流程（D072～D077），契约以 [接口契约 §10.1](V1-接口契约.md) 为准；实现进度只在 [V1 实现状态](../../02-产品与版本/当前版本/V1-实现状态.md) 维护，本文不记录。聊天流式事件只通过调用方传入的 `Channel` 推送，不发全局事件，也不存在 `send_message`、`conversations` 或 `emit("chat_chunk")` 形态。当前桌面 Workbench 的单任务命令是 `run_workbench_task`、`list_workbench_tasks`、`start_workbench_tool_task`、`advance_workbench_tool_task`、`cancel_workbench_tool_task`、`cancel_workbench_task`，与聊天命令并存。

```
用户输入 "你好"
   ↓
前端：Workbench 组件创建 Channel<ChatStreamEvent>
   ↓
Tauri IPC：invoke('send_chat_message', { input, onEvent })
   ↓
后端：host::context 校验主窗口并派生用户（输入不含 user_id）
   ↓
校验：会话归属、Provider/模型快照与目标指纹、Skill 固定版本重验、
      内容长度、每用户单活动生成、client_request_id 幂等
   ↓
装配上下文：仅 completed 轮次，24 KiB 总预算，按整轮从最旧丢弃
   ↓
一个事务：写任务行（workbench_tasks，kind = chat）+ 技能引用
          + 用户消息 + 助手占位消息（generating）
   ↓
在注册表登记取消令牌（键为任务 ID，归属窗口标签）
   ↓
返回 SendAck { task_id, user_message_id, assistant_message_id, ... }
   ↓（以下在后台继续）
ProviderManager.stream_provider_bound_cancellable_with_provenance
（调用方 Workbench，request_id = 任务 ID）→ OpenAI 兼容 / Anthropic 上游
   ↓
流式返回：delta / reasoning_delta 写入 Channel，内容在内存中累积
   ↓
终态事务：条件更新助手消息与任务状态（completed / interrupted / failed）
   ↓
Channel 发送 done 或 error（携带落库后的消息快照）
   ↓
前端：以快照为准渲染，用户看到流式响应
```

事件可能先于 `invoke` 返回到达，前端按 `assistant_message_id` 缓存。窗口销毁或页面重载时宿主取消该窗口的全部生成，已收到部分按中断保存；进程被强杀时本次未提交的内容可能丢失，重启后按中断恢复，不自动重发（D074）。

**单实例（D077）**：应用启动时先在应用数据目录下取得 `dgos.lock` 的独占文件锁（标准库 `File::try_lock`，要求 Rust 1.89 及以上），之后才打开数据库，并持有到进程退出；取不到锁则记录固定错误并以非零状态退出，不触碰数据库。进程被杀时由内核释放锁。这样启动恢复（把 `generating` 消息与 `running` 任务置为中断）不会误伤另一个进程的活动任务。已知限制：第二次启动不会聚焦已有窗口；这是建议性锁，网络文件系统上的语义不保证；Windows 与 Linux 未验证。

### 3.2 动态加载模块

现行流程见[接口契约 §8.3～§8.6](V1-接口契约.md)和[总体架构 §4.3](../总体架构.md)；没有 `load_module` 命令。

```
页面附着：attach_module_host(onInstruction: Channel)
   ↓
启用与授权：enable_module → grant_module_permission（用户在 Settings 确认）
   ↓
start_module → ModuleOperationManager 受理，返回 operation_id
   ↓
ModuleRuntimeSupervisor：固定准入清单（D041）+ 包摘要校验
   ↓
指令通道推送 load（源码由宿主读取）
   ↓
页面：Blob URL 动态 import() 并渲染
   ↓
report_module_host 回执 loaded → runtime ready
```

### 3.3 Skills 调用（可选增强）

下方 HTTP Skill 服务调用流是 D016 前的历史参考，不能代表当前 Skills 能力。当前 D016 流程为：读取经校验、固定版本/hash 的 `SKILL.md` 内容包 → 作为受控上下文准备给 Workbench task；Skills 文本本身不执行 HTTP/CLI 或获得工具权限。

```
用户发起对话，选择 Skill
   ↓
WorkbenchService.send_message()
   ↓
1. ProvidersManager.call() → LLM 响应
   ↓
2. SkillsManager.call_skill(skill_id, response)
   ↓
HTTP 请求到 Skill 服务
   ↓
Skill 处理（如格式化、增强）
   ↓
返回增强后的结果
   ↓
合并展示给用户
```

## 4. 数据流

### 4.1 用户数据隔离

用户由宿主会话解析，不由前端传入：尚无账户时为 `default-user`，有账户时为已登录账户（FR-008，接口契约 §2.1、§9）。数据以单个 `dgos.db` 中各表的 `user_id` 字段隔离。旧目标设计中的“JWT Token（包含 user_id）→ 所有请求携带 Token”流程作废（D053）。当前流程如下，统一边界见 [服务与领域边界 §3.5](../服务与领域边界.md#35-auth统一身份与安全边界fr-008009010)：

```
桌面窗口 / 模块调用通道 / LAN handler
   ↓ 请求不携带用户身份
宿主会话解析器 `SessionResolver`（无账户为 default-user；有账户为登录用户）
   ↓
HostExecutionContext（用户 + 来源 + request_id）
   ↓
Application Service → Repository：WHERE user_id = ?
```

### 4.2 模块权限检查（四层，见 [FR-009 §2.4](../../03-功能规格/V1/03-系统功能/09-模块权限管理.md#24-四层权限模型与生命周期语义2026-10-31)）

```
模块调用 host.providers.call → module_call_provider（类型化通道）
   ↓
1 准入：(module_id, version, integrity) 在 BUILTIN_PINS 中  → 否：1004021
2 manifest 上限：当前 manifest 声明了 providers.call        → 否：1004004
3 用户授权：module_permissions 中当前用户已授予（逐次读库）  → 否：1004004 + denied 审计
4 runtime：已启用、ready、路由有效、在途 ≤ 8、120 秒期限     → 否：1004004 / 1001005 / 1001006
   ↓
执行能力
```

## 5. 技术特性

### 5.1 模块热更新

**现状（D042、D055、D098）**：V1 不使用 Module Federation 插件（D098 移出 V1 范围，后续可选的加载适配，不承诺版本），也不加载任意远程 JavaScript。模块入口源码由宿主在 Rust 侧读取并校验，经指令通道交给主窗口页面，用 Blob URL 做原生动态 `import()`，在主 realm 内执行，只共享 `host.React`。热更新的新实例先加载、旧实例后卸载，状态只在页面内存中经 `onBeforeUpdate`/`onAfterUpdate` 交接，失败回滚。准入边界是编译进宿主的固定清单（D041/D052）；同 realm 不是安全沙箱。下面的 Federation 代码是 D004 的历史规划草图，不是现状。

```javascript
// 模块定义
export default {
  name: 'my-module',
  filename: 'remoteEntry.js',
  exposes: {
    './App': './src/App',
  },
  shared: ['react', 'react-dom'],
};

// 动态加载
const module = await import('http://localhost:3001/remoteEntry.js');
```

### 5.2 流式响应

**实现**：Tauri `Channel`（D042）。调用方创建 `Channel` 并作为命令参数传入，宿主只向它推送，不使用 `emit`/`listen` 全局事件；Provider 流见接口契约 §5.2，聊天流见 §10.1。局域网远程的流式响应使用 WebSocket（D013，FR-010，未实现）。

```rust
// 后端（示意，真实实现见 src-tauri/src/provider_streams.rs）
on_event.send(ProviderStreamEvent::Delta { text })?;
```

```typescript
// 前端
const onEvent = new Channel<ProviderStreamEvent>();
onEvent.onmessage = (event) => appendToMessage(event);
await invoke('call_provider_stream', { providerId, modelId, request, onEvent });
```

## 6. 非功能特性

### 6.1 性能

| 指标 | 目标 | 实现方式 |
|------|------|---------|
| 启动时间 | < 2s | Rust 编译优化 + 懒加载 |
| 模块加载 | < 1s（规划目标） | 可信模块 runtime（D042；未做性能度量） |
| command 响应 | P95 < 200ms（规划目标） | 异步 I/O + 本地 SQLite |
| UI 帧率 | > 60fps（规划目标） | React 19 |
| 内存占用 | < 200MB | Rust 无 GC + 按需加载 |

### 6.2 安全

| 层次 | 措施 |
|------|------|
| **后端** | Rust 内存安全 + 参数化查询 |
| **认证** | 桌面本地账户（FR-008，Argon2id，会话只在宿主内存）已实现；局域网访问凭据 + 会话（FR-010，D053）未实现；任何入口都不使用 JWT |
| **权限** | 模块级粗粒度权限检查 |
| **数据** | Provider/MCP 凭据使用 OS vault（D023），不是 AES-256/SQLite 加密 |
| **前端** | Tauri CSP + XSS 防护 |

### 6.3 可维护性

| 措施 | 说明 |
|------|------|
| **强制模块化** | Rust 编译期保证，单文件 < 1000 行 |
| **类型安全** | Rust + TypeScript 端到端类型安全 |
| **文档驱动** | spec-docs-pro 规格驱动开发 |
| **自动化测试** | 单元测试 + 集成测试 + E2E |
| **CI/CD** | 尚未配置 CI；自动检查为规划 |

所有架构决策记录在 [V1 冻结决策](../../06-决策记录/V1-冻结决策.md)：

- **D002**：SQLite 而非 PostgreSQL

- **D006**：粗粒度模块级权限
- **D007**：局域网服务始终开启
- **D008**：统一设计系统强制复用
- **D009**：无限画布分多版本实现
