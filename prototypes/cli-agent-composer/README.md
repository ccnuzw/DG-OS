> 设计草案，2026-11-10。依据用户六张参考图及“先进行设计”的要求制作。本目录是独立、可交互的设计交付，不进入生产构建。所有模型、能力、用量和发送结果均为演示数据；不调用 CLI、不保存凭据、不授予真实权限。刷新重置演示状态。本文是本轮设计规则的唯一工作稿，不提升生产实现状态。

## 打开与评审

直接打开 [index.html](index.html)，或在项目根目录运行：

```sh
python3 -m http.server 4186 --bind 127.0.0.1 --directory prototypes/cli-agent-composer
```

访问 `http://127.0.0.1:4186/`。顶部评审条的六个按钮分别对应参考图，不属于生产界面。也可使用 `?scene=permission`、`model`、`reasoning`、`settings`、`usage` 或 `rest` 直接进入对应画面。

## 设计结论

进入已打开项目的活动工作区即自动信任该工作区，取消输入区授权按钮和二次信任弹窗。选择 Provider／模型后即可选择推理强度。正常界面不再显示能力准备说明、协议限制长文、原生已确认设置、数据来源、未确认等诊断文字。

输入框保持两行消息区；底栏左侧为附件、偏好设置，右侧依次为运行模式、模型、脑形图标与档位、分隔线、用量环和发送。项目及分支位于框外下方。模型与推理共享轻量选中底色，菜单向上展开；点击外部或 Esc 关闭，键盘焦点回到入口。设置菜单内切换偏好和推理滑杆调整后保留弹层，运行模式和模型选择后立即关闭。

截图中的“向所有智能体提问”对应多智能体分发；DG-OS 当前对话是单会话，使用“向智能体提问…（@ 文件，/ 命令）”。不把参考产品的多智能体语义混入当前发送行为。

## 自动信任规则

用户已明确选择自动信任，本稿不再把是否自动信任作为待选项。实现应由宿主记录可信打开动作，不能仅删除前端弹窗或永久传 `trust_workspace: true`。

1. 用户打开项目并进入其活动工作区，宿主解析当前账户、项目、workspace 和真实目录身份，为该精确工作区建立 Agent 信任；同一身份重复进入幂等，不重复询问。
2. 已打开项目首次进入新版 CLI Agent 时，也按同一规则自动补建授权，不要求重新打开项目。隐藏的历史标签不自动启动 CLI；进入活动工作区只建立信任，选定 Provider／模型后自动准备所需原生能力。
3. 用户明确选择另一个 workspace／worktree 时，宿主按该目标的真实身份自动建立信任，不继承父目录或同名路径的授权。目录被替换、已删除或路径失效时显示“工作区已变化，请重新打开”；用户重新打开后自动信任，无额外确认。
4. 信任包括允许该 CLI 加载当前工作区的原生配置、Hooks 和 MCP，并启动其原生准备流程；这一事实在项目设置的权限说明中可查，输入区不显示常驻说明。
5. 手动撤销是显式拒绝，普通重绘／切标签不能自动反授予。撤销后显示一行“此工作区已停用 Agent”及“重新启用”；点击重新启用直接授予，取消额外确认。重新打开前也不得用隐藏预备进程绕过撤销。
6. 直接终端、独立服务、账户切换、归属和目录身份校验维持自己的边界；自动信任 Agent 工作区不授权其他账户或任意目录，也不把原生待审批操作视为已批准。

## Provider、模型与推理

配置继承继续采用已有会话 > 项目默认 > 应用默认。平台切换只过滤目录，Provider 选择只确定待选来源；点击模型才提交完整 Provider／model 绑定，成功关闭。失败保留弹层、搜索和输入草稿，只在失败项旁显示短错误。

后台能力准备不再依赖额外信任操作。已知能力配置可在首发前直接选择并保存意图；能力加载中允许继续输入，推理弹层只显示一行“正在读取可用档位…”。准备完成后显示实际档位；无需再点“连接”“授权”或“应用”。

参考采用关／低／中／高／超／极六档；生产由实际 CLI、模型与协议的能力返回生成刻度。`关`必须真实支持禁用推理，不能映射成原生默认；`超`／`极`只有存在相应可执行档位才出现。没有可调档位时入口保留脑形图标，悬停或点击显示一句“此模型不支持调整”；加载失败显示“读取失败 · 重试”。不会为凑六档按模型名称猜参数。

选中后入口立即回显草稿值，下一次显式发送提交；失败保留选择与消息，错误就地展示。正常状态不显示“未确认”或原生回执字段。正在执行的回合不追改参数；暂锁相关控件并以悬停提示“本轮完成后可调整”。旧会话换 Provider／CLI 涉及新会话时，保留草稿并明确“在新对话中使用”，不得伪装为原会话无缝换引擎。

## 五种运行模式

界面采用一个菜单，底层分别保存任务方式和执行权限。推理强度是独立维度，选择“深度”不自动修改推理档位。

| 模式 | 设计目标 | 落地要求 |
| --- | --- | --- |
| 手动确认 | 修改文件、执行命令和外部工具按需逐次确认；读取沿原生可信规则 | 不承诺读取操作也逐项弹窗；菜单短说明需与实际审批策略保持一致 |
| 自动编辑 | 工作区内文件编辑自动批准，其余操作仍按原生策略确认 | 对接真实 `accept_edits` 能力，不能把无关命令也自动批准 |
| 规划 | 分析后给出计划，用户确认执行前不修改文件、不运行有副作用的命令 | 允许必要只读查询；计划通过后返回进入规划前的执行模式。截图“完全不执行工具”不直接照搬为不真实保证 |
| 深度 | 进入规划，先澄清目标、比较方案，再产出计划；确认后执行 | 新增结构化任务方式；不得用“推理高”冒充深度流程，不使用普通 prompt 文字当权限约束 |
| 全自动 | 用户显式选择后，原生 CLI 支持范围内自动批准工具操作 | 菜单内明确风险，点击本身作为该会话授权，不再二次确认；仍保留账户、凭据及宿主目录边界，不能称为“跳过所有权限检查” |

全自动只属于当前会话，恢复必须重新校验同一账户、目录和有效授权，不能默认扩散到其他项目。选择模式不批准切换前已有的 pending 请求；等待审批时仍在原操作附近解决。

五项属于本次设计目标，不能在实现阶段静默砍成三项。某 CLI 缺少模式能力时应在该项上给简短不可用原因，已有会话不能自动迁移引擎。要将全部五项正式开放，需要完成协议适配及真实执行验证。

## 偏好与用量

- 响应语言和精简模式属于会话偏好，作用于后续回复；主题沿现有应用外观系统，不建立第二份主题存储。
- 下一步提示建议控制建议区显隐；跟随 AI 修改控制自动定位文件和滚动，用户手动浏览后不强拉回。
- 流式响应开关只改变展示方式，关闭时缓冲到回合结束；不改变 CLI 请求、取消、审批事件或失败语义。
- 代码高亮只改变渲染，不修改消息原文。偏好点击即更新，失败还原已确认值并显示短错误。
- 用量全部来自实际原生回执；缺失字段显示 `—`，不能填 0 或用演示值代替。上下文占用与累计 Token 是不同统计，缓存是否包含在累计输入中按来源计算，不重复求和。
- 压缩按钮仅在 CLI 支持且会话空闲时可用；调用真实原生压缩，完成后由新回执刷新占用。失败保留原数值，不能前端直接减少进度条。
- 原型中设置开关只验证交互状态，主题可实际切换；压缩只演示占用变化，发送只产生明确标注的演示回执。@ 文件、/ 命令及原生执行链继续由现有生产组件承接，本原型不冒充这些能力已实现。

## 实施验收目标

1. 已打开项目进入对应活动 workspace，选模型后无需任何信任确认，可在第一条消息前设置支持的推理档位并真实生效。
2. 模式／模型／推理入口与六图结构一致；正常输入区不存在用户要求删除的诊断文字，选中后无需额外应用按钮。
3. 五种模式具有上述可观察行为；全自动实际原生生效但不越过宿主边界，规划／深度在计划获准前不能产生写入副作用。
4. 模型切换、能力失败、权限撤销、目录替换、快速切项目与账户时，不丢草稿、不串设置、不迟到启动旧工作区。
5. 所有弹层支持鼠标、键盘与 Esc；窄窗不溢出，焦点可见，图标有可访问名称。生产复用用户主题、字号和布局缩放。
6. 用量、压缩、偏好均由真实数据和行为驱动；原型验证不能替代两家真实 CLI、Tauri IPC 与桌面验证。
